# AMOS OS Architecture Audit — 2026-09-04

## Conclusion
The vault has a strong governance/runtime spine but is not yet MECE at the cognitive-organism/detail level. The most serious defects are not missing folder names; they are empty or shallow organ implementations, mixed taxonomic axes, duplicate navigation surfaces, and incomplete transformations between knowledge/context/evidence/provenance/causal/world-model graphs.

## Verified structural findings
- Root already distinguishes physical storage, functional ownership, authority precedence, runtime order and epistemic status.
- `05_COGNITIVE_ORGANISM` declares a rich organ registry, but multiple declared organ folders are empty (including Cognition, World Model and Identity at audit time).
- `25_COGNITIVE_MATRIX` exposes a 30×17×9×3 interaction space, but its status percentages are rule-derived architecture coverage, not empirical implementation completeness.
- Memory is substantially stronger than the empty cognitive organs: semantic classes, lifecycle, provenance, contradiction, freshness and retrieval firewalls are defined.
- Root contains several legacy/home/MOC compatibility notes. These are navigation debt unless explicitly marked redirect/legacy rather than parallel authority.

## MECE repair
AMOS should be represented on orthogonal axes, never as one flat hierarchy:
1. **Authority axis:** Canon → Policy/Governance → Control/Commit → Effect.
2. **Cognitive-function axis:** Perception → Attention → Representation/Binding → Workspace → Reasoning → World/Causal Model → Simulation → Value/Goal → Planning/Decision → Action → Outcome → Learning/Reflection.
3. **Execution axis:** Kernel primitives → Engines → Agents → Skills → Workflows → Tools/Interfaces.
4. **Information axis:** Observation → Evidence → Memory → Knowledge → Model → State → Decision record.
5. **Assurance axis:** Provenance → Security → Observability → Tests → Operations → Archive.
6. **Scale axis:** H/M/L recursive decomposition.
7. **Lifecycle axis:** create/admit/use/revalidate/commit/observe/learn/consolidate/retire/repair.

No item may gain authority merely because it appears “higher” on another axis.

## Graph substrate correction
Do not use `graph` as one generic architecture object. Define typed graph families:
- Entity/Ontology Graph — what things and relations are represented.
- Context Graph — minimum decision-relevant working subgraph.
- Evidence Graph — evidence atoms and support/contradiction relations.
- Provenance Graph — ancestry, transformation and correlation topology.
- Dependency/Proof Graph — load-bearing premises and invalidation closure.
- Causal Graph — explicitly typed causal hypotheses/edges.
- Temporal/Event Graph — events, intervals, ordering and epochs.
- State Graph — versioned current/historical conditions.
- Goal/Plan Graph — objectives, subgoals, constraints, plans and rollback points.
- Authority Graph — identities, grants, scopes, delegations and revocations.
- Memory Lineage Graph — encoding, consolidation, supersession, forgetting.
- World Model Graph — entities, latent variables, transition rules and uncertainty.

Key invariant: `ContextGraph != ProofGraph`. The context graph optimizes cognition; the proof graph justifies conclusions. Validation may expand beyond initial context.
