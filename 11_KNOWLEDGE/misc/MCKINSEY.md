Formula for McKinsey-Style Decks

0. First principle: each slide is a decision machine

These decks are not “presentation slides” in the normal sense. They are compressed executive reasoning units.

Each slide is built to answer:

What is the answer? Why is it true? What should leadership do next?

The uploaded EX deck uses this pattern across employee experience: context, urgency, value case, lifecycle, journey redesign, operating model, sprint agenda, enablers, and proof cases. It emphasizes journeys, personas, moments that matter, transformation roadmap, operating model, and measurement discipline.  

The SME revenue-pool deck uses the same logic but with a more analytic/data-heavy style: market sizing, segmentation, heatmaps, revenue pools, sector cuts, clusters, and prioritization.  

So the true formula is:

Executive slide = answer headline + structured exhibit + quantified evidence + implication

Not decoration. Not storytelling only. Decision compression.

The headline must be a sentence with a claim.

Not:

The headline should usually contain:

actor
action
insight
implication

[Subject] + [verb] + [insight] + [business implication]

Everything must align to a grid.

Use numbers to anchor credibility

Even conceptual slides benefit from numbered steps, stages, or dimensions.

Use color sparingly

Color should mean category, priority, risk, or movement — not decoration.

Use white space as hierarchy

The slide can contain many objects if the viewer still knows where to look first.

5. MECE Principle
MECE means:
Mutually Exclusive, Collectively Exhaustive
It is the logic discipline that prevents overlap and gaps.
Mutually Exclusive
Each category should be distinct.
No double counting.
Collectively Exhaustive
Together, the categories should cover the whole problem.
No missing areas.
Example: bad segmentation for mobility:
Cars
EVs
Public transport
Motorbikes
Urban transport
This is not MECE because EVs can be cars, motorbikes, buses, or fleets. Urban transport overlaps with all modes.
Better MECE segmentation:
1. Passenger mobility
2. Freight and logistics mobility
3. Enabling infrastructure
4. Policy and governance
5. Financing and market mechanisms
6. Digital and data platforms
Or mode-based MECE:
1. Two-wheelers
2. Passenger cars
3. Buses and mass transit
4. Rail
5. Freight trucks
6. Last-mile delivery
7. Non-motorized mobility
The choice of MECE structure depends on the strategic question.

0. The Core Correction

4. Hypothesis Portfolio Layer
What possible answers are we testing?
Junior consultants write one hypothesis.
Senior teams build a portfolio of competing hypotheses.
This is critical because strategy is not about proving your first idea. It is about testing strategic options against evidence.
Hypothesis portfolio equation
Hypothesis Portfolio =
Base case
+ Upside case
+ Downside case
+ Contrarian case
+ No-regret case
For Vietnam mobility:

H3: EV ecosystem acceleration should be the national anchor
H4: Logistics productivity should be prioritized over passenger mobility
H5: Incremental infrastructure improvement is safer given execution constraints
The deck must test these, not simply assert one.
No overlap with decision architecture: decision architecture defines what leadership must choose; hypothesis portfolio defines possible answers.

5. Decomposition Layer
How is the problem broken down without gaps or overlap?
This is where MECE belongs, but MECE is only one part.
The decomposition layer has three tools:
1. Issue tree
2. Driver tree
3. System map
They are not the same.
5.1 Issue tree
Breaks the strategic question into questions.
What must we know?
5.2 Driver tree
Breaks value or performance into causal drivers.
What mathematically drives the outcome?
5.3 System map
Shows actors, dependencies, flows, and constraints.
How does the system actually work?
No-overlap distinction
Issue tree = questions
Driver tree = economics / causality
System map = relationships and dependencies
For Vietnam mobility:
Issue tree:
What demand, bottlenecks, options, and execution model matter?

Driver tree:
Mobility value = demand × access × reliability × affordability × productivity × emissions reduction ÷ system friction

System map:
Citizens, cities, logistics firms, vehicle OEMs, charging providers, grid operators, ministries, investors, data platforms, public transit operators
This is the actual consulting problem-solving engine.

8. Insight Synthesis Layer

This is where elite consulting separates itself.
Analysis produces facts. Synthesis produces meaning.
A junior slide says:

“Congestion is not only a transport issue; it is becoming a productivity, emissions, logistics, and urban-competitiveness constraint, making corridor-level intervention more valuable than dispersed infrastructure spending.”
Insight equation

Observation
+ Pattern
+ Root cause
+ Implication
+ Action consequence
Bad insight
EV adoption is growing.

EV adoption will remain constrained unless charging, financing, grid readiness, and fleet conversion are sequenced as one ecosystem rather than treated as separate initiatives.
This is what clients pay for: not the fact, but the synthesized implication.

3. Comparable
4. Decision-relevant
5. Strategically meaningful
No overlap with hypothesis portfolio: hypotheses are beliefs to test; options are designed choices to decide among.

Recommendation equation

Do not pursue:

- digital mobility pilots without data governance

This is important. Strategy is as much about exclusion as inclusion.
