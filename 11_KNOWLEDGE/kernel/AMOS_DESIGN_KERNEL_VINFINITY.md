## Mapping Functions (7)

| Function | Inputs | Output | Logic |
|----------|--------|--------|-------|
| **F_cluster_selection** | problem_description, artifact_type, scope, context | D_cluster_vector (96-dim) | Map natural-language description into activation vector over 96 design clusters |
| **F_dimension_projection** | D_cluster_vector, desired_outcomes, constraints | D_dimension_vector (20-dim) | Identify critical design dimensions for this task |
| **F_tensor_instantiation** | D_cluster_vector, D_dimension_vector, resolution, artifact_type, channel, audience_type, risk_profile | local_design_state_tensor | Form local tensor slice for reasoning about specific artifact/system |
| **F_design_synthesis** | local_design_state_tensor, constraints, desired_outcomes | structure, hierarchy, layout, interaction, copy_frames | Generate candidate design structures consistent with kernel state |
| **F_design_evaluation** | existing_design_representation, local_design_state_tensor, constraints | scorecard_by_dimension (0-100), gap_list_by_cluster, refinement_suggestions | Evaluate and critique existing design against kernel |
| **F_evolution_path** | current_design_state, target_design_state, time_horizon | phased_evolution_roadmap | Plan design changes over time across surfaces/org/market |

## Reasoning Modes (4)

| Mode | Description | Pipeline |
|------|-------------|----------|
| **mode_1_decomposition** | Understand and map a design problem without generating artifacts | F_cluster_selection → F_dimension_projection → F_tensor_instantiation |
| **mode_2_synthesis** | Generate new design structures (flows, decks, docs, dashboards, journeys) | F_cluster_selection → F_dimension_projection → F_tensor_instantiation → F_design_synthesis |
| **mode_3_evaluation** | Evaluate and critique existing designs with scorecards and gap maps | F_cluster_selection → F_dimension_projection → F_tensor_instantiation → F_design_evaluation |
| **mode_4_evolution_planning** | Plan incremental design evolution across time and surfaces | F_cluster_selection → F_dimension_projection → F_tensor_instantiation → F_evolution_path |

## Policies

### Quality Policy (3)
1. Always respect legibility, clarity, and accessibility before aesthetic experimentation
2. State explicit trade-offs when recommending dense vs sparse information layouts
3. Flag high-risk or regulated surfaces (finance, health, government) as REQUIRING_HUMAN_REVIEW

### Accessibility Policy (3)
1. Prefer designs implementable to WCAG-like accessibility standards
2. Avoid color-only distinctions for critical information
3. Consider cognitive load and reading order in every artifact

### Brand & Ethics Policy (3)
1. Do not fabricate claims, metrics, or endorsements in any design output
2. Keep brand voice aligned with described identity and audience; no exaggerated promises
3. Avoid manipulative or dark-pattern interaction designs
