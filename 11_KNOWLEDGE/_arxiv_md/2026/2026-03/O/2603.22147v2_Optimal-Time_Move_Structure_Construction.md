Abstract
The move structure represents a permutation π of [0, n) as a covering set of O(r) disjoint intervals
(contiguous subsets of [0, n)), where r is the minimum number of intervals whose values permute
together. Formally, r = 1 + |{i ∈[1, n) : π(i) −1 ̸= π(i −1)}|. The move structure takes O(r) words
of space. Given the index of the interval containing i, it allows computing π(i) and the index of
the interval containing π(i) in O(1)-time. Therefore, for permutations where r ≪n, it allows their
representation and navigation in significantly compressed space. The previous best O(r)-space move
structure construction algorithm takes O(r log r)-time. In this paper, we describe a construction
algorithm achieving optimal O(r)-time and space. We also show that using our improved algorithm
within a recent previous work allows the computation of the longest common prefix array in O(r)-
working space and optimal O(n)-time given the run-length-encoded Burrows-Wheeler transform.
Finally, we implement our improved move structure construction algorithm and find that it is faster
than the previous best algorithm while using comparable memory.

Introduction
Nishimoto and Tabei’s move structure [14] represents a “runny” permutation in compressed
space. For any permutation π over a domain [0, n), let r = 1+|{i ∈[1, n) : π(i)−1 ̸= π(i−1)}|
be the minimum number of contiguously permuted disjoint intervals covering [0, n). The move
structure represents π in O(r) words of space while allowing constant time evaluation of π(i)
given the index of the interval that contains i. Bertram, Fischer, and Nalbach [4] described
the current fastest move structure construction algorithm, taking O(r log r)-time and O(r)-
space. The move structure has been used extensively in recent algorithmic developments
using Burrows-Wheeler transform (BWT) based compressed text indexing strategies.
The BWT [7] forms the basis of many efficient algorithms and applications in text
compression, indexing, and pattern matching.
When computed over a repetitive text
collection of total length n, its run-length encoded BWT (RLBWT) contains relatively fewer
runs r. Hence, many techniques have been developed in compressed O(r)-space [8,14] which
often grows sublinearily with respect to n. This is true for collections of DNA sequencing
data, and thus the RLBWT is often used for applications in genomics. Indeed, the length of
the text can reach the order of trillions on pangenome sized collections [11,16,20,21] and
thus RLBWT-based data structures are commonly used.
Indexes built on repetitive texts rely on the RLBWT-based permutations LF, FL, ϕ and
ϕ−1 to perform efficient pattern-matching queries. These permutations can be represented
as a move structure in O(r)-space while achieving O(1)-time queries for a permutation
step [4,8,17]. Recently, Sanaullah et al. [16] showed how to compute the longest common
prefix array (LCP) from an RLBWT in O(n + r log r)-time and O(r)-space using move
structures for these permutations. Their technique, which has many applications to matching
algorithms and data structure construction, depends on the optimal-time guarantees of a
single move query to achieve their time complexity.
However, the O(r log r)-time construction of a move structure can be a bottleneck in the
complexity of algorithms which use them. Indeed, the O(r log r)-time factor in Sanaullah et
al.’s [16] method is the result of move structure construction. In this paper, we provide an
optimal O(r)-time and space move structure construction algorithm. Therefore, we also give
the first optimal O(n)-time algorithm to compute the LCP array from the RLBWT in O(r)
working space, illustrating the usefulness of move structure construction to other algorithms.
Finally, we implement our algorithm and find that on RLBWT-based permutations it has
improved runtime and comparable memory to the previous best algorithm.

Preliminaries
2.1
Notation
An array A of |A| = n elements is represented as A[0..n −1]. A predecessor query on
an array/set is defined as A.pred(x) = max{y ∈A | y ≤x} and a successor query as
A.succ(x) = min{y ∈A | y > x}. Over a set of distinct elements, j = A.rank(x) refers to the
index of y = A.pred(x) in sorted order and we use the notation A[j] = y to access this value.
A string S[0..n −1] is an array of symbols from an ordered alphabet Σ with |Σ| = σ. Let
S[i..j] represent the substring S[i] . . . S[j]. A prefix of S is a substring S[0..j], where a suffix
is some substring S[i..n −1]. Let lcp(S1, S2) denote the length of the longest common prefix
between strings S1 and S2. A text T[0..n −1] is assumed to be terminated by the special
symbol $ /∈Σ of least order so that suffix comparisons are well defined. We use the word
RAM model, assuming machine words of size W = Θ(log n) with basic arithmetic and logical

2.2
Suffix Array and Burrows-Wheeler Transform
The suffix array (SA) of a text T[0..n −1] is SA[0..n −1] such that SA[i] is the starting
position of the ith lexicographically smallest suffix of T. The inverse suffix array (ISA) is
its inverse such that ISA[i] is the lexicographic rank of the ith suffix in T. The Burrows-
Wheeler Transform (BWT) [7] is a permutation BWT[0..n −1] of a text T[0..n −1] such
that BWT[i] = T[(SA[i] −1) mod n]. The BWT is reversible by using the last-to-first (LF)
mapping LF(i), a permutation over [0, n −1] satisfying SA[LF(i)] = (SA[i] −1) mod n. The
first-to-last (FL) mapping is its inverse satisfying SA[FL(i)] = (SA[i] + 1) mod n. Let r be
the number of maximal equal character runs of the BWT. The run-length encoded BWT
(RLBWT) is an array RLBWT[0..r −1] of tuples where RLBWT[i].c is the character of the
ith BWT run and RLBWT[i].ℓits length.
The permutation ϕ over [0, n −1] is defined such that ϕ(SA[i]) = SA[(i −1) mod n],
returning the SA value for the suffix of preceding lexicographic rank. Its inverse ϕ−1 is defined
symmetrically such that ϕ−1(SA[i]) = SA[(i + 1) mod n]. The longest common prefix array
(LCP) stores the lcp between lexicographically adjacent suffixes in T[0..n−1], i.e., LCP[0..n−1]
such that LCP[0] = 0 and LCP[i] = lcp(T[SA[i −1]..n −1], T[SA[i]..n −1]) for i > 0. The
permuted LCP array (PLCP) reorders the LCP array such that PLCP[i] = LCP[ISA[i]]. An
irreducible LCP is an LCP[i] where i is the start of a BWT run, and an irreducible PLCP is
its equivalent PLCP[SA[i]]. We refer to the arrays of irreducible LCP and PLCP values as
LCP+[0..r −1] and PLCP+[0..r −1] respectively.
2.3
LCP Array from RLBWT
Kasai et al. [10] gave the first optimal-time O(n) algorithm to construct the LCP array from
the SA/BWT. Kärkkäinen, Manzini, and Puglisi [9] then introduced the ϕ algorithm which
modified Kasai et al’s [10] method to instead first compute the PLCP array from which the
LCP array can be recovered. However, both approaches require constant-time random access
to the text and thus O(n)-space. The approaches of Beller et al. [3] and its extension by
Prezza and Rosone [15] avoid random access to the text by using a wavelet tree to compute
the LCP array from the BWT in O(n log σ)-time. This results in compact o(n log σ) bits of
working space in addition to the input/output.
Recently, Sanaullah et al. [16] showed how to compute the LCP array from the RLBWT
in O(n + r log r)-time and O(r) working space by modifying the ϕ algorithm using move
structures. They utilize that only the O(r) irreducible PLCP values are needed; when
sampled alongside a ϕ/ϕ−1 move structure, the remaining PLCP values can be recovered.
They also show how to simulate random access to T as required in the ϕ algorithm by using
a move structure for FL. However, a single step of the algorithm requires comparing symbols
from arbitrary positions in the text. Their key insight is that with a proper sampling of ISA
values in O(r)-space, they can apply the ϕ algorithm by jumping to the correct position in a
move structure for FL in O(n)-time and O(r)-space to compute the irreducible PLCP values.
However, the overall time complexity of this approach inherits the O(r log r)-time con-
struction bottleneck of a balanced move structure needed to support FL queries, resulting in
O(n + r log r)-time and O(r) working space to compute the LCP array from an RLBWT.
Although length capping [6] has shown that certain RLBWT operations involving O(n)
consecutive move queries, such as suffix array enumeration and BWT inversion, can be done

2.4
Move Structure
For a permutation π over {0, . . . , n −1}, let P be the set of r distinct positions such that
either i = 0 or π(i −1) ̸= π(i) −1. For simplicity, let P[r] = n so that the domain of the
permutation is captured by P without needing to store n alongside it. This defines a disjoint
set of intervals, where, for any j ∈P, the jth input interval with length ℓ= P[j + 1] −P[j] is
defined as [P[j], P[j+1]). By definition of P, input intervals permute contiguously such that if
position i belongs to the jth interval then π(i) can be computed as π(i) = π(P[j])+(i−P[j]).
However, finding which interval a given i belongs to would require a predecessor query on P
and hence ω(1) query time [2].
▶Definition 4. Given a permutation π over {0, . . . , n −1}, let P be the set of r distinct
positions such that either i = 0 or π(i −1) ̸= π(i) −1, extended with P[r] = n. Then P
defines the set of input intervals of π where [P[j], P[j + 1]) is the jth input interval.
If we assume that we have i and know the rank of its predecessor in P, i.e its input
interval, then Nishimoto and Tabei’s move structure [14] computes π(i) and the rank of π(i)’s
predecessor in P in O(r)-space and O(1)-time. Let Pπ = {π(i) | ∀i ∈P[0..r −1]}. Then,
knowing i belongs to interval j, we can easily compute π(i) = Pπ[j] + (i −P[j]). However, to
return the interval of π(i) without a rank query, they store Prank(π) = {P.rank(π(i)) | ∀i ∈
P[0..r −1]}; intuitively, the input interval containing Pπ[j]. Since π(i) ≥Pπ[j], we perform
a linear scan of P starting from position Prank(π)[j] until we find the largest rank j′ such
that P[j′] ≤π(i) to return the input interval containing π(i). This computation is referred
to as a move query.
▶Definition 5. For P with respect to a permutation π per Definition 4, then Pπ = {π(i) | ∀i ∈
P[0..r −1]} and Prank(π) = {P.rank(π(i)) | ∀i ∈P[0..r −1]}.
▶Definition 6. For a permutation π over {0, . . . , n −1} represented by the input intervals
P[0..r], a move query takes a position i ∈[0, n) and rank j ∈[0, r) of its predecessor in P,
and returns π(i) and the rank j′ = P.rank(π(i)) of its predecessor in P.
Move structures were created for use with RLBWT based permutations LF and ϕ as well as
their respective inverses FL and ϕ−1. As such, they can be represented in space proportional
to the number of BWT runs [14]. Given the RLBWT as input, these permutations can be
constructed in O(r)-space.

3
Optimal Move Structure Balancing
We present an optimal-time and space move structure construction algorithm which satisfies
the balancing criterion described by the proof of Nishimoto and Tabei’s original theorem [14],
improving on the O(r log r)-time and O(r)-space balancing of of Bertram, Fischer, and
Nalbach [4]. The algorithm relies two key insights. First, we maintain linked lists instead of
balanced search trees to support balancing operations. This requires us to replace explicit
predecessor queries by instead using satellite data to compute them when required. Second,
we balance π and π−1 simultaneously, whereas previous methods balanced only π. This
results in an algorithm taking optimal O(r)-time and space.
3.1
Linked Lists
We maintain two linked lists with respect to a permutation π: P, representing the input
intervals P, and Q, representing the output intervals Q. Mappings between input and output
intervals are described by τ and τ −1. Finally, predecessors of starting positions of intervals
in one set with respect to the other are maintained to emulate predecessor queries. The
components of P and Q are defined explicitly in Definition 16.
▶Definition 16. The linked lists P and Q are initialized to r nodes with respect to P, Q
where |P| = |Q| = r such that the jth node p ∈P contains:
p.next pointing to the node corresponding to the (j + 1)th input interval,
p.idx = P[j],
p.τ pointing to the node corresponding to τ(j) in Q,
p.predQ pointing to the output interval k = Q.rank(p.idx) in Q,
and the kth node q ∈Q contains:
q.next pointing to the node corresponding to the (k + 1)th output interval,
q.idx = Q[k],
q.τ −1 pointing to the the node corresponding to τ −1(k) in P,

3.2
Algorithm Description
We proceed using a modification of the balance-on-the-fly approach of Bertram, Fischer,
and Nalbach [4], iterating left to right over the intervals. Heavy intervals are balanced
during this scan, or when they are created by an insertion into an already-balanced portion
of the intervals. We maintain the balanced-up-to parameter t ∈[0, n] initialized to 0 and
incremented during balancing until we finish. Since we balance left to right in both P and Q
simultaneously, this maintains the invariant that any intervals in P or Q starting before t
must not be heavy up to either the end of their ranges or the position t.
▶Definition 20. Assume the balanced-up-to parameter is t. Then for arbitrary p ∈P, if
p.idx < t, then | (p.idx, min(t, p.next.idx)) ∩Q| < 2α. Similarly, for arbitrary q ∈Q, if
q.idx < t, then | (q.idx, min(t, p.next.idx)) ∩P| < 2α.
We maintain pointers to pt ∈P and qt ∈Q which are the respective input and output
intervals containing the current t. At each iteration, we select either pt or qt to balance,
choosing the one with the minimum starting position. If tied, we choose the longer interval
to balance. If they have the same length then they are already balanced by definition and we
advance both pointers. Then, we begin a balancing step if the interval is heavy by making
the initial insertion, and then make the corresponding insertion in the other list using τ or
τ −1 and recurse if necessary as in Section 2.4.1. We explain how to update t later, but note
that we always increase it upon completion of an iteration.
The intuition behind balancing in both directions is that we can obtain O(1)-time
maintenance of predecessor pointers if the corresponding insertion using τ or τ −1 is at a
position less than t. Otherwise, when inserting at a position greater than or equal to t, we
maintain all pointers except predecessors. However, our left-to-right scan of the intervals can
amend these as we reach them, since updating pt and qt requires following next pointers up
to the next pt and qt. During this update, we can recover predecessor information similar to
the initialization of Lemma 19. Thus, we also maintain the invariant that our predecessor
pointers up to and including pt and qt are always maintained.
▶Definition 21. Assume pt ∈P and qt ∈Q are the respective nodes containing t. Then for
arbitrary p ∈P, if p.idx ≤t, then p.predQ is correctly maintained. Similarly, for arbitrary
q ∈Q, if q.idx ≤t, then q.predP is correctly maintained.
We must show that we perform the necessary balancing steps as outlined in Section 2.4.1
using our linked lists while maintaining P and Q pointers and the balanced-up-to invariant.
Assume we are at some step in the iteration and w.l.o.g. that we choose to balance qt ∈Q.
That is, we perform the inverse operation if selecting pt ∈P where the same arguments hold.
First, we show how to perform the balancing operation and any recursive steps necessary to
maintain the invariants with t in O(1)-time per step. Then, we show how to update t, qt
and pt such that predecessor information is maintained and the invariants hold.

3.3
Balancing Step
First, we prove that each balancing step (meaning an insertion into P and Q is required)
takes O(α)-time and maintains the invariants.
▶Lemma 22. Assume w.l.o.g. we are balancing qt, then we can maintain the invariants
of Definitions 20 and 21 up to the current t in O(α) = O(1)-time per interval inserted.
Proof. Let qs = qt.idx and qe = qt.next.idx. We compute the weight |(qs, qe) ∩P| by
accessing p′ = qt.predP and iterating over p′.idx using p′ = p′.next until we reach p′.idx ≥qe
or the weight exceeds 2α; this takes O(α)-time. If the output interval is heavy, we recover
the (α + 1) largest element x in (qs, qe) ∩P during this scan. Then, we insert node qx
corresponding to [x, qe) into Q and update next pointers while setting qx.idx = x. Let
p = qt.τ −1 with ps = p.idx, pe = p.next.idx, and x′ = ps + (x −qs). We insert node px′
corresponding to [x′, pe) into P and update next pointers. Finally, we set px′.idx = x′ and
can now update the τ pointers with qx.τ −1 = px′ and px′.τ = qx. These insertion and update
steps into the linked lists are O(1)-time in total.
If x′ ≥t, then we are finished balancing and the invariant of Definition 20 is maintained. If
x′ < t, then we must also update the px′.predQ pointer and check if balancing is maintained.
Since px′.idx = x′ < t, then ps < t and by the invariant of Definition 21 we can use
the predecessor pointer to let q′ = p.predQ. Since the invariant of Definition 20 holds,
|(ps, pe) ∩Q)| ≤2α. Thus, we can perform an O(α)-time scan using q′ = q′.next until we
find the largest q′.idx ≤x′, after which we set px′.predQ = q′. The same argument implies
that we can continue iterating using q′ = q′.next where x′ ≤q′.idx < pe to update their
predecessor pointers to q′.predP = px′ where necessary in O(α)-time.
Overall, these balancing operations for a single step are all O(α)-time. Further, we
identify whether recursion on the initial q′ = p.predQ is required for balancing by checking
if it is heavy during an O(α)-time scan over nodes in P. Since recursive work to maintain
invariants is identical to above, each step takes O(α)-time; we continue with recursive steps
whenever x′ < t until balanced is maintained, or we stop whenever some insertion is at
position x′ ≥t. Thus, the overall work is O(α)-time per interval inserted.

Update Step

▶Lemma 23. Assume w.l.o.g. we are balancing qt, then we can update t, qt and pt after
recursive balancing finishes such that we can maintain the invariants of Definitions 20 and 21.

6
Conclusion
We have described the first optimal O(r)-time and space move structure construction
algorithm. This improves on the previous best approach by Bertram, Fischer, and Nalbach [4]
using O(r log r)-time and O(r)-space. As a result of combining the improved construction
algorithm with the approach of Sanaullah et al. [16], we obtain the first optimal O(n)-time
LCP computation algorithm from an RLBWT in O(r) working space. Additionally, from an
RLBWT, we obtain in O(r)-space:
Optimal O(r)-time construction of balanced move structures for LF and FL,
O(n)-time construction of balanced move structures for ϕ and ϕ−1,
and an optimal O(n)-time algorithm for enumerating the LCP array.
Since the balancing algorithm described here balances with respect to both π and its
inverse π−1, a natural followup is to collapse both into a single move structure. That is, we
store the interval starts in P ∪Q. We call this an invertible move structure. Supporting move
queries in both directions currently requires two move structures with O(r)-space additional
satellite data for coordinate conversions. Possible benefits of the invertible move structure
include common coordinates for π and π−1 move queries without satellite data, computing
both π and its inverse in constant time, and removing the need for the “offset field” [5] in
practical implementations. We leave detailed investigation as future work.

In practice, our implementation and experimental evaluation of optimal move structure
balancing resulted in better runtime and comparable memory when compared to the previous
best method. Further optimizations, such as multi-threading and memory optimizations,
could result in even better practicality (for example, Move-r includes options for multiple
threads). Future work should explore substituting the improved move structure construction
into methods which rely upon it to measure how large the speedup is when compared to
overall computation of the algorithm.
A possible application of LCP computation from the RLBWT is Shivakumar and Lang-
mead’s [18] mumemto tool which computes maximal match queries with respect to a collection
of sequences. Given an RLBWT, its remaining bottleneck was LCP enumeration [6], where
we stream the output rather than save the entire LCP array. Our improvements provide an
O(n)-time and O(r)-space algorithm for mumemto, which may be of practical interest.
The current best known result for construction of the RLBWT from a given text in
O(r)-space is Nishimoto, Kanda, and Tabei’s [13] O(n + r log r)-time algorithm. Therefore,
the construction of move structures computing LF, FL, ϕ, ϕ−1 in O(r)-space from the text
remains O(n + r log r)-time. This work removes the move structure balancing bottleneck
from this time bound. Now, the only remaining obstacle to lowering these time complexities
is improving upon the result for RLBWT construction in O(r)-space.

To analyze improvements made with our O(r)-time balancing algorithm, we expand upon

A.1
LCP Array from BWT Background
The first algorithm computing the LCP array from BWT or SA in optimal O(n)-time was
an O(n)-space approach by Kasai et al. [10] using SA[0..n −1], ISA[0..n −1], and T[0..n −1].
From i = 0 →n −1 it compares suffix T[i..n −1] with its lexicographically preceding suffix
(the suffix starting at j = SA[(ISA[i] −1) mod n]). The suffixes T[i..n −1] and T[j..n −1]
are compared symbol by symbol until a mismatch occurs at T[i + ℓ+ 1] ̸= T[j + ℓ+ 1]
at which point we set LCP[ISA[i]] = ℓ. The key insight is that if ℓ> 1 symbols match at
iteration i, then at least ℓ−1 symbols match in iteration i + 1.
Consider that, if ℓ> 1, then for j = SA[(ISA[i] −1) mod n], T[i..n −1] = cwu and
T[j..n −1] = cwv have a shared prefix cw of length ℓwhere c is a single symbol and
u ̸= v. Since T[j..n −1] is the lexicographic predecessor of T[i..n −1], it follows that
T[j + 1..n −1] = wv is lexicographically smaller than T[i + 1..n −1] = wu. By property of
the suffix array, the lexicographically smallest suffix with the largest shared prefix for any
suffix is its predecessor. Therefore, T[i + 1..n −1] shares a matching prefix of length at least
ℓ−1, the string w, with its lexicographic predecessor since there exists a lexicographically
smaller suffix matching this length. Thus, we can safely skip ℓ−1 comparisons in iteration
i + 1 when LCP[ISA[i]] = ℓ. A consequence of this insight is that comparisons of equal
symbols occur at most n times (since each one increments ℓand i + ℓis non-decreasing from
0 →n −1) and character comparisons of non-equal symbols occur at most n times (since
each one increments i). Therefore at most 2n symbol comparisons occur, implying an overall
O(n)-time algorithm.
Notice that the access pattern to LCP is not sequential, and further that j = SA[(ISA[i]−1)
mod n] can be replaced with j = ϕ(i). The ϕ algorithm by Kärkkäinen, Manzini, and
Puglisi [9] is a variant of the algorithm of Kasai et al. [10] which constructs the PLCP array
first using ϕ. This allows them to omit ISA by taking as input T[0..n −1] and SA[0..n −1]
and constructing ϕ[0..n −1]. Using j = ϕ(i) they make the same comparisons as prior, but
now set PLCP[i] = ℓsequentially as i is incremented. The final LCP array is then computed
using the fact that LCP[i] = PLCP[SA[i]].
The above algorithms all rely on random access to the text T; when stored in memory to
achieve constant time, this requires n log σ bits. Beller et al. [3] introduced the first method

A.2
PLCP Move Structures
A known property of the PLCP array is that if PLCP[i] is reducible, then PLCP[i] =
PLCP[i −1] −1 [9].
▶Corollary 32. Let I = { i ∈[0, n) | PLCP[i] is irreducible }. Then where j = I.rank(i),
PLCP[i] = PLCP+[j] −(i −I[j]) [8,9].
A particularly useful relationship exists between ϕ intervals and irreducible PLCP val-
ues [8]. The jth input interval of ϕ, [P[j], P[j + 1]), is such that PLCP[P[j]] is irreducible
and corresponds to PLCP+[j]. Otherwise, for any i ∈(P[j], P[j + 1]), PLCP[i] is reducible.
Thus, given PLCP+ alongside a ϕ/ϕ−1 move structure, we can output PLCP[i] with respect
to our current position i in the permutation in O(1)-time [17,19].
A.3
Modified ϕ Algorithm
A key difference from the ϕ algorithm of Kärkkäinen, Manzini, and Puglisi [9] is that Sanaullah
et al. [16] only need to compute the irreducible PLCP array, PLCP+[0..r −1]. Thus, they
only compute ϕ(i) when position i corresponds to an irreducible PLCP[i]. Notice that these
positions are the same as the input interval starts P with respect to the permutation ϕ, and
thus we can compute I = { i ∈[0, n) | PLCP[i] is irreducible } in O(n)-time and O(r)-space.
As such, the modified ϕ algorithm iterates over k = 0 →r −1 setting i = I[k] at the start of
each iteration. The amount of work is equivalent to the ϕ algorithm, since this is equal to
iterating over i = 0 →n −1 and filling only irreducible positions. To update ℓ> 0 for a new
iteration k, we set ℓ= ℓ−(i −I[k −1]) to account for skipped reducible PLCP positions.
