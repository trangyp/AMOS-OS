Abstract
We present a machine-verified proof of the correctness of Toom-Cook multiplication
with generalized integer evaluation points. Toom-Cook is a class of fast multiplication
algorithms parameterized by a triple (𝑘𝑥, 𝑘𝑦, ⃗𝑣) consisting of two positive integer split
sizes 𝑘𝑥, 𝑘𝑦and a vector
⃗𝑣of distinct evaluation points. As part of our proof, we verify
that for any selection of 𝑘𝑥+𝑘𝑦−1 distinct integer evaluation points, we can compute
a threshold function 𝜃(𝑘𝑥, 𝑘𝑦, ⃗𝑣) such that, if the algorithm’s base-case problem size
is set above this threshold, then the algorithm’s termination is guaranteed regardless
of the values of the operands. The threshold formula, which we derive by obtaining
upper bounds on the subproblem sizes produced by the Toom-Cook recurrence, does
not depend on the operands; it depends only on 𝑘𝑥, 𝑘𝑦,
⃗𝑣, and the base 𝑏in which we
operate.
We write the proof in Lean 4, making use of the Mathlib library. We formalize the
algorithm, our base case threshold formula, and our key lemma statements in Lean.
We then use the AI theorem prover Aristotle to assist in completing the machine
verification of the algorithm’s correctness. This proof, through its synthesis of human
input and AI assistance, demonstrates the considerable power of AI to automate the
machine verification process.

Introduction
Large integer multiplication has applications across mathematics, computing, and physics.
While the standard long multiplication (a.k.a. grade-school multiplication) algorithm takes

1.1
Multiplication algorithms
The standard long multiplication (a.k.a. grade-school multiplication) algorithm for integers
has been known since antiquity. The earliest recorded explicit specification of this algorithm,
to our knowledge, is contained in Brahmagupta’s Brahma-sphuta-siddhanta (c. 7th century
CE) [5].
The quadratic running time of this algorithm was conjectured to be asymptotically opti-
mal by Kolmogorov [14].
In 1962, Karatsuba [15] refuted this conjecture by devising a
divide-and-conquer algorithm that reduces multiplication of two 𝑛-digit operands to three
multiplications with operands that have roughly 𝑛/2 digits, thus achieving a running time of
𝑂(𝑛log2 3).
Toom [19] and Cook [6] vastly generalized Karatsuba’s approach, showing that by dividing
each problem into more subproblems of smaller size, multiplication can be performed in
𝑂(𝑛1+𝜀) time for arbitrarily small 𝜀> 0. The Toom-Cook class of algorithms is the primary
subject of this paper; we detail it in Section 2.
Schönhage and Strassen showed that multiplication can be performed in
̃𝑂(𝑛) time us-
ing the Fast Fourier Transform (FFT) [18]. The exact running time of their algorithm is
𝑂(𝑛log 𝑛log log 𝑛); but they conjectured that 𝑂(𝑛log 𝑛) would be achievable and optimal.

A recent series of papers [8, 13, 12, 10] in this domain made steady progress on this con-
jecture. This line of work culminated in the celebrated algorithm of Harvey and van der
Hoeven [11], which uses more complicated FFT-based techniques to achieve 𝑂(𝑛log 𝑛) time
complexity.
However, this algorithm is galactic, i.e., it is only eﬀicient at problem sizes
too large for any practical context [11]. The Schönhage-Strassen conjecture remains open,
since there is no proof of asymptotic optimality. In fact, we are not aware of any non-trivial
general lower bounds on the asymptotic time complexity of integer multiplication.
1.2
Lean, Aristotle, and AI-assisted theorem proving
Our Toom-Cook proof is specified in Lean, a language for formalizing and machine-verifying
mathematical proofs. Given a Lean formalization of a proof, the Lean backend is able to check
that proof’s correctness. Lean provides a large number of tactics, or commands specialized
for solving particular types of proof goals. We also make extensive use of Mathlib, a library
of mathematical tools and lemmas implemented in Lean.
Aristotle, an AI tool developed by Harmonic, is capable of generating valid Lean proofs by
itself. Given a piece of Lean code containing unfilled lemma headers, Aristotle will attempt
to fill in the proofs of those lemmas, making no changes to the rest of the code. Harmonic’s
October 2025 white paper on Aristotle [1] provides more information on the tool’s internals.
At the core of Aristotle is a reinforcement learning-based system that generates natural-
language proofs of lemmas, renders them in Lean code, and then progressively refines them
using feedback from the Lean proof checker.
Thus, Aristotle knows when its code does
not pass the checker, and it can amend the code accordingly. However, Aristotle also has
limitations: it does not always succeed at reaching the goal, and even when it does, its proofs
often require emendations to work in other Lean environments.
A significant portion of our proof code is Aristotle-generated. In accordance with the spirit
of this project, we also made judicious use of GPT-5 to find Mathlib lemmas and help
structure our code. We also note that not all of Aristotle’s proof passed our local Lean
checker initially; we attribute this to subtle differences between Aristotle’s Lean backend
and ours. The emendations needed to fix this typically involved rewriting tactic calls into
more explicit proofs.

1.4
Challenges and our approach
While the Toom-Cook family of algorithms is well understood, expositions on the general
case have omitted the base case threshold 𝜃, i.e., an exact specification of the problem size
at which to switch from the recursive case to the base case. It turns out that, in the case of
generalized evaluation points, this threshold cannot be chosen as an absolute constant (see
the illustrative example in Section 3.1.1). This is because the threshold required to ensure
termination actually increases based on the splitting parameters (𝑘𝑥, 𝑘𝑦) and evaluation
points ( ⃗𝑣).
Writing machine-verifiable proofs is time-consuming, since it requires spelling out low-level
details. In the case of recursive algorithms like Toom-Cook, one of the most time-consuming
steps in machine verification is proving termination. The challenge lies in stating explicit
bounds on the sizes of problems and resultant subproblems, and also in showing that the
sizes are actually strictly decreasing between successive recursion depths above the base case.
We adopt an AI-driven approach to this task, taking advantage of the existence of an AI
proof assistant that can push user-specified lemma goals through to completion.
Our first main contribution is the derivation of an explicit base case threshold formula
𝜃(𝑘𝑥, 𝑘𝑦, ⃗𝑣), such that Toom-Cook-(𝑘𝑥, 𝑘𝑦,
⃗𝑣) can use the recursive case until the problem
size—the digit count of the operand with larger absolute value—no longer exceeds 𝜃. The
algorithm switches to the base case when the problem size is ≤𝜃(𝑘𝑥, 𝑘𝑦, ⃗𝑣). (Note that the
base 𝑏in which we work is also implicit in the formula; all operations and representations
in the algorithm take place in base 𝑏. Thus, we do not explicitly notate 𝑏in the parameter
list.)
The derivation of 𝜃requires an explicit formulation of the problem size as a function of the
digit counts of all the components that contribute to it. To obtain our upper bound on the
asymptotic behavior of the problem size, we separate out those components that depend
on the operands from those that do not; the result is a clean, immediately usable formula
for a valid base-case threshold in terms of those components that do not depend on the
operands.

Base case threshold formula
3.1
Motivation for deriving the formula
In practical implementations of Toom-Cook, the evaluation points are small enough (and the
base-case 𝑃𝑥,𝑦large enough) that termination is not in question. For instance, one version of
Toom–3 implemented in the GNU GMP uses a fixed threshold of 74 digits [9] with eﬀicient
points. However, if
⃗𝑣is allowed to contain arbitrarily large integer points, then it becomes
necessary to derive a formula for a base case threshold 𝜃(𝑘𝑥, 𝑘𝑦, ⃗𝑣). We demonstrate this
necessity below.

5
Conclusion
We have presented a machine-verified correctness proof of the Toom-Cook multiplication
algorithm given arbitrary integer evaluation points.
The proof requires a formula for a
base-case threshold that ensures the algorithm’s termination for any integer values of the
operands 𝑥, 𝑦. By analyzing the behavior of the recurrence’s subproblem sizes over time, we
derive an upper bound 𝜃(𝑘𝑥, 𝑘𝑦, ⃗𝑣) on the base-case threshold required for termination. We
machine-verify that this 𝜃—which can be expressed entirely in terms of our working base
𝑏, the point vector
⃗𝑣, and the splitting parameters 𝑘𝑥and 𝑘𝑦—is a valid threshold. Our
proof, which uses the assistance of Aristotle, demonstrates the power of AI to automate
the most time-intensive (and often tedious) parts of the machine verification process. Our
results suggest that the synthesis of human analysis and AI tools can facilitate the machine
verification of several useful algorithms.
