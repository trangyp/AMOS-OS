Faster Exact Algorithms for Equal-Subset-Sum
Ryosuke Yamano∗
Tetsuo Shibuya†
Abstract
We study exact algorithms for Equal-Subset-Sum in the worst-case setting: given a set S of
n integers, find two distinct subsets A, B ⊆S whose sums are equal. We establish a new state-
of-the-art bound for this problem by improving the fastest known algorithm, due to Randolph
and Węgrzycki (STOC 2026), from O∗(1.7067n) time and space to an algorithm that runs in
O∗(1.6994n) time and uses O∗(1.5664n) space. We also improve the best known polynomial-
space running time, due to Mucha, Nederlof, Pawlewicz, and Węgrzycki (ESA 2019), from
O∗(2.6817n) to O∗(2.5430n). Finally, we investigate time-space tradeoffs for this problem and
improve the running times achievable under a broad range of exponential-space bounds.

Introduction
Subset-Sum is a fundamental NP-hard problem, which can be formulated as follows.
Problem 1.1 (Subset-Sum). Given a multiset S of n integers and a target integer t, output a subset
A ⊆S such that t = P
a∈A a, if such a subset exists.
Subset-Sum admits a simple meet-in-the-middle algorithm, due to Horowitz and Sahni [19],
that runs in O∗(2n/2) time 1. This remains the standard running-time bound for exact algorithms
for Subset-Sum, and the fastest known algorithm [13] improves over the O(2n/2) bound only by a
polynomial factor. Whether there exists an algorithm for Subset-Sum that runs in O∗(2(0.5−δ)n)
time for some constant δ > 0 remains a long-standing open question.
Closely related to this open problem, Howgrave-Graham and Joux [20] broke this meet-in-the-
middle barrier in the average-case setting by giving an O∗(20.337n)-time algorithm, which was later
improved to O∗(20.283n) by [8, 9]. The algorithm of Howgrave-Graham and Joux introduced the
representation technique, which was later also used for Equal-Subset-Sum (ESS), an important
variant of Subset-Sum that can be formulated as follows.
Problem 1.2 (Equal-Subset-Sum (ESS) [31]). Given a set S of n integers, output two distinct
subsets A, B ⊆S such that P
a∈A a = P
b∈B b, if such subsets exist.
ESS admits a simple meet-in-the-middle algorithm that runs in O∗(3n/2) time. Surprisingly, the
authors of [25] broke this meet-in-the-middle barrier for ESS in the worst-case setting by exploiting
the representation technique, giving an algorithm that runs in O∗(1.7088n) time and space. In
the average-case setting, the authors of [12] gave an O∗(30.387n) ≤O∗(1.5299n)-time algorithm
for ESS. The open question of whether the running time for ESS in the worst-case setting can be
improved beyond O∗(1.7088n) [21, Section 5, Question 1] was answered affirmatively very recently
by Randolph and Węgrzycki [28], who gave an algorithm that runs in O∗(1.7067n) time and space.
1.1
Our Results
In this work, we focus on exact algorithms for ESS in the worst-case setting. All our algorithms
are Monte Carlo algorithms that never return false positives, and their error probabilities can be
reduced to 2−Ω(n) by repetition. Our first result establishes a new state-of-the-art algorithm for
ESS by further improving the result of [28]. While the running-time improvement is our primary
contribution, the algorithm also reduces the space usage by a much larger exponential factor.
Theorem 1.3. There exists a Monte Carlo algorithm for ESS that runs in O∗(1.6994n) time and
uses O∗(1.5664n) space.
Our second result improves the polynomial-space running time for ESS. We improve upon
the O∗(2.6817n)-time algorithm of [25] by analyzing two approaches suited to different parame-
ter regimes: one based on recent improvements for low-space Element Distinctness [11], and the
other using the fast polynomial-space Subset-Sum algorithm of [5] as a subroutine.
Theorem 1.4. There exists a Monte Carlo algorithm for ESS that runs in O∗(2.5430n) time and
uses polynomial space.

any space bound S ≤O∗(2n/4). This tradeoff was later improved for almost all choices of the
tradeoff parameter by [3]. In contrast, for ESS, the analogous Schroeppel–Shamir-type tradeoff,

1.2
Our Main Techniques
The algorithms of [25] focus on the solution size ℓ= |A|+|B|, where A and B form a disjoint solution
of ESS. They gave an algorithm that runs in O∗(2ℓ) time and space for ℓ> n/2, which is fast when
ℓis small. In our algorithm, we introduce a simple random modification to the input instance; see
Algorithm 1 in Section 3. This modification reduces the solution size ℓwith inverse-exponential
probability. Although we need to pay an additional exponential cost to successfully reduce ℓ, the
exponential speedup obtained from the reduction in ℓdominates this cost in the bottleneck case
ℓ≈0.773n of [25]. Thus, by combining this input modification with the O∗(2ℓ)-time and space

algorithm of [25], we obtain Theorem 1.3. Since the modified instance may have ESS solutions that
do not correspond to any solution of the original instance, we carefully filter the candidates to avoid
returning such spurious solutions.
Our modification can also be viewed as a time-space tradeoff. It pays an additional exponential
cost in time to reduce ℓ; since the underlying algorithm uses O∗(2ℓ) space, this reduction in ℓ
translates directly into an exponential saving in space. We exploit this idea in our time-space tradeoff
algorithms in Section 5.2. By choosing the size of the modification appropriately, our algorithm can
be used under a space bound of O∗(2αn) for a constant α, especially when α > 1/2. For more
restrictive space bounds, we modify the algorithm of [25] by replacing the explicit enumeration of
all candidates with random access to the candidate set, implemented via the Fast Subset-Sum Oracle
technique of [1]. This allows us to apply the time-space tradeoff for Element Distinctness [23]; see
Section 5.3 for further details. By combining these algorithms with several other algorithms tailored
to different parameter regimes, we obtain the full time-space tradeoff curve stated in Theorem 1.5.

1.3
Related Works
The recent attention to exact algorithms for ESS has also led to improvements for the closely related
Pigeonhole ESS problem [27], a constrained variant of ESS in which all input integers are positive
and their sum is at most 2n −2. By the pigeonhole principle, a solution is guaranteed to exist.
Thus, Pigeonhole ESS is a total search problem, and it has also been studied in the TFNP context
[4, 30]. Pigeonhole ESS admits a meet-in-the-middle-based algorithm that runs in O∗(2n/2) time,
which was recently improved to O∗(2n/3) time [22, 21].
A natural optimization variant of ESS is the Subset-Sum-Ratio problem [31], in which the task is
to find two disjoint subsets whose sums have ratio as close to 1 as possible. A 1.324-approximation
algorithm was given in [31], and the first FPTAS for the problem was given in [6]. This FPTAS was
later simplified in [26]. Subsequent works improved the running time [24, 2, 10].
ESS also has connections to computational biology [16, 14]. The authors of [15] considered
k-ESS, in which the task is to find k disjoint subsets whose sums are all equal. Other variants of
ESS were studied in [17], which also established their NP-hardness.

We adopt the input assumptions from [25]: the input set S consists of positive integers and
satisfies P(S) ≤2O(n). We enforce these assumptions using the following preprocessing lemma,
which is based on [25, Appendix A of the full version]. For completeness, we provide a proof in
Appendix A of this paper.
Lemma 2.3. Given a set S of n integers satisfying |s| ≤2m for all s ∈S, the following holds. If
0 ∈S or m ≥2n, then ESS on S can be solved in O(poly(n, m)) time. Otherwise, with probability at
least 1 −O(2−n), we can construct, in O(poly(n, m)) time, a set S′ of n + ⌈log n⌉positive integers
satisfying 0 < s′ ≤2O(n) for all s′ ∈S′, and satisfying the following properties: if S′ has no
ESS solution, then neither does S; conversely, from any ESS solution of S′, we can reconstruct a
corresponding ESS solution of S in O(poly(n, m)) time.
Lemma 2.3 increases the input size by only O(log n). Thus, a running time of the form O∗(2Θ(n))
changes only by a factor of 2O(log n) = poly(n), which is absorbed in the O∗(·) notation.
For simplicity, we also assume that n is divisible by 12. This can be achieved by setting M =
P(S) + 1 and adding O(1) elements of the form M, 2M, 4M, 8M, . . . to S. We define a minimum
solution as follows.
Definition 2.4 (Minimum solution). For an ESS instance with input set S, a solution A, B ⊆S is
called a minimum solution if |A|+|B| is minimized. We refer to the value |A|+|B| as the minimum
solution size, denoted by ℓ, and define the minimum solution ratio as ℓ′ = ℓ/n.
By trying all possible values ℓ∈[n], we incur only a polynomial overhead. If no execution finds
a solution, then the algorithm reports that the instance is a No instance. Thus, in the following, we
may assume that the minimum solution size ℓis given in advance.
When analyzing the bounds in terms of the minimum solution ratio ℓ′, we may upper-bound
the running time and space usage by maximizing over the continuous interval (0, 1], instead of the
discrete set {1/n, 2/n, . . . , (n −1)/n, 1} of possible values of ℓ′.

Lemma 3.1. Let S′ be the modified instance produced by Algorithm 1, and let (xi, yi) denote the
i-th pair of elements obtained from S by the algorithm. Suppose that S′ admits an ESS solution
A′, B′ ⊆S′ with A′ ∩B′ = ∅. If, for every obtained pair (xi, yi), at most one of the generated
values xi + yi and xi −yi belongs to A′ ∪B′, then the solution (A′, B′) for S′ can be transformed in
polynomial time into a valid ESS solution for the original instance S.
Proof. For each obtained pair (xi, yi), we reconstruct the original elements as follows. If xi + yi
belongs to the solution, then we replace it by xi and yi in the same subset. If xi −yi belongs to
the solution, then we replace it by xi in the same subset and place yi in the other subset. Observe
that these transformations preserve the equality of the subset sums. Applying this transformation
independently to every obtained pair yields a valid ESS solution for the original instance S. Since
the number of obtained pairs is at most n/2 and each pair is processed using only a constant number
of arithmetic operations, the reconstruction procedure runs in polynomial time.
By Lemma 2.3, all input integers are positive, and thus xi + yi > xi −yi for every obtained
pair (xi, yi). During this modification process, if a generated value coincides with another element
of the modified instance, then these equal values cannot originate from the same pair.
In this
case, the corresponding elements immediately yield a valid ESS solution for the original instance
by Lemma 3.1, and thus the algorithm may terminate early. Therefore, in the following, we assume
that no value collisions occur in the modified instance, and hence |S| = |S′|.
Moreover, the input assumption imposed by Lemma 2.3 continues to hold, since all generated
integers remain positive and are at most twice the maximum value in the original input set S.
