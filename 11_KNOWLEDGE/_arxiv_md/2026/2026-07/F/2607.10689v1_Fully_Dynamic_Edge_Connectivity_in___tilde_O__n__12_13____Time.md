Fully Dynamic Edge Connectivity in ˜O(n12/13) Time
Yotam Kenneth-Mordoch∗
Robert Krauthgamer†
July 14, 2026
Abstract
In the (fully) dynamic edge connectivity problem, the goal is to maintain the edge connectiv-
ity λG of an n-vertex graph G that undergoes edge insertions and deletions. Our main result is a
randomized algorithm for maintaining edge connectivity in dynamic simple graphs using worst-
case update and query time ˜O(n12/13), for all values of λG. This is the first algorithm that has
o(n) update and query time, as all existing algorithms achieve this only when λG is below n1/11
or above n1/2 (up to polylogarithmic factors). We then use the tools developed for this purpose
to design two additional algorithms. The first one is a deterministic algorithm for the exact same
task, that uses n1+o(1) worst-case update and query time or ˜O(n) amortized update and query
time; this gives a polynomial improvement over existing deterministic algorithms. The second
one is a deterministic algorithm for the same task but in dynamic unweighted multigraphs, that
uses ˜O(n3/2) worst-case update and query time.

Introduction
The edge connectivity of an (unweighted) graph G, denoted λG, is the minimum number of edges
that need to be removed from G to disconnect it. This fundamental graph parameter has been
studied across a wide range of computational models, including the classical sequential setting [NI92,
KS96, SW97, Kar00, GMW20, MN20], parallel computation [GG18], the distributed Congest
model [GK13, DHNS19, DEMN21], graph streams [MN20, AD21], and the cut-query and quantum
query models [RSW18, AEG+22, AL21]. We focus on maintaining the edge connectivity in the
fully dynamic setting, where the input graph G = (V, E) on a fixed set of n vertices that undergoes
edge insertions and deletions. In this setting, the goal is to minimize the time it takes to update
the data structure after an edge insertion or deletion (called update time) and the time it takes to
query the edge connectivity (called query time). Throughout, the worst-case update time is the
maximum time taken by the algorithm to process any single update in any update sequence. When
we mention only the update time it is implied that the query time is the same. Similarly, when the
type of update time is not specified, we refer to the worst-case and not, say, amortized.
Maintaining edge connectivity in the fully dynamic setting has a rich history spanning over 40
years [Fre85, GI91]. Early work focused on the regime where the edge connectivity λG is a small
constant, giving efficient algorithms for λG ∈{1, 2, 3, 4} [Fre85, GI91, EGIN97, HdLT01, KKM13].
Recent work on the bounded connectivity regime has given efficient algorithms for values of λG up
to no(1) using no(1) worst-case update time [JST24, EHL25, EHL26].
The first algorithm for polynomial values of λG was given in [Tho07]; it uses ˜O(√nλ7
max) worst-
case update time, where λmax is the maximum edge connectivity throughout the execution and
˜O(·) hides polylogarithmic factors in n. A similar technique was later used in [dVC25] to obtain
˜O(√nλ5.5
max) worst-case update time, which is sublinear in the number of vertices when λmax <
n1/11/ polylog(n). Unfortunately, when λmax ≥n3/11, this bound is no better than ˜O(n2), the
trivial solution of recomputing the edge connectivity from scratch after each update.
Recently, several algorithms have achieved ˜O(n) worst-case update and query time for general
λG, improving upon the trivial solution of ˜O(n2) time [GHN+23, KK26b, HKMR25].1 In addition,
the algorithm of [KK26b] achieves o(n) worst-case update time for λG ≥n1/2 polylog(n). Hence,
the only regime where o(n) worst-case update time was not known is λG between n1/11 and n1/2
(omitting polylogarithmic factors). This left a tantalizing open question: can one achieve o(n)
worst-case update and query time for all values of λG? We answer this question affirmatively by
presenting the first such algorithm for simple graphs. In addition, our framework gives the first
deterministic algorithm for maintaining edge connectivity in simple graphs with worst-case update
time n1+o(1), and the first algorithm for multigraphs with worst-case update time o(n2) (both for
general λG).

Results

One of the main tools introduced in recent works on

sparse graph that preserves all minimum cuts that are non-trivial, i.e. contain more than one vertex.

Technical Overview
We now give a technical overview of our algorithms and their analysis. Our main technical con-
tribution is a new framework for maintaining the edge connectivity of a dynamic graph based on
dynamizing the minimum cut algorithm of [MN20]. Our framework achieves o(n2) worst-case up-
date time for all values of λG. In contrast, all previous sublinear algorithms (in m) for general
λG are based on constructing a non-trivial minimum cut sparsifier. This technique is sufficient
for obtaining our deterministic and multi-graph algorithms (Theorems 1.2 and 1.3), but not for
obtaining our main result of worst-case update time o(n) for all values of λG (Theorem 1.1). Our
second contribution is combining our framework with a non-trivial minimum cut sparsifier to yield
our main result.
As mentioned above, our main technical result is a dynamic (and deterministic) version of the
minimum cut algorithm of [MN20]. We dynamize that algorithm by incremental rebuilding, where
we divide updates into epochs comprising O(λG) updates each. In each epoch we build a specialized
data structure that is easy to update during the epoch, and allows answering edge connectivity
queries without accessing the entire graph. Towards the end of the epoch, we reconstruct the data
structure in the background and then switch to the new data structure at the beginning of the next
epoch. Throughout, the age of a data structure is the number of updates that have been applied
to the graph since it was constructed, and a data structure is called valid if its age is at most the
number of updates it can handle. We denote the graph after t updates by Gt and the number of
edges in Gt by mt. The following theorem summarizes the guarantees of our algorithm.
Theorem 2.1 (Dynamic Version of [MN20]). There exists a deterministic algorithm that, given
an initial weighted graph G = G0 on n vertices, constructs in time ˜O(m0) a data structure that
supports the following operations:
1. update(e,w): Update the weight of an edge e by w ∈{±1} in polylog(n) time.
2. query(): Return the edge connectivity of the current graph Gt in ˜O(n) time.
The data structure is valid for c · λG0 updates for some small constant c > 0.
We now give an overview of the algorithm and its analysis. The algorithm of [MN20] is based
on the 2-respecting min-cut framework of [Kar00]. Given a tree T = (V, ET ), a cut C ⊆V is
said to 2-respect T if |ET ∩C × (V \ C)| ≤2, where EH(S, T) is the set of edges in a graph H
between vertex subsets S, T ⊆V . The key idea of this celebrated framework is that one can find
in near-linear time a set of spanning trees of a graph G such that every minimum cut C of G
2-respects some tree T in the packing. We extend the original analysis of [Kar00] to show that
every cut C that is near-minimum, namely cutG(C) ≤(1 + η)λG for a small constant η > 0 where
cutG(C) is the weight of the cut C, also 2-respects some tree T in the packing. A similar result was
previously shown in [CQX19] in the context of bounding the number of approximate minimum cuts
in the graph. The following lemma proves this fact, and uses it to show that every minimum cut
of Gt 2-respects some tree in a packing of G0. To make the algorithm deterministic, we leverage
the deterministic skeleton graph construction of [HLRW24].
Lemma 2.2. There exists a deterministic algorithm that, given a weighted graph G = G0 constructs
a weighted tree packing T of G with polylog(n) trees in ˜O(m0) time.
Furthermore, for every
t ≤c · λG0, for a small enough constant c > 0, if C ⊆V is a minimum cut of Gt then C 2-respects
some tree in the packing.

The second part of the framework is an efficient algorithm that given a tree T, finds a minimum
cut that 2-respects it. This is where [MN20] differs from the original algorithm of [Kar00], which
relies on a clever dynamic programming technique to find the minimum cut among those that
2-respects a given tree in near-linear ˜O(m) time. The key insight of [MN20] is that it suffices to
check the value of ˜O(n) cuts instead of all O(n2) possible 2-respecting cuts. To efficiently query
the values of these cuts, the algorithm constructs a data structure that allows querying the value
of certain cuts in the graph, as follows.
Definition 2.3 (Tree Cut-Query Oracle). A tree cut-query oracle is a data structure constructed
for a rooted spanning tree T of a weighted graph G, that supports querying the weight of the following
cuts:
1. any cut that 2-respects T; and
2. any cut C ⊆V such that C = ∪i∈[k]Si where each Si is a contiguous set of vertices encountered
during a post-order traversal of T and k = O(1).
Lemma 2.4. There exists a deterministic data structure for tree cut-query oracle that given an
initial weighted graph G = G0 and a fixed rooted spanning tree T of G0, with construction time
˜O(m0). Furthermore, the data structure supports edge insertions/deletion to G using polylog(n)
worst-case update time, and can return the value of a cut in polylog(n) query time.
The original algorithm of [MN20] builds a static tree cut-query oracle, based on the 2D semi-
group range searching data structure of [Cha88]. It then adds sampling queries to the oracle, which
allows it to find the ˜O(n) cuts relevant to query. We obtain our dynamic algorithm, by using the
dynamic version of the data structure of [Cha88]. We note that while it is possible to show that the
random sampling method is robust to edge updates, and thus can be used in our dynamic algorithm,
we require our framework to be deterministic; thus, we introduce a new deterministic procedure for
finding the ˜O(n) cuts relevant to query. Our procedure leverages the structural insights of [MN20]
to design a deterministic binary search procedure that finds the relevant cuts in ˜O(n) time using
O(log n) cut queries per relevant cut. Our deterministic procedure works also in the static setting,
which may be of independent interest. We encapsulate our deterministic variant of [MN20] in the
following lemma, whose proof appears in Section 4 and which immediately implies Theorem 2.1.
Lemma 2.5. There exists a deterministic algorithm that, given a spanning tree T of a weighted
graph G and a corresponding tree cut-query oracle, finds in time ˜O(n) a minimum cut among those
that 2-respect T.
Proof of Theorem 2.1. Begin by constructing a tree packing T with |T| ≤polylog(n) of G using
Lemma 2.2. Then, for each tree T ∈T, construct a weighted tree cut-query oracle using Lemma 2.4.
When encountering an edge update, update each tree cut-query oracle accordingly. Finally, to
answer a query for the edge connectivity of Gt, find the minimum cut that 2-respects each tree
T ∈T using Lemma 2.5 and return the minimum among them. The crucial observation is that as
long as t ≤c · λG, for an appropriate constant c, every minimum cut of Gt 2-respects some tree
T ∗∈T by Lemma 2.2 Thus, the algorithm finds it, or another cut of equal or smaller value, when
finding the minimum cut that 2-respects T ∗.
To conclude the proof we analyze the time complexity of the algorithm. Updating each tree
cut-query oracles takes polylog(n) time by Lemma 2.4, and the total update time over all T ∈T
is polylog(n). In addition, the construction of the tree packing and all the tree cut-query oracles
takes ˜O(m) time. We conclude that the overall time complexity of the algorithm is ˜O(m) for the
construction and polylog(n) for each update.

• A deterministic algorithm with worst-case update time k · no(1).

2.2
Deterministic Dynamic Edge Connectivity in Simple Graphs
Our deterministic algorithm is similar to our randomized algorithm for simple graphs, but instead
of using an NMC sparsifier it operates directly on an NI sparsifier of the graph. We provide an
alternative self-contained proof of this result in Appendix C.
Proof of Theorem 1.2. The algorithm maintains a maximal n-packing of forests of the graph.
Throughout, assume that the algorithm is given a 2-approximation of the edge connectivity λG
of the graph and that the edge connectivity is at least no(1).
This can be achieved using the
algorithm of [EHL26] with no(1) worst-case update time, which does not affect the overall time
complexity of the algorithm.
Divide the updates into epochs of λG/40 updates. Assume that at the beginning of each epoch
the algorithm is given the data structure of Theorem 2.1 of a 2λG-NI sparsifier of G whose age
is less than λG/80.
Throughout the epoch, whenever an edge is inserted or deleted in G, the
algorithm inserts/deletes updates the data structure accordingly. By Lemma 2.8, we have that
every non-trivial minimum cut of Gt is a minimum cut of the 2λG-NI sparsifier, for every t in the
epoch. Therefore, to answer a minimum cut query, it suffices to query the data structure, and
return the minimum between it and the minimum degree of Gt.
When only λG/80 updates are left in the epoch, use the first 2λG forests in the packing to build
a 2λG-NI sparsifier of G, and construct the data structure of Theorem 2.1 on the 2λG-NI sparsifier.
Constructing the data structure takes ˜O(nλG) time by Theorem 2.1, and thus one can spend ˜O(n)
time during λG/160 updates to build the data structure in the background. During the last λG/160
updates of the epoch, apply all the queued updates to the new data structure, and then switch to
it at the beginning of the next epoch. Notice that the age of the data structure at the end of the
epoch is at most λG/80, and thus it is valid for the next epoch. Finally, observe that the algorithm
constructing the data structure requires a static copy of the maximal 2λG-packing of forests, which
we obtain by queueing the updates to the maximal 2λG-packing of forests and applying them in
the next λG/100 updates after the data structure is constructed.
Finally, the algorithm uses n1+o(1) worst-case update time or ˜O(n) amortized update time,
depending on the choice of the algorithm for maintaining the maximal n-packing of forests by
Lemma 2.7, which concludes the proof.

When only c√n/10 updates remain in the epoch, the algorithm checks if λG > (1−c/2)√n, and
if this occurs it constructs the data structure of Theorem 2.1 on the weighted version of G. Observe
that this guarantees that if λG > √n at the beginning of the next epoch, then the data structure
exists and is valid for the next epoch. When constructing the data structure, the algorithm spends
at most ˜O(n3/2) time after each update to build the data structure in the background (spread over
O(√n) updates), and then switches to the new data structure at the beginning of the next epoch.
Notice that the age of the data structure at the end of the epoch is at most c√n/10, and thus it
is valid for the next epoch. Finally, the algorithm constructing the data structure requires a static
copy of the weighted version of G, which we obtain by queueing the edge updates and applying
them in the next c√n/100 updates after the data structure is constructed.
To conclude we analyze the time complexity of the algorithm.
The weighted version of G
can be easily maintained using O(1) time per update, and the maximal 2√n-packing of forests
can be maintained using ˜O(n1/2) randomized or n1/2+o(1) deterministic worst-case update time
by Lemma 2.7. In addition, we spend at most ˜O(n3/2) time after each update to build the data
structure of Theorem 2.1 in the background, and thus the worst-case update time is ˜O(n3/2). The
query time is ˜O(n3/2) when λG ≤√n, and ˜O(n) when λG > √n, which is always at most ˜O(n3/2).
Therefore, the algorithm uses ˜O(n3/2) worst-case update time and query time, which concludes the
proof.

Faster Dynamic Edge Connectivity.
While our work achieves o(n) worst-case update time

Heavy-Light Decomposition.
We use the heavy-light decomposition of [ST83], in a standard
variant where every path contains the tree edge entering its topmost vertex (if it exists). Through-
out, let T be a tree rooted at an arbitrary vertex r, and for a vertex v let v↓denote the subtree of
T rooted at v and |v↓| the number of vertices in it. For a non-leaf vertex v, its heavy child is the
child u maximizing |u↓| (breaking ties arbitrarily), the edge (v, u) is the corresponding heavy edge,
and every other edge from v to a child is a light edge. The paths formed by heavy edges are called
heavy paths, and the decomposition of T into heavy paths is a heavy-light decomposition. Notice
that a light edge (v, u) satisfies |u↓| ≤|v↓|/2, so every root-to-leaf path of T contains at most log n
light edges, and hence at most log n paths in the decomposition.
Theorem 3.2 ([ST83]). There exists an algorithm that, given a tree T on n vertices, computes a
heavy-light decomposition of T in O(n) time.

Sublinear Update Time for Edge Connectivity
In this section we prove Lemma 2.12, giving an algorithm that maintains the edge connectivity of
a dynamic graph G on n vertices with ˜O(n/δG) worst-case update time, where δG is the minimum
degree of G. We begin by introducing some tools that will be used throughout the section, and
then we give an overview of our algorithm and its analysis. We first introduce the following data
structure from [HKMR25].
Definition 5.1 (Dynamic Cutset (DCS)). A Dynamic Cutset (DCS) is a dynamic data structure
that maintains a forest F and a dynamic graph G. It supports the following operations on F:
• insertF (e): Insert e into F.
• deleteF (e): Delete e from F.
It also supports the following operations on G:
• insertG(e): Insert e into G.
• deleteG(e): Delete e from G. If e is in F, remove it from F.
• query(v): Return an edge e in G that has one endpoint in the component of F containing v
and one endpoint elsewhere, or return ⊥if no such edge exists.
Theorem 5.2 (Lemma 8 of [HKMR25]). There exists a randomized DCS data structure with
worst-case update time of polylog(n) and query time of polylog(n).
Remark 5.3. There also exists a deterministic DCS data structure which requires an no(1) overhead
in the update and query time, which can be used to derandomize parts of our algorithm.
We will also use the following easy result.
Claim 5.4. There exists an algorithm that, given a DCS on a graph G with forest F such that
F has r connected components, the list of component IDs, and every vertex v knows the ID of the
component it belongs to in F, constructs a maximal k-packing of forests of G/F with O(rk) edges
in ˜O(rk) time.
Proof. The algorithm iteratively constructs a single spanning tree T of G/F, deletes all edges of
T from G/F, and repeats this process k times.
It is easy to see that the result is a maximal
k-packing of forests of G/F. We show that each iteration takes ˜O(r) time, and adds O(r) edges to
the sparsifier yielding our desired result.
To construct a spanning tree of G/F, start with some v ∈V . Then, call query(v) to find an
edge e = (u, w) and add it to T, where u is in the same component as v in F and w is in a different
component. It is possible to determine the endpoints of e in T by checking which component of F
contains w, and which component contains u. This can be done in O(1) time as each vertex knows
the ID of the component it belongs to by the theorem statement, and the components of F are the
vertices of G/F. Then, merge the components containing u, w in F by calling insertF ((u, w)).
Repeat this process until query(v) returns ⊥, which means that no more vertices exist in the
spanning tree containing the component of v. Then, iterate over the next component in G/F and
15


## Page 17


repeat the process until every component of G/F has been processed. At the end of the process,
every component in T has an outgoing edge or it was found to be an isolated vertex in G/F.
The total time complexity of this process is ˜O(r) as it adds O(r) edges to T and each edge
is found in polylog(n) time. To repeat the process k times, delete the edges of T from G/F by

5.1
Algorithm Overview
We are now ready to describe the algorithm of Lemma 2.12. Our algorithm uses the star-contraction
procedure [AEG+22] to construct a weak NMC sparsifier (see Definition 2.10). Recall that a weak
NMC sparsifier of a graph G is a contraction H of G, such that for every cut C ⊆V of value at
most λG + 1
10δG in G, no edge in E(C, V \ C) is contracted in H with constant probability.
We will use the τ-star-contraction procedure, introduced by [KK25], which is a variant of
the star-contraction procedure of [AEG+22] that is defined for a degree threshold τ. Sample a
set of center vertices R ⊆V by including each vertex v ∈V independently with probability
p = O(log n/τ). Let V≥τ = {v ∈V \ R | dG(v) ≥τ} be the set of non-center vertices with degree at
least τ, where throughout dG(v) is the degree of v in G. Then, for every v ∈V≥τ, uniformly sample
a vertex r ∈NG(v)∩R, where NG(v) is the neighborhood of v in G, and contract the corresponding
edge (v, r), keeping parallel edges, which yields a contracted multigraph G′. The main guarantee
of this procedure is that every non-trivial near-minimum cut of G, i.e., not composed of a single
vertex, with cutG(C) ≤λG +
1
10δG is preserved in G′ with constant probability. The following
theorem states this formally.
Theorem 5.5 ([AEG+22, KK25, KK26b]). Let G = (V, E) be an unweighted graph on n vertices
and let C be a non-trivial cut with cutG(C) ≤λG +
1
10δG.

We note that previous works [AEG+22, KK26b] only prove the theorem for exact minimum
cuts, however the same proof extends for any cuts of value λG + ϵδG for a small enough ϵ > 0. For
completeness, we include the proof of Theorem 5.5 in Appendix A. We will use the implementation
of the τ-star-contraction procedure of [KK26b] for the dynamic setting. The main insight of the
implementation is that one can fix the center vertices R at the beginning of the algorithm, and
then simply (re)assign vertices to centers as new edges come in. We use this insight to maintain
a DCS on the contracted graph G/F of the τ-star-contraction, where F is the forest of contracted

Dynamic Maximum k-Packing of Forests
In this section we show how to maintain a maximal n-packing of forests, proving Lemma 2.7. Such
results were previously used in the literature (see e.g. [ADK+16, KK26b]), and we include the
proof for completeness.
Throughout we assume the existence of a minimum spanning forest data structure with the
following guarantees.
Definition B.1 (Minimum Spanning Forest). A fully dynamic minimum spanning forest (MSF)
data structure maintains a spanning forest of a dynamic graph G undergoing edge insertions and
deletions, and supports the following operations:
• insert(e): Insert edge e into G.
• delete(e): Delete edge e from G.
An edge insertion only changes the spanning forest if the inserted edge connects two components,
and an edge deletion only changes the spanning forest if the deleted edge is in the spanning forest,
in which case it finds a single replacement edge if one exists.
Theorem B.2. There exist dynamic MSF data structures with the following guarantees:
• A deterministic data structure with no(1) worst-case update time [CGL+20].
• A deterministic data structure with polylog(n) amortized update time [HdLT01].
• A randomized data structure with polylog(n) worst-case update time [KKM13, GKKT15].

Proof of Lemma 2.7. The algorithm maintains k dynamic MSF data structures, T1, T2, . . . , Tk, in
parallel one for each forest in the packing. The input for the MST Ti is the graph Gi = G\Si−1

insert it into each of the k MSTs, until it is successfully inserted into one of them. Given an edge
deletion e, delete it from each of the k data structures. If e is in one of the trees, it is deleted
from that tree and might be replaced by a single replacement edge, which is then deleted from all
subsequent trees. It is easy to see that {T1, . . . , Tk} is a maximal k-packing of forests of G.
To conclude, we analyze the update time of the algorithm. Denote the update time of the
MST data structure by τ. Each inserted edge is added to at most k trees, since once it is inserted
into one of the k data structures, it will not be inserted into any of the subsequent ones. For an
edge deletion, notice that if the edge is in one of the trees, it is deleted from that tree and at
most one replacement edge is inserted into that tree. This replacement edge is then deleted from
all subsequent trees. Therefore, each tree sees at most a single edge deletion. Hence, the total
update time for an edge deletion is at most kτ. Plugging in the values of τ for the three MST data
structures above gives the desired result.

Simple Deterministic Dynamic Minimum Cut Algorithm
In this section we give an alternative, self-contained proof of Theorem 1.2. To prove Theorem 1.2,
we use the following result on deterministic construction of a strong NMC sparsifier in near-linear
time [KT19, HRW17].
Theorem C.1 ([KT19, HRW17]). There exists a deterministic algorithm that, given a simple graph
G on n vertices and m edges, constructs a strong NMC sparsifier of G with ˜O(n/δG) vertices and
˜O(m/δG) edges in ˜O(m) time.
Proof of Theorem 1.2. The algorithm maintains a maximal n-packing of forests of the graph, and
a heap of vertex degrees to track the minimum degree δG. We divide the updates into epochs of
δG/40 updates. Assume that at the beginning of each epoch we are given a strong NMC sparsifier
H of a 2δG-NI sparsifier of G whose age is less than δG/80. Throughout the epoch, whenever an
edge e = (u, v) is inserted or deleted in G, insert/delete the corresponding edge in H (if u, v are not
contracted in H). By combining Lemmas 2.8 and 2.11, we have that every non-trivial minimum
cut of Gt is a minimum cut of Ht for every t in the epoch, where Ht is the NMC sparsifier with the
same updates applied. Therefore, to answer a query of the minimum cut of Gt, it suffices to run
a static deterministic minimum cut algorithm on Ht such as [HLRW24] and return the minimum
between it and the minimum degree of Gt.
When there rest only δG/80 updates left in the epoch, use the first 2δG forests in the packing to
build a 2δG-NI sparsifier of G, and then build a strong NMC sparsifier of the NI sparsifier. Notice
that constructing the NI and NMC sparsifiers takes ˜O(nδG) time by Theorem C.1, and thus we can
spend ˜O(n) time during δG/160 updates to build the NMC sparsifier in the background. In the
final δG/160 updates of the epoch, we apply all the edge updates that arrived during the previous
δG/160 updates to the new NMC sparsifier, ˜O(log n) time per update, and then switch to the new
NMC sparsifier at the beginning of the next epoch. Observe that the age of the NMC sparsifier
at the end of the epoch is at most δG/80, and thus it is valid for the next epoch. The algorithm
constructing the NMC sparsifier requires a static copy of the maximal n-packing of forests, which
we obtain by queueing the updates to the maximal n-packing of forests and applying them in the
next δG/80 updates after the NMC sparsifier is constructed.
