Efficiently Listing Projected Trees,
and Equivalence of Listing and Enumeration
Karl Bringmann*
Nick Fischer†

Abstract
The subgraph isomorphism problem and its generalizations such as conjunctive queries, where
some nodes are projected, are among the most fundamental problems in graph algorithms and
database theory. In this paper, we study the listing and enumeration variants of these problems
and present two main results.
(1) We present the first algorithms for enumerating projected trees with polynomial prepro-
cessing time ( eO(n17.42)) and polylogarithmic delay (polylog(n)). Prior to this work, all algorithms
in the literature required time Ω(nΩ(k) + t ) or t · nΩ(1) to list all copies of a k-node tree with
projections, where t is the number of solutions. Our result generalizes to arbitrary projected
hypergraphs, achieving enumeration in preprocessing time eO(m17.42·subw(H )) and polylogarith-
mic delay, where subw(H ) is the submodular width of the pattern hypergraph H . We heavily
rely on fast (rectangular and output-sensitive) matrix multiplication, which we complement by
fine-grained lower bounds indicating that any algorithm beating time Ω(nΩ(k) + t ) must rely on
fast matrix multiplication.
(2) As our second main result, we present a generic enumeration-to-listing reduction, es-
tablishing that listing and enumeration are equivalent under natural assumptions. For (col-
ored) subgraph isomorphism, our reduction transforms any listing algorithm running in time
O(f (n,m) + t · g (n,m)) into an enumeration algorithm with preprocessing time O((f (n,m) +
g (n,m)+m)log2 n) and delay O(g (n,m)). We utilize this equivalence as a tool for proving our
first main result, and we expect that our generic reduction will find many future applications.

Introduction
The subgraph isomorphism problem and its variants are among the most fundamental graph
problems, with a large number of applications in various areas such as databases, network motifs,
statistical physics, and probabilistic inference. Within theoretical computer science, it is primarily
studied by two communities: algorithm design and database theory. Although closely related, these
communities adopt slightly different viewpoints, and our results apply to both.
The algorithms community typically studies the Uncolored H -Subgraph problem (e.g. [CN85,
Kow03, ABKZ22, ABF23, JX23, AKLS23, DMVX24, JVZ24, VW25, BG25]). Here, H is a fixed pat-
tern graph, the input is a large host graph G , and any copy of H in G is considered a solution.
In contrast, the database theory community usually studies the Colored H -Subgraph and Col-
ored H -Subhypergraph problems, also known as (self-join-free) join queries (e.g., [Yan81, NRR13,
Vel14, NPRR18, JR18, Dur20, Hu25, KHS25]). Here, writing V (H ) = [k] = {1,...,k}, the given host
(hyper-)graph is equipped with a partition V (G ) = V1 ∪··· ∪Vk, and a solution is an H -copy that
respects this partition. See Section 3 for formal problem definitions. While the color-coding
technique [AYZ95] provides a reduction from the Uncolored to the Colored problem, in general
these variants are not equivalent. (An exception is the triangle, the most intensely studied pat-
tern [IR78, P˘at10, BPVZ14, KPP16, VX20], for which Colored and Uncolored are equivalent.)
In this paper our focus lies on the well-studied generalization of these problems where some
nodes in H are projected. Formally, let I ⊆V (H ). In the (Colored or Uncolored) (H ,I )-Subgraph
problem, a solution is a tuple of vertices (vi)i∈I in G that can be extended to a (colored or uncol-
ored) copy of H . The accordingly defined Colored (H ,I )-Subhypergraph problem is also known as
conjunctive queries or join-project queries and constitutes one of the most important problems in
database theory, because it formalizes the core functionality of SQL queries (e.g., [BDG07, KNS17,
BGS20, CK20, DHK20, DZFK24, DHK25, KNS25, KNS26]); see, e.g., [Mar13, DRW19] for work on this
problem in the algorithm theory community.
For decision algorithms, which decide whether there exists a solution, there is clearly no dif-
ference between join queries and conjunctive queries (as projections are equivalent to existen-
tial quantifiers). The problems only diverge for more complex problem variants, e.g., asking to
count [Yan81, DRW19], list, or enumerate solutions. In this paper, we study listing and enumeration.
Formally, for any of the problems P defined before, in P -Listing the task is to compute the set of all
solutions, and the running time analysis involves the total number of solutions t . In P -Enumeration,
the task is also to compute the set of all solutions, but we bound the time until the first solution
is printed (called preprocessing time) and the maximum time between printing two consecutive
solutions (called delay). The time after printing the last solution can also be assumed to be bounded
by the delay. Both listing (e.g. [CN85, AKLS23, JX23, ABKZ22, ABF23, DMVX24, JVZ24, BG25, VW25])
and enumeration (e.g. [KR95, Uno97, Str19, HHMW20, CS21, JX23, MM24, BG25]) are widely studied
in the algorithm theory community, and the same holds for the database community.
Instead of (H ,I )-Subhypergraph Listing we write (H ,I )-Listing for short; similarly for Enumera-
tion. In this paper, we study Colored and Uncolored (H ,I )-Listing and Enumeration. Unless further
specified, we consider the algorithmically harder Colored variant. Throughout, the pattern H is fixed,
and we focus on the complexity in terms of the number of vertices n and the number of edges m of
the host graph G . That is, O-notation suppresses factors of the form f (k), or more generally any
factors depending only on (H ,I ); this is called “data complexity” in the database community. We
will also use eO-notation to hide factors of the form polylog(n), or equivalently polylog(m).
We present two main results, which we discuss in more detail below:
1. When H is a tree, we show that Colored and Uncolored (H ,I )-Listing are in time eO(n17.42 + t ).
The best previously known running time was Ω(nΩ(k)+t ) or t ·nΩ(1). For general hypergraphs H ,
we show that Colored and Uncolored (H ,I )-Listing are in time eO(n17.42·subw(H ) + t ), where
subw(H ) is the submodular width of H . We obtain analogous improvements for enumeration.

2. Any enumeration algorithm with preprocessing time TP and delay TD yields a listing algorithm
running in time O(TP + (t + 1) · TD ), by simply running the enumeration algorithm until it has
printed all t solutions and terminates. We are the first to prove a generic converse to this
statement, an enumeration-to-listing reduction, for a class of problems that includes Colored
(H ,I )-Subhypergraph. We use this as a tool to prove the previous item.
1.1
Polynomial Preprocessing for Projected Trees
Let us start by discussing projected trees, i.e., in this subsection H is always a tree. Without projections,
Yannakakis’ seminal work [Yan81] provides an algorithm for Colored H -Listing in linear time O(m+t ),
where m is the number of edges of the host graph and t is the number of solutions. Variants of
this algorithm also solve Colored H -Enumeration with preprocessing time O(m) and delay O(1),
and count the number of trees in time O(m) [Yan81, BDG07]. These algorithms can be converted to
the uncolored setting by color coding [AYZ95], at the cost of replacing O by eO (and increasing the
hidden dependence on k from polynomial to exponential), see Section 9 for details.
With projections, Bagan, Durand, and Grandjean [BDG07] classified which projected trees can
be enumerated with preprocessing time O(m) and delay O(1): This is possible if (H ,I ) is free-connex,
i.e., the induced subgraph H [I ] is a connected subtree of H . Otherwise it is impossible, assuming a
believable hypothesis on matrix multiplication.1 The same classification also applies to listing in
linear time O(m + t ).
Hence, for general projected trees linear time is impossible, and instead we need to relax the
goal and ask: What is the smallest c = c (H ,I ) such that (H ,I )-Listing is in time eO(m c + t )? As our
first main result, we prove that c ≤17.42.
Theorem 1. For every tree H and every I , (Colored or Uncolored) (H ,I )-Listing is in time eO(n17.42 +t )
and (Colored or Uncolored) (H ,I )-Enumeration is in preprocessing time eO(n17.42) and delay eO(1). If
n × n matrix multiplication is in time eO(n2), then the n17.42 term improves to n3. For the Colored
problems, the dependence on k hidden by eO-notation is polynomial poly(k).
This extends the classic results for listing and enumerating trees [Yan81, BDG07, AYZ95] to
projected trees, at the cost of relaxing the preprocessing time from O(m) to eO(n17.42) and the delay
from O(1) to eO(1). Using n ≤O(m), which holds after removing isolated vertices, the n17.42 terms
can also be replaced by m17.42.
1.1.1
Comparison with Prior Work
Let us discuss why our result is extremely surprising given the state of the art. For any tree on k
nodes, (H ,I )-Listing is trivially in time O(nk) and O(mk−1), since the search space size is trivially
bounded by nk and, slightly less trivially, by mk−1. Some prior work considered listing algorithms in
time t ·mΩ(1) or enumeration algorithms with delay mΩ(1) (e.g. [Hu24, DHK25]), but in this paper we
focus on polylogarithmic delay eO(1) or output-linear listing time eO(m c + t ). In this setting, to the
best of our knowledge no algorithm in the literature unconditionally beats the trivial time bounds.
Specifically, consider the projected-(k −1)-star query:
pattern (H ,I ) with V (H ) = {0,1,...,k −1}, E (H ) = {{0,i} : i ∈[k −1]}, I = [k −1].
No algorithm for projected-(k −1)-Listing in the literature unconditionally runs in time eO(nk−ϵ + t )
or eO(mk−1−ϵ + t ), for any ϵ > 0. In Section A we verify this claim for some algorithms for which it

setting, our running times are even polynomial in k.
We remark that the use of fast matrix multiplication normally improves the running time expo-
nent by at most a factor 2/3. Indeed, if ω = 2 then fast matrix multiplication improves over trivial
matrix multiplication by a factor 2/3 in the exponent, so this factor is what we can hope to gain
for applications of fast matrix multiplication. In this light, Hu’s [Hu24] improvement from mk−1 to
m2/3·(k−1)+O(1) is very natural. In contrast, our improvement from nk to n17.42 is extremely surprising
and in fact at first sight seems impossible. We have not seen a similar effect for any other problem
setting. In our case, this stark improvement is possible because we insist on listing in output-linear
time eO(n c + t ) (or enumeration with polylogarithmic delay).
Finally, let us compare with the Colored (H ,I )-Counting problem, where the task is to count the
number of solutions. Without projections, a variant of Yannakakis’ [Yan81] classic algorithm solves
this problem in time O(m). With projections, a parameterized complexity classification was shown
in [DRW19]; this includes a fine-grained lower bound ruling out that Colored projected-(k −1)-star-
Counting can be solved in time O(nk−1−ϵ) for any ϵ > 0. That is, allowing projections makes counting
trees intractable. In contrast, we show that listing and enumerating trees remains tractable with
projections.
1.1.2
Discussion of Drawbacks
In comparison with the classic results that trees without projections can be listed in time O(m + t )
and enumerated in preprocessing time O(m) and delay O(1), our result has three drawbacks, most
of which are necessary:
Superlinear Preprocessing Time
Unlike the linear preprocessing time O(m) for trees without
projections, we need preprocessing time eO(n17.42) ≤eO(m17.42), and conditioned on very fast matrix
multiplication we still need preprocessing time eO(n3) ≤eO(m3). This is a necessary relaxation, be-
cause our algorithm works for all projected trees (H ,I ), in particular also for non-free-connex (H ,I ),
for which O(m) preprocessing time and constant (or polylogarithmic) delay is impossible by the
known fine-grained classification mentioned above [BDG07].
Polylogarithmic Delay
While constant delay is possible for trees without projections, we need
polylogarithmic delay eO(1). At the core, this comes from polylogarithmic factors in the running time
of a fast rectangular matrix multiplication algorithm that we are using. We leave it open whether the
delay can be improved to O(1) without significantly worsening the preprocessing time.

Fast Matrix Multiplication
Finally, our algorithms are impractical due to the use of fast (rect-
angular) matrix multiplication. However, we show that any algorithm that breaks the trivial time
bounds nk or mk−1 must be impractical, as it must use fast matrix multiplication. Specifically, we
consider combinatorial algorithms, which intuitively are algorithms that do not use fast matrix
multiplication, and show that if projected-(k −1)-star-Listing has a fast combinatorial algorithm
then so does k-Clique, contradicting the Combinatorial k-Clique Hypothesis. See Section 11 for
more discussion.
Theorem 2. Let k ≥3. Assuming the Combinatorial k-Clique Hypothesis, no combinatorial algorithm
solves (Colored or Uncolored) projected-(k −1)-star-Listing in time eO(nk−ϵ + t ) or eO(mk−1−ϵ + t ), for
any ϵ > 0.
This lower bound is similar to [FKZ23, Theorem 11] and [DZFK24, Theorem 8.5].

1.3
Generalizations to Graphs and Hypergraphs
Now let us broaden our perspective from trees to general (hyper)graphs H . For H -Detection, where
the task is to decide whether there exists a solution, Marx in his seminal work [Mar13] defined
the submodular width subw(H ) and showed that the problem can be solved in time nO(subw(H )),
and requires time at least nsubw(H )Ω(1) assuming the Exponential Time Hypothesis. The PANDA
algorithm [KNS17, KNS25] improved the running time to eO(msubw(H )), and generalized the result
to H -Listing in time eO(msubw(H ) + t ) and H -Enumeration in preprocessing time eO(msubw(H )) and
delay O(1) (see also [KNS26, KC26]).
While projections are irrelevant for the detection problem, it remained open whether the known
listing and enumeration algorithms can be generalized to incorporate projections. As discussed in
Section 1.1.1, already on projected trees prior work had a worst-case preprocessing time of Ω(nk)
or Ω(mk−1), or a delay of mΩ(1). (For example, the PANDA algorithm [KNS17, KNS25] solves (H ,I )-
Listing in time eO(mfc-subw(H ,I ) + t ), where fc-subw(H ,I ) is the free-connex submodular width of
(H ,I ), which is k −1 for the projected-(k −1)-star; see Section A.)
We show that (H ,I )-Enumeration is in preprocessing time nO(subw(H )) and delay eO(1), thus fully
generalizing Marx’ result from detection to listing and enumeration of projected hypergraphs.
Theorem 7. For every H ,I , (Colored or Uncolored) (H ,I )-Listing is in time eO(m17.42·subw(H ) + t ), and
(Colored or Uncolored) (H ,I )-Enumeration is in preprocessing time eO(m17.42·subw(H )) and delay eO(1).
This has the same drawbacks as in the case of projected trees, most of which are again necessary:
(1) In contrast to the eO(msubw(H )) preprocessing time for H -Enumeration, for (H ,I )-Enumeration we
only obtain preprocessing time mO(subw(H )). However, preprocessing time eO(msubw(H )) is impossible,
by the fine-grained classification of the special case where H is a tree and thus subw(H ) = 1 [BDG07].
(2) In contrast to PANDA’s delay of O(1) we only achieve delay eO(1); we do not know whether
this can be improved. (3) Our algorithm is impractical due to the use of fast (rectangular) matrix
multiplication; this is necessary already for projected stars.
1.4
Equivalence of Listing and Enumeration
Listing and enumeration are widely studied in the database community and in the algorithm theory
community. So far they have been studied separately. Here we show that under natural assumptions
listing and enumeration are equivalent.
Recall that reducing listing to enumeration is trivial: If we have an enumeration algorithm with
preprocessing time TP and delay TD then we obtain a listing algorithm in time O(TP + (t + 1)· TD ) by
running the enumeration algorithm until it has printed all t solutions and terminates. Reducing
enumeration to listing is the difficult direction. So far, all attempts at this direction were restricted to
specific classes of listing algorithms (e.g. [Uno03] and [CS24, Section 3.3] presented a conversion of
so-called flashlight listing algorithms). As our second main result, we present the first enumeration-
to-listing reduction which makes no assumptions on the structure of the listing algorithm. It makes
some natural assumptions on the listing problem, which are typically satisfied for colored problems.
Applying our reduction to Colored (H ,I )-Sub(hyper)graph yields the following result.
Theorem 8. Let f ,g be monotone functions such that f (n,m) and g (n,m) can be computed in time
O(f (n,m) + g (n,m)). If Colored (H ,I )-Listing is in time O(f (n,m) + t · g (n,m)), then Colored (H ,I )-
Enumeration is in preprocessing time O((f (n,m)+ g (n,m) + n + m)log2 n) and delay O(g (n,m)).
We make use of this theorem in the proof of Theorem 1: At the core, we design a fast algorithm
for Colored (H ,I )-Listing, running in time O(f (n,m)+t ·g (n,m)) for f (n,m) = eO(m17.42·subw(H )) and

From Restricted Trees to Arbitrary Trees
From this point on, the remainder of our algorithm is a
sequence of reductions, reducing more and more general problems to the algorithm for restricted
trees from the previous paragraph.
Let us consider an arbitrary tree H and an arbitrary I ⊆V (H ). First, we observe that leaves not
in I can be removed by a simple, linear-time reduction. Second, for each i ∈I that is not a leaf, we
can split the problem at i into subproblems on the connected components of H −i. These two
reductions ensure that I is exactly the set of leaves. Finally, after picking a suitable root, we note
that nodes with more than two children can be replaced by a path of nodes each of which has two
children, and that for a node with one child we can attach a dummy child. (For each new edge in H
we also introduce a perfect matching in the host graph.) This turns the tree into a rooted full binary
tree. Altogether, the three reductions turn the tree H and the subset I into a restricted projected tree
where the algorithm from the last paragraph applies. This extends the applicability of the algorithm
and proves Theorem 1 for colored listing. See Section 6 for details.

From Listing to Enumeration
So far we discussed Colored (H ,I )-Listing. We can extend the
algorithm to Colored (H ,I )-Enumeration by applying our enumeration-to-listing reduction. This
reduction roughly works as follows. Suppose there is a listing algorithm that solves an instance I
with t solutions in time f (I ) + t · g (I ). We let this algorithm run with a time budget of 2f (I ). If it
uses up its time budget and aborts, then we branch on the first bit of the search space, recursively
solving subinstances I0,I1. In the analysis, we use that each inner node of the recursion tree has
more than b := f (I )/g (I ) solutions, which bounds the size of the recursion tree. Specifically, we
show that at the time of printing the j-th solution, the size of the recursion tree is O(d + d j/b),
where d = O(logn) bounds the recursion depth. Since each recursive call has a direct time budget
of O(f (I )), the total time before printing the j-th solution is O(f (I )·d + j ·g (I )·d ). Thus, we arrived
at an “amortized” enumeration algorithm, and a well-known contruction converts this into a proper
enumeration algorithm with preprocessing time O(f (I )·d ) and delay O(g (I )·d ). Here we described
a variant of our Theorem 8; the general tradeoff (in particular, the algorithm with preprocessing
time O(f (I ) · d 2) and delay O(g (I )) as claimed in Theorem 8) requires additional ideas and a careful
charging argument, see Theorem 29 in Section 8.
From Colored to Uncolored Problems
So far we discussed the colored problems. The classic color
coding technique [AYZ95] converts algorithms from the colored setting to the uncolored setting.
Specifically, it replaces a given uncolored problem instance by several uncolored problem instances,
such that the union of the solution sets of the constructed uncolored instances is the solution set
of the original uncolored instance. This readily reduces uncolored listing to colored listing: Run
the colored listing algorithm on all colored problem instances constructed by color coding, then
compute the union of the listed solutions, e.g., by sorting and deduplicating. For enumeration, by
following the same recipe we obtain a “cheating” enumeration algorithm which may print the same
solution multiple times. The Cheater’s Lemma [CK21] then converts such a cheating enumeration
algorithm into a proper enumeration algorithm, see Section 9.
This finishes the outline of the proof of Theorem 7.
Faster Algorithm for Projected-d-Stars

From Restricted Trees to General Trees
The previous section forms the core of our algorithm, showing that if H is a rooted full binary tree
and I is its set of leaves then (H ,I )-Listing is in time eO(t + n3/eα). In this and the next sections we
generalize it further and further by a sequence of reductions. By the end of this section, we will be
able to handle general projected trees, i.e., H is any tree and I is any subset of its nodes. Parts of this
reduction are similar to arguments by Hu [Hu24].
As our first step, we generalize from rooted full binary trees to general trees H while insisting that
I is still the subset of leaves. In the reduction, we replace nodes with more than two children by a path
of nodes each of which has two children (for each new edge in H , we introduce a perfect matching
in the host graph), and we attach a new dummy child to each node with one child (corresponding to
a fully connected singleton vertex in the host graph).

From Listing to Enumeration
For search and decision problems that are classically studied in complexity theory, a simple, yet
fundamental result is a search-to-decision reduction, which we will review in Section 8.2. For
listing and enumeration problems, we prove an analogous result, namely an enumeration-to-listing
reduction. It works in almost the same general setting as the classic search-to-decision reduction,
except that the running time bounds also need to be constructible.
8.1
Technical Setup
Throughout Section 8, we consider a generic setup of a computational problem where any instance I
is associated to a search space U = {0,1}d and a set of solutions S ⊆U . We denote by t = t (I ) := |S|
the number of solutions and we call d = d(I ) the depth.
The following definition formalizes that we can split a given instance I by fixing the first bit of
the search space to 0 or 1, generating corresponding subinstances I0 and I1.
Definition 26. A splitting algorithm is an algorithm that given an instance I of depth d > 0 computes
instances I0 and I1 of depth d −1 such that for every b, x1,..., xd−1 ∈{0,1} the tuple (x1,..., xd −1) is a
solution to Ib if and only if (b, x1,..., xd−1) is a solution to I .
For a splitting algorithm split, a function f that maps instances to nonnegative integers is
split-monotone if f (I0) ≤f (I ) and f (I1) ≤f (I ) for every instance I and (I0,I1) = split(I ).
We call split an s-splitting algorithm, for a function s, if split is a splitting algorithm, its
running time on instance I is bounded by s(I ), and s is split-monotone.
8.2

8.3
Our Result: Enumeration-to-Listing Reduction
Analogously to the search-to-decision reduction, we prove an enumeration-to-listing reduction. We
start by introducing different meanings of listing and enumeration.
We work with the same technical setup defined in Section 8.1. A listing algorithm is given an
instance I and computes the set of solutions S. A strong listing algorithm is given an instance I
and a number t ′ and computes min{t ,t ′} solutions to I . For listing algorithms and strong listing
algorithms we are interested in bounding the total running time.
An enumeration algorithm has the same correctness guarantee as a listing algorithm, but instead
of studying the total running time, we focus on bounding the preprocessing time (the time until the
first solution is printed) and the delay (the maximum time between two consecutive solutions are
printed). The time after printing the last solution can also be assumed to be bounded by the delay.
It is clear that any enumeration algorithm with preprocessing time f (I ) and delay g (I ) yields a
strong listing algorithm running in time O(f (I )+ min{t ′,t +1} ·g (I )) ≤O(f (I )+ g (I )+ min{t ′,t } ·
g (I )), by simply running the enumeration algorithm until it has printed t ′ solutions (or until it
has printed all t solutions and terminates). Moreover, a strong listing algorithm running in time
O(f (I )+min{t ,t ′}·g (I )) yields a listing algorithm running in time O(f (I )+t ·g (I )), by simply setting
t ′ := 2d . Our result is a converse to these simple reductions.
Definition 28. A pair of functions (f ,g ), each mapping instances to nonnegative integers, is con-
structible if f (I ) and g (I ) can be computed in time O(f (I ) + g (I )+ 1), for a given instance I .
Theorem 29 (Enumeration-to-Listing Reduction). Let split be an s-splitting algorithm, f ,g be
constructible, split-monotone functions, and β ∈[0,1] be a constant. If there is a listing algorithm
running in time O(f (I ) + t · g (I )), then there is an enumeration algorithm with preprocessing time
O((f (I ) + g (I ) + s(I )) · d 2−β) and delay O(g (I )· d β).
We stress that Theorem 29 assumes that the given listing algorithm is deterministic, and the
resulting enumeration algorithm is also deterministic.
The choice of β ∈[0,1] describes a tradeoff. At one extreme β = 1, we obtain preprocessing time
O((f (I )+ g (I )+ s(I ))· d ) and delay O(g (I )·d ); at the other extreme β = 0, we obtain preprocessing
time O((f (I ) + g (I ) + s(I )) · d 2) and delay O(g (I )).
Let us discuss the requirements of Theorem 29. First, it assumes splittability (specifically, that
there is an s-splitting algorithm split and f ,g are split-monotone). This is a well-motivated
requirement, because it is also used in the classic search-to-decision reduction (Theorem 27), and
because Colored (H ,I )-Subhypergraph has this property as we will verify soon. In addition to
splittability, Theorem 29 requires the time bounds f ,g to be constructible, which is used in our
reduction to set certain parameters. This requirement is also satisfied for typical listing algorithms,
as most time bounds are expressed in terms of the input size n, and it is typically assumed that n
can be read from the input instance in constant time, so if f and g are simple enough then f (I ) and
g (I ) can even be computed in constant time.

algorithm split. Indeed, fixing a bit of the search space to b ∈{0,1} corresponds to removing from

this is again a valid instance. To perform this removal, it suffices to iterate once over all vertices and
hyperedges to filter out the surviving ones. This runs in time O(n + m); for concreteness suppose
that the running time is bounded by s(G ) := c · (n(G ) + m(G )) for some constant c > 0. Note that

f ,g is constructible. Since split constructs subhypergraphs and f ,g are monotone, f and g are
also split-monotone. Hence, the requirements of Theorem 29 are satisfied. With β := 0, it yields
the claimed enumeration algorithm.

Open Directions
We leave the following open questions on the enumeration-to-listing reduction.

Improvements
Can the overhead factors be further improved? Specifically, is it possible to improve
the overheads in preprocessing time and delay from the current tradeoff (O(d 2−β),O(d β)) to, e.g.,
(O(d 1.99),O(1)) or (O(d ),O(d 0.99)) or even (O(d),O(1))?
It is natural to expect that the overhead in preprocessing time must be at least d , at least in the
general setting considered here, as this is the overhead of the classic search-to-decision reduction.
Can one prove this?
Non-constructible time bounds
Is there a similar reduction without the assumption that the
time bounds are constructible? Note that, e.g., treewidth is a subgraph-monotone parameter, but it
cannot be computed efficiently, so time bounds involving treewidth are not constructible, which
shows a limitation of the current reduction.
Uncolored problems
While we demonstrated our reduction for Colored (H ,I )-Listing, it is not
directly applicable to Uncolored (H ,I )-Listing, since the uncolored problem does not have a self-
reduction and is not splittable in the sense of Definition 26. Could there be a variant of Theorem 29
that would work for uncolored problems?
More applications
Does our reduction have applications beyond subgraph listing and conjunctive
queries, such as enumerating spanning trees, matchings, etc.? Or is there some variant of the
reduction that would admit more applications?
Randomized algorithms
Theorem 29 assumes that the given listing algorithm is deterministic,
and yields a deterministic enumeration algorithm. In some settings of randomized algorithms it
might be possible to avoid the factor d overhead altogether.
8.6
Proof Preparations
We will make use of the Cheater’s Lemma from [CK21], which formalizes ways in which an enumera-
tion algorithm may cheat so that it can still be converted into a proper enumeration algorithm. The
original statement of this lemma uses very specific running time bounds, therefore here we rework
it to allow more general time bounds. (Later in this paper we will need yet another variant, which
we call variant II.)
Lemma 33 (Cheater’s Lemma, Variant I). Let f ,g be constructible functions with f (I ) ≥g (I ) for
all I . Suppose there is a listing algorithm that for any 1 ≤j ≤t prints the j-th solution in time at most
f (I )+ j ·g (I ). Then there exists an enumeration algorithm with preprocessing time O(f (I )) and delay
O(g (I )).
Proof. We augment the listing algorithm with a counter that is incremented after each step, so it
counts the number of steps performed by the algorithm. We run this augmented algorithm, gathering
its listed solutions. After the (f (I )+ j ·g (I ))-th time step, we print the j-th gathered solution. If at
this point less than j solutions have been gathered, then we terminate.
Note that to run this algorithm we need to know f (I ) and g (I ), and we can indeed compute f (I )
and g (I ) in time O(f (I ) + g (I )), since f ,g is constructible.
The guarantee of the listing algorithm ensures that j solutions are gathered in time at most
f (I )+ j ·g (I ), so after the (f (I )+ j ·g (I ))-th time step we can print the j-th gathered solution. This
holds for any 1 ≤j ≤t . Thus, if at this point less than j solutions have been gathered, then j > t , in
which case we have already listed all j −1 = t solutions and correctly terminate.
Clearly, the first solution is printed in time O(f (I ) + g (I )) = O(f (I )) and the time between
printing two solutions is O(g (I )). The time between printing the last solution and terminating is
also O(g (I )). That is, we obtained an enumeration algorithm with preprocessing time O(f (I )) and
delay O(g (I )).

Conditional Lower Bounds
The starting point of our lower bounds is the Clique(k,n1,...,nk) problem. Here, the input is a
k-partite graph G = (V1 ∪··· ∪Vk,E ) where |Vi| = ni for all i ∈[k], and the goal is to decide if G
contains a k-clique. Clearly, any k-clique in G (if exists) must pick exactly one vertex from each part.
For n1 = ... = nk = n, the fastest known algorithm for the problem works by grouping the k parts
into 3 roughly balanced groups, which induce a tripartite graph on nk/3+O(1) vertices, then running
a triangle detection algorithm on this tripartite graph. Since triangle detection can be solved in
matrix multiplication time, this gives an nωk/3+O(1)-time algorithm for Clique(k,n,...,n). If only
“combinatorial” algorithms are allowed (i.e., fast matrix multiplication is disallowed), then the state
of the art is essentially brute-force. This gives rise to the following frequently used hypotheses in
fine-grained complexity; see e.g. [ABV15, ABBK17, BGL17].
Combinatorial k-Clique Hypothesis. Let k ≥3 and δ > 0. No combinatorial algorithm can solve
Clique(k,n,...,n) in time O(nk−δ).
k-Clique Hypothesis. Let k ≥3 and δ > 0. No algorithm can solve Clique(k,n,...,n) in time
O(nωk/3−δ).
Next we pose a new hypothesis that has not been previously used.
Lopsided 4-Clique Hypothesis. Let β ≥1 and δ > 0. No algorithm can solve Clique(4,n,n,n,nβ) in
time O(n2+β−δ).
The known algorithms solve Clique(4,n,n,n,nβ) by building a (possibly dense) n2 ×nβ matrix,
and thus take time Ω(n2+β). The hypothesis formalizes this running time barrier, postulating that
no algorithm can be faster. Naturally, the level of trust in a new hypothesis is significant lower.
Nevertheless, we use it as a barrier towards faster listing algorithms.
After discussing the relevant hypotheses, we now present our main reduction. This is a generic
reduction from Clique(k,n1,...,nk) to listing projected-(k −1)-stars.
