Abstract
We study dynamic algorithms for maintaining fundamental algebraic properties of matrices, specifi-
cally, rank, basis, and full-rank submatrices, with applications to maximum matching on dynamic graphs.
Prior dynamic algorithms for rank achieve subquadratic update times but scale with the matrix dimen-
sion n, and could not always maintain the corresponding objects such as a basis or maximum full-rank
submatrix.
We present the first dynamic rank algorithms whose update time scales with the matrix rank r,
achieving e
O(r1.405) time per entry-update and e
O(r1.528 + z) per column-update, where z is the number
of changed entries. This extends to e
O(|M|1.405) edge-update time to maintain the size |M| of a maximum
matching. We also give dynamic algorithms for maintaining a column-basis subject to column-updates
and a maximum full-rank submatrix subject to entry-updates.

Introduction
Dynamic algebraic algorithms maintain properties of matrices and vector spaces while the input undergoes
changes. These algorithms, when used as subroutines, have led to improvements in various areas such as
convex optimization [CLS21, Bra21, JKL+20, JLSW20], network-flows [DGG+22, GLP21, BLL+21, BGJ+22,
BZ23], online algorithms [DSW22, HSSZ19], failure-sensitive oracles [GV20, WY13, BS19, GR21].
Many dynamic graph problems (where the goal is to maintain certain graph properties while the graph
undergoes edge insertions and deletions) such as reachability [San04, GKMP25, KS23a], strong-connectivity
[KS23c] shortest path [San05, KS23b, BK23b, BN19], matching [San07], near additive spanner [BHG+21,
BFN22], have also been addressed using dynamic algebraic techniques.
In fact, it has been shown that
achieving subquadratic upper bounds for many of these problems requires the use of algebraic techniques.
[AV14, BHG+21].
This work focuses on two of the most fundamental properties of matrices and vector spaces: rank and
basis. Formally, the problem is defined as follows: we are given an n × n matrix (i.e., a collection of vectors)
that undergoes updates (e.g., column replacements). After each update, we must return the new rank or
basis. The “update-time” refers to the time required to compute and return the new rank or basis after an
update. We consider both column-updates (where an entire column/vector is replaced) and entry-updates
(where a single matrix entry is modified).
Dynamic Rank & Matching:
Given a graph G, the size of a maximum matching is equal to half the rank
of the graph’s Tutte-matrix1. Hence, by maintaining the rank of a dynamic matrix under entry-updates, we
can maintain the size of a maximum matching in a graph that undergoes edge insertions and deletions. The
latter problem is known as dynamic maximum matching. Via further reductions, this also extends to other
graph problems such as dynamic vertex-capacitated max-flow.
Dynamic maximum matching is a well-studied problem in the dynamic graph area with substantial
amount of work in recent years for the approximate setting [Beh23, Kis23, BK23a, BKS23a, ABR24,
BKSW24, AKK25].
In the exact setting, the upper bounds for n-vertex graphs are O(n1.528) [FF09],
O(n1.446) [San07] and O(n1.405) [BNS19].
These upper bounds for exact matching are achieved via the
reduction from matching to rank, i.e., despite the graph application, these dynamic algorithms are entirely
algebraic and maintain the rank of the Tutte-matrix. The algebraic approach and slower progress in the
exact setting can be explained via conditional lower bounds. The two highest corresponding conditional
lower bounds for dynamic matching are Ω(nω−1) ∼Ω(n1.372) based on the triangle detection conjecture2
[AV14], and Ω(n1.405) [BNS19] based on the hinted-Mv conjecture3. These lower bounds imply that any
upper bound must be algebraic (i.e., make use of fast matrix multiplication) to beat the naive eO(n2) upper
bound4 of recomputing the matching from scratch on dense graphs [BLN+20, CKL+23]. Further, depending
on which conjecture one believes, the current O(n1.405) update time is conditionally optimal or nearly so
(with only a o(n0.04) gap to triangle detection for current bounds on ω). While these conditional lower
bounds seemingly rule out substantial further progress in the exact setting, they only holds for distinguish-
ing between matching-size (or rank) n vs n −1. Thus, the lower bounds do not apply to graphs with small
maximum matchings (or matrices with small rank), leaving open the possibility of significant improvements
for the low-rank/small-matching case.
Such improvements for low-rank matrices have previously been obtained in the static setting. While
computing the rank of an n × n matrix A generally takes O(nω) time, [CKL13] showed how to compute the
rank in only eO(nnz(A) + rω) time, where nnz(A) is the number of non-zeros (i.e., time to read the input
matrix A) and r is the rank of the input matrix. So for low-rank matrices (e.g., r < n1/2), the rank can be
computed in nearly-linear time.
On the one hand, this highlights a gap in the dynamic setting: for sparse low-rank matrices, naïve
recomputation of the rank from scratch via [CKL13] is already faster than the current O(n1.405) dynamic
algorithms. So no non-trivial dynamic algorithm is known for such matrices. On the other hand, the result
of [CKL13] suggests that it may be possible to improve the dynamic complexity by having it depend on rank

Dynamic Basis and Full-Rank Submatrix:
The rank of a set of vectors (or a matrix) is the size of
the maximum linearly independent subset (or size of the maximum full-rank submatrix). Previous fastest
dynamic rank data structures [San07, BNS19, BFNP24] can maintain the rank (i.e., size of basis/submatrix),
but not the actual basis or submatrix itself. These algorithms work via a black-box reduction by [San07],
which reduces dynamic rank to dynamic matrix inverse (here one must maintain the inverse while the input
matrix changes over time). Thus improvements for dynamic matrix inverse [BNS19, BFNP24, ABGZ24]
have directly translated to better algorithms for dynamic rank and matching size.
However, when it comes to maintaining an actual basis, the only known algorithm is that by [FF09]
which, rather than a black-box reduction, was a dynamic algorithm specifically designed for maintaining the
rank5. Thus, this algorithm has not benefited from recent advances in dynamic matrix inversion, and thus
the update time remains at O(n1.528), which is slower than the O(n1.405) update time for rank. If there was
a black-box reduction from basis/full-rank submatrix to dynamic matrix inverse, similar to how there is a
reduction from rank, then these issues would be resolved.
The ability to maintain the size, rather than the corresponding object, is a common limitation of dy-
namic algebraic algorithms. This issue extends to the applications of dynamic algebraic algorithms such
as maintaining reachability, strong-connectivity, maximum matching, or shortest paths in dynamic graphs.
[AV14] have proven that solving these problems in the dynamic setting faster than the trivial eO(n2) requires
the use of fast matrix multiplication, i.e., algebraic techniques. However, given the algebraic nature, most
dynamic algebraic algorithms maintain numbers/quantities rather than the respective combinatorial objects.
For example, [San05, BN19, KS23b, BFN22] maintain distances (i.e., length of shortest path) rather than
the paths. [San07] maintains the size of the maximum matching rather than the matching. For reachability,
[San04, DI05] maintain boolean reachability information, but not the respective paths. [BNS19] maintains a
boolean output whether the graph is strongly-connected, but not the strongly-connected components. This
inability to maintain the underlying object is a major draw-back of dynamic algebraic methods and has
been stated as open problems in [BN19, BNS19]. Recently, studying how to maintain objects via dynamic
algebraic techniques has developed to an active area of research with first progress for paths: [KMS22] ex-
tended dynamic reachability to path reporting, and [BHG+21, AB24] can maintain shortest paths. [KS23c]
extends strong-connectivity to maintaining the strongly-connected components. However, for maintaining
a maximum full-rank submatrix (rather than just the rank), or a maximum matching (rather than just its
size), the question remains open.
In this work, we give the first reduction from basis (and maximum full-rank submatrix) to dynamic rank.
The latter reduces to dynamic matrix inversion [San07], thus, all recent improvements to dynamic matrix
inverse now also extend to dynamic basis. As a full-rank submatrix corresponds to the vertex set used by
the maximum matching, this is also the first fully dynamic algorithm that maintains information about the
exact maximum matching beyond its size.
1.1
Our Results
Maintaining the Rank
Our first result are improved time complexities for maintaining the rank of a
dynamic n × n matrix, scaling with the rank of the matrix rather than its dimension. In the following,
nnz(A) is the number of non-zero entries in A, when given in sparse representation.
Theorem 1.1. There are randomized dynamic algorithms that maintain, with high probability, the rank of a
dynamic n × n matrix A. Both have preprocessing time eO(nnz(A) + rank(A)ω) and their update times are:
• eO(rank(A)1.405) time per entry-update,
• eO(rank(A)1.528 + z) time per column-update, where z is the number of entries changed in the column.

current best bounds for fast rectangular matrix multiplication [ADV+25].
Since the rank of a graph’s Tutte-matrix is twice the size of a maximum matching, Theorem 1.1 directly
implies algorithms for dynamic maximum matching size. For bipartite graphs, a reduction by [KLST01]
allows us to maintain the weight of the maximum weight matching as well.
Theorem 1.3. There are randomized dynamic algorithms that maintain with high probability
• the weight k of a maximum weight matching in a bipartite graph with O(W ·k1.405) time per edge-update,
where W is the weight of the updated edge.
• the size |M| of the maximum matching M in a general graph in O(|M|1.405) time per edge-update.
The previous best bounds for these problems were O(n1.405) for maximum matching and O(W 2.405·n1.405)
for the weighted case [San05, BNS19].
Maintaining a Basis
The dynamic algorithms of Theorem 1.1, and those of [San05, BNS19] can only
maintain the rank of a matrix (i.e., set of vectors) but not a corresponding basis. We extend the results to
maintain a column-basis:
Theorem 1.4. There is a randomized dynamic algorithm that maintains with high probability a column-basis
of a dynamic n×n matrix A in eO(z+rank(A)1.528) time per column update. Here z is the number of entries
changed during the column update.
The dynamic algorithm is robust against output-adaptive adversaries.

Column-updates to a matrix

Maintaining a Full-Rank Submatrix
Given a matrix A ∈Fn×n, computing a full-rank submatrix
corresponds to first constructing a column-basis (i.e., subset of columns of A) and row-basis (i.e., subset of
rows of A), and then taking the submatrix induced by the row and column set7.
Running Theorem 1.4 or [FF09] on A and A⊤would allow to maintain a maximum full-rank submatrix
in O(rank(A)1.528) or O(n1.528) time. However, maintaining the rank can be done in O(rank(A)1.405) time
via Theorem 1.1 (or O(n1.405) via [San07, BNS19]).
To address these issues, we develop a new approach for maintaining a maximum full-rank submatrix. We
show that maintaining such a submatrix (and thus also the rank of a matrix) reduces to merely detecting
when a dynamic matrix becomes singular (i.e., non-invertible; det(A) = 0) for the first time.
Theorem 1.6. Assume there is a data structure that detects when a dynamic n × n matrix A becomes
singular for the first time, with U(n) time per entry-update. Let P(n) be the preprocessing time.
Then there is a dynamic algorithm for maintaining a maximum full-rank submatrix (i.e., sets I, J ⊂[n]
with det(AI,J) ̸= 0 and |I| = |J| = rank(A)) after O(P(n) + nω) time preprocessing with eO(U(n)) entry-
update time.
The reduction is randomized, correct with high probability, and works against an output-adaptive adversary.
A reduction from rank to singularity-detection was previously given by [San07], but it could only maintain
the rank, and not a corresponding object such as a basis or full-rank submatrix.
By applying our reductions to dynamic determinant algorithm of [BNS19], we obtain the following result:
Theorem 1.7. There is a dynamic algorithm that maintains with high probability a rank(A) × rank(A)-
sized full-rank submatrix of a dynamic n × n matrix A. After each update, the data structure returns the
set of row/column-indices that define the submatrix. The preprocessing time is O(nω) and the update time
is eO(n1.405) per entry update.
This result also implies that we can maintain the vertex set of a maximum matching in a dynamic graph
undergoing edge updates. This improves over previous algorithms, which could only maintain the size of the
matching [San07, BNS19, BFNP24].
Remark: Combinatorial Approach
A combinatorial approach for maintaining a matching (besides
recomputation from scratch in eO(n2) time [BLN+20, CKL+23]) is to find an augmenting path in O(n2) time
after each update. Beating quadratic time requires algebraic techniques [AV14].
Given how there is an O(n2) combinatorial and O(n1.405) algebraic algorithm, it is natural to ask if there
is also an O(|M|2) combinatorial algorithm matching the O(|M|1.405) proven in Theorem 1.3. We observe
that there is an O(|M|2) time combinatorial algorithm based on augmenting paths using vertex sparsification
from [GP13].
Theorem A.1. There is a deterministic algorithm that maintains the maximum matching M ⊂E in a
dynamic bipartite graph G = (V, E) subject to edge updates in O(|M|2) time.

Further Related Work
In addition to the conditional lower bounds stated in the introduction, there is also an Ω(n) conditional
lower bound for dynamic maximum matching based on the OMv-conjecture [HKNS15].
Dynamic matching (maximal, maximum, weighted, etc.) is one of the most well-studied problems in the
dynamic graph area, see e.g.,[ABD22, BDL21, BFH19, BS16, BS15, PS16, Waj20, GP13, LMSV22, Kis22,
BKS23b, Kis21, CZ19, CS18, LMSV22, BK21, BHN16, BDH+19, ACC+18, BGS11, OR10, Beh23, Kis23,
BK23a, BKS23a, ABR24, BKSW24, AKK25] and references therein.
Maintaining small matching/max-
flow in the partially dynamic setting (only insertion/only deletions) was studied in [Hen97, GK21, GH23].
Further dynamic algebraic problems that have been studied are dynamic characteristic polynomial [FS11],
dynamic Frobenius normal form [KS23b], dynamic matrix vector multiplication [ABM25], dynamic convolu-
tion (polynomial multiplication) [RT97]. [FHM01] studied dynamic algebraic algorithms from the perspective
of algebraic circuit lower bounds.
Similar to the exact setting, in the better-than-2 approximate setting the dynamic matching algorithms
from [Beh23, BKSW24, BKS23a] can also only maintain the size but not the matching itself. Unfortunately
our techniques for maintaining the vertex set seem to be difficult to extend to the approximate setting,
because they rely on distinguishing size n vs n −1 (i.e., existence of a perfect matching).
1.3
Preliminaries/Notation
We write [n] for set {1, ..., n}. For matrix M ∈Fn×n and sets A, B ⊂[n], we let MA,B be the submatrix
consisting of the rows and columns with index in A and B respectively. Similarly, we let M−A,−B be the
matrix obtained via deleting the rows and columns with index in A and B respectively. For bipartite graphs
G = (U ∪W, E) with |U| = |W| = n, we define the biadjacency matrix A ∈FU×W via Au,w = 1 if {u, w} ∈E
and Au,w = 0 otherwise. For permutation σ : [n] →[n] the sign of σ is sign(σ) = (−1)t where t is the number
of inversions (i.e., number of pairs i < j with σ(i) > σ(j)).
Lemma 1.8 (Schwartz-Zippel-Lemma). Let F be a field and f be a non-zero polynomial of degree d with
variables x1, ..., xn, i.e., f ∈F[x1, ..., xn]. Let r1, ..., rn be i.i.d. uniformly sampled elements of F. Then
P[f(r1, ..., rn) = 0] ≤d/|F|.
Intuitively, this lemma states that if there exists some input for f which evaluates to non-zero, then
finding such an input is trivial by simply sampling a random input.
Lemma 1.9 ([CKL13, Lemma 2.4&2.5]). Given n, k ∈N, in O(n) time we can construct a random n × r
matrix M ∈Fn×r with r = Θ(k), such that
• each column of M has at most 2⌈n/r⌉non-zero entries, and each row has 2 non-zero entries.
• for any matrix A ∈Fm×n, we have with probability at least 1 −O(1/k + k/|F|) that rank(AM) =
min(rank(A), r).
The matrix M in Lemma 1.9 can be seen as a rank-preserving random projection. It projects m many
n-dimensional vectors (the rows of A) onto a smaller r-dimensional space such that with constant probability
the rank is preserved. Since the new space is r-dimensional, the rank is preserved only when at most r, hence
rank(AM) = min(rank(A), r). Further, the projection M is sparse, i.e., changing an entry of a row-vector
v⊤will change only 2 entries in its projection v⊤M.
Remark:
We can assume without loss of generality that field F has size poly(n), otherwise we use a field
extension of such size [CKL13, Lemma 2.1]. Further, there is k0 = Θ(1) such that for all k > k0, the success
probability of Lemma 1.9 is at least 1/2. We can then further boost the success probability of Lemma 1.9
by sampling several M1, ..., Mℓand returning maxi∈[ℓ] rank(AMi). Then we have w.h.p., that the returned
rank is min(rank(A), r).

Technical Overview
We begin by outlining how to maintain a maximum sized full-rank submatrix (Theorem 1.7) in Section 2.1.
The idea of the algorithm is based on constructing a gadget matrix by interpreting the full-rank submatrix
problem graphically using connections between the determinant of a matrix and perfect matchings in graphs.
Rather than a full-rank submatrix, we identify a vertex-set that must be deleted such that a perfect matching
becomes possible.
Then, in Section 2.2, we explain how to improve the maintenance of rank (Theorem 1.1) and basis
(Theorem 1.4) for low-rank matrices. These latter results are based on a random projection technique by
[CKL13].

By property (ii), we know a full-rank submatrix of A, which is exactly what our dynamic algorithm is
supposed to return after each update. Property (i) will hold after we are done processing the update to A,
but uniqueness does not hold while processing the update, as we are performing a binary search to find one
valid S, T.
To outline how we maintain these two properties, consider the following possibilities after we receive an
entry-update to A. Since a single entry Ai,j is updated, the rank of A can change by at most 1, giving us
the following cases:
(a) The rank increases, so we can add one more row and column to the full-rank submatrix of A. In
particular, our task is to find and remove an index from S and an index from T, such that (ii) holds
again.
(b) The rank decreases, so we must remove a row and column from the (previously) full-rank submatrix
of A. In particular, the task is to find and add an index to S and an index to T, such that (ii) holds
again. This task is trivial since updating entry Ai,j means that the i-th row and j-th column are
precisely the ones to be removed from the submatrix, i.e., S ←S ∪{i}, T ←T ∪{j}.
(c) The rank stays the same. We can reduce this to case (b)+(a): After an update to Ai,j, we add i, j to
S, T, then attempt to remove an index from S and from T again via the procedure of (a).
So our update routine is as follows: Before updating entry Ai,j, we check if the update will make A−S,−T ,
and thus H, singular. If it would, we add i to S and j to T before making the update. In either case, we
update Ai,j and then attempt to find an index to remove from S and an index to remove from T and remove
them. We do this last step (searching for and removing a pair of indices) twice.
We are left with describing the procedure for finding s ∈S and t ∈T such that after removal we still
have det(A−S,−T ) ̸= 0. To do this, we construct our gadget matrix B such that the following holds:
Property 2.2. Given S, T ⊂[n] and C = {l, ..., r}, C′ = {l′, ..., r′}, the matrix B has the property that all
S′, T ′ ⊂[n] with det(B−T ′,−S′) ̸= 0 are precisely the sets S′ = S \{c}, T ′ = T \{c′} for c ∈C ∩S, c′ ∈C′ ∩T.
Thus, when det(H) ̸= 0, then know there is some S′, T ′ with det(A−S′,−T ′) ̸= 0, and by repeatedly
halving the size of C, C′ we can binary search for a single valid S′, T ′.
Given the binary search structure, it suffices to restrict to C, C′ to be certain intervals. (When n is a

the C, C′ needed in the binary search, there is a matrix B with Property 2.2. Further, changing one entry
in S, T and halving sets C, C′ results in only O(1) changed entries in B. Thus, after an update to matrix A,

2.2
Maintaining Small Rank&Basis (Section 4)
The complexity of the submatrix-algorithm outlined in previous subsection scales in dimension n. Here we
outline how to maintain small rank more efficiently (Theorem 1.1), and how to maintain a basis (Theorem 1.4)
more efficiently for low-rank matrices. Our results rely on Lemma 1.9 (see preliminaries) by [CKL13].
Maintaining just the rank is simple with the above lemma, and we start by outlining that algorithm.
Then we extend the algorithm to also maintain a basis.
Maintaining Rank (Theorems 1.1 and 1.2)
Let us assume for now that we just want to maintain
rank(A) up to some parameter k, i.e., we maintain min(rank(A), k).
To do this, we first sample two matrices L, R via Lemma 1.9 and then compute L⊤AR. By Lemma 1.9
we have rank(L⊤AR) = min(k, rank(AR)) = min(k, rank(A)). So by maintaining the rank of L⊤AR, we
maintain the rank of A up to k.
Further, by Lemma 1.9, there are only 2 non-zero entries per row in L, R. Thus an entry-update to A

changes only 4 entries of L⊤AR. Also observe that matrix L⊤AR is of size O(k) × O(k) due to width of
L, R. Thus if we can maintain the rank of an n × n matrix in U(n) update time, then we can now maintain
min(rank(A), k) in 4 · (U(O(k))) = O(U(k)) update time. We run O(log n) independent copies of this so at
least one preserved the rank with high probability. Thus resulting in eO(U(k)) update time.
Next, we extend this to eO(rank(A)) update time.
To do this, we maintain the product L⊤AR for
different powers of k = 2i, i = 0, ..., log n. Whenever the rank of A changes by constant factor, we initialize
a new dynamic rank data structure for some k = 2i with i = ⌈log(rank(A))⌉+ 1. Until we must initialize a
data structure for k = 2i±1, there must be at least 2i−1 updates. (Because each update can change the rank
by at most 1.) So the initialization cost amortizes over O(2i) updates. This leads to an amortized update
time of
eO(U(rank(A)) + P(rank(A))/ rank(A)),
where P(n), U(n) are the preprocessing and update time complexity of a dynamic rank data structure for
n × n matrices.
In case of column-updates, the same techniques works, because changing one column of A changes at
most 2 columns of L⊤AR. So there, too, the reduction has only a constant-factor blow-up for the number
of updates.
Maintaining Basis (Theorems 1.4 and 1.5)
When performing a column update, the rank can change
by at most 1. In particular, if the updated column was already part of the basis then it might have to be
removed or replaced. If the updated column was not part of the basis, then it might need to be added to
the basis. In either case, the task of maintaining a basis reduces to the following problem: Given dynamic
matrix A and a linearly-independent set of column-vectors B, find if there is a column in A that can be
added to B.
Observe that if all columns of A are linearly dependent to B, then any linear combination Av is also
dependent to B. Conversely, if A contains a column that is linearly independent, then there exists v = ei (a
standard unit vector) such that Av is independent of B. By Schwartz-Zippel-Lemma 1.8, this then implies10
that for random vector v, we also have that Av is independent of B with high probability. Now assume we
have a dynamic rank data structure supporting column updates. If adding column Av to B increases the
rank, we know A contains an independent column. We can use this to binary-search for the first independent
column in A, by repeatedly zeroing out half the entries of v. Each step in the binary-search corresponds
to adding and removing a column Av to B. So we need O(log n) column-updates to find a new linearly
independent column.
The last bottleneck is that computing Av takes O(n2) time. Thus we must maintain the possible Av-
products that occur during the binary-search, rather than computing them from scratch in each iteration.
During initialization, we precompute all Av-products that could show up during binary-search. Then
when a column of A changes, there are only O(log n) matrix-vector-products that must be updated. In
particular, updating one product Av during a column-update to A takes only O(z log n) time, where z is
the number of entries changed in A by the update.
In summary, let U(n) be the update time of maintaining rank of a dynamic n × n matrix H, subject to
column-updates. Then we can maintain a column basis in time
O((U(n) + z) log n).
This is eO(n1.528 + z) update time using [BNS19].

In this section, we prove our reduction from maximum full-rank submatrix to singularity detection.
Theorem 1.6. Assume there is a data structure that detects when a dynamic n × n matrix A becomes
singular for the first time, with U(n) time per entry-update. Let P(n) be the preprocessing time.

The reduction is randomized, correct with high probability, and works against an output-adaptive adversary.
As outlined in Section 2.1, the reduction is simple if we assume all non-zero entries of the matrix are
random field elements, because then full-rankness is equivalent to perfect bipartite matching. The main
challenge is to prove an equivalent result when the input matrix does not have random entries. To do this,
we translate the graph reduction from Section 2.1 to matrix perspective. Hence we strongly recommend
readers to first read Section 2.1 before reading Section 3.
The gadget-graph described in Section 2.1, is translated to a biadjacency matrix, whose determinant is
analyzed in Section 3.1. That analysis requires careful handling of signs of permutations, which would not

In Section 3.2, we analyze the determinant of the binary-tree-matrix and analyze the determinant behavior

Lastly, in Section 3.3 we combine the results and prove that the binary-search yields an algorithm for

Adaptivity
The output of our dynamic algorithm would w.h.p. be the same if we always compute rank(B)
deterministically and append to B the first column from A that is linearly independent from B. Thus the
output of our data structure is pseudo-deterministic and works against an adaptive adversary.
4.4
Dynamic Maximum Matching Weight & Size
In this subsection, we prove Theorem 1.3 via standard reductions.
Theorem 1.3. There are randomized dynamic algorithms that maintain with high probability
• the weight k of a maximum weight matching in a bipartite graph with O(W ·k1.405) time per edge-update,
where W is the weight of the updated edge.
• the size |M| of the maximum matching M in a general graph in O(|M|1.405) time per edge-update.
The result for maximum matching follows from the well-known reduction to the rank of a Tutte-matrix.
Lemma 4.3 ([Tut47]). Given graph G = (V, E), let A be the symbolic matrix where for each edge {u, v} ∈E,
Au,v = xuv = −Av,u. Then rank(A) is twice the size of the maximum matching in G.
In particular, if A′ ∈Fn×n is matrix A where we replace each xuv with a random element of polynomially-
sized field F, then w.h.p. rank(A′) is twice the size of the maximum matching in G.
The bound for maintaining the size of a matching in eO(|M|1.405) thus follows directly by maintaining the
rank of A′ via the data structure of Theorem 1.1 in eO(rank(A′)) time. Each edge update changes 2 entries
in A′, and thus we must perform only two entry-updates to the dynamic rank data structure.
The result for weighted matching follows from Lemma 4.4.
Lemma 4.4 ([KLST01]). Let G be an integer weighted bipartite graph. Construct H as follows: For v ∈
V (G) let wv be the largest incident edge weight. Create wv many vertices v1, ..., vwv in H. For each edge
{u, v} ∈E(G), create edges {u1, vw}, {u2, vw−1}, ..., {uw, v1}, where w is the weight of edge {u, v}.
Then the size of the maximum matching in H is equal to the maximum weight matching in G.
Let A′ be the randomized Tutte-matrix of graph H. Then a weight W edge-update to G changes W
edges in H and thus W entries in matrix A′. The rank of A′ is the size of the maximum matching in H
and thus the weight of the maximum weight matching in G. In particular, we can maintain the maximum
weight in eO(W · rank(A′)1.405) = eO(W · k1.405) time per edge-update, where W is the weight of the updated
edge and k is the weight of the maximum weight matching.

In this section, we give a deterministic combinatorial algorithm for maintaining a maximum matching |M|
on a bipartite graph G in O(|M|2) per update.
Theorem A.1. There is a deterministic algorithm that maintains the maximum matching M ⊂E in a
dynamic bipartite graph G = (V, E) subject to edge updates in O(|M|2) time.
The algorithm is based on the following observation, which is a variation of the “core-graphs” of [GP13]:
Let W ⊂V be the matched vertices, then any augmenting path of length ≥3 uses (except for the first and
last unmatched edge on the augmenting path) only edges from the induced subgraph G[W]. Let W ′ ⊇W
by adding for each w ∈W an unmatched neighbor to the set (if w has an unmatched neighbor). Then there
is an augmenting path of length ≥3 in G if and only if there is an augmenting path of length ≥3 in G[W ′],
obtained by simply replacing the first and last vertex on the augmenting path. By |W ′| ≤2|M|, finding an
augmenting path in G[W ′] takes only O(|M|2) time.
To prove Theorem A.1 rigorously, we need to take care of how to maintain the set W ′.
We describe a helper data structure that supports some basic operations on graphs.
Lemma A.2. There is a deterministic data structure that supports the following operations on a graph G
on n vertices.
• Initialize() the empty graph in O(n2).
• Test(e) that returns if e ∈E(G).
• Insert(e) that inserts an edge e /∈E(G) in O(1).
• Delete(e) that removes an edge e ∈E(G) in O(1).
• Subgraph(S) that returns G[S] induced by S ⊆V (G) in O(|S|2).
• ExternalNeighbors(S) that returns a mapping x : S →V (G) ∪{⊥} such that for each vertex v ∈S,
x(v) ∈NG(v) \ S, or x(v) = ⊥if none exist, in O(|S|2).
The main difficulty is the ExternalNeighbors operation. We would like to enumerate neighbors in O(1)
time each, which suggests using an adjacency list. However, we also wish to check if edges are present in
O(1) time, which suggests using an adjacency matrix instead.
Proof. We will use a hybrid of an adjacency matrix and an adjacency list. It will be convenient to store each
edge as two arcs.
We assume the vertices are labeled 1, . . . , n and so can be used to index into an array.
We will store an n × n matrix A where each entry Auv is either empty or a node indicating the presence
of an arc from vertex u to vertex v. We also have n special row nodes and n special column nodes, one for
each row and column, respectively.
The nodes in each row will be linked in a circular doubly-linked list, along with their row node. The
nodes in each column will be linked in a circular doubly-linked list, along with their column node. In other
words, each arc stores the previous and next arc (not necessarily ordered by label) in its row list and the
previous and next arc in its column list.
Testing if an edge uv is present can be done by checking if Auv is nonempty.
To insert an edge uv, we fill Auv with a node, and insert it into the row list for u using the special row
node, and likewise for the column. We do the same for Avu.
To delete an edge uv, we remove the node Auv from its row and column lists, and set it to empty.
To output G[S], we just look at the S × S entries in A.
To find an entry of NG(v) \ S (if one exists) in O(|S|), we iterate over the neighbors of v (by iterating
through the linked list starting at its row node) and skip ones that belong to S. We can determine what
belongs to S using an auxiliary array of size n that gets temporarily marked with the entries in S.

Lemma A.4 (Theorem A.1). There is a deterministic data structure that maintains a maximum matching
M of a bipartite graph G on n vertices which supports the following operations.
• Initialize() the empty graph in O(n2).
• Insert(e) that inserts an edge e /∈E(G) in O(|M|2).
• Delete(e) that removes an edge e ∈E(G) in O(|M|2).
• Matching() that returns a maximum matching of G in O(|M|).
Proof. We will maintain G in an instance of the data structure of Lemma A.2, along with a set of edges M.
We will keep the invariant that between operations, M is a maximum matching of G.
Observe that if M is a maximal matching in G whose size is at most one fewer than a maximum matching
in G, we can make it maximum matching in O(|M|2) as follows. Let x ←ExternalNeighbors(V (M)). Let
W ←V (M) ∪{x(v) : v ∈V (M)} \ {⊥}. We then construct G[W] explicitly. By Lemma A.3, either M is a
maximum matching, or it has an augmenting path in G[W]. We can find an augmenting path P in G[W] (if
one exists) in O(|W|2) using breadth-first search, and set M ←M∆P to get a maximum matching. Each
of these steps can be done in O(|M|2) time.
To delete an edge e /∈M, we simply remove it from G. The size of the maximum matching cannot
increase, so M remains a maximum matching.
To delete an edge e ∈M, we remove it from G and from M. Now, M is a maximal matching in G whose
size is at most one fewer than a maximum matching in G. We now augment as in the preceding discussion.
To insert an edge uv where u, v /∈V (M), we insert it in G and in M.
To insert an edge uv where u ∈V (M) or v ∈V (M), we insert it in G. Then, M is a maximal matching
in G whose size is at most one fewer than a maximum matching in G. We now augment as in the preceding
discussion.

Other Facts about Basis
The following lemma shows that maintaining a maximum nonsingular submatrix is equivalent to maintaining
a row and column basis. Note that the requirement of having bases here is crucial: a linearly independent
set of rows and a linearly independent set of columns do not necessarily index a full-rank submatrix (for
example, the first row and second column of an identity matrix).

Lemma B.1. Let A ∈Fm×n be a matrix and I ⊆[m], J ⊆[n]. Then, AI,J is a nonsingular submatrix of
size |I| = |J| = rank(A) iff the rows of A indexed by I form a row basis and the columns of A indexed by J
form a column basis.
Proof. If AI,J is nonsingular and |I| = |J| = rank(A), then
rank(A) = |I| = rank(AI,J) ≤rank(AI,[n]) ≤rank(A)
Thus, the rows indexed by I are rank(A) linearly independent rows of A, and are thus a basis. Similarly,
the columns indexed by J are rank(A) linearly independent columns of A, and are thus a basis.
Conversely, suppose that I indexes a row basis and J indexes a column basis. Then, every row of A
with index not in I can be written as a linear combination of rows of A with index in I. In particular,
rank(AI,[n]) = rank(A).
Similarly, every column of A with index not in J can be written as a linear
combination of columns of A with index in J. The same holds for AI,[n] in place of A, using the same
linear combinations. Hence, rank(AI,J) = rank(AI,[n]) = rank(A). Since |I| = |J| = rank(A), AI,J is
nonsingular.
Lemma B.2. Let A ∈FV ×V be the Tutte matrix of a graph G = (V, E). Then, the rows of A indexed by
I ⊆V form a row basis iff I is the vertex set of a maximum matching in G.
Proof. Suppose the rows of A indexed by I form a row basis. Since the Tutte matrix is skew-symmetric, the
columns of A indexed by I form a column basis. By Lemma B.1, AI,I is nonsingular. Note that AI,I is the
Tutte matrix of G[I] (the subgraph of G induced by I). Since AI,I is nonsingular, G[I] must have a perfect
matching. That is, there is a matching in G with vertex set I. This must be a maximum matching: if J
is the vertex set of a larger matching, then AJ,J is nonsingular and so rank(A) ≥rank(AJ,J) = |J| > |I|,
contradicting I indexing a row basis.
Conversely, suppose I is the vertex set of a maximum matching in G. Then, AI,I, being the Tutte matrix
of G[I], is nonsingular. Thus, the rows of A indexed by I are linearly independent. Let J ⊇I index a row
basis in A. By the previous paragraph, J is the vertex set of a maximum matching in G. Hence, J = I.
