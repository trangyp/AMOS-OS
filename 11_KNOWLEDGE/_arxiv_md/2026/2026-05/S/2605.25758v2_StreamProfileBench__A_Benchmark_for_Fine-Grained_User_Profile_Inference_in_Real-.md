Abstract
Large Language Models (LLMs) have reshaped
user profiling, yet current evaluations mainly
focus on static data snapshots. This paradigm
overlooks the reality of personalized systems,
where User-Generated Content (UGC) arrives
continuously and fine-grained profile evolve
rapidly.
To bridge this gap, we introduce
StreamProfileBench, a large-scale benchmark
for fine-grained streaming user profiling. We
formalize streaming user profiling as a continu-
ous state maintenance task and curate a highly
authentic dataset comprising over 120,000
UGC posts from 7,000+ real users across five
diverse platforms. By leveraging the temporal
correlation of user interests, we further propose
a novel, annotation-free evaluation framework.
Extensive experiments across 14 leading LLMs
reveal that continuous profile updating remains
an open challenge. Models exhibit a systemic
conservative bias, over-retaining past interests
while failing to recognize interest decay. Abla-
tion experiments further validate the practical
utility and necessity of the streaming paradigm.

Introduction
User profiling is the foundation of personalized
service systems, aiming to extract attributes, in-
terests, and intentions from personalized traces
such as user-generated content (UGC) (Eke et al.,
2019; Prottasha et al., 2025; Tan and Jiang, 2023).
The rapid development of Large Language Mod-
els (LLMs) has reshaped the profiling paradigm
by extending user representations from latent vec-
tors to natural language descriptions (Gao et al.,
2023; Geng et al., 2022; Bao et al., 2023). Today,
LLM-based user profiling has become a key online
component in a wide range of complex personal-
ized systems, including recommendation systems,
conversational assistants, and role-playing agent

systems (Liu et al., 2025b; Wang et al., 2023; Piao
et al., 2025).
Previous studies have explored LLM-based user
profiling across from demographic attribute profil-
ing (Li et al., 2025; Prottasha et al., 2025) to interest
and preference profiling (Lu et al., 2025; Sabouri
et al., 2025; Shi et al., 2025a). However, these
efforts predominantly operate on static data snap-
shots. Such static settings are insufficient when
user profiling serves as an online component in
complex personalized systems, where two inherent
challenges arise: 1) Streaming Data: users con-
tinuously generate new content over time, making
it impractical to perform profiling in a single pass
over a fixed corpus. 2) Evolving Profiles: user
interests are inherently hierarchical (Qi et al., 2021;
Tan and Jiang, 2023). While coarse-grained prefer-
ences remain largely stable, fine-grained interests
shift rapidly (Purificato et al., 2024). A profile that
fails to track these fine-grained shifts quickly be-
comes outdated, causing degraded personalization
quality in downstream systems.
The streaming paradigm naturally addresses
both challenges. Incrementally ingesting arriving
content ensures currency, directly responding to
streaming data; the persistent profile state further
enables tracking interest decay and mapping the
narrative of evolution, capturing the dynamics of
evolving profiles. Figure 1 illustrates these advan-
tages over static profiling.
To operate effectively in such scenarios, LLMs
need to both incrementally ingest arriving UGC
and dynamically maintain user profiles as interests
evolve, which prior user profiling evaluation work
has largely overlooked (Wang et al., 2025; Prot-
tasha et al., 2025). While works such as Person-
aMem (Jiang et al., 2025a) and Inside Out (Zhao
et al., 2026) have explored maintaining evolving
user profile with LLMs, they rely on simulated dia-
logues and do not address the challenge of continu-
ously profiling users from real-world UGC streams.

To fill this gap, we propose StreamProfileBench,
a large-scale benchmark for fine-grained streaming
user profiling. Curated through a rigorous pipeline,
it structures over 120,000 real-world posts from
7,000+ users across five platforms into continuous
streams via a buffering mechanism. Furthermore,
we formalize streaming profiling as a state main-
tenance task, leveraging future interest anchors
as self-verifying ground truth to rigorously assess
models’ ability to track temporal interest drift.
Experiments across 14 LLMs show that stream-
ing profile maintenance remains an open challenge.
The strongest models achieving 52.26% average
recall and 54.97% F1 recall, while weaker models
only achieve 25.18% average recall and 18.85%
F1 recall. Specifically, models struggle with novel-
interest recognition and interest decay, revealing
a shared inability to track how interests dynami-
cally emerge and fade over time. Furthermore, our
ablations validate the practical superiority of the
streaming mechanism, demonstrating that incre-
mental persona passing consistently outperforms
both no-passing and long-context baselines.
To summarize, our contributions are threefold:
• We define the problem of streaming user pro-
filing, where LLMs must continuously track
and maintain user profiles from incrementally
arriving UGC, and formalize it as a state main-
tenance task.
• We propose StreamProfileBench, a user-
centric benchmark of 7,000+ real users and
120,000+ posts across five platforms, with an
evaluation framework that uses future inter-
est anchors as self-verifying ground truth for
temporal interest drift.
• We benchmark 14 popular LLMs. Results
show that even frontier models struggle with
streaming user profiling, with novel-interest
recognition and interest decay as the dominant
limitations, while ablations further validate
the practical merit of the streaming formula-
tion.

Related Work
User Profile Construction
Recent research has
increasingly explored the use of LLMs to derive
structured user representations from unstructured
user-generated content (UGC), including tasks
such as stance detection (Hu et al., 2024), ideol-
ogy identification (Mu et al., 2024), and sentiment
analysis (Kheiri and Karimi, 2023). Wu et al. (Wu
et al., 2024) demonstrate that incorporating users’
historical responses improves profiling accuracy.
PersonaX (Shi et al., 2025b) employs behavior
clustering to extract representative profile features,
while NextQuill (Zhao et al., 2025b) utilizes causal
inference to identify signals that reflect users’ true
preferences. DPL (Qiu et al., 2025) further models

User Profile Evaluation
A range of benchmarks
have been proposed to evaluate user profiling meth-
ods (Bartkowiak and Podstawski, 2025; Liu et al.,
2025c; Ren et al., 2026). LaMP (Salemi et al.,
2024) models user preferences based on histori-
cal behaviors and uses prediction accuracy. PrefE-
val (Zhao et al., 2025a) constructs long-context
conversational histories to assess models’ ability
to understand and infer user preferences. Person-
aBench (Tan et al., 2025) uses synthetic privacy
data to evaluate user attribute and preference ex-
traction. However, these benchmarks are limited
to static prediction, leaving long-term profile track-
ing largely unexplored. PersonaMem-v1 (Jiang
et al., 2025a) investigates whether models can mem-
orize, update, and apply evolving profiles, while
PersonaMem-v2 (Jiang et al., 2025b) further incor-
porates implicit preferences; however, both rely on
synthetic persona without grounding in real UGC.
Unlike prior work, StreamProfileBench utilizes real
social media data to evaluate a model’s ability to
continuously infer and maintain accurate user pro-
files over time, offering a more realistic evaluation
setting. Table 1 shows the comparison of profile
benchmarks.

3.1
Task Definition
General Formalization
Traditional user profil-
ing is modeled as a stateless mapping. Given a
user’s UGC history B, the model fθ produces a
static profile as follows:
P = fθ(B)
This formulation ignores two fundamental prop-
erties of real-world UGC as mentioned in introduc-
tion. UGC in real-world arrives as an unbounded
stream and user interests shift over time. We there-
fore formalize streaming user profiling as a state
maintenance problem: both unbound and non-
stationarity properties demands a maintaining task
form, giving rise to a read–update–write loop that
evolves the profile with each incoming batch.
Formally, at each time step n, the model receives
a new batch of UGC Bn from the current time win-
dow along with the user profile Pn−1 carried over
from the previous step. Using Pn−1 as contextual
prior, the model jointly reasons over the accumu-
lated profile and the current observation Bn to pro-
duce an updated profile Pn, transforming user pro-
filing into an incremental, temporally-aware pro-
cess:
Pn = fθ(Bn, Pn−1)
Evaluation Formalization
At each step, the
model is required to produces a free-form natural-
language profile Pn that can encode any informa-
tion it deems relevant, serving as its persistent mem-
ory of the user. This free-form design avoids impos-
ing structural constraints that could influence with
evaluation. However, no reliable automatic met-
ric exists for directly assessing Pn, and large-scale
human annotation is prohibitively costly.
We therefore complement Pn with a structured
prediction target focused on interest profiling,
which is a core dimension in streaming scenarios
with clear temporal dynamics. Leveraging the tem-
poral coherence between user interests and future
UGC, we extract a ground-truth interest anchor set
Tn = {t1, t2, . . . } from future batch, where each
ti is a user-authored marker that explicitly man-
ifests a proactive interest. The platform-specific
extraction rules are in Appendix A.1. The model is
asked to infer which anchor reflect the user’s future
interests. by selecting from an candidate pool Cn
that mixes ground-truth tags in Tn with distractors.

3.3
Data Curation
Our benchmark is built upon a large-scale UGC cor-
pus spanning five major Chinese social platforms
over a 30-day observation window, encompassing
approximately 137 million posts and 17.4 million
active users daily. Detailed statistics are provided
in Appendix C.1. From this massive raw data, our
pipeline with following components yields the fi-
nal StreamProfileBench: a fully anonymized, high-
quality user-centric dataset partitioned into tempo-
rally balanced batches. Comprehensive details for
all stages are provided in Appendix C.2 and C.3.
(I) User Filtering: We target users exhibiting
authentic self-expression, sustained activity, and
topical diversity. Such kind of users are selected
via a two-stage pipeline: (1) a daily coarse filter
that screens records at three progressive granu-
larities (user→content→anchor) using shared and
platform-specific rules, and (2) a long-term stage
that use activity-based stratified sampling to retain
users with appropriate active frequency.
(II) UGC Buffering: Since naive calendar-day
partitioning causes severe input-length imbalances
due to drastically varying UGC volumes, we main-
tain a per-user chronological buffer. It emits a
streaming step Bn only when the accumulated posts
reach a platform-specific threshold, ensuring a uni-
form information load per batch.
(III) Candidate Pool Construction: We con-
struct offline distractor sources: Dviral samples fil-
tered daily trending tags, while Dpeer retrieves se-
mantic neighbors via an incrementally updated vec-
tor clustering index.
(IV) Personal Information Protection: Fol-
lowing standard regulations, we anonymize ten PI
categories using salted hashes for identifiers and an
LLM-based span detection pipeline for text, vali-
dated by manual review.

Conclusion
In this work, we present StreamProfileBench, the
first benchmark for fine-grained streaming user
profiling in real-world scenarios, formalizing this
challenge as a state maintenance task equipped
with a temporal self-verifying mechanism. Our
benchmark comprises over 120,000 UGC posts
from 7,000+ real users across five diverse platforms.
Evaluation of 14 LLMs reveals that models strug-
gle with the streaming profiling task, conservatively
preferring historical traits while remaining highly
vulnerable to interest decay. Furthermore, ablation
experiments validate the practical necessity of the
streaming paradigm. Overall, this work highlights
critical capability gaps of current LLMs in stream-
ing profiling, establishing a foundation for more
robust long-horizon personalized agent systems.

Limitations
While our benchmark provides a comprehensive
evaluation of streaming profiling, several limita-
tions present avenues for future work. First, be-
cause our current dataset relies primarily on ex-
plicit UGC, future iterations can incorporate more
implicit and interactive signals to capture the mul-
tifaceted nature of real-world engagement and con-
struct more holistic user profiles.
Second, al-
though the current window effectively captures
long-term dynamics, extending observations across
multiple years would enable a deeper analysis of
macroscopic lifecycles. Finally, we believe lever-
aging our existing dataset to train a specialized,
lightweight model for long-term user profiling is
meaningful. This approach would distill the com-
plex capabilities of large language models into a
more efficient architecture, facilitating practical
and cost-effective deployment in real-world stream-
ing environments.
Ethical Considerations
We carefully consider the ethical implications of
constructing and releasing this benchmark.
• Data sources. All records in this benchmark
are collected from publicly accessible user-
generated content on mainstream Chinese so-
cial media platforms. No private messages,
friends-only posts, protected accounts, non-
public APIs, or purchased data are involved in
the construction process; we only access con-
tent that the posting user explicitly published
to the public feed.
• Personal information protection. To min-
imize re-identification risks, the entire cor-
pus is processed through the anonymization
pipeline described in Section 3.3 before re-
lease, so that no directly identifiable personal
information is exposed in the public version
of the dataset.
• Intended use. The benchmark is intended
solely for academic research on streaming
user interest modeling.
It is not intended
for commercial user profiling, targeted adver-
tising, individual-level tracking, social scor-
ing, behavior manipulation, or any real-world
decision-making that materially affects in-
dividual users. Use of this benchmark im-
plies agreement to these restrictions.
We
will release the benchmark under a research-
only license that explicitly forbids commer-
cial redistribution and any attempt at user re-
identification.
• Representativeness and biases. The bench-
mark reflects the demographic, linguistic, and
topical distribution of active users on the five
collected platforms. Results should not be ex-
trapolated to other languages, platforms, or
user populations without careful validation.
Overall, we believe releasing this benchmark
benefits the academic community by enabling re-
producible evaluation of streaming user-profiling
methods, and we commit to updating the released
data promptly based on community feedback, in-
cluding any takedown request from identifiable
users.

Interest Anchor Extraction
This section expands on the notion of interest an-
chors. An interest anchor is a user-authored marker
embedded in a post that signals deliberate topical
intent—a hashtag, an explicit question, a book-
marking action, or any other discrete token whose
presence indicates the user has consciously commit-
ted to a topic rather than mentioning it in passing.
Because anchors are written by the user themselves,
they provide a ground-truth signal that is both fine-
grained and free of human annotation, and they
form the basis of Tkeep, Tnew, and the distractor
components Dpeer and Dviral in the candidate pool
Cn.
Anchor sources across platforms.
Each of the
five platforms surfaces anchors through a differ-
ent native mechanism, reflecting differences in
content format, community conventions, and UI
affordances. We therefore implement a separate
extractor per platform, unified by a shared post-
processing cleaner (length bounds, blacklist filter-
ing, density constraints; see Appendix C.2). Ta-
ble 8 lists the extraction rule, a representative ex-
ample, and the accepted tag-density interval for
each platform.
Why these sources qualify as anchors.
The
common property of all five extraction rules is that
the resulting tokens are intent-bearing: using a
hashtag on Weibo or Xiaohongshu is a voluntary
act of joining a topic stream, a Zhihu question title
is the explicit framing chosen by the asker, and a
Douban “watched / want-to-read” marker is a delib-
erate bookmarking action tied to a concrete work.
This distinguishes anchors from ordinary content
tokens, which may appear by chance or as part of
a quoted passage and therefore carry far noisier
supervision.
Normalization.
Before being used as ground
truth or entering the distractor pool, raw anchors
go through a shared normalization step. The details
of this cleanup pipeline, and of how the resulting
anchors flow into Dviral and Dpeer, are given in
Appendix C.2.

C. Temporal Buffering Layer
The surviving users still post on highly uneven
schedules: some produce a handful of substantial
posts per week, others dozens per day. Slicing their
streams by calendar day would yield batches rang-
ing from empty to several hundred posts, either
starving the model or overwhelming its context
window. The pipeline instead replaces physical-
time slicing with information-load slicing: for ev-
ery user, a small SQLite-backed reservoir tracks
her cumulative cleaned posts, platform member-
ship, and time cursor, and emits a batch only when
enough valid content has accumulated.
The reservoir exposes two primitives:
• Push. Cleaned posts are inserted into the
user’s buffer in chronological order together
with their extracted anchors. Each push also
updates the running count of valid posts.
• Pop. A pop fires once the number of valid
posts in the buffer reaches a platform-specific
trigger θ(p): 5 for Weibo, Xiaohongshu, and
Douban, and 3 for Toutiao and Zhihu, where
the per-post information load is larger. Upon
triggering, all buffered content is packed into
one streaming step Dn, subjected to a density
re-audit, and emitted; the buffer is then cleared
and the time cursor advanced.
An upper bound on the number of posts per pop,
preventing highly active users from producing ex-
cessively long batches. Because the trigger is user-
local and content-driven, the resulting batches carry
approximately uniform information load across
users while respecting each user’s natural cadence:
slow posters produce fewer but semantically ma-
ture batches, and burst posters are naturally rate-
limited without being dropped.

• Global random sampling. For every collec-

The pipeline processes each user record in three

• Stage 1 — Identifier hashing.
The raw

• Stage 2 — LLM span identification. Each
user’s bio and all posts_text are sent

The LLM is instructed to act only as a
span detector, returning a JSON list of
(text,

ing any rewritten output. This deliberately
avoids generative rewriting, which would drift
in punctuation, emoji, and wording even at
temperature = 0. The prompt enumerates
the ten categories, lists the permitted context
triggers for CONTACT and BANK, and passes the
original username as an anchor used solely
for self-name detection—after first masking
any PI patterns inside the username itself, so
that no raw PI leaves the local environment.
• Stage 3 — Deterministic replacement and
safety net. The LLM’s span list is merged
with a regex pass over the three regex-clean
categories (PHONE / EMAIL / ID), de-duplicated,
and sorted by decreasing span length to
prevent shorter substrings from corrupting
longer ones.
Replacements are applied to
bio, posts_text, and also candidate_pool,
ground_truth, and meta, keeping evaluation
labels aligned. A final regex re-scan rejects
any record that still exposes a PHONE / EMAIL
/ ID pattern. Running the regex pass uncondi-
tionally also provides robustness against LLM
failures: content-safety refusals and silent
under-detection are both absorbed, since the
regex layer always catches hard PII that the
LLM might have missed.

Baseline design.
The long-context baseline

• streaming. At the final step N the model

=
