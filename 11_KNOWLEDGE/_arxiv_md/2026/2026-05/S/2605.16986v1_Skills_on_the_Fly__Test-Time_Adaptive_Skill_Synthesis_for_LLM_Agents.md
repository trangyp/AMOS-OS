ABSTRACT
LLM agents benefit from reusable skills, yet test-time tasks often require guidance more specific
than a static skill library can provide. We propose SkillTTA, a Test-Time Adaptive Skill Synthesis
method that retrieves a small set of training trajectories relevant to the current task and synthesizes
them into a temporary, task-specific textual skill. The solver model is kept fixed, so adaptation
happens entirely through generated context rather than parameter updates. We evaluate the method
on SpreadsheetBench, ALFWorld, and BigCodeBench. Compared with static trajectory-to-skill
synthesis using GPT-5.5, task-specific skills improve SpreadsheetBench Pass@1 from 0.397 to 0.505
and BigCodeBench Pass@1 from 0.517 to 0.651. On ALFWorld, the method matches a heavier
memory-learning baseline within four points of success rate while producing the shortest successful
trajectories among reported methods. Ablations on SpreadsheetBench further show that synthesized
skills outperform raw trajectory prompting, that top-k retrieval should stay small, and that failed
trajectories are especially useful because they expose recurring evaluator-facing mistakes.
Keywords LLM agents · test-time adaptation · skill synthesis · retrieval

Introduction
Skills are a natural interface for reusing agent experience: they state what to do, what to avoid, and what task-specific
checks matter, without replaying every step of a previous attempt. This abstraction is especially useful for LLM agents,
which increasingly solve interactive and tool-using tasks by combining reasoning, actions, environment feedback, and
external harness components such as memory, skills, and protocols [Yao et al., 2023, Zhou et al., 2026, Yang et al.,
2025]. A useful skill, however, needs to be grounded in evidence from prior executions. Stored trajectories provide
that evidence by showing which actions work, which outputs satisfy strict evaluators, and which superficially plausible
strategies fail. Prior work on reflective and experiential agents further shows that such experience can be converted
into natural-language memories or lessons that improve later decisions without parameter updates [Shinn et al., 2023,
Zhao et al., 2023]. The central question is therefore how to synthesize stored experience into the right skill for the task
currently being solved.
Existing approaches reuse agent experience at different granularities. The simplest retrieves raw trajectories and appends
them to the prompt as demonstrations. A second family synthesizes trajectories offline into static or global skills that
can be retrieved later [Ni et al., 2026, Wang et al., 2024]. A third family performs test-time adaptation by learning over
memory utilities or model parameters, using feedback to update which memories or behaviors should be preferred
[Zhang et al., 2026, Wang et al., 2026].
These approaches share a common limitation: they choose the adaptation unit before seeing how the current task should
compress prior experience. Raw trajectories preserve too much, including tool chatter, accidental constants, failed
branches, and task-local details that consume context without specifying an operational policy. Static skills compress
experience, but they are written before the target task is known and therefore must remain broad enough for future

The missing adaptation unit is a temporary skill synthesized online for the current task. SkillTTA collects a pool of
trajectories from training tasks before evaluation. At test time, for each target task it computes an embedding over stable
task metadata such as the instruction, task type, function signature, object/receptacle structure, or spreadsheet output
range. It retrieves a small set of related trajectories and synthesizes them, together with the current task context, into a
task-specific SKILL.md that is injected into the solver prompt. The solver remains fixed throughout, so all adaptation is
expressed as text.
The key design choice is to adapt the agent’s textual policy rather than its weights. Relative to raw trajectory retrieval,
the synthesized skill strips irrelevant local details and surfaces reusable procedures, pitfalls, and checks. Relative
to a static skill pool, the skill is synthesized after seeing the current task metadata, so it can specialize to task-local
contracts such as spreadsheet answer ranges, ALFWorld action grammar, or BigCodeBench return types. Relative
to parameter-level or value-learning adaptation, the method uses a single retrieval-and-synthesis step and remains
compatible with closed API models.
Our contributions are:
• We formulate Test-Time Adaptive Skill Synthesis, where retrieved trajectories are compressed online into a
temporary skill specialized to the current task.
• We introduce SkillTTA, a parameter-free adaptation pipeline that connects raw trajectory retrieval with static
skill libraries.
• We show that dynamic task-specific skills improve LLM agents on spreadsheet manipulation, interactive
household tasks, and practical code generation compared with strong static skill and memory baselines.
• We provide ablations showing that skill synthesis is more effective than raw trajectory prompting, that retrieval
quality and top-k matter, and that failed trajectories can provide high-value corrective evidence.

Related Work
Trajectory-to-skill synthesis.
Trajectory-to-skill methods compress execution experience into reusable natural-
language policies. Earlier systems such as Voyager build reusable skill libraries for open-ended embodied agents
[Wang et al., 2023], and ExpeL extracts natural-language insights from agent experience for later decision making
[Zhao et al., 2023]. Trace2Skill synthesizes trajectory-level lessons into transferable agent skills by analyzing broad
execution experience and consolidating lessons into a static skill directory [Ni et al., 2026]. Agent Workflow Memory
similarly induces reusable workflows for web agents in offline or online settings [Wang et al., 2024]. SkillTTA differs
in both timing and scope: rather than generating a global skill library before evaluation, it retrieves trajectories for each
target task and synthesizes a temporary skill conditioned on that task’s metadata.
Agent memory and retrieval.
Memory-augmented agents retrieve past experiences to guide future decisions.
Generative Agents stores complete natural-language experience records, synthesizes higher-level reflections, and
retrieves them to plan behavior [Park et al., 2023], while Reflexion stores verbal feedback in episodic memory to
improve subsequent trials [Shinn et al., 2023]. MemRL treats memory retrieval as a reinforcement learning problem
over episodic memory, using semantic retrieval followed by Q-value-based utility selection and iterative feedback
updates [Zhang et al., 2026]. This improves long-horizon adaptation but requires repeated interaction and memory
utility learning. Our method uses semantic retrieval as a lightweight front end and replaces iterative value learning with
one-shot textual synthesis.
Test-time adaptation.
Test-time adaptation methods modify behavior at evaluation time through retrieved examples,
retrieved skills, or parameter updates. TARSE, for example, retrieves both skills and experiences for reasoning agents
and performs lightweight test-time adaptation [Wang et al., 2026]. SkillTTA targets the space between retrieval-only
context construction and parameter-level adaptation: it adapts the solver by generating a task-conditioned textual policy
while leaving model parameters unchanged.
Agent harnesses and skill ecosystems.
Recent surveys frame practical LLM agents as harnessed systems in which
skills, memories, protocols, tools, and search procedures externalize capabilities that are difficult to keep inside
model weights alone [Zhou et al., 2026, Yang et al., 2025, Xi et al., 2025]. This shift also raises new system-level
questions around how skills are governed, audited, and evolved. SkillProbe studies security auditing for emerging
skill marketplaces through multi-agent collaboration [Guo et al., 2026], while SkillMAS couples skill evolution with
multi-agent system restructuring after deployment [Pan et al., 2026]. SkillTTA is complementary to these directions: it
does not propose a marketplace, protocol standard, or multi-agent organization, but focuses on the narrower question of
how a single solver can receive a task-specific skill synthesized from retrieved execution evidence at test time.
3
Methodology
3.1
Problem Formulation
We have a training collection Dtrain and a test collection Dtest from the same task family. For each training task i, we
have a task description xi, metadata mi, an execution trajectory τi, and optionally an evaluation label yi ∈{T+, T−}
indicating success or failure. For each test task q, the agent receives only its visible task context (xq, mq). The goal is
to improve the fixed solver policy without updating the solver parameters.
SkillTTA maintains a trajectory pool
P = {(xi, mi, τi, yi)}n
i=1
and constructs a task-specific skill sq for each test task. The solver conditions on (xq, mq, sq) and produces the final
action sequence or answer. In all experiments, the solver is GPT-5.4-mini; only the skill synthesis model varies between
GPT-5.4-mini and GPT-5.5.
3.2
Pipeline Overview
The pipeline runs in five stages, shown in Figure 2. (1) We build a trajectory pool from training tasks, retaining both
successful and failed executions as reusable evidence. (2) For each pool item, we construct an embedding string from
stable task metadata. (3) At test time we retrieve the top-k related trajectories by cosine similarity, with benchmark-
specific filters over success or failure labels. (4) A synthesis model receives the target context and the retrieved evidence,
then compresses them into a concise temporary SKILL.md. (5) The fixed solver conditions on the target context and
this temporary skill to produce the final action sequence or answer.

3.3
Task Metadata Retrieval
The retrieval representation is designed to capture task similarity without leaking target answers. For SpreadsheetBench,
the embedding text contains the instruction, instruction type, and output position. Optionally, the instruction is first
summarized into dimensions such as action, selection, calculation, output, constraints, and validation. For ALFWorld,
the embedding text contains the task family, goal object, object category, target receptacle or tool, room type, goal
sentence, initial room receptacles, and required subgoals. For BigCodeBench, retrieval uses the natural-language
instruction, code prompt, and library list, and excludes tests, canonical solutions, task IDs, and benchmark-only
metadata.
This design follows a conservative principle: retrieval should be driven by semantic and structural task similarity, not by
accidental details in a trajectory. The trajectory itself is used only after retrieval, when the synthesis model can inspect
it as evidence for reusable procedures and failure modes.
3.4
Task-Specific Skill Synthesis
Given a target task q and retrieved trajectories Rq, the synthesis model generates a temporary skill:
sq = Gθ(xq, mq, Rq).
The prompt explicitly treats the target context as authoritative and retrieved trajectories as non-binding evidence. This
prevents retrieved examples from overwriting task-local constraints such as spreadsheet answer ranges, ALFWorld
action grammar, or BigCodeBench return contracts.
The skill format is benchmark-specific but follows a shared structure. SpreadsheetBench skills summarize when to use
the skill, likely failure modes, and candidate procedures. ALFWorld skills provide action policy, search strategy, failure
recovery, and completion checks. BigCodeBench skills state the visible target contract, conservative implementation
guidance, ambiguities, common failure modes, and a static checklist. In every benchmark, the prompt forbids copying
concrete answers, target tests, exact local constants, benchmark IDs, or one-off details from retrieved trajectories.
In deployment, the synthesized skill is injected through the same interface used by the solver’s ordinary task context.
For SpreadsheetBench, the skill is paired with compact spreadsheet previews and execution traces but may only provide
procedural guidance, not cell values or final answers. For ALFWorld, it is inserted into a ReAct-style prompt and

3.5
Why Temporary Skills
A temporary skill provides a useful middle ground between examples and parameters. Raw trajectories preserve too
much: they include failed branches, local constants, and irrelevant tool outputs. Static skills preserve too little about the
current task: they are written before seeing the target instruction and must be broad enough to apply across many tasks.
A temporary skill, synthesized only after retrieval and only for one target task, can express narrow procedural guidance
while remaining abstract enough to avoid direct answer copying.
4
Experiments
4.1
Experimental Setup
4.1.1
Datasets and Metrics
We evaluate SkillTTA on three task families with different agentic failure modes. SpreadsheetBench evaluates real-world
spreadsheet manipulation with test-case-based grading [Ma et al., 2024]; we follow Trace2Skill by splitting Verified-400
with seed 0 into 200 training tasks and 200 test tasks, and report Pass@1. ALFWorld evaluates text-based household
interaction grounded in embodied task structure [Shridhar et al., 2021]; we sample 1000 training tasks from the original
training set with seed 42 and evaluate on the 140-task valid-seen set, reporting success rate and average steps on
successful episodes. BigCodeBench evaluates practical Python code generation with library use [Zhuo et al., 2024]; we
split the instruct-full set with seed 123 into 798 training tasks and 342 test tasks, and report Pass@1 and Pass@3.
4.1.2
Baselines
We compare against baselines without task skills and baselines that reuse skills or memories. Zero-shot and ReAct
use the fixed solver directly. Trace2Skill is the static skill-synthesis baseline; in the main table, we report its strongest
observed variant among error-only, success-only, and all-trajectory settings. MemRL learns memory utilities through
repeated interaction and Q-value updates; the main table reports its three-epoch setting, which corresponds to three full
training-set rollouts.
The baselines also differ substantially in adaptation cost. MemRL performs one full training-set rollout per epoch
before updating memory utilities, so the reported setting requires three full passes over the training tasks. Trace2Skill
consolidates skills through hierarchical patch iteration, which is approximately log n rounds over the trajectory pool.
SkillTTA instead uses the indexed trajectory pool directly at test time and performs one retrieval-and-synthesis step for
each target task, without updating Q-values, model parameters, or an offline skill hierarchy.
4.1.3
Implementation Details
All task-solving runs use GPT-5.4-mini as the solver. For skill synthesis, we evaluate GPT-5.4-mini and GPT-5.5.
Main results use all retrieved trajectories when applicable. Retrieval-based methods use top-k = 3 unless an ablation
explicitly changes k, and retrieval embeddings use text-embedding-3-large. Synthesis and solver temperatures are
0, except for BigCodeBench Pass@3, where the three solver samples use temperature 0.7. SpreadsheetBench ablations
default to failed trajectories except for the trajectory-source ablation.
4.2
Main Results
Table 1 shows that task-specific skill synthesis consistently improves over static skill synthesis on SpreadsheetBench
and BigCodeBench.
SpreadsheetBench.
SkillTTA reaches 0.505 Pass@1 with GPT-5.5 synthesis, compared with 0.397 for Trace2Skill
and 0.418 for ReAct. With GPT-5.4-mini synthesis, the same dynamic-skill design reaches 0.443, still above the
corresponding Trace2Skill result of 0.420.
BigCodeBench.
SkillTTA improves both single-sample and multi-sample code generation. With GPT-5.5 synthesis,
it reaches 0.651 Pass@1 and 0.673 Pass@3, compared with 0.517 and 0.582 for Trace2Skill.

4.3
In-Depth Analysis
Ablation Study.
Figure 3(a) shows that the gain comes from synthesizing trajectory evidence into a skill, rather
than simply adding more experience to the prompt. The synthesized skill reaches 0.540 Pass@1, while raw trajectory
prompting reaches 0.422, no retrieval reaches 0.410, and random retrieval reaches 0.445. Trajectory evidence is most
useful after it is compressed into an operational policy.
Impact of Trajectory Source.
Figure 3(b) shows that failed trajectories are highly informative. Failed-only retrieval
is the strongest source choice, and the tuned failed-trajectory top-3 configuration reaches 0.540. Failed attempts
expose concrete pitfalls—producing only an action plan, giving formulas without editing the workbook, stopping after
inspection code, or repeating empty follow-ups after execution errors—that are easier to convert into corrective skill
rules than to imitate as raw examples.
Impact of Retrieval Numbers.
Figure 3(c) shows that increasing retrieval size can hurt. Top-3 outperforms both
top-5 and top-9. Skill synthesis benefits from a small set of closely related evidence; adding more trajectories introduces
heterogeneous procedures and distracts the synthesis model from the target contract.

5
Conclusion
We presented SkillTTA, a test-time adaptive skill synthesis method for LLM agents. The method retrieves related
training trajectories for each test task and synthesizes them into a temporary task-specific skill that conditions a
fixed solver. This provides a compact, dynamic alternative to raw trajectory prompting, static skill retrieval, and
parameter-level adaptation. Experiments on SpreadsheetBench, ALFWorld, and BigCodeBench show that online skill
synthesis is a strong and lightweight way to reuse agent experience, with ablations confirming the importance of skill
compression, focused retrieval, and failure-derived corrective guidance.

A.2
General Skill Synthesis Prompt Template
The following template abstracts the skill synthesis prompt used for trajectory-to-temporary-skill conversion. Dataset-
specific fields are written in braces. The target task context is treated as the binding contract, while retrieved trajectories
serve only as evidence for reusable procedures, failure modes, and corrective checks.
System role. You synthesize reusable {domain} skills into SKILL.md files for a {benchmark} target task to
help a future agent solve the task. If the retrieved trajectories are failed attempts, use them as evidence for
likely pitfalls, root causes, and corrective checks. If the retrieved trajectories are successful attempts, use them
as evidence for reusable procedures, robust execution patterns, and validation checks. Do not copy concrete
answers, file paths, local constants, benchmark-only values, or one-off details.
User role. Create a standalone SKILL.md for a {benchmark} target task. Use {target_task_context} to
align the skill with the current task’s visible contract, such as {task_type}, {input_or_state_context},
{output_or_action_contract}, and {constraints}. Use {retrieved_trajectories} to extract gen-
eralizable lessons rather than one-off details. Retrieved trajectory lessons must never override the current target
context.
Required output format.
# SKILL.md
## When to use
- A concise summary of when to use this skill.
## Possible Failure Modes
- Summarize mistakes indicated by retrieved trajectories.
- Convert failures into corrective checks and reusable warnings.
## Possible procedures
- Give generative guidance for solving this family of tasks.
- Do not give the detailed solution directly.
Visible payload. The target context contains {target_visible_fields}. Each retrieved trajectory contains
{retrieved_visible_fields}, including its success/failure label when available and compacted trajectory
evidence.
A.3
Benchmark-Specific Implementation Notes
SpreadsheetBench.
For each target spreadsheet task, retrieval uses the instruction, instruction type, and answer
position as the embedding text. In the instruction-summary variant, the instruction is summarized into action, selection,
calculation, output, constraints, and validation fields before embedding. The synthesis prompt includes compacted
trajectory and solution excerpts, but explicitly forbids copying example-specific constants, spreadsheet preview values,
file paths, or final answers.
ALFWorld.
For ALFWorld, the embedding text contains task family, goal object, object category, target receptacle or
tool, room type, goal sentence, initial room receptacles, and required subgoals. The generated skill is injected into a
ReAct-style agent and focuses on action policy, search strategy, failure recovery, and completion checks. Retrieved
successful trajectories provide action-order evidence; failed trajectories, when used, provide short pitfall summaries
rather than actions to imitate.
BigCodeBench.
For BigCodeBench, retrieval uses only the natural-language instruction, code prompt, and library
list. Target tests, canonical solutions, and benchmark-only metadata are excluded from retrieval and hidden from

A.4
Cost Scaling Interpretation
MemRL performs runtime reinforcement learning over episodic memory. In our comparison, each MemRL epoch
corresponds to one full training-set rollout, so a three-epoch MemRL run requires three full passes over the training
tasks and associated model calls. Trace2Skill uses hierarchical patch iteration to consolidate skills, which can be
approximately understood as log n rounds over the training trajectory pool. In contrast, SkillTTA performs a single
retrieval-and-synthesis step per test task and does not update model parameters, Q-values, or an offline skill hierarchy.
With an indexed retrieval pool, retrieval can be treated as a sublinear lookup over the trajectory pool followed by one
skill synthesis call for the target task.
