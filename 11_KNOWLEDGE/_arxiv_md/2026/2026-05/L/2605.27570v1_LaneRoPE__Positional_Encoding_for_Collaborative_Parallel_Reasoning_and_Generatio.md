Abstract
Parallel LLM test-time scaling techniques (e.g., best-of-N) require drawing N > 1
sequences conditioned on the same input prompt. These methods boost accuracy
while exploiting the computational efficiency of batching N generations. However,
each sequence in the batch is traditionally generated independently and hence
does not reuse intermediate generations, computations, or observations from other
sequences. In this paper, we propose LaneRoPE to enable coordination and collab-
oration among N > 1 sequences at generation time. LaneRoPE involves two key
ideas: (a) an inter-sequence attention mask to make sampling of sequences depen-
dent on one another; and (b) a RoPE extension that injects positional information
that captures relative positions between tokens, both within and outside a particular
sequence. We evaluate our approach on mathematical reasoning tasks and find
promising results: LaneRoPE enables collaboration among sequences, yielding
additional accuracy gains under limited generated sequence length. Importantly,
since LaneRoPE enables coordination with minimal changes to the underlying
LLM architecture and introduces a negligible overhead at inference time, it is
appealing to rapidly incorporate parallel reasoning into existing LLM inference
pipelines.

Introduction
Parallel test-time scaling methods improve LLM performance with additional inference-time compute
instead of finetuning [4, 2, 35, 29, 32]. The key idea of these methods is generating multiple
responses (each potentially with its own reasoning trace) for a given input, and optionally, ranking
and aggregating responses with a reward model. The multiple responses are typically generated in
parallel during the same forward pass (i.e., batched inference), and benefit from a hardware efficiency
standpoint, since this amortizes memory transfers, minimizes kernel launch overheads, and better
utilizes compute cores at each generation step. Despite its efficiency, parallel inference is largely
uncoordinated: for a given input, the output sequences are generated independently. This prohibits
exploiting inherent decomposable problem structures [36], limits the sharing of intermediate outputs
between sequences, and the generation of diverse responses.

Building on powerful parallel inference, how can we make multiple sequences coordinate with
each other during generation? Two families of approaches have gained traction, each with their
inherent trade-offs. The first family of approaches leverage ‘explicit branching’ [9, 22, 36, 38]
mechanisms: at inference time, a single sequence adaptively fans-out to multiple search paths (e.g.,
one path per decomposed subproblem) and funnels them into a single response. Although they
encourage the LLM to explicitly decompose tasks, the dynamic nature of how variable number of
parallel processes are spawned and merged introduces challenges in predicting runtime compute
resources and more importantly, they depend on specialized run-time engines. The second family
of ‘collaborative’ approaches [12, 27, 7], under which our approach falls, introduce a more flexible
means of coordination primarily by enabling shared visibility (Fig. 1a) into intermediate generations
of all parallel sequences. These techniques are practically attractive, since they rely on a fixed
number of generation sequences (i.e., constant batch size; see Fig. 1b) and can hence largely leverage
batching support by both LLM inference engines and the underlying hardware. In particular, existing
techniques [12, 27] exploit an interesting insight that multiple sequences can be ‘virtually ordered’
into a single sequence by reparameterizing the positions or positional encodings. However, we argue
that this is inherently a multi-sequence generation problem and inference must accurately reflect
positions both along the token dimension (as typically done) and sequence (or lane) dimension. In
the rest of this manuscript, we use lane and sequence interchangeably to refer to batch elements
generated simultaneously and inter-dependently.
In this work, we propose LaneRoPE to better enable parallel reasoning and generation. Similar to
parallel test-time scaling techniques [32, 35] and collaborative reasoning [12, 27, 7], we assume
a constant number of sequences (Fig. 1b) generated at inference. Our approach involves two
key insights. First, we make intermediate reasoning traces and outputs visible across sequences
by conditioning the next token on previous tokens from all sequences. We achieve this by using
causal cross-sequence attention masks and generalizing attention score calculations to extend to
inter-sequence tokens. Second, we extend rotary positional encoding ‘RoPE’ [30] to additionally
capture relative distances among sequences (Fig. 1b), allowing us to learn the attention structure
across parallel generations in a dynamic and task-dependent manner. Our formulation is expressive
enough to capture a range of parallel inference techniques, ranging from independent sampling (e.g.,
self-consistency) to the fully dense attention masks used in GroupThink [12].
Our evaluation of LaneRoPE on standard mathematical reasoning datasets (e.g., AIME, MATH500)
and two open-weight LLMs shows promising results. Overall, we find that the LLMs demonstrate
a reliable accuracy improvement across multiple benchmarks. The flexibility in our formulation
enables LaneRoPE to be integrated into existing models with minimal modification and, importantly,

Contributions
We summarize our contributions as:
• A novel method to enable fine-grained token-level collaboration during batched parallel
generation of language models. Notably, our method encompasses some existing techniques
but its superior flexibility and generality allow for further fine-tuning.
• A recipe to synthesize collaborative reasoning traces which can be used for supervised
fine-tuning (SFT).
• A fine-tuning pipeline to unlock and strengthen the parallel reasoning capabilities of pre-

Related Work
LLMs, Reasoning and Test-time Search.
Large language models (LLMs) have attracted sig-
nificant attention, largely due to their remarkable performance across a range of tasks. Many of
these tasks (e.g., math, coding) test the LLM’s ability for generalization, abstraction, and multi-step
problem solving. Especially for such tasks, reasoning [33, 14] has proven to be a powerful paradigm
and has significantly improved success rates at solving challenging problems. These techniques can
be further extended to explore various reasoning paths before concluding with a final solution. The
reasoning search paths can take various structures, but can broadly be classified into sequential [21],
graph-like [37, 1], or parallel [32, 2]. In this work, we primarily study reasoning as a parallel search
problem.
Parallel Reasoning: Independent and Inter-dependent.
A popular strategy to scale compute at
test-time to improve accuracies is with parallel generations [32, 4]. For a given problem, multiple
sequences (potentially chain-of-thought reasoning followed by a solution) from the same LLM
are sampled in parallel and ranked (e.g., using a reward model) to determine the final solution.
Prior works [32, 4, 2, 29, 35] primarily demonstrate effectiveness where the sequences are sampled
independently. This however leads to inefficient use of compute, since there is little collaboration
between sequences and risks redundant compute between sequences. A new recent line of work
explores whether the sequences can be sampled inter-dependently [7], such that LLMs can decide
to adaptively parallelize and coordinate during generation. This line of inter-dependent generation
broadly falls under two categories: (a) ‘adaptive branching’ [13, 22, 25, 36, 3, 38, 34, 15] where
at generation time, special tokens (e.g., fork and merge) signal the inference engine to spawn or
merge multiple parallel sequence generations; and (b) ‘fine-grained collaboration’, as in [12, 27] and
recently [7], where sequence generation is always parallel (constant batch size) and each sequence can
attend to part or all of the tokens generated by other sequences using dynamic attention masks. Our
approach falls into the second category, and unlike previous works we introduce a flexible framework
to positionally encode cross-sequence tokens which additionally account for relative inter-sequence
distances.
Positional Encoding in LLMs
Large language models (LLMs) incorporate positional encodings to
inject sequence order information into transformer architectures, since the self-attention mechanism
alone is permutation-invariant [31]. The original Transformer used fixed sinusoidal position encodings
[31], while subsequent models like BERT adopted learned positional embeddings [6], both providing
each token with an absolute position bias. To improve generalization beyond fixed-length contexts,
relative positional encodings were introduced to encode pairwise token distances directly in self-
attention [28], allowing the model to focus on relative order. More recent approaches modify
how positional information enters the attention mechanism to enable better extrapolation to longer
sequences. For example, rotary positional encodings (RoPE) rotate query/key vectors by angle
proportional to token index, effectively combining absolute and relative positional information
[30]. Similarly, ALiBi (Attention with Linear Biases) eliminates explicit embeddings and instead
adds a distance-dependent bias to attention scores, allowing models trained on shorter sequences

Initialization Strategy: NTK-aware correction for GroupThink
To mitigate the negative virtual
indexes limitation of GroupThink, we draw inspiration from the "NTK-aware" interpolation methods
like YaRN [23] which modify RoPE’s frequencies to extend the context length of pre-trained models.
The main idea is that, despite the translation equivariance of RoPE, frequencies with a relatively long
period compared to the pre-trained context length enable the model to encode absolute positions,
rather than relative ones. We suspect these low frequencies suffer the most from the negative relative
indexes of GroupThink, which fall outside the portion of the period typically observed during pre-
training. Hence, we introduce a scaling function γ(θt) ∈[0, 1] which smoothly decays to 0 the
frequencies below a certain threshold, i.e. Ω:= {γ(θt)Kθt}t, such that the lane index has limited
effects on them and they maintain their capacity to represent absolute positions; see Appendix B for
more details.
In practice, we combine these strategies: lane frequencies ω′ = KΘ (GroupThink or NTK) for

4
Training LaneRoPE
To elicit cross-lane interactions in a base model, we consider two fine-tuning strategies: i) supervised
finetuning (SFT) on a dataset that mimics collaborations, and ii) optimizing with a training objective
adapted from Kahneman-Tversky Optimization (KTO) [8] on a dataset of (un)successful reasoning
traces independently generated by the base model.
4.1
SFT with collaborative data
We construct this dataset using Qwen3-30B-A3B-Thinking-2507 [26], using questions from the
DeepScaleR-Preview-Dataset [17]. To simulate collaboration across N lanes using a sequential LLM,
we prompt the LLM to play the role of N different assistants in a step-by-step manner. An assistant’s
message at each step ends after 128 new tokens. After each step, an assistant is prompted to generate
a new message by completing its own answer, pre-filled with the text it generated so far, which
follows a user message providing the query and the text previously generated by other assistants. For
the final SFT dataset, we separate the text generated by each assistant into individual traces such
that each trace only contains the messages of one assistant. As a result, a model fine-tuned on this
dataset requires a form of cross-sequence interaction to be able to fit the data. In total, we generate
3 conversations with N = 2, 3 or 4 assistants on a subset of questions of the dataset, resulting in
about 50k raw conversations. See Apx. E for more details. To focus on quality over quantity, we
further filter the original generations based on the following criteria. First, we only keep samples

where all the assistants give the correct answer. Second, we employ a length limit in range 10 −30
messages per lane and remove all samples outside that range. Third, we use a simple heuristic to filter
out conversations with little or no interactions between the assistants. After this curation process, the
final SFT dataset consists of 4797 conversations. See Apx. E.1 for an example of the SFT dataset.
4.2
KTO with independent reasoning traces
We sample 8 completions with the base model (either DeepSeek-R1-Distill-Qwen-1.5B or
DeepSeek-R1-Distill-Qwen-7B) and a maximum completion length of 4096, for each of the
40315 questions of the DeepScaleR-Preview-Dataset [17]. Among these, we keep only those
queries where at most half of the answers were correct, to ensure a sufficiently challenging dataset.
Importantly, we preserve both good and wrong completions to be used for the KTO loss [8], which
respectively maximizes and minimizes their likelihoods, up to some per-sample saturation. Hence, we
create a dataset by grouping the completions of each query into subsets of N = 2, 3, 4 lanes, ensuring
each subset contains at least one correct answer, for about 15k total groups; during training, LaneRoPE
is able to cross-attend among the N lanes within each subset. While SFT with independently
sampled data would force our model to mimic the i.i.d. distribution, batches with mixed good/wrong
completions can encourage a non-trivial joint distribution among parallel lanes via the KTO loss:
e.g. it’s easier to minimize the likelihood of a wrong completion when its final answer doesn’t match
that of the other completions in the batch. See Appendix D.
4.3
Other training details
To train our models, we first initialize them from open-source pre-trained LLMs using a combination
of the initialization strategies described earlier. In particular, we use a "sequence gap" K = 8192 to
bias the model towards a GroupThink-like behavior but also set a strong positional bias (| ˆβ|2 ≥1000.)
to encourage the model to attend to tokens in other sequences only when necessary. Then, we train
our models for one epoch on these curated datasets. In our experiments with small 1.5B, we train all
their weights while we use LoRA (including trainable biases) for the 7B ones to reduce memory cost
at training time and fit at least 4 lanes within a single GPU. When indicated with a ∗, we also train
the frequencies Ωof the LaneRoPE itself.

Inference time measurements
An important benefit of LaneRoPE is that it comes with little-to-no overhead over standard transformer
architectures. Indeed, inference can be done by interleaving the input tokens into a N times longer
sequence (with sufficient care of tracking indexes) and then using standard methods. This strategy
allows for using memory efficient attention back-ends, such as Flash Attention, which minimize the
(theoretical) overhead due to the increased context length: in practice, in Tab. 2 we find negligible

increments in inference time with respect to the standard model when cross-attending between
multiple lanes within a batch. In particular, we observe no difference when using larger numbers
N of lanes: the main delay (∼6%) in LaneRoPE is observed with N = 1 lane too, despite being
logically equivalent to a standard transformer architecture. This suggests its cause lies in the pre- and
post-processing done in our customized "generate" implementation (e.g. reshaping and interleaving
the inputs) rather than the attention mechanism.
We also compare the inference time of (our implementation of) Bridge [7] as an interdependent-

this architecture choice leads to up to 25% increase in inference time with respect to our LaneRoPE

6
Conclusion
In this paper, we addressed the problem of collaborative parallel inference, where multiple sequences
(e.g., within the same batch of a forward pass) can access each other’s partial generation to condition
future reasoning. In particular, we proposed a novel and flexible method - which encompasses
some previous approaches - to model token-level inter-sequence interactions efficiently, along with
a data-generation recipe to create high-quality parallel and collaborative reasoning traces for fine-
tuning. Our empirical results show improved reasoning capabilities in parallel setups and open up
opportunities for better parallel scaling strategies beyond independent sampling.
Limitations and Future Work
We do not yet employ a dedicated training scheme for merging
outputs from multiple lanes, and developing such mechanisms remains an open area for refinement.
Our current experiments focus on N ≤4 collaborating lanes, though the method itself is designed to
extend naturally to a larger number of lanes. While LaneRoPE increases context length by a factor
of N, we found this to have negligible impact on performance in the small batch regime - relevant
for inference on the edge - in Sec. 5.3. Finally, while a small SFT stage with synthetic data proved
sufficient to unlock parallel reasoning capabilities, an additional refinement stage with Reinforcement
Learning with Verifiable Feedback (RLVF), as done in [7], could unlock novel collaborative behaviors
and strategies in an unsupervised way and further strengthen the overall reasoning performance.

C.1
Accuracy
For completeness, Table 3 reports the Accuracy (Pass@1) of the models we compared on different
mathematical reasoning benchmarks. However, we highlight an important difference with the
maj@4 metrics we reported in Table 1 in the main paper: accuracy (Pass@1) measures the average

advantage, being able to attend to N > 1 reasoning traces when producing each individual answer.
In contrast, Table 1 provides a more fair comparison where each model has the same constant budget
of 4 parallel completions, aggregated via majority voting.
Comparison with Bridge [7]
We could not reproduce the accuracy (Pass@1) scores of the baseline
DeepSeek-R1-Distill-Qwen-1.5B and DeepSeek-R1-Distill-Qwen-7B models reported by
the authors of Bridge in [7]. In particular, comparing the results in Table 3 with the ones reported
in Table 1 of [7], our evaluations of our base models show lower accuracies (e.g. 77.2 vs 82.15 for
DeepSeek-R1-Distill-Qwen-7B on MATH500), despite our attempts to use the same evaluation
parameters (temperature 0.6, top-p= 0.95 and 4096 max generated tokens). This suggests other
differences in evaluation which make a direct comparison with their reported results misleading.
For this reason, instead of reporting the numbers from [7], we chose to implement Bridge ourselves
(following the details in the [7]) to train and evaluate it with the same setup of our models.

KTO training
The KTO loss has form
v(x, y) =
λDσ(β(log π −log πref −z0)) for positive example y
λUσ(−β(log π −log πref −z0)) for negative example y
(19)
where π is the policy model, i.e. the model we want to train and πref is a reference model. λU and λD
are hyper-parameters controlling the weights of undesirable and desirable examples, for non-balanced
datasets (we use λD = 1, λU = 0.7). β is a hyperparameter (we use β = 0.1) that controls the
strength of the regularization with the reference model. With respect to [8], we do not use the KL
term z0 since it is more expensive to compute and the models are initialized to independent sampling
and, therefore, already similar to the model that generated the data. In our experiments, whenever we
adapt a base model with LaneRoPE, we always use the base model as a reference model πref in the
KTO loss. Moreover, we replace the sigmoid σ with an asymmetric function σ′ defined as

For training, we use a learning rate of 1e-6 and a batch size of 72 for the 1.5B models, where we tune

Evaluation
In all our experiments, we instruct the models to provide an answer within \boxed{}.
Hence, for each sequence, we extract the answer from the last occurrence of \boxed{} in the
completion and, then, use the Lighteval framework [10] to score it.
When computing the majority voting scores in Fig. 4, from each sample of k sequences, we filter out
sequences that do not contain any \boxed{} before computing the majority. When using LaneRoPE
(or other interdependent methods like Hogwild! and Bridge) models with N > 1 lanes and a budget
of k parallel sequences, we sample K/N independent groups of N inter-dependent sequences, i.e.
maintaining the same batch size overall.
All generations use a temperature of 0.6 and top-p value of 0.95 (as recommended in [5]) and are
limited by 4096 maximum tokens.
E
Synthetize Collaborative Reasoning Traces
Below are the system prompt used to instruct the model on how the conversation will work and
the user prompt used to communicate to the assistant the query and the text generated by the other
assistants so far.
At each step, we prompt the model from scratch, pre-filling its own message with the text it generated
in previous iterations and adding the text generated by the other assistants in the user prompt. An
assistant’s message at each step ends after 128 new tokens and the assistants generate for up to
30 steps. Note also that, since the user message is constantly updated, there is no reuse of the
Key-Value cache in consecutive messages. In total, we generate 3 conversations with N = 2, 3 or
4 assistants for a subset of questions of DeepScaleR-Preview-Dataset [17]., resulting in about 50k
raw conversations (pre-filtering). In the final data filtration phase (after filtering out any conversation
with wrong answers), we score each conversation by counting the number of occurrences of other
assistants’ names in an assistant’s completion, together with few other key phrases that suggest some
disagreement happened (e.g. "Alice you are wrong"), and keep those with a count above 2N.
