Abstract. Ladder logic translation is an important problem in industrial automa-
tion because without it, it is difficult to switch Programmable Logic Controller
(PLC) vendors. The prevailing translation problem highlights mismatched pro-
gramming environments, incompatible ladder logic constructs, limitations in terms
of differences in the semantic expressiveness of the vendor formalisms and inte-
grated black-box proprietary engineering tools which are exemplified in our ex-
ample case; Rockwell to Siemens PLC code translation. This work presents a
mathematical formulation of the problem, the detailed architecture of a solution
which supports XML extraction, structural normalization, constrained generative
function (LLM), and system integration via the TIA Portal Openness API as rig-
orously engineered pipeline for automated translation of Rockwell Ladder Pro-
grams to Siemens S7 ladder programs. Finally, we present results that show that
the translations retain high semantic consistency across instruction categories.
Keywords: LLM Code Translation, PLC programming, Siemens, Rockwell
Introduction
Code translation with Large Language Models (LLMs) is an important problem in en-
terprise software [1], but industrial automation remains difficult because PLC ecosys-
tems are highly vendor-specific. For example, Rockwell Automation employs the XML-
based L5X format, whereas Siemens TIA Portal exposes S7 program blocks through the
TIA Openness API [2][3]. Although both platforms nominally adhere to IEC 61131-3,
substantial differences remain in execution semantics, branch representations, and gen-
eral instruction formalisms which limits practical interoperability despite XML stan-
dardization [4] [5]. Although, migration tools exist, they often rely on static instruction
mappings that require extensive manual correction for nested branch logic and other
vendor-specific constructs [6]. Recent advances in LLM reasoning capabilities, together
with growing adoption in industrial engineering [7][8], create opportunities for trans-
lating structured industrial logic through symbolic representations [9][10]. Platform-
agnostic intermediate representations have previously been explored for automation
and verification tasks [11] [12]; however, our approach performs an object-oriented
reduction of serialized XML to support constrained LLM-guided translation and deter-
ministic post-processing. Figure 1 describes the overall architecture of the translator.

Formalism of sequence transduction over IR
In our example case, <Task> elements define execution behavior and scheduling con-
straints, <Program> elements determine scan order through <ScheduledPrograms>,
and <Routine> elements encode executable logic units. Therefore, we define the in-
termediate representation (IR) as the n-tuple, such that IR = (T, P(·), R(·), L(·)),
where each component captures a distinct layer of the PLC execution hierarchy. Let
T = {ti}n
i=1 denote the finite set of execution tasks, with associated program mappings
P(ti) = {pi1, pi2, . . . , pik} and routine mappings R(pij) = {rij1, rij2, . . . , rijm}.
Each routine containing ladder logic is then expressed as an ordered rung sequence
L(rijm) = (u1, u2, . . . , uk).
Sequence transduction formulation
We define the semantic function associated with a routine r as the composition of its
constituent rung-level transformations:
δr = uk ◦uk−1 ◦· · · ◦u1
(1)
Given that function composition is non-commutative in general, i.e., the ordering of
transformations is essential, we know that
ui ◦uj ̸= uj ◦ui
(2)
It therefore follows that the mapping from an ordered sequence of instructions to its
induced transformation,
(u1, . . . , uk) 7→δr
(3)
is inherently order-sensitive. This implies that the intermediate representation (IR) in-
duces a sequence-dependent transformation over instruction space, i.e., a sequence
transduction problem for which an LLM can be applied.
Hierarchical Compositional Structure
Additionally, the mapping shown in (3) implies that the IR induces a structure through
its hierarchy from derived higher-order compositions. Let ⃝be a composition operator
over transformation mappings. The IR induces higher-order compositions like so:
δr = ⃝u∈L(r)u,
δp = ⃝r∈R(p)δr,
δt = ⃝p∈P (t)δp
(4)
Therefore, the full execution semantics of a PLC may be expressed as the nested com-
position:
δ = ⃝t∈T δt
(5)
This is crucial because it formalizes how complex PLC execution semantics emerge
from the composition of simple instructions in a principled, order-sensitive way and fits
well with sequence based ML algorithms. All symbols retain their meaning from the IR
formalism.

Architecture Overview and LLM Translation Engine
The architecture in Figure 1 implements a staged pipeline that transforms Rockwell
L5X ladder logic into Siemens SimaticXML importable through TIA Portal. The pro-
cess begins with recovery of the L5X XML using a best-effort parser written in C#,
followed by construction of a deterministic object-oriented intermediate representation
(IR) capturing task hierarchies, routines, rung structures, and symbolic tag references.
This reduces the burden on the generative model while remaining constrained by the
SimaticXML schema. The core translation stage employs an LLM fine-tuned on aligned

pairs of L5X-derived representations and SimaticXML blocks. The model is condi-

validity[2]. Deterministic post-processing then applies rule-based structural corrections
for common translation failures, including ladder network reconstruction and reference
normalization, before assembling a fully importable Siemens engineering project. The
translation engine shown in Figure 2 constitutes the semantic core of the pipeline.

Schema-constrained Prompting & Consistency Check
Translation prompts embed explicit structural context, including SimaticXML schema
fragments, Siemens block templates (OB, FB, FC), and permissible instruction enu-
merations, thereby constraining generation toward structurally valid outputs. For each
rung-level IR instance, the model additionally generates a natural-language behavioral
explanation and derives a SimaticXML representation. A cosine similarity metric [13]
is then computed between SimaticXMLs derived from Rockwell L5X and from natural-
language descriptions; outputs below a predefined threshold are rejected.

Conclusion
Our evaluation focuses on a shift register control program and is intended to validate
the proposed translation architecture rather than provide comprehensive coverage of
all PLC constructs. Results in Table 1 and Figure 4 show that explicitly modeled hier-
archical structures are preserved deterministically, achieving 100% accuracy in Task /
Program / Routine mappings. High accuracy in arithmetic operations (92.7%) and tag
handling (91.2%) further suggests that constrained intermediate representations(IR) im-
prove symbol-level translation consistency. In contrast, reduced performance in brack-
eted branch logic (85.4%) and rung-to-network translation (90.6%) highlights the pri-
mary failure mode of the system, since branch structures must often be reconstructed
implicitly from L5X representations. Future work should therefore focus on extending
the IR to encode branch topology and control-flow dependencies more explicitly in or-
der to reduce ambiguity during translation.
