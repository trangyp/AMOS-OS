Recovery Algorithms for Linear Batch Codes
Baran D¨uzg¨un, Henk D.L. Hollmann , Ago-Erik Riet , Vitaly Skachek , Vladislav Taranchuk
Abstract—Various types of recovery algorithms for batch
codes have been investigated, such as asynchronous recovery
or recovery as afforded by batch codes obtained from Almost
Affinely Disjoint (AAD) families. In this paper, we offer the
first systematic investigation of linear batch codes equipped with
particular recovery algorithms. We introduce and investigate
various known and new types of algorithms, and we investigate
the order hierarchy of these types of batch codes. The simplest
known recovery algorithms are those associated with graph-based
batch codes. We investigate the resulting batch codes for arbitrary
bipartite graphs, thereby generalizing some known results.
Index Terms—batch code, recovery algorithm, online, asyn-
chronous, Almost Affinely Disjoint, L-AAD families, simple
recovery sets, graph-based batch codes.
I. INTRODUCTION
Batch codes are methods for storing data in an encoded
form that allow the recovery of a batch of original data sym-
bols from coded symbols in disjoint sets of positions. Batch
codes were originally proposed in [9] for load balancing in
distributed systems with multiple servers. Also, generalizations
of batch codes called PIR codes were proposed in [9] for use
in Private Information Retrieval. Later, switch codes, another
variant of batch codes, were proposed in [22] and [21] to
improve data throughput in network switches. In this paper,
we are mainly interested in linear batch codes [11], [19], [20],
[23], where the data symbols are considered as elements of
a finite field, and the data, written as a vector, is encoded by
employing a linear transformation of that vector over the field.
In this paper, after some preliminaries in Section 2, we
review the various notions of a batch code in Section 3.
We are mainly interested in linear primitive multiset batch
codes. Then in Section 4, we investigate various online and
asynchronous variations of such batch codes. Asynchronous
batch codes have been introduced and investigated in [17],
but the notion of an online batch code and (m, L)-strongly
asynchronous batch code may be new. We define a gener-
alization of L-AAD families that we call L-AAD* families,
and we show that an L-AAD* family of size m results in
an (m, L)-strongly asynchronous batch code, hence a t-batch
code with t = ⌈m/L⌉. One of the main results here produces
an inclusion chain for the various families under study. Finally,
in Section 5 we investigate graph-based batch codes, various
types of systematic batch codes that are generated by a system-

Formally, a linear batch code can now be defined as follows.
Definition 3.3: A linear batch code with parameters [n, k, t]q
is a k × n matrix G over a finite field Fq with rank k,
with the property that for every batch (i.e., for every mul-
tiset) {{i1, . . . , it}} ⊆[k], there are pairwise disjoint sets
R1, . . . , Rt ⊆[n] such that Rj is a recovery set for position
ij (j ∈[t]). We sometimes refer to such a code as an [n, k]q
t-batch code.
Note that in the terminology of [9], a linear batch code is a
primitive multiset batch code that is linear.
In what follows, we will also be interested in linear batch
codes of a special type.
Definition 3.4: A systematic linear batch code is a systematic
generator matrix, that is, a k × n matrix of the form G =
[IM], over Fq, where I is the k ×k identity matrix and M a
k ×(n−k) matrix. Such a code will be called binary if q = 2
and M is a (0, 1) matrix.
We are also interested in recovery sets of a special type.
Definition 3.5: (See [15, Definition 2].) Let G = [IM] be
a k×n matrix. A recovery set for position i is called simple if
it contains exactly one element from the set of column indices
{k + 1, . . . , n}.
Note that if G = [IM] is a k × n matrix over F2 and if
R = {i1, . . . , im, k + j} is a recovery set for position i with
i1, . . . , im ∈[k] and 1 ≤j ≤n −k, then i /∈{i1, . . . , im}
and the (k + j)th column of M has a ‘’1” in the positions
i1, . . . , im and i, and in no other positions.

IV. REQUEST-SERVING ALGORITHMS FOR BATCH CODES
A [n, k, t]q batch code, by definition, requires that we can
serve any batch of at most t requests by t pairwise disjoint
recovery sets. However, this requirement does not tell us how
to choose the recovery sets. In this section, we will introduce
and investigate various possible request-serving algorithms for
batch codes, some investigated before, and some new. Batch
codes equipped with such an algorithm will make recovery
easier.
A. Online batch codes
An online algorithm bases the current action only on knowl-
edge of the past, but not on the future.
Definition 4.1: An [n, k, t]q batch code will be called online
if it is possible to satisfy a request sequence i1, . . . , it one-by-
one, where, for every j ∈[t], the choice of the recovery set
Rj to serve the current request ij depends only on the chosen
recovery sets R1 for i1, ..., Rj−1 for ij−1, but not on the
future requests ij+1, . . . , it.
We now describe a useful characterization of online batch
codes. We need some preparation.
Definition 4.2: Given an [n, k, t]q batch code G, a recov-
ery history sequence for G is a (possibly empty) sequence
R1, . . . , Rs (0 ≤s ≤t), where R1, . . . , Rs are mutually

Definition 4.3: Let H be a collection of recovery history
sequences of length at most t for a [n, k, t]q batch code G.
1) H is called prefix-closed if every prefix of a recovery
sequence in H is again contained in H.
2) H has the extension property (or, is t-extendable) if for
every incomplete recovery history sequence R1, . . . , Rs
in H (so with s < t) and every i ∈[k], there exists a
recovery set R ⊆[n] for i such that R1, . . . , Rs, R is

3) H has the exchange property if for every complete re-
covery history sequence R1, . . . , Rt in H, for every i ∈
[k] and for every j ∈[t], there is a recovery set R for i
such that the sequence R1, . . . , Rj−1, R, Rj+1, . . . , Rt

Theorem 4.4: An [n, k, t]q online batch code G is charac-
terized by a collection H of recovery history sequences for G
which is prefix-closed and t-extendable.
Proof. According to the definition, formally an online batch
code is characterized by choice-functions fj (j = 1, . . . , t).
Here f1 associates with every i ∈[k] a recovery set R ⊆[n]
for i, and given a request sequence i1, . . . , ij and mutually
disjoint recovery sets R1 for i1, ..., Rj−1 for ij−1, the choice
function fj associates the sequence R1, . . . , Rj−1 and the last
request ij with a specific recovery set Rj for ij disjoint from
R1, . . . , Rj−1. Now let H be the collection of all sequences
R1, . . . , Rs (s ≤t) of pairwise disjoint recovery sets that can
arise after applying the choice functions f1, . . . , fs, for a given
request sequence i1, . . . , is. Obviously, H is prefix-closed.
Moreover, if R1, . . . , Rs ∈H with s < t, then, by definition,
there are i1, . . . , is such that fj(R1, . . . , mRj−1, ij) = Rj for
j = 1, . . . , s; so if i ∈[k], then R := fs+1(R1, . . . , Rs, i) is a

R1, . . . , Rs, R ∈H. So H also has the extension property.
Conversely, given a collection H as in the theorem, we
can obviously use that collection to create choice functions
f1, . . . , ft for an online batch code (note that these choice
functions need not be unique).
□

such a batch code as t-online.

Theorem 4.5: Let H∗be a collection of complete recovery

R1, . . . , Rj−1, R is also contained in H. This proves that H

B. Asynchronous batch codes
An asynchronous algorithm is a method where various
processes operate simultaneously but independently of each
other. In the case of an asynchronous t-batch code, at any time
at most t recovery processes are running, where each process
serves a request for the recovery of a specific information bit.
Once a process is finished, a new request can be received,
which is then served by a new recovery set, chosen to be
disjoint from the other recovery sets presently in use. We
require that any new request can always be served if fewer
than t recovery processes are running. Asynchronous batch
codes were first introduced in [17, Definition III.1]. Our
treatment here will be slightly different.
We first describe a useful characterization of asynchronous
batch codes, in the same style as our earlier characterization
of online batch codes. We need some preparation.
Definition 4.8: A recovery history for a given [n, k, t]q batch
code G is a set of the form {R1, . . . , Rs} (0 ≤s ≤t), where
R1, . . . , Rs are mutually disjoint minimal recovery subsets
of [n]. We refer to such a recovery history as incomplete if
s < t and complete if s = t.
We think of a recovery history as representing the recovery
sets currently in use.
Definition 4.9: Let H be a collection of recovery histories
of size at most t for a given [n, k, t]q batch code G.
1) H is called subset-closed if every subset of a recovery
history in H is again contained in H.

C. Strongly online and asynchronous batch codes
We now discuss strong variations of online and asyn-
chronous codes, which turn out to be the same.
Definition 4.15: An [n, k, t]q strongly online batch code is
a pair (G, R) where G is an [n, k, t]q batch code and R ⊆
P([n]) is a collection of recovery sets for G with the property
that the collection H(R) consisting of all the recovery history
sequences R1, R2, . . . , Rs with R1, . . . , Rs ∈R and 0 ≤s ≤
t is t-extendible.
So the pair (G, R) is strongly t-online if we can serve a
sequence of requests i1, . . . , it one-by-one, by choosing an
arbitrary recovery set for position i1 from R, then choosing
an arbitrary recovery set for position i2 from R that is disjoint
from R1, etc.
Similarly, we can also define a stronger form of asyn-
chronous batch codes.
Definition 4.16: An [n, k, t]q strongly asynchronous batch
code is a pair (G, R), where G is an [n, k, t]q batch code, and
R is a collection of recovery sets for G with the property that
the collection H = H(R) consisting of all recovery histories
{R1, . . . , Rs} with R1, . . . , Rs ∈R and 0 ≤s ≤t is t-
extendable.
Interestingly, we have the following.
Theorem 4.17: Let G be an [n, k, t]q batch code and let
R be a collection of subsets of [n]. Then (G, R) is strongly
t-online if and only if (G, R) is strongly t-asynchronous.
Proof. Obviously, H(R) is t-extendable if and only if H(R)
is t-extendible. Since H(R) is prefix-closed and H(R) is
subset-closed by definition, the result immediately follows
from Theorem 4.4 and Theorem 4.10.
□
In what follows, we will refer to a pair (G, R) where G is
an [n, k, t]q batch code and R has the equivalent properties
in Definition 4.15 or 4.16 as a t-strongly asynchronous batch
code. We have not yet been able to find an example of an
asynchronous t-batch code that is not strongly t-asynchronous,
but we have no doubt that these two notions are distinct.
However, it is not hard to prove that these notions are the
same when t ≤2.
D. (m, L)-strongly asynchronous batch codes
Inspired by the type of batch codes obtained from Almost
Affinely Disjoint (L-AAD) families [1], [12], [14], [15] and
by the graph-based batch codes in [17], we now introduce a
type of strongly online batch code with an even simpler online
algorithm. We need some preparation.
Definition 4.18: Let G be an [n, k, t]q batch code. A service
w.r.t. G is a pair (i, R) of a request i ∈[k] and a recovery
set R ⊆[n] for i in G; we sometimes refer to a service
(i, R) w.r.t. G as a service for i. A service for a given batch
{{i1, . . . , is}} of requests is a set {(i1, R1), . . . , (is, Rs)} of
services where R1, . . . , Rs are mutually disjoint.
Definition 4.19: Let m and L be positive integers. An
[n, k, t]q batch code G will be called (m, L)-strongly asyn-
chronous if there exists a collection S of services w.r.t. G
with the following properties.
1) For every i ∈[k], there are at least m distinct services
(i, R) for i in S.
2) For every i, j ∈[k] (possibly with i = j), every service
(i, R) for i in S excludes at most L services for j in S.
Here a service (i, R) excludes a service (i′, R′) if R
and R′ are not disjoint.
In what follows, an (m, L)-strongly asynchronous batch code
will refer to a pair (G, S) as in Definition 4.19. We sometimes
refer to such a code as an [n, k, m, L]q strongly asynchronous
batch code. We now show that an (m, L)-strongly asyn-
chronous batch code indeed is a batch code, and in fact is
a strongly asynchronous batch code.
Theorem 4.20: Let (G, S) be an [n, k, m, L]q-strongly on-
line batch code, and let R be the collection of all recovery sets
R for which (i, R) ∈S for some i ∈[k]. Then (G, R) is an
[n, k, t]q strongly asynchronous batch code with t = ⌈m/L⌉.
Proof. Below, we refer to the elements in S as admissible
services. Suppose that request sequence i1, . . . , is−1 is served
by the admissible services (i1, R1), . . . , (is−1, Rs−1), and
consider a new request is. By property (1), position is has at
least m admissible services, and by property (ii), every service
(ij, Rij) excludes at most L of the admissible services for is.
So if every admissible service for position is is excluded by
one of (i1, R1), . . . , (is−1, Rs−1), then (s −1)L ≥m. We
conclude that every sequence of services of length s −1 can
be extended to serve another request as long as (s−1)L < m,
with the new service only depending on the recovery sets used
in preceding services; hence we obtain a strongly online t-
batch code, where t is the integer for which (t −1)L < m ≤
tL. Then t −1 < m/L ≤t, hence t −1 < ⌈m/L⌉≤t; since
t is integer; we conclude that t = ⌈m/L⌉.
□
The above ideas where in fact motivated by the following.

V. GRAPH-BASED BATCH CODES
In this section, we are interested in recovery sets of a special
type, such as those occurring in graph-based batch codes and
batch codes obtained from L-AAD families. We will only
consider binary batch codes here, so in this section, we only
consider q = 2 and we assume that matrices are defined
over F2.
Definition 5.1: (See [15, Definition 2].) Let G = [IkB] be a
systematic (binary) k×n matrix, where Ik is the k×k identity
matrix and B = (Bi,j) is a binary k × (n −k) matrix. Recall
that a recovery set for position i w.r.t. G is called simple if it
contains exactly one element from the set of column indices
{k + 1, . . . , n}. We say that a batch code is simple if it is
systematic and employs only simple recovery sets.
Simple batch codes G = [IkB] are best understood in terms
of a bipartite graph associated with B as introduced in [16].
Let Γ = Γ(B) be the bipartite graph with biadjacency matrix
B [2, page 17]. That is, Γ has vertex set [k] ∪B, where B :=
{B1, . . . , Bn−k} is the set of parity symbols (corresponding to
the columns of B), with an edge {i, Bj} if and only if Bi,j ̸=
0. Write V = V (Γ) := [k] ∪B to denote the set of vertices
of Γ; for v ∈V , let Γ(v) denote the neighborhood of v, the set
of vertices connected to v, and write d(v) := |Γ(v)|, the degree
of v. Note that there is a one-to-one correspondence between
systematic (binary) matrices [IB] and bipartite graphs Γ. Note
also that we have a one-to-one correspondence between edges
in Γ and simple recovery sets for G, where an edge {i, B}
(i ∈[k], B ∈B) in Γ corresponds to the simple recovery sets
R(i, B) := {B} ∪Γ(B) \ {i} for i; here we associate the set
of column indices [n] with the set of vertices [k]∪B of Γ. We
now investigate the batch code properties of the simple batch
codes associated with Γ. Here the following simple result is
crucial.
Lemma 5.2: The edges {i, B} and {i′, B′} (i, i′ ∈[k],
B, B′ ∈B) in Γ represent intersecting recovery sets if and
only if one of the following holds:
1) B′ = B (this includes the case where i′ = i and the
recovery sets are equal).
2) B′ ̸= B, i′ = i, and there is a 4-cycle i−B−i′′−B′−i
for some i′′ ̸= i.
3) B′ ̸= B, i′ ̸= i, and there is a 4-path i ∼B ∼i′′ ∼
B′ ∼i′ in Γ, where i′′ ̸= i, i′.
This follows immediately from the definitions of R(i, B)
and R(i′, B′). Our main result on (graph-based) simple batch
codes is the following.
Theorem 5.3: Let G = [IB] be a systematic binary k × n
matrix, and let Γ = Γ(B) be the associated bipartite graph.
Then G is a simple (m, L)-strongly asynchronous [n, k, t]2
batch code with t = ⌈m/L⌉for the collection R of simple
recovery sets R(i, B) := {B} ∪Γ(B) \ {i} corresponding to
edges {i, B} in Γ if and only if the following conditions hold:
1) For every i ∈[k], we have d(i) ≥m.
2) Every edge {i, B} in Γ is contained in at most L −1
4-cycles.
3) Given i, i′ ∈[k] with i′ ̸= i and an edge {i, B} in Γ
such that i′ /∈Γ(B), there are at most L (not necessarily
disjoint) distinct 3-paths in Γ between B and i′ that do
not contain i.
Proof. Recall that a simple recovery set for i ∈[k] takes
the form of a recovery set R(i, B) for a block B ∈B with
i ∈Γ(B), and consists of the “non-systematic” column of G
indexed by B together with the “systematic” columns of G
corresponding to points in Γ(B) \ {i}.
According to Definition 4.19, G is (m, L)-strongly online
for the collection R in the theorem precisely when each
i ∈[k] is contained in at least m members R(i, B) of R
and if every recovery set R(i, B) for i intersects at most L
recovery sets for every i′ ∈[k]. The first condition obviously
holds precisely when for every i ∈[k], we have d(i) ≥m,
which is condition 1 in the theorem. For the second condition,
we will use Lemma 5.2. So consider a recovery set R(i, B)
corresponding to the edge {i, B} in Γ, for i ∈[k] and B ∈B.
This recovery set intersects itself in B, and intersects another
recovery set R(i, B′) with B′ ̸= B for i in a point i′ ∈[k]
precisely when i −B −i′ −B′ −i is a 4-cycle containing the
edge {i, B}. So the second condition holds for recovery sets
for i (so with j = i in condition 2) in Definition 4.19) precisely
when condition 2 in the theorem holds. Finally, let i′ ∈[k]
with i ̸= i′. A recovery set R(i′, B′) for i′ corresponding to the
edge {i, B} intersects the recovery set R(i, B) corresponding
to the edge {i′, B′} with i ̸= i′ precisely when B = B′ or
when B ̸= B′ and there exists a point i′′ such that {i′′, B}

VI. CONCLUSIONS
We have initiated the investigation of batch codes equipped
with efficient recovery algorithms. In particular, we have
introduced t-online batch codes, able to handle up to t requests
as they come in, we explored t-asynchronous batch codes,
able to run up to t recovery processes simultaneously, and
we discussed various forms of t-strong batch codes, able to
handle up to t requests by making arbitrary choices of the
recovery sets for the requests as long as any new recovery
set is disjoint from the ones already in use. We have also
shown that the corresponding types of batch codes obey a strict
hierarchy, where (m, L)-strong with t ≥⌈m/L⌉implies t-
strong implies t-asynchronous implies t-online implies general
t-batch. Finally, motivated by the recent constructions of batch
codes from Almost Affinely Disjoint Families, we first have
introduced a generalization of L-AAD families that we call
L-AAD*, and we have shown that such a family of sizem
gives rise to a binary (m, L)-strongly asynchronous batch
code. Then we have studied graph-based simple batch codes,
systematic batch codes employing only simple recovery sets,
and derived necessary and sufficient conditions on the bipartite
graph to obtain an (m, L)-strong batch code. Our results here
generalize and improve various previous results on L-AAD
and L-AAD* families and on graph-based batch codes.
