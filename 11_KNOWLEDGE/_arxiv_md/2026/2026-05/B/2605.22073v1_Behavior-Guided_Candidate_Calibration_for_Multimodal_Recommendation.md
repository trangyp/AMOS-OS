Abstract
Multimodal recommendation benefits from content signals, but
the gain depends on how those signals interact with the rank-
ing pipeline. We find that moderate cross-view agreement helps,
while stronger agreement suppresses recommendation-specific vari-
ation. Spectral analysis shows a clear split: low-frequency com-
ponents capture shared structure, and higher-frequency compo-
nents preserve more discriminative signal. Based on this finding,
we introduce a behavior-guided candidate calibration model that
converts training-only co-user overlap into signed candidate ev-
idence and applies it only to the shortlist produced by the mul-
timodal backbone. The backbone keeps the representation space
stable; behavior evidence acts only where ranking is decided. Re-
sults on Amazon Baby, Sports, and Electronics show consistent
gains over strong multimodal baselines. Code is available at https:
//github.com/LIZESHENG13/bridge.

Introduction
Images, titles, descriptions, and brands provide useful side infor-
mation for recommendation, especially when interaction data are
sparse. This has motivated a broad family of multimodal recom-
menders that combine user-item interactions with visual and textual
item features [3, 25–27]. Recent surveys synthesize this literature
from representation, modeling, and optimization perspectives [17].
Recent work has improved the representation layer by building
item-item graphs from content, denoising multimodal features, or
enforcing stronger consistency across views [5, 10, 24, 32, 39]. The
common premise is simple: a better multimodal representation
should yield a better ranker.
Our diagnostics support a more selective view. Content evi-
dence helps, but only within an effective range. Moderate cross-
view consistency improves ranking, whereas stronger consistency
suppresses recommendation-specific variation. Frequency analysis
further shows a shared-vs-private split: low-frequency bands are
aligned across views, while higher-frequency bands retain more

ranking signal. That asymmetry matters because ranking is decided
in a narrow candidate set. Once alignment becomes too strong, it
blurs the local distinctions that separate plausible items from near
neighbors.
BRIDGE turns these observations into a behavior-guided design.
The multimodal encoder defines the base candidate geometry, and
co-user behavior authorizes only local residual corrections inside
that candidate set. DFGE preserves frequency-aware multimodal
evidence, BEN converts training-only co-user overlap into signed
behavior support, and CRI applies that support only within the
candidate scope. On Amazon Baby, Sports, and Electronics, BRIDGE
reaches 0.1128, 0.1262, and 0.0778 Recall@20, respectively, with
corresponding NDCG@20 values of 0.0525, 0.0594, and 0.0385.
A second gap is operational. In retrieval-and-rank pipelines,
the shortlist is already the decision bottleneck. A content signal
that helps representation learning can still hurt ranking when it is
allowed to move every score in the catalog. BRIDGE isolates that
failure mode: the multimodal backbone defines the shortlist, and
behavior evidence is allowed to revise only the candidates that the
backbone has already made plausible. This localizes correction to
the region where ranking is actually decided.
The contributions of this work are:
• We identify two diagnostics in multimodal recommenda-
tion: direct cross-view consistency has an effective range,
and the representation spectrum separates shared low-frequency
evidence from more private higher-frequency variation.
• We propose DFGE, a dual-frequency graph evidence en-
coder that preserves that spectrum with band routing and
structural regularization.
• We propose BEN and CRI, which turn training-only co-user
overlap into signed behavior evidence and use it only to
calibrate the candidate scope used at training and inference.

attention, hierarchical multi-step fusion, and multimodal large lan-
guage model coupling [21, 23, 31, 34, 40]. The common theme is
to improve representation quality before ranking. BRIDGE differs
by asking when content evidence should be trusted by the ranker
rather than how aggressively it should be fused.
The key distinction is that most alignment methods treat cross-
view agreement as a proxy for better ranking. In practice, that
assumption is too strong. Once content matching becomes dom-
inant, it can erase the differences that separate a plausible item
from a near duplicate or a popular lookalike. BRIDGE keeps the
same multimodal evidence, but uses it to define candidate geometry
rather than to rewrite every score in the catalog. The question is
not whether two views can be aligned. The question is whether
that alignment should change the rank of a specific candidate.
This is why the strongest recent alignment systems still leave a
gap. They can improve the encoder, the fusion block, or the item
graph, but they do not decide when the resulting evidence should
be allowed to alter the shortlist. BRIDGE treats that decision as part
of the model, not a post-hoc choice.
2.2
Frequency-Aware and Behavior-Guided
Recommendation
Frequency-aware recommenders separate stable structure from
fine-grained variation. SMORE [16], FITMM [32], SSR [33], MSCF-
Net [6], DuGRec [13], D-DPDG [28], and Sequences-as-Nodes [23]
show that spectral views can organize multimodal or collabora-
tive evidence. These works differ in whether the spectrum is used
for denoising, co-frequency enhancement, or explicit band rout-
ing. BRIDGE uses the same general intuition but keeps the band
decomposition as a representation core rather than a standalone
predictor.
That makes BRIDGE different from frequency-aware denoising
pipelines. Those models usually use the spectrum to suppress noise
or separate stable from unstable components, while BRIDGE uses

the decomposition to decide which bands remain shared evidence
and which bands are left as residual variation for candidate calibra-

The same point applies to band routing. A decomposition can
denoise a representation, but denoising alone does not explain
how the output should affect ranking. BRIDGE keeps the spectrum
inside the backbone and lets candidate calibration consume only
the bands that remain useful after decomposition. This keeps the
representation and the calibration rule aligned with one another.
2.3
Behavior-Guided, Causal, and Sequential
Multimodal Control
In parallel, behavior-guided methods such as BPR [22], LightGCN
[4], DRAGON [37], FGCM [15], JBM-Diff [18], and causal-inspired
multimodal recommendation [30] use interaction structure to vali-
date or filter content-derived relations. More recent work extends
this idea to dual-graph diffusion, modality coherence, and multi-
intention or sequential settings [2, 12, 21, 31, 34, 41]. BRIDGE com-
bines these lines, but uses behavior only as a local authorization
signal for candidate- level residual calibration rather than as a global
fusion or denoising target.
That distinction matters because many behavior-guided methods
still operate globally. They improve the score function, the graph
structure, or the fusion rule, but the behavior signal is applied across
the item space. BRIDGE keeps the same evidence and narrows its
effect to a top-𝐾candidate set, which makes the behavior branch
easier to interpret and less likely to distort the catalog-wide ranking
order.
Together, these strands motivate BRIDGE’s dual-frequency and
candidate-calibrated design.

4
Motivating Observations
BRIDGE is motivated by three empirical observations. Together
they suggest a simple design principle: multimodal information
should be preserved, but content should be treated as conditional
evidence, not as a command.
4.1
Direct Consistency Has an Effective Range
We run a compact direct-consistency diagnostic on Amazon Baby
using the same backbone and split, while varying only the consis-
tency strength. Without direct consistency, Recall@20 is 0.0922. A
moderate setting with a contrastive loss weight of 0.01, a similarity
weight of 0.3, and UI cosine improves it to 0.1024, showing that
cross-view consistency can be useful. However, a stronger setting
with a contrastive loss weight of 0.1 and a similarity weight of 1.0
drops Recall@20 to 0.0836, showing that direct consistency has an
effective range. Once this objective dominates, it can suppress pri-
vate recommendation factors that are not shared by all modalities.
We also checked a lighter setting with a contrastive loss weight
of 0.001 and a similarity weight of 0.1 under another seed, which
reached Recall@20 of 0.0982 and still stayed below the moderate
setting.
4.2
Low Frequency Agrees; High Frequency
Ranks
Frequency diagnostics further clarify where the useful information
lives. Low-frequency components show strong cross-view agree-
ment, while high-frequency components show weaker agreement.
Recommendation performance follows the opposite pattern: high-
frequency views rank better than low-frequency views, although
both are weaker than the complete representation. Figure 2 visu-
alizes this diagnostic as a pair of range plots. The bands here are
representation-spectral bands obtained from graph-smoothed chan-
nel matrices, not graph Laplacian eigenvectors; Section 5.1 gives the
formal interpretation. This motivates a useful split: low frequency is
a natural substrate for shared structure, whereas higher-frequency
variation carries more local ranking evidence that should be han-
dled cautiously.
4.3
Behavior Evidence Decides When
Calibration Helps
Content-derived corrections are not uniformly beneficial. In our
diagnostics, global score correction often hurts, while top-𝐾candi-
date correction can improve ranking. Co-user behavior evidence
is also consistently strong, especially on sparse Amazon domains.
We therefore interpret behavior evidence as a local validity test
for candidate calibration. If a candidate is also supported by user
co-occurrence, a small correction may recover items missed by
sparse collaborative training. If not, the same content relation may
simply identify substitutes or visual lookalikes.

5
Method
Figure 1 summarizes BRIDGE. The method follows one principle:
frequency-specific multimodal evidence should be preserved before
behavior evidence calibrates the final ranking. BRIDGE separates
this process into three modules. DFGE learns the frequency-aware
graph representation and base score 𝑠base(𝑢,𝑖). BEN estimates nor-
malized behavior evidence 𝑏𝑢𝑖from the training interaction graph.
CRI injects that evidence as a signed residual only inside the candi-
date scope. The base encoder therefore defines the ranking geome-
try, and the behavior branch only adjusts local decisions.

6.1
Experimental Setup
We evaluate BRIDGE on Amazon Baby, Sports, and Electronics from
the Amazon review benchmark [14] under the common MMRec-
style implicit-feedback split. Baby has 19,445 users, 7,050 items,
and 160,792 interactions. Sports has 35,598 users, 18,357 items, and
296,337 interactions. Electronics has 192,403 users, 63,001 items, and
1,689,188 interactions. We use BEIT3-derived multimodal features
and report Recall@10, Recall@20, NDCG@10, and NDCG@20. For
fair comparison, all baselines in Table 1 are evaluated under the
same processed interaction splits, the same BEIT3 feature files, and
the same full-sort evaluation protocol. The strongest baselines are
therefore compared in our setting rather than under a different
feature or split configuration. Unless otherwise stated, reported
numbers use seed 2020.
For all three datasets, the behavior graph is constructed strictly
from the training split. Each interaction file carries a training, vali-
dation, or test partition marker. We first build Dtr from the training
partition and compute co-user edges, user histories, item popular-
ity, and user degree from this training matrix only. Validation and
test interactions are not used in the behavior graph. Baby contains
118,551 training interactions, 20,559 validation interactions, and
21,682 test interactions. Sports contains 218,409 training interac-
tions, 37,899 validation interactions, and 40,029 test interactions.
Electronics contains 1,254,441 training interactions, 211,296 val-
idation interactions, and 223,451 test interactions. No cold-start
users are present in validation or test after filtering, so the same
leakage-free construction is used on all three datasets.
All BRIDGE main results use candidate-aware training. For each
training mini-batch, the model computes the detached base top-
𝐾𝑐candidate set of each involved user and masks the behavior
residual outside this set, as defined in Eq. 18. At test time, the
same 𝐾𝑐-restricted residual is applied to the base top-𝐾𝑐list in
Eq. 20. Thus the residual branch is trained and evaluated under the
same candidate-level scope. The training sampler is still pairwise
BPR rather than a full listwise reranker, but it avoids the stronger
mismatch in which a residual is learned globally and used only
locally.
The reported hyperparameters follow the dataset and model
configuration files. We use a 64-dimensional embedding size, two
graph layers, and three frequency bands. The item graph uses 10
neighbors. The learning rate is 10−4, the regularization weight is
10−3, the IB weight is 1.0, the behavior top-𝐾is 1000, the behavior
weight is 0.4, the behavior evaluation top-𝐾is 200, and the train
candidate top-𝐾is 200. The behavior graph uses cosine similarity,
sum-sqrt aggregation, and z-score normalization. Training uses
Adam for 300 epochs with batch sizes 2048 and 4096, zero weight
decay, and seed 2020. These settings are shared by the main tables,
the ablation suite, and the calibration sweeps. The experiment suite
is organized to match the method: Table 1 compares overall ranking
quality, Tables 2 and 3 isolate the residual and spectral controls,
and Table 4 checks whether the gains come from a head-item boost
or from a broader redistribution of ranking mass.
6.2
Main Results
Table 1 follows the common overall comparison format and places
BRIDGE in the rightmost column. The baseline set spans pair-
wise ranking (BPR [22]) and graph collaborative models (Light-
GCN [4], MMGCN [27], GRCN [26], DualGNN [25], and LATTICE
[35]). It also includes multimodal variants (VBPR [3], SLMRec [24],
BM3 [39], FREEDOM [38], DiffMM [5], MMIL [31], AlignRec [10],
SMORE [16], and FITMM [32]). The comparison therefore covers
classical collaborative ranking and recent multimodal systems un-

On the three reported datasets, the selected BRIDGE setting is the
fixed-𝜆𝑏candidate calibration rather than the conservative coef-

The margin is most pronounced on Electronics, where sparsity and
popularity skew make a global residual less reliable. This matches

clearest benefit from candidate-level calibration. This pattern is
consistent with the data regime: as the interaction graph becomes
sparser, the model benefits more from a restricted residual than
from a global score adjustment.
6.3
Diagnostics
At the validation-selected Baby checkpoint, the pair coefficient
mean is 0.7365, the behavior correction absolute mean is 0.6886, the
low-item norm mean is 6.3819, the high-item norm mean is 2.7333,
and the low-high item cosine is 0.0560. These values are consistent
with the view that the two frequency components capture different
signals and that the residual branch acts as a local correction rather
than a global rewrite. The low-frequency band carries stronger
cross-view agreement and larger energy, the high-frequency band
is less aligned but still informative, and the low-high cosine is near
zero. BRIDGE therefore uses the low bands as shared structure
and the high bands as local variation, rather than treating the full
representation as a single fused signal.

7
Discussion
The results support a frequency-first design. DFGE is not a cosmetic
front end: it defines the candidate geometry on which ranking acts,
and the frequency objectives keep low-frequency shared evidence
and higher-frequency private variation from collapsing into one
signal. BEN turns co-user overlap into signed behavior evidence,
and CRI decides where that evidence may alter the score. The
behavior-only, raw co-occurrence, and EASE controls show that
neighborhood evidence does not replace representation learning or
reduce to a generic ItemKNN signal. The learned fusion variants
stay close to the fixed residual but do not exceed it, so additional
calibration capacity is not the main driver. Together, the controls
indicate that candidate restriction is the main safeguard against
global score distortion.
Recent dual-graph, retrieval-enhanced, and dual-path alignment
models point in a nearby direction: they strengthen modality in-
teraction with extra routing, completion, or alignment modules
[1, 2, 7–9, 11, 29]. BRIDGE keeps the backbone interpretable and
pushes complexity into the evidence-selection rule: the base score
carries the multimodal representation, and the behavior residual
only decides where that score may be locally corrected.

7.1
Practical Implications
A useful reading of the control suite is to separate backbone quality
from residual authority. DFGE builds the candidate manifold. BEN
converts co-user overlap into signed evidence. CRI decides where
that evidence may alter the score. The gain from BRIDGE comes
from keeping those roles separate. When the same evidence is


## Page 10


Li et al.
allowed to act globally, it starts competing with the multimodal
backbone and the improvement shrinks. Candidate restriction is
therefore not an implementation detail; it is the mechanism that
keeps the residual aligned with ranking.
This also explains the popularity diagnostics. Head items domi-
nate the base ranking because they are easier to reconstruct from
sparse co-occurrence, while mid, tail, and cold items depend more
on cross-modal structure. BRIDGE does not impose an explicit
anti-popularity penalty. It preserves head accuracy and reallocates
useful mass to less exposed items that survive the candidate gate.
The exposure shift in Table 4 is a by-product of better localization,
not a separate regularizer.
At inference, BRIDGE adds a small residual pass over a cached
candidate list. The item graph is precomputed, the behavior graph
is derived from training interactions only, and the residual is never
asked to rewrite the full catalog. That keeps the method compatible
with standard retrieval-and-rank pipelines. The main failure mode
is equally clear: if the backbone fails to place a relevant item in the
candidate set, the residual cannot recover it. No calibration rule
removes that ceiling.
Noisy co-user neighborhoods can also blur BEN, especially when
user overlap is sparse or interaction bursts are highly local. In
those settings the conservative coefficient variant is a safer operat-
ing point because it limits the magnitude of correction. The fixed
candidate-weighted residual is stronger when the backbone already
produces a reasonable shortlist, which is the regime targeted by
the benchmark.
7.2
Calibration Behavior
The validation sweep shows that BRIDGE is not sensitive to a
single hand-picked coefficient. The fixed-𝜆𝑏setting wins on all
three datasets, but the conservative coefficient control remains close
enough to preserve the same qualitative behavior. That matters
because the residual is not trying to learn a second ranking model;
it only has to decide how much local correction is safe. When the
coefficient is too small, the behavior branch becomes decorative.
When it is too large, it starts to fight the backbone. The five-point
grid identifies the middle ground without introducing a heavy
search cost.
The same pattern appears across the frequency design. The low-
frequency component carries the stable cross-view structure, while
the higher-frequency bands capture sparse and item-specific vari-
ation. The IB surrogate and the frequency regularizer are both
needed because they serve different roles: one controls how much
each node can route into the bands, the other preserves a useful
band geometry once the routing has happened. The ablations show
that dropping either term weakens the ranking signal, while chang-
ing the basis has only a small effect. The decomposition is therefore
structural, not basis-specific.
The resulting scope is narrow on purpose. BRIDGE assumes
that the base backbone already places a relevant item in the candi-
date set. It does not attempt to rescue items that never surface in
retrieval, and it does not attempt to override a weak multimodal
representation. Those limits are acceptable in the benchmark set-
ting, where the objective is to sharpen the top of the list rather than
to replace retrieval. The design therefore fits the standard two-stage
pipeline used in practical recommenders.
Because the same setup is used across all methods, the residual
effect can be interpreted directly. If a baseline is strong in Recall
but weak in NDCG, the calibration branch is improving ordering
rather than just retrieving more items. If head exposure drops while
mid and tail recall rise, the residual is redistributing ranking mass
without collapsing popular items. Those are the behaviors reported
by the tables and controls, so the narrative stays tied to measured
outputs.
7.3
Limitations and Reproducibility
BRIDGE makes one explicit tradeoff: it keeps the base encoder as
the ranking backbone and uses behavior evidence only as a local
calibration signal. That choice preserves interpretability and blocks
global score rewrites, but it also makes candidate quality the main
ceiling on performance. If the base top-𝐾list is weak, the resid-
ual branch cannot recover items that never enter the candidate
scope. The SVD band routing adds one decomposition over each
64-dimensional channel block, yet the cost is bounded and the mul-
timodal item graph is cached, so the additional overhead remains
modest.
The implementation is reproducible from the information in
this paper and the accompanying anonymous code package. The
behavior graph is built only from the training split, the same BEIT3
feature files are used across all methods, and validation selects the
residual weight before test evaluation. The released code stores the
complete configuration, including candidate size, behavior top-𝐾,
band count, and random seed, so the reported numbers can be
regenerated without any author-identifying information. The pack-
age also records the split manifest, feature paths, preprocessing
scripts, and full evaluation commands, so the same results can be
reproduced from the raw benchmark files without manual inter-
vention. Because the same feature cache is used for every method,
the comparison isolates ranking behavior rather than feature en-
gineering. The reported tables use full-sort evaluation with fixed
seeds and a validation-only sweep over the residual coefficient.
8
Conclusion
We presented BRIDGE, a behavior-guided residual integration frame-
work for multimodal recommendation. BRIDGE uses DFGE to or-
ganize multimodal evidence into frequency bands, BEN to convert
training-only co-user overlap into signed behavior evidence, and
CRI to apply that evidence only inside the candidate set produced by
the backbone. Across Baby, Sports, and Electronics, this candidate-
level design improves both Recall and NDCG, with the strongest
gains in NDCG, which means the method sharpens the ordering
near the top of the list rather than only recovering more items at
larger cutoffs.
The main lesson is that multimodal recommenders do not need
a global residual rewrite to benefit from behavior evidence. They
need a bounded calibration rule that acts only where the back-
bone has already produced plausible candidates. That separation
keeps the method interpretable, reproducible, and compatible with
standard two-stage pipelines. The remaining limit is explicit: if a
relevant item never enters the candidate set, no residual can recover

operating point for top-𝐾multimodal ranking.
