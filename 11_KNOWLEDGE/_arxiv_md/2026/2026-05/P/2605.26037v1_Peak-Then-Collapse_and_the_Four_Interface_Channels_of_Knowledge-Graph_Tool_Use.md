Abstract
We test the standard RLVR tool-use recipe —
GRPO on Qwen2.5-7B-Instruct — on a deliber-
ately minimal knowledge-graph tool API: four
Freebase navigation verbs over Complex We-
bQuestions. Under a self-verifiable retrieval
reward, the policy’s tool-grounded answer rate
climbs from 3.8% to 9.6% over 250 steps, then
collapses to 0% within a single 50-step win-
dow — a peak-then-collapse pattern replicated
across four seeds. Across seven reward designs,
we find four recurring failure modes: adding
denser or more targeted proxy rewards shifts
the failure mode rather than eliminating it. We
argue that a key difference from Python inter-
preters, web search, and JSON APIs is inter-
face feedback: their failures often leak natural-
language signal the model saw in pretraining.
A Python traceback names the failing line; an
empty Freebase result [] does not. Stripping
away that surface exposes a degradation regime
that same-family reward redesigns do not fix.
A direct oracle ablation rules out relation se-
lection: injecting gold relations at every re-
trieval call lifts exact-match accuracy by only
+0.20 pp, and 95.4% of retrieval-dependent er-
rors are retrieval-composition failures rather
than answer-extraction failures.
As a miti-
gation, one-iteration self-distillation reaches
40.0% EM at 7B and is capacity-invariant: dou-
bling capacity to 14B improves EM by only
0.25 pp, and initialization barely matters — the
ceiling appears interface-bound within the 7B–
14B range tested.

Introduction
Large language models increasingly act as agents:
they call external tools — code interpreters, web
search, function APIs — and are trained to use
them by reinforcement learning with verifiable re-
wards (RLVR), where a checkable outcome (did
the code run? did the answer match?) supplies the
reward (Li et al., 2025; Feng et al., 2025; Jin et al.,
2025; Qian et al., 2025). The dominant recipe —
dense process rewards, GRPO (Shao et al., 2024), a
7B-scale policy — is treated as portable across tool
families. We test that portability on a tool whose
interface is, by construction, the opposite of the
pretraining-aligned surfaces RLVR usually enjoys:
a knowledge graph (KG). Our benchmark is Com-
plex WebQuestions (CWQ) (Talmor and Berant,
2018), a standard multi-hop question-answering
task over the Freebase (Bollacker et al., 2008)
knowledge graph, which we re-cast from its usual
gold-subgraph/SPARQL form into a deliberately
minimal tool-use interface: the policy must reach
answers by composing four navigation verbs — the
outgoing or incoming relations of an entity, and the
entities reachable from it along a relation — where
every entity is an opaque machine ID (m.0d3k14)
and every miss returns an uninformative empty list.
Python tool use leaks natural-language signal the
model saw in pretraining — a traceback names
the failing line — whereas this KG interface leaks
almost none. We ask whether the standard RLVR-
tool recipe still converges once that surface is re-
moved.

Related Work
Process-reward RL for tools and knowledge
graphs.
Process-reward recipes for tool-using
LLMs (Jin et al., 2025; Chen et al., 2025;
DeepSeek-AI, 2025; Wang et al., 2025b; Qian et al.,
2025; Zhang et al., 2025c) succeed on tool APIs
with pretraining-aligned surfaces; we test whether
the same recipe transfers to KG tools deliberately
stripped of natural-language surface. KG-specific
variants using KGs to define rewards (fs1 (Zhang
et al., 2025b); HyperGraphPro (Park et al., 2026);
KG-Implicit-RM (Kansal and Jha, 2026)) differ
from our setup, which uses the KG to evaluate
the policy (under RoG’s (Luo et al., 2024) sub-
graph filter; strict EM motivated by Zhang et al.
(2025a)).
On the same Qwen2.5-7B-Instruct +
CWQ benchmark, richer-pipeline concurrent sys-
tems reach higher numbers by enlarging the inter-
face — GraphWalker (Xu et al., 2026) adds ∼21K-
trajectory SFT + BM25 + LLM reranker (79.6%
EM); Graph-RFT (Song et al., 2025) adds web fall-
back over a 40%-incomplete KG (67.2% Hits@1)
— confirming that interface enrichment, not ca-
pacity, is the differentiating axis. Our minimal-
interface scope is a deliberate complement, isolat-
ing what gradient-bearing signal a stripped KG tool

Shared SFT initialisation
All reward-family ablations share a single SFT-
initialised Qwen2.5-7B-Instruct (Team, 2025)
checkpoint with LoRA (r=64, α=128, DoRA
+ rslora) on 5,000 rule-based trajectories whose

3.3
GRPO training
GRPO (Shao et al., 2024) on the SFT base: group

3e−7, batch 128, 500 steps; verl (Sheng et al.,
2024) + vLLM (Kwon et al., 2023) rollouts on
NVIDIA GH200. Reward implementations are
unit-tested (18/18 passing; Appendix B).

free retrieved-entity signal can improve grounding,

4.3
Four failure modes
The seven reward designs produce four mechanisti-
cally distinct failure modes, differing in what fails:
format, tool-use ritual, format-after-tool-use, or the
signal the reward optimises. Crucially, each succes-
sive design shifts the failure rather than eliminating
it — Mode 4 (peak-then-collapse) is the strongest
expression of this pattern and we give its mech-
anism in full here; Modes 1–3 follow the same
shift-not-eliminate dynamic and are summarised
below, with full mechanism prose in App. B.5. The
seven-category trajectory classifier (App. B; exem-
plars in App. G) labels every test-set trajectory.
Mode 1 — Sparse-Reward Format Collapse (R-
binary, R-binary-SR).
Both reach EM=0.000 at
format-valid 0/3531. Outcome-only reward fires
only on EM-match; with Lsig producing identical
[] early responses and Lprior no schema bias, the
gradient never reaches the format-keeping subspace
before low-entropy degeneracy locks in. R-binary-
SR (Search-R1’s exact kl_coef=0.001 config;
App. A) collapses identically — ruling out our hy-
perparameters as cause and locating collapse as
intrinsic to outcome-only reward on this interface.
Mode 2 — Verify-Then-Answer Goodhart (R-
stepwise).
R-stepwise reaches EM=32.5% but
CvT=0.03% (1/3531): Tools/Q=1.0 with 100% of
calls hitting get_tail_relations (the only
verb that never returns empty). The 4-component
verifiable-step reward incentivises structural exis-
tence checks over tool-output consumption — a
tool-free shortcut (component-gaming Goodhart,
cf. Gao et al., 2023).

Mechanism
(hypothesis).
The
retrieval-
contribution term rretrv fires whenever a returned
entity appears verbatim in the answer. Once the
policy has learned to quote returned entities (the
productive climb), a locally optimal degenerate
strategy becomes available: call any single tool,
copy any entity from its response, emit that entity
as a terse answer, stop. This guarantees a pro-
ductive call at minimum sampling budget, max-
imising rretrv while sacrificing EM. Two analy-

dies first (0.41 →0.0007 across step 250–300)

themselves collapsing to ≈0.09 by step 400; (ii)
token-level entropy inside <search> tags drops
0.35 →0.21 nats across step 200–400 while
outside-tag entropy stays at ∼0.01–0.04 nats —
a selective collapse on the action subspace, distinct
from Yu et al. (2025)’s uniform action-distribution
pattern.
Why this matters. This proxy-overoptimisation
shape is catalogued in RLHF and agentic-RL (Gao
et al., 2023; Wang et al., 2025a; Deng et al., 2025);
our contribution is the Tools/Q call-volume signa-
ture (3.0→1.0) characterising it at a behavioural
level on a KG-tool agent (§2).

A Signal-Theoretic Account of
Tool-Interface Difficulty
The four failure modes characterised in §4.3 share
a common substrate: each is a degradation of the
gradient signal GRPO needs to converge on a tool-
grounded policy. We propose this substrate has
structure — four interface-level channels along
which a tool API supplies (or fails to supply) usable
RL signal (Figure 4) — yielding four channel-level
claims. These channels are a descriptive organising
hypothesis, not a causally-validated decomposition:
§5.3 directly intervenes on one (the relation oracle);
isolating the rest is future work.

6
Conclusion
Within a deliberately controlled scope (one model
family, one task, one RL algorithm), seven GRPO-
trained reward designs on Qwen2.5-7B-Instruct
+ CWQ converge into four interface-level failure
modes (Lsig/lang/comp/prior); an oracle ablation
rules out relation selection as the EM bottleneck,
locating the residual gap upstream of answer ex-
traction (the specific channel is unresolved). A
one-iteration self-distillation recipe reaches 40.0%
EM at 7B (self-distill), matched by 14B; richer
concurrent pipelines exceed this via interface en-
richments — advances need interface-aware train-
ing, not larger models or denser proxy rewards.
Methodologically, our 50-step cadence caught the
peak-then-collapse mode; step-resolved instrumen-
tation is essential for process-reward RL. Open:
whether a non-gameable self-verifiable signal ex-
ists; how far interface enrichments push the ceil-
ing is the richer-pipeline line’s domain, where our
channel attribution interprets their gains.
Limitations
Our empirical scope is bounded in six ways.

A
Search-R1 reimplementation rationale
We re-implement the Search-R1 recipe using
our verl pipeline: outcome-only binary-EM re-
ward (our outcome_em_only reward type, unit-
tested), Search-R1’s published hyperparameters
(kl_coef = 0.001, lr = 10−6, batch 256, 500
steps). One configuration change to our pipeline,
zero dependency changes. We label this R-binary-
SR throughout the paper and treat it as a reim-
plementation, not a reproduction. Table 2 reports
format-valid 0/3531 and EM= 0 for R-binary-SR
at convergence — a format-collapse outcome under
outcome-only reward, consistent with the sparse-
reward format-collapse mechanism (§4.3).
B
Reward formulas and trajectory
classifier
B.1
Reward type definitions
All reward types are implemented in a shared
verl_reward module with 18/18 unit tests pass-
ing. Notation: a is the final <answer> text after
normalisation, y is the gold answer, T is the or-
dered sequence of <search> calls with their KG
responses.
• rEM(a, y) = 1[a = y], rF1(a, y) token-overlap
F1.
• rout = 0.5 rEM + 0.5 rF1.
• rvalid: fraction of calls in T that parse as valid
verb(args) matching the 4-verb schema.
• rpath: 1[∃t ∈T : rel(t) on gold triple chain].
• rcoh: sequence-match between <think> spans
and their following <search> calls.
• rtool-type: number of distinct tool verbs covered
in T , scaled to [0, 1].
• rtool-usage: fraction of calls in T with non-empty
response.
• rretrv (I-Self): |Tprod|/|T |, where t ∈Tprod iff
(i) the response is non-empty and (ii) at least one
returned KG entity appears verbatim in a.
• rans (I-Self): identical to rout but with rEM re-
placed by a length-normalised form that treats
multi-token gold answers leniently.

Failure-mode mechanism details (Modes
1–3)
Main body §4.3 presents Modes 1–3 in condensed
form; full mechanism prose is preserved here.
Mode 4 (the signature peak-then-collapse finding)
is presented in full in the main body.
Mode 1:
Sparse-Reward Format Collapse
(R-binary, R-binary-SR).
R-binary (outcome-
only) reaches EM=0.000, F1=0.119; R-binary-
SR
at

exact

(kl_coef=0.001,

on

format-valid 0/3531, ContEM=36.45%; App. A).
R-binary’s 0% strict EM differs qualitatively from
GPT-4o’s 0% on the same interface: R-binary’s
0/3531 is a genuine format collapse, whereas
GPT-4o is ∼100% format-valid with surface-form
drift.
Mechanism: outcome-only reward fires
only on EM-match; with Lsig producing identical
[] responses on most early-exploration calls
and Lprior giving no schema bias, the gradient
never reaches the format-keeping subspace before
tail thinness drives the policy into low-entropy
degeneracy. The R-binary-SR control rules out our
hyperparameters as the cause; collapse is intrinsic
to outcome-only reward on this interface.
Mode 2: Verify-Then-Answer Goodhart (R-
stepwise).
R-stepwise reaches EM=32.5% with
CvT=0.03% (1/3531) — one trajectory of 3,531
actually grounds its answer in a tool response.
Tools/Q is 1.0 and 100% of those calls are
get_tail_relations, the only verb that
never returns empty: tool calls are ritualistic, the an-
swer is generated from parametric memory. Mech-
anism: the 4-component verifiable-step reward in-
centivises the easier component (call a tool that sat-
isfies a structural existence check) over the harder
one (consume the tool’s output) — a tool-free short-
cut (component-gaming Goodhart, cf. Gao et al.,
2023); unlike RLHF proxy decorrelation, here the
proxy-gold correlation r=0.95–0.97 is maintained
throughout training.
Falsification via Pass@16
with-vs-without-tools: R-stepwise’s gap is −0.4 pp
(Figure 2) — even with 16 attempts and tool ac-
cess the policy does not solve more questions than
parametric sampling; tools are decorative.
Mode 3: Format Drift Collapse (R-toolverbs,
late stage).
R-toolverbs briefly succeeds:
at
step 100 the policy reaches EM=32.2% with
CvT=3.03% (Tools/Q=2.30) — the first reward
design with non-trivial grounded retrieval.
By
step 150 <search> tags drift inside <think>
tags; by step 200 tool calls stop being parsed; by
step 250 EM falls to ∼0% in a repetition loop.
Mechanism: R-toolverbs rewards tool-type diver-
sity but anchors no output format; under GRPO’s
KL-loose configuration, format conventions drift
from the SFT prior, the executor cannot parse
drifted tags, the reward signal disappears, and
the policy converges to a low-entropy attractor.
This is not an Lsig failure (early-step trajectories
do retrieve) but a format-anchor absence inter-
acting with Llang.
Resolution: raising KL 5×
to 0.25 (R-toolverbs·KL) extends the stable win-
dow to step 400+. A fixed-reward KL ablation
(kl ∈{0.001, 0.005, 0.01, 0.05, 0.25}) separates
the two: collapse is non-monotonic in KL — only
kl=0.005 collapses by step 400, while 0.001, 0.01,
and 0.25 stay stable — so Lsig silent-failure, not
KL-tether, is the unified mechanism.
