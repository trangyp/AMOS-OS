Abstract
The geometric congruence problem is a fundamental building block in many computer vision
and image recognition tasks. This problem considers the decision task of whether two point sets
are congruent under translation and rotation. A related and more general problem, geometric
hashing, considers the task of compactly encoding multiple point sets for efficient congruence
queries. Despite its wide applications, both problems have received little prior attention in space-
aware settings. In this work, we study the two-dimensional congruence testing and geometric
hashing problem in the streaming model, where data arrive as a stream and the primary goal is
to minimize the space usage.
To meaningfully analyze space complexity, we address the underaddressed issue of input
precision by working in the finite-precision rational setting: the input point coordinates are
rational numbers of the form p/q with |p|, |q| ≤U.
A main result of this paper is a logarithmic-space randomized streaming algorithm for a
stronger variant of congruence testing, which we call congruence identification. On the input of
two n-point multisets with U-rational coordinates, the task is to decide whether the two sets are
congruent and, if so, to recover a valid transformation. We obtain a 3-pass randomized streaming
algorithm for this problem using O(log n(log U + log n)) space.
Using the congruence identification algorithm as a building block, we obtain a constant-pass
space-efficient streaming algorithm for geometric hashing. For a collection of n-point query sets
S1, . . . , Sm ⊆Q2 with rational precision U, we give a 6-pass O(m log n(log n+log U+log m))-space
randomized streaming algorithm that outputs a hash function of length O(log n + log U + log m).
Our key technical tool for achieving space efficiency is the use of complex moments. While
complex moment methods are widely employed as heuristics in object recognition, their effective-
ness is often limited by vanishing moment issues (Flusser and Suk [IEEE Trans. Image Process
2006]). We show that, in the rational setting, it suffices to track only O(log n) complex moments
to ensure a non-vanishing moment. This provides a sound theoretical guarantee for recovering
a valid rotation in positive instances, thereby overcoming the central difficulty in congruence
identification.

Introduction
Geometric congruence is a classical problem with broad use in various areas such as computer vision
and image recognition. The basic setup of the geometric congruence problem consists of two point
multisets A, B ⊆Dd of size n each, where D ⊆R. Multiple occurrences of the same point are
allowed within each set[1]. Two variants of the problem are considered in this work:
• In the congruence testing problem (denoted by CongTestn,D,d), the goal is to determine whether
there exists a rotation ρ : Rd →Rd and a translation t ∈Rd such that a 7→ρ(a) + t defines a
bijective map from A to B that preserves multiplicities, in which we say that A is congruent
to B via ρ and t.
• In the congruence identification problem (denoted by CongIdenn,D,d), the goal is to retrieve a
possible pair of ρ and t if A and B are congruent, and output ⊥otherwise.
It is clear that congruence identification is a stronger variant compared to congruence testing. We
make remarks on two simplifications. First, if the input sizes are not fixed to n, we track the
cardinalities of A and B and immediately reject when they differ. Second, allowing reflections does
not increase the difficulty: any such congruence has the form B = ρ(σ(A)) + t, where ρ is a rotation,
t is a translation, and σ is either the identity I or a fixed reflection J [Aku98]. Therefore, we simply
try both choices of σ and run our algorithm in parallel without affecting asymptotic complexity.
We study the geometric congruence problem allowing multiplicities, which in particular subsumes
the integral-weight geometric congruence problem. This framework captures more realistic settings,
such as determining whether two colored pixelated objects are congruent.
Generalizing the congruence testing problem of deciding whether two point sets are congruent,
geometric hashing approaches from the perspective of data structure, with a focus on efficient query
processing over multiple point sets. Formally, the input of the geometric hashing problem (denoted
by GeomHashm
n,D,d) consists of m point multisets (also called query sets) A1, . . . , Am ⊆Dd of size n
each. The goal is to output a congruence hash function H : [m] →{0, 1}s (with high probability).
A congruence hash function should satisfy that for any i, j ∈[m], H(i) = H(j) if and only if Ai
and Aj are congruent. Apart from the (time or space) complexity required to generate the hash
function, we also aim to minimize the hash length s in order to support efficient comparison queries.
1.1
Geometric Congruence Algorithms in RAM Model
The time complexity of the geometric congruence problem has been extensively studied in the RAM
model. In two dimensions, Manacher [Man76] gives an O(n log n)-time algorithm by sorting the
points by angle and performing a cyclic string matching. In three dimensions, Atkinson [Atk87]
achieves the same O(n log n) bound using the closest-pair structures. In four dimensions, Kim and
Rote [KR16] give an O(n log n) algorithm. For d ≥4, Akutsu [Aku98] devises an O(n(d−1)/2 log n)-
time randomized algorithm for d dimensions based on the birthday paradox.
Compared to congruence testing, geometric hashing has received less attention from the worst-
case algorithmic viewpoint, but it is widely applied in the computer vision literature, see for example
[WR97]. While closely related to congruence, geometric hashing places additional emphasis on

1.2
Streaming Model and Limitations of Prior RAM-Model Algorithms
In this work, we consider geometric congruence in the streaming model. In this model, data arrive
sequentially in an adversary order. A streaming algorithm scans the stream forward for one or
more passes while using limited space for storage and computations. Two common variants are the
insertion-only model, where elements are only inserted, and the turnstile model, where elements
may be inserted or deleted.
All the aforementioned RAM-model approaches do not extend efficiently to the streaming model:
sorting already requires Ω(n) space [MP80], and finding the closest pair cannot be done in sublinear
space as shown in Appendix C. There is also a bit-complexity issue that the Real-RAM model
hides: even before worrying about Ω(n) streaming lower bounds, the intermediate values used
by RAM-model routines may not be representable in polylogarithmic space. For example, the
centroid c = 1

U-rational, so “centering” already breaks the intended space bound if we implement it faithfully.
This becomes a direct obstruction for geometric hashing, since a hash must be a finite output,
without a finite-precision representation, hashing exact reals is not well-defined and cannot be
stored or compared within polylogarithmic space. Recognizing the fundamental obstacle of using
RAM-model techniques in designing polylogarithmic streaming algorithms, we shift our attention to
moment-based approaches.
Moment-based methods were introduced to image analysis in the classical work of Hu [Hu62], who
derived seven algebraic combinations of geometric moments that remain invariant under translation,
rotation, and scaling. Since then, moment invariants have been applied in various recognition and
matching tasks due to their computational simplicity and memory efficiency, including aircraft
silhouette identification [DBM77], scene matching [WH78], and template matching under rotation
[Gos85]; see also the survey [PR92] and the references therein.
As mentioned above, basic arithmetic on bounded-precision rationals can already cause substan-
tial precision blowups. Our main result is that, despite these complications, congruence identification

It has long been observed in the computer vision community that moment-based methods

classification when the shape catalogue is large, and is arguably overkill for mere congruence testing.

Real Register Model
In this section, we give a 2-pass deterministic streaming algorithm for a variant of the two-dimensional
congruence identification problem assuming perfect-precision storage. This idealized algorithm forms
the theoretical basis for our bounded-precision rational version, even though it does not address the
practical streaming space constraints.
In the real register model, each rational value is stored in a real register with no precision
loss, and each register counts as a single unit of space regardless of the magnitude of the value it

Rational Register Model
In this section, we present the algorithm for the two-dimensional congruence identification problem
in the rational register model, where the inputs are finite-precision rational numbers. The core of
this section is to address the precision issues neglected in the real register model. Note that although
the algorithm in this section is randomized, randomness comes only from the choice of the prime p
(and the induced map φp) and from the randomized equality testing used for fingerprinting.
4.1
Precision Issues in Adopting the Real-register CongSList Algorithm
The precision issue poses an obstacle to applying the real-register algorithm from the very first step:
centroid computation. As shown in Observation 2.1, the sum of n U-rational numbers may require
precision up to nUn. Consequently, the centroid of n points in Q⟨U⟩[i] is guaranteed to be at most
nUn-rational complex, which requires a prohibitive amount of space, O(n log U + log n), to store
with full precision. The higher complex moments require even higher precision.
The next natural approach is to group points that are approximately equidistant from the
imprecise centroids. However, the precision required to identify points exactly on the same radius
is prohibitively high: perturbing the n-th roots of unity to rational coordinates can produce a
set where all distances from the centroid are distinct yet arbitrarily close. Any points mistakenly
collected from different orbits would violate the equal-radius assumption necessary for Theorem 1.5,
consequently invalidating the moment calculations.
The key insight for our rational-register algorithm is that the equal-radius check in recentred
moment calculations reduces to testing whether the distance of a point to the centroid equals a
given value, which can be done efficiently in Fp[i]. The modulo-p hashing approach also allows us to
reconstruct candidate rotations with p chosen from a moderate range. While the hash performs
poorly for individual higher-order complex moments due to a high collision rate (by the pigeonhole
principle), it is the quotients of moments that are relevant, which enjoy good precision guarantees.

precision, can be recovered successfully with high probability.

Rational Congruence Identification in Three Dimensions
An immediate obstacle to extending our two-dimensional algorithms to R3 is the absence of a direct
analogue of the correspondence between R2 and C. A dimension-reduction approach might suggest
using a birthday-paradox argument to sample a matched pair (a, b) ∈A × B with ρ(a) + t = b
and project the instance onto a plane, thus reducing to the two-dimensional case and achieving
O(√n log n(log n + log U)) space usage. However, the non-vanishing moment guarantee fails for a
plane in Q3: for example, consider
S = {(7, 0, −7), (0, −7, 7), (5, −8, 3), (−7, 7, 0), (−5, 8, −3)}.
Each u ∈S satisfies ∥u∥2 = 98 and lies on the plane x + y + z = 0, yet P
u∈S u = 0.
Employing an enhanced birthday-paradox method inspired by [Aku98], we design a 6-pass
randomized streaming algorithm for CongIdenn,Q⟨U⟩,3 with sublinear space complexity.
Theorem 6.1. CongIdenn,Q⟨U⟩,3 can be solved by a 6-pass randomized streaming algorithm using
O(n5/6 log4 U log n) space with probability at least 2/3.

While the full algorithm and its correctness are deferred to Appendix F, we provide an overview
here. The main goal of our algorithm is to produce two families of non-coplanar anchor 3-tuples,
PA ⊆A3 and PB ⊆B3, each of size O(n5/6), to test candidate transformations via the alignment
of anchor points. The first anchor point is obtained by collecting points at a fixed distance from

centroid or points on a fixed-radius sphere according to Observation F.1. The second and third
points are selected via a birthday-paradox argument. Once PA and PB are obtained, the algorithm
checks if there exists (α, β) ∈PA × PB such that (α, β) is a matched pair that aligns the sets A
and B. The existence can be verified efficiently due to the size guarantees of PA and PB, and
the alignment can be checked using Karp–Rabin hashing. By the birthday-paradox argument
(Lemma F.2), such a matched pair exists with high probability whenever A and B are congruent.

Hardness of the Exact Closest-pair Problem in Streaming
It is a folklore result (see e.g. [Sha07]) that the closest-pair problem reduces to set-disjointness in
communication complexity. We present the reduction here for completeness.
Suppose Alice and Bob each hold a vector A, B ∈{0, 1}n. We construct a stream of points by
inserting the point (2x, 0) whenever Ax = 1 for each x ∈[n], followed by inserting the point (2x, 1)
whenever Bx = 1 for each x ∈[n].
If there exists an index x with Ax = Bx = 1, then the two points (x, 0) and (x, 1) in the stream
have distance exactly 1. If the sets are disjoint, then every pair of points is separated by a distance
of at least 2. Thus, deciding whether the closest-pair distance is 1 or at least 2 solves set disjointness.
Since set disjointness requires Ω(n) bits of communication even in the randomized setting, any
randomized streaming algorithm that finds the closest pair exactly also requires Ω(n) space.

Communication Complexity
Communication complexity forms a core toolkit for establishing lower bounds in streaming models.
In this section, we review the key aspects relevant to this work and refer readers to [KN96, Rou16]
for additional background.
For a two-player communication problem F : X × Y →{0, 1}, the randomized communication
complexity with error δ (denoted Rcc
δ (F)) is the minimum cost among all private-coin protocols for
F that err with probability at most δ on every input. We omit δ when using the canonical value
δ = 1/3.
One of the most well-studied problems in communication complexity is the equality function
EQn : {0, 1}n × {0, 1}n →{0, 1}, defined by EQn(x, y) = 1 iff x = y. The following lower bounds
can be found in any communication complexity textbook.
Fact E.1 (e.g. [KN96]). Rcc(EQn) = Θ(log n).
In most communication-complexity literature and streaming applications, public-coin and private-
coin randomized models are treated as essentially equivalent. By Newman’s theorem [New91], the
communication complexities of an n-bit function in these two randomness models differ by at most
O(log n). Even though this logarithmic overhead is usually inconsequential, this distinction becomes
significant for our reduction to EQn, where the public-coin communication complexity is O(1) while
the private-coin complexity is O(log n). Due to the space-aware nature of the streaming model,
private randomness is the more appropriate randomness setting. The following lemma shows that
the canonical reduction in fact yields a private-coin communication protocol.
Lemma E.2. Suppose a streaming problem P is reduced from a communication problem F. If
Rcc(F) ≥c, then any p-pass randomized algorithm solving P requires Ω(c/p) space.
Proof. For an input (x, y) to F, generate the data stream for P based on the reduction by placing
all x-dependent items first, then all y-dependent items, and lastly any input-independent items.
Notice that no items in the data stream can depend on both x and y. Now Alice and Bob can
create a communication protocol Π for F by simulating a streaming algorithm A for P as follows.
In a pass, Alice first runs A until all x-dependent items are exhausted, and she sends the current
memory state σ to Bob. Upon reception of σ, Bob resumes the streaming algorithm A on the rest
of the data stream, and he sends the current memory state σ′ to Alice at the end of the pass.
If A is a p-pass s-space algorithm, the above communication protocol involves (2p −1) rounds
of communications and thus the total communication cost is at most (2p −1)s. Moreover, when

simulating the streaming algorithm, each random bit is revealed only to the currently active player.
Thus, every use of randomness in A can be treated as private randomness in Π. In fact, A may
need to store information from the random strings for later use by the same active player during
the simulation, which can only further reduce the communication cost of Π. Now, the randomized
communication complexity lower bound of c implies that (2p −1)s ≥c, hence s = Ω(c/p).
