Abstract
Recent work showed how to construct nearest-neighbor graphs of
linear size, on a given set P of n points in Rd, such that one can answer
approximate nearest-neighbor queries in logarithmic time in the spread.
Unfortunately, the spread might be unbounded in n, and an interesting
theoretical question is how to remove the dependency on the spread.
Here, we show how to construct an external linear-size data structure
that, combined with the linear-size graph, allows us to answer ANN
queries in logarithmic time in n.
1. Introduction
The nearest neighbor search problem, also known as proximity search, is a
fundamental challenge in computing. It involves preprocessing a finite set of
points P endowed with a metric d such that one is able to quickly answer
(numerous) proximity queries. A single such query asks for the point in P

cause a linear-factor blowup in the query time.
Our work studies the fundamental question of whether one can effi-

Greedy permutation and NN graphs.
Har-Peled et al. [

greedy permutations to construct a navigable graph. Such a greedy permu-
tation can be computed using a k-center clustering algorithm. Specifically,
the clustering algorithm of Gonzalez [

point from the set P and iteratively selects the point maximizing the distance

plete set generates a specific ordering referred to as the greedy permutation
[ Har11 ]. Notably, provided that the dimension of P is constant (in Euclidean
or doubling metrics), this permutation can be constructed in O(n log n) time
[ HM06 ], where n = |P|.
The algorithm of Har-Peled et al. [

tion p1, . . . , pn of P. The distance of pi to the prefix P[i −1] = {p1, . . . , pi−1}

How to handle the spread.
For a set P in a metric space, its spread
is Ψ = ∇(P)/cp(P). It is the ratio between the longest distance and the
shortest distance between any two points of P. In practice, the spread Ψ tends
to be small, especially if the data is high-dimensional. Thus, logarithmic
dependency in the spread is acceptable in practice. Nevertheless, because
the spread can potentially be unbounded, obtaining a dependency in log n
instead of log Ψ remains a natural and non-trivial challenge, as the usage of
graph-based search for ANN is still not well understood.
Additional background
Doubling metrics.
The doubling dimension of a metric space [
 KL04 ]
provides a generic way to measure the dimension of the data. It is a proxy
for our understanding of dimension, as Rd has doubling dimension O(d);
see

low-dimensional Euclidean space can also be used in spaces with bounded
doubling dimension; see Har-Peled and Mendel [  HM06 ].
Hierarchical spanning trees (HST).
A HST is an embedding of a finite
metric space into a tree, in a way that approximates the metric.
Such
trees can provide an easily computable, but low-quality, approximation to
the original metric. They are also used to provide a O(log n)-distortion, in
expectation, using Bartal’s embeddings [ Bar96 ,
 Bar98 ,
 FRT04 ].

Result I: Reduction to the bounded-spread case.
As a first step, we
show a general reduction from the general case to the bounded-spread case.
Our reduction combines three data structures: (i) a data structure that can
answer nO(1)-ANN queries quickly, (ii) a low-quality HST of the input point
set P, and (iii) a data structure that can perform (1+ε)-ANN queries quickly
for the case where the input has polynomially-bounded spread. Our final
result is to reduce the query cost to (essentially) performing a single query
to each of the data structures mentioned, each with no dependency on the
spread, while incurring only a O(log n) blowup in the space.
Indyk and Motwani [
 IM98 ] provided a deceptively similar reduction
(later simplified in the journal version [
 HIM12 ]).
The difference is that
their underlying building block is a data structure that can answer (approx-
imate) near-neighbor queries: For a query q (and a fixed prespecified r),
the near-neighbor query asks to decide if d(q, P) < r or d(q, P) > r. This
(approximate) near-neighbor data structure is assumed to work even if the
diameter of P is unbounded, where P is the input set. It is not clear how
to implement this near-neighbor data structure when using graph search,
and this reduction does not seem to apply in our settings. Interestingly, our
new reduction can be used as a replacement for the reduction of Indyk and
Motwani [ IM98 ,
 HIM12 ], at least in the Euclidean case.
Given a query point q, we use an nO(1)-ANN data structure to obtain a
rough estimate p of the nearest point. Although inaccurate, this estimate
tells us the right “resolution” to search at. To make use of this information,

we construct a family of nearest neighbor graphs at different resolutions, each
with polynomial spread, that can answer ANN queries in logarithmic time
in n. We use an HST to both select the relevant points at each resolution
and cluster them into spread-bounded subgraphs. We then use off-the-shelf
algorithms to construct an ANN graph for each such subgraph, and with
the help of the HST, we identify the correct graph in which to perform the
ANN query. The space for this data structure is (roughly) Θ(n log n); see
 Theorem 4.15 for details.
Result II: Optimal space.
To remedy the suboptimal space of the above
construction, we aim to overlay the spread-bounded subgraphs into a single,
universal search graph that avoids the overlap these subgraphs have. It turns
out that the search graph of Har-Peled et al. [
 HRR26 ], which is based on
computing a greedy permutation of the point set, already provides us with
this universal graph. Unfortunately, the search time on this graph depends
on the spread and can be quite long. This inefficiency is because the search
goes through many of the resolutions present in the point set. Our strategy
is to use an external data structure to skip directly into the latter part of
the search path, which is already close to the desired answer, and do the
search from there, thus speeding up the query time.
As in our general reduction, we use an nO(1)-ANN data structure to tell
us the right “resolution” to search at. We can use an HST to find the first
point in the greedy permutation that lies within this resolution. We then
take a further step back in the permutation by means of a “reverse tree” to
ensure that the searched radius is large enough. From there, we use a slightly
modified version of the search of [
 HRR26 ] to get (1 + ε)-close to the nearest
neighbor in a number of steps that depends only on ε and the number of
points. Putting things together, we obtain a linear-size nearest neighbor
graph that, together with the additional external linear-size data structure,
can answer queries in logarithmic time in n. See
 Theorem 5.13
 for a precise
statement.
Parts of our analysis of the new algorithm require a better understanding
of the original algorithm of Har-Peled et al. [

analysis is cleaner, more robust, and provides a better insight into why the
graph search approach based on greedy permutations works.

2. Background
Here we include standard definitions and background we need for the paper.

2.1. Metric spaces
Definition 2.1. A metric space is a pair (X, d), where X is a set and
d : X × X →[0, ∞) is a metric on X. The metric satisfies the conditions:
(i) d(x, y) = 0 if and only if x = y, (ii) d(x, y) = d(y, x), and (iii) d(x, y) +
d(y, z) ≥d(x, z) (triangle inequality).
Definition 2.2. For a real interval [α, β], its spread is the ratio β/α. For a
set X ⊆R, its spread is the spread of the interval [min X, max X].
Definition 2.3. For a set P ⊆X, its diameter is ∇d(P) = maxx,y∈P d(x, y).
Its closest pair distance is cp(P) = minx,y∈P:x,y d(x, y). The ratio be-
tween these two quantities is the spread: Ψ(P) = ∇(P)/cp(P).
Definition 2.4. For a point x ∈X and a radius r ≥0, the ball of radius r
centered at x is the set b(x, r) = {z ∈X | d(x, z) ≤r} .
Definition 2.5. For a metric space X, the minimum λ, such that any ball in
the space can be covered by at most λ = λ(X) balls of half the radius, is the
doubling constant of the space. The quantity d = ⌈log2 λ⌉is the doubling
dimension of the metric space.

2.2. Packing/covering
Definition 2.6. For a set P, and a radius r, its r-expansion is the set
P ⊕r = ∪p∈Pb<r(p), where b<r(x) = {z ∈X | d(x, z) < r} .
A subset X ⊆P is an r-cover of P if P ⊆X ⊕r. By comparison, a set
X ⊆P is r-separated if cp(X) ≥r.
Definition 2.7. Consider a metric space (X, d), and a set P ⊆X. A set
N ⊆P is an (r, R)-packing for P if N is an R-cover of P, and it is also
r-separated. The set N is an r-packing if it is an (r, r)-packing.
To compute a packing, one can iteratively insert points from P into the
current set, provided that the distance to the existing points remains ≥r,
terminating only when no eligible candidates remain. In specific scenarios,
more efficient algorithms are known [ HR15 ,
 EHS20 ].
2.3. Nearest neighbor
Definition 2.8. For a set P in a metric space (X, d) and a query point
q ∈X, the nearest neighbor (i.e., closest point) to q in P is denoted by
nn(q) = nnP(q) = arg minp∈P d(q, p). The distance between q and its nearest
neighbor in P is ℓ⋆= d(q, P) = minp∈P d(q, p).
Definition 2.9. For ε ∈(0, 1), and a query point q ∈X, a point p is a (1+ε)-
ANN (approximate nearest neighbor) for q if d(q, p) ≤(1 + ε)d(q, P).
2.4. Hierarchically well-separated trees (HSTs)
Definition 2.10. Let P be a set of elements, and let H be a tree whose leaves
are the elements of P. The tree H defines a hierarchically well-separated
tree (HST) on P if for each vertex u ∈H there is an associated label Υu ≥0,
such that Υu = 0 if and only if u is a leaf of H. Furthermore, the labels are
such that if a vertex u is a child of a vertex v, then Υu ≤Υv. The distance
between two leaves x, y ∈H is defined as dH(x, y) = Υlca(x,y), where lca(x, y)
is the least common ancestor of x and y in H, which is a metric on P.
Usually, an HST is built over a finite metric space X = (P, d). We use
the convention that HSTs are always expansive: For all x, y ∈P, we have
d(x, y) ≤dH(x, y).
Definition 2.11. For a parameter t ≥1, the HST H for P is a t-HST (t-
approximate HST) if d(x, y) ≤dH(x, y) ≤td(x, y), for all x, y ∈P.

3.1. Greedy permutation
In the exact greedy permutation, one picks any arbitrary first point p1 ∈P.
In the ith step, for i > 1, the prefix P[i −1] = {p1, . . . , pi−1} was already
computed, and one computes the radius
δi =
max
p∈P\P[i−1] d(p, P[i −1]).
(3.1)
The next point in the exact greedy permutation is the point pi that realizes
the quantity δi (i.e., the furthest point in P from P[i −1]). We continue this
process until we get a full ordering of the points of P. The radii in the greedy
permutation are monotonically decreasing: δ1 ≥δ2 ≥· · · ≥δn.
Definition 3.1. Given a finite metric space X = (P, d) and some κ ≥1, a
κ-greedy permutation is an ordering p1, . . . , pn of the points of P, with
associated radii δ1 ≥δ2 ≥· · · ≥δn, such that:
(A) The point p1 is an arbitrary point of P, and δ1 = maxp∈P ∥p −p1∥.
(B) For all i ∈JnK = {1, . . . , n}, the i-prefix P[i] = {p1, . . . , pi} of P forms
a (δi, κδi+1)-packing of P (where δn+1 = 0).
The naive approach to computing an exact greedy permutation requires
O(n2) time, as it must repeatedly identify the furthest point to determine
the next point in the sequence. However, for a set P of n points in Rd (or
in a metric space of bounded doubling dimension), Har-Peled and Mendel
[ HM06 ] show that a κ-greedy permutation can be computed in O(n log n)
time, for κ = 1 + 1/nO(1). Similarly to [
 HRR26 ], we assume that the exact
greedy permutation is available for the sake of exposition.
3.2. Graph-based search for ANN
Search procedure.
Consider a directed graph G = (P, E) defined over
the set of n points P in some metric space. To compute the ANN (or k
closest such points) for a query point q, we start from an arbitrary start
vertex s. In a Dijkstra-like fashion, we extract the point in the queue that
is closest to the query q and add all its unvisited outgoing neighbors to
the queue. Central to this approach is a greedy pruning step: the queue is
constrained by retaining only the L candidates nearest to q, where L is some
prespecified parameter. The procedure concludes once the priority queue is
empty, returning the k nearest elements found within the set of all visited
vertices as the approximate solution to the query q.

Greedy routing.
A more straightforward search strategy begins at an
arbitrary vertex and iteratively steps to an adjacent vertex that is closer to
the query point, continuing until it reaches what is typically an approximate
local optimum. There are two standard forms: (A) An “impulsive” variant
proceeds immediately as soon as a significantly closer neighbor is found.
(B) A more “mature” variant moves to the closest among all neighboring
vertices. Indyk and Xu [
 IX23 ] demonstrated that when the underlying graph
is O(1/ε)-navigable, this procedure computes a (1 + ε)-ANN.
3.3. A NN graph via greedy permutation
Here we describe in more detail the construction of Har-Peled et al. [

Given a set P of n points in Rd and a parameter ε ∈(0, 1/2), the algorithm
first computes the greedy permutation of P. Specifically, let P = {p1, . . . , pn}
be the ordering of the points by the greedy permutation. One also computes
for each point pi its friends list Fi.
Definition 3.2. The friends list of pi is the set
Fi = P[i −1] ∩b(pi, cδi/ε)
(3.2)
of all points of P[i −1] = {p1, . . . , pi−1} that are at distance at most cδi/ε
from pi, where c = 26 (the original paper set c = 4, but our variant needs a
larger value for the analysis to go through).
In spaces with constant doubling dimension, the algorithm computing the
greedy permutation can also compute the friends list for all points [

Next, the algorithm builds a directed graph G = (P, E), with the edges
being
E = {pj →pi | pj ∈Fi, for i = 1, . . . , n} .
In the constructed graph, the list of outgoing edges Ev from a vertex v is
sorted in increasing order by the index of the destination. This can be done
by always adding the outgoing edges at the end of this list.

The search is done using the “impulsive” greedy
routing; see

4. Approximate nearest neighbor via HST
The input is a set P of n points in a metric space with doubling constant λ
(which we treat as a constant), and a parameter ε ∈(0, 1/2).
4.1. Fast (1 + ε)-ANN queries via HST if one is lucky
The first step in our analysis is to resolve ANN queries when the nearest
neighbor is “easy” to compute using the available machinery. Intuitively, one
can compute a low-quality ANN quickly, and if the data is distributed in the

Proof: This is well known, and we provide a proof for the sake of completeness.
We sketch a simple solution that is suboptimal, but good enough for our
purposes. Using DFS numbering (i.e., in-order and post-order numbers stored
at each node), and storing these numbers in H, one can decide in constant
time whether or not a node v in H is an ancestor of a node v ∈H. We can
assume that each node of H has only two children (by splitting higher-degree
nodes into a chain of nodes of degree 2). The HST H has size O(n), and being
a tree of maximum degree 2, it has an edge u →p(u), such that its removal
breaks the tree into two trees H\u and Hu, where Hu is the subtree rooted at
u, such that each of these trees have at most 2
3 fraction of the vertices of H.
We build the query tree D as follows — it stores u, its label, its parent, and
its parent label. It then computes the query tree for H\u and Hu recursively
and attaches them to the root node of D.
The query is answered by traversing down D. The current node x in D
corresponds to a subtree Hx of H that contains the desired edge. Specifically,
the query process always has a leaf lx of Hx that the desired edge lies on
the path to the root from lx. Now, the algorithm checks whether the edge
u →p(u) stored at x is the desired edge — this happens if u is an ancestor of
lx (since both nodes appear in H, this can be answered using the DFS numbers
computed for H), and r is in the range of the labels of u and its parent. If
this is the case, then the query returns u as the desired node. Otherwise, the
query process needs to continue the query either downward, if the current
