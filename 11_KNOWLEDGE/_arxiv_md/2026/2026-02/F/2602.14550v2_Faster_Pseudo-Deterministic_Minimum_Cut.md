Abstract
Pseudo-deterministic algorithms are randomized algorithms that, with high constant prob-
ability, output a fixed canonical solution. The study of pseudo-deterministic algorithms for the
global minimum cut problem was recently initiated by Agarwala and Varma [ITCS’26], who
gave a black-box reduction incurring an O(log n log log n) overhead. We introduce a natural
graph-theoretic tie-breaking mechanism that uniquely selects a canonical minimum cut. Using
this mechanism, we obtain: (i) A pseudo-deterministic minimum cut algorithm for weighted
graphs running in O(m log2 n) time, eliminating the O(log n log log n) overhead of prior work
and matching existing randomized algorithms. (ii) The first pseudo-deterministic algorithm for
maintaining a canonical minimum cut in a fully-dynamic unweighted graph, with polylog(n) up-
date time and ˜O(n) query time. (iii) Improved pseudo-deterministic algorithms for unweighted
graphs in the dynamic streaming and cut-query models of computation, matching the best
randomized algorithms.

Introduction
The study of pseudo-deterministic algorithms was initiated by [GG11]. Such algorithms are ran-
domized, yet output a fixed solution with high constant probability. Formally, we call a randomized
algorithm A pseudo-deterministic if for every input x, there exists a canonical output s(x) such
that Pr [A(x) = s(x)] ≥2/3. Such algorithms are often useful when a consistent output is desired,
for example when interacting with an adversary or when the algorithm is used as a building block
in a larger algorithm. These attractive properties have motivated the study of pseudo-deterministic
algorithms in various contexts, including matching problems, matroid intersection, undirected con-
nectivity, and more [GG17, OS17, GL19, AV20, GG21, CLO+23].
The study of pseudo-deterministic algorithms for the global minimum cut problem was only
initiated recently by [AV26]. Their approach is based on the isolation lemma of [MVV87], and the
strategy for its derandomization of [GG17]. Using this, they show that given a weighted graph on
n vertices and m edges, it suffices to make O(log n log log n) calls to any randomized minimum cut
algorithm in a black box manner to find a canonical minimum cut with high probability. Applying
this approach to the O(m log2 n) time randomized minimum cut algorithm of [GMW20] yields an
O(m log3 n log log n) time algorithm, which is faster than current deterministic algorithms that use
O(m logc n) time for some large constant c [HLRW24].1
In contrast, our approach is based on a graph theoretic tie-breaking mechanism that ensures the
uniqueness of the canonical minimum cut. This approach offers two main advantages. First, it yields
a faster pseudo-deterministic minimum cut algorithm running in O(m log2 n) time by modifying
the algorithm of [GMW20] to account for the tie-breakers.
Second, our algorithm can also be
applied to find the same canonical minimum cut in a contraction of the original graph.2 We exploit
this property to design the first pseudo-deterministic fully-dynamic minimum cut algorithm. This
algorithm is also adversarially-robust, as pseudo-deterministic algorithms are inherently resistant
to adaptive updates.

Pseudo-Deterministic Minimum Cut
Our main technical contribution (Theorem 1.1) is a
new randomized algorithm that finds the lexicographically-first minimum cut in O(m log2 n) time.
The algorithm is actually more general, as it allows for general vertex priorities to be used as a
third tie-breaker instead of using P(S) = |S|. Given vertex priorities P : V →N, denote the weight
of a set of vertices S as P(S) = P
v∈S P(v). Using vertex priorities allows us to use our minimum
cut algorithm in the fully-dynamic setting, as we explain in the next section. Note that setting all
vertex priorities to 1 is equivalent to finding the lexicographically-first minimum cut.
Lemma 1.7. There exists a randomized algorithm that given a graph G = (V, E) a designated
source vertex s, an ordering h : V \ {s} →[n −1] and vertex priorities P : V →N, returns a cut
S ⊆V \ {s} that minimizes the tuple (cutG(S), LN(S), P(S)). The algorithm runs in O(m log2 n)
time and succeeds with high probability.
Our algorithm is based on the O(m log2 n) time algorithm of [GMW20]. We modify the algo-
rithm to use our tie-breakers and find the lexicographically-first minimum cut, without increasing
the running time of the original algorithm.
Pseudo-deterministic fully-dynamic algorithm.
Our pseudo-deterministic fully-dynamic min-
imum cut algorithm (Theorem 1.2) is based on [HKMR25]. Their main result is a data structure
that can be either deterministic or randomized, depending on the known components used in its
construction. It supports edge updates, and upon request constructs a non-trivial minimum cut
sparsifier (NMC) of the current graph defined as follows.
Definition 1.8 (Non-Trivial Minimum Cut Sparsifier (NMC)). A non-trivial minimum cut sparsi-
fier (NMC) of a graph G = (V, E), is a contraction H = (VH, EH) of G such that for every S ⊆V
that is a non-trivial minimum cut in G, it holds that cutH(S) = cutG(S).6 Here, a cut S ⊆V is
called non-trivial if |S| ̸= 1, n −1.
Our dynamic algorithm first fixes some source vertex s ∈V and an ordering h : V \{s} →[n−1]
of the other vertices. It then uses the data structure of [HKMR25] to maintain an NMC of the
dynamic input graph G, alongside the first vertex in the ordering with minimum degree in G.
When queried for a minimum cut, the algorithm constructs the NMC and runs our algorithm of
Lemma 1.7 on it to find a lexicographically-first minimum cut. Finally, the algorithm compares
the corresponding cut in G to the trivial cut given by the first vertex with minimum degree in
G, and returns the lexicographically-first among the two. Notice that since all of our algorithms
provide high-probability guarantees, we can use a union bound to show that the algorithm re-
turns the canonical minimum cut with high probability against an adaptive adversary throughout
poly(n) updates and queries. We argue below that this cut corresponds to the lexicographically-first
minimum cut in the original graph.

We note that [HKMR25] also give an adversarially-robust fully-dynamic minimum cut algo-
rithm, but it is slower than ours. It uses a version of their NMC data structure that is deterministic
during edge updates, and leverages randomization only for constructing the NMC. Since the update
procedure is fully deterministic, it is robust to adaptive updates. Unfortunately, the deterministic
components lead update and query time of no(1), n1+o(1) respectively. In contrast, using an NMC
data structure that is randomized achieves an update time polylog(n) and query time ˜O(n). This
opens the algorithm to adversarial attacks, however we fix this issue using our pseudo-deterministic
minimum cut algorithm (applied on the NMC). The following theorem summarizes the randomized
data structure of [HKMR25] and using it we prove Theorem 1.2.
Theorem 1.9 (Theorem 1 of [HKMR25]). There is a fully-dynamic algorithm, that given as an

non-trivial minimum cut sparsifier (NMC) of G in ˜O(n) time with high probability. Furthermore,
the NMC has O(n/δ) vertices and O(n) edges, where δ is the minimum degree of G.

2.2
Link-Cut Tree
Our algorithm uses the link-cut tree data structure [ST83], which is a rooted tree with dynamic
edge costs that supports various operations in amortized logarithmic time. We assume that the
costs of the tree are on the vertices, by associating each edge’s with its lower vertex; this mapping
is bijective since the tree is rooted. Specifically, we use the variant presented in [GMW20].
Lemma 2.5 (Link-Cut Tree). A link-cut tree is a data structure that maintains a rooted tree T on
a fixed vertex set V with vertex costs, and supports the following operations in amortized O(log |V |)
time.
1. T.ADD(u, ∆): adds ∆to the cost of every vertex from u to the root (including u).
2. T.SUBTREE(u): returns the minimum cost vertex (and its cost tuple) in the subtree rooted
at u.
Note that our algorithms use lexicographically ordered tuple costs (x1, . . . , xk), and that link-cut
trees can support tuple costs without increasing time complexity.

Pseudo-Deterministic Minimum-Cut Algorithm
In this section we prove Lemma 1.7. We begin by giving an overview of the algorithm of [GMW20]
(which follows closely the algorithm of [Kar00]), and then proceed to explain how we modify it to
find the lexicographically-first minimum cut. We say that a cut k-respects a spanning tree T, if
the intersection between the edges of T and the those of the cut has cardinality at most k. The
algorithm of [GMW20] is composed of two main parts. First, it finds a packing of O(log n) trees
such that with high probability every minimum cut 2-respects at least one tree in the packing.
Theorem 3.1 (Theorem 3 of [GMW20]). There exists a randomized algorithm that, given a
weighted undirected graph G, in O(m log2 n) time constructs a set of O(log n) spanning trees T
such that with high probability every minimum cut 2-respects at least one tree in T.
After obtaining the tree packing, the algorithm uses an efficient dynamic program to find the
minimum cut that 2-respects every tree in the set, and finally it returns the minimum cut found
throughout its execution. Our main technical lemma is a modified algorithm for this second part,
which finds a lexicographically-first cut that 2-respects a given tree, rather than just any minimum
cut. This lemma immediately implies Lemma 1.7.
Lemma 3.2. There exists an algorithm that, given a spanning tree T of a graph G, a source vertex
s, and an ordering h : V \ {s} →[n −1], finds a lexicographically-first minimum cut that 2-respects
T in time O(m log n).
Proof of Lemma 1.7. Begin by constructing a tree packing T using Theorem 3.1. With high prob-
ability the lexicographically-first minimum cut of G 2-respects some tree in T by the guarantees of
the tree packing algorithm of [GMW20]. Therefore, applying Lemma 3.2 on every tree in T and
returning the lexicographically-first minimum cut among all cuts found, yields the lexicographically-
first minimum cut of the graph with high probability. Finally, the time complexity of the algorithm
is O(m log2 n) since we run Lemma 3.2 O(log n) times, and the time complexity of the tree packing
is also O(m log2 n).

The rest of the section is devoted to proving Lemma 3.2.
The algorithm for finding the
lexicographically-first cut that 2-respects the tree is divided into three cases - when it 1-respects
the tree, when it 2-respects the tree and the edges (e, e′) defining the cut are not on a path to the
root (independent case), and when it 2-respects it and the edges (e, e′) defining the cut are on some
path to the root (descendant case). It is straightforward to see that every cut that 2-respects the
tree falls into one of these cases. Note that the proof for the 1-respecting and independent cases are
relatively simple modifications of the algorithms of [GMW20], while the descendant case requires
a more substantial modification. Finally, throughout this section we root T at the source vertex s.
3.1
1-Respecting Cut Case
For the first case, the algorithm of [GMW20] finds cutG(S) for every cut S ⊆V that 1-respects
T, and then returns the minimum among them. Our modified algorithm additionally computes
the values LN(S), P(S) for each 1-respecting cut S, and returns the cut minimizing the tuple
(cutG(S), LN(S), P(S)). The following lemma immediately yields the main result of this section.
Lemma 3.3. The tuple (cutG(S), LN(S), P(S)) of every cut that 1-respects a given spanning tree
can be computed in time O(m + n).
Proof. Every cut S ⊆V that 1-respects the tree T is of the form v↓for some v ∈V \ {s}.
Therefore, P(S) = P(v↓) = P
u∈v↓P(u), which can be rewritten recursively as P(v↓) = P(v) +

Lemma 3.4 (Lemma 5.1 of [Kar00]). The values of all cuts that 1-respect a given spanning tree

Descendant Case
We say that a cut is a minimum descendant cut of u if it is of the form u↓\v↓for some descendant v
of u and has minimum value among all such cuts. Similarly, a lexicographically-first descendant cut
is a descendant cut S ⊆V of u minimizing the tuple (cutG(S), LN(S), P(S)). Finally, throughout
this section we abuse the notation by referring to vertices by their place in the ordering h, i.e. given
a cut S ⊆V we denote LN(S) = arg minx∈S h(x).
The main result in this section is an algorithm that finds a lexicographically-first descendant cut
for each u ∈V , extending the approach of [GMW20] with additional tie-breakers. The algorithm
of [GMW20] performs an Euler tour of the tree, and updates a link-cut tree T ′ on the same edges
as T after each step of the tour. When encountering the vertex u on the way down, the algorithm
finds the minimum descendant cut of u by calling T ′.SUBTREE(u). Our algorithm employs a
similar process, but maintains two link-cut trees T1, T2 that have the same edges as the spanning
tree T, each with a different cost tuple.
The first element of both cost tuples is calculated in

whether there exists a minimum descendant cut of u whose lexicographic number is LN(u↓), that
is it achieves the lowest possible lexicographic number of any descendant cut of u. It then updates
the edge costs of T2 to refine the search for the lexicographically-first minimum cut, and finds the
lexicographically-first minimum descendant cut by calling T2.SUBTREE(u).

3.3
Independent Case
In this section, we show how to find a lexicographically-first minimum cut defined by two indepen-
dent edges in the tree. The main result of this section is the following lemma.
Lemma 3.10. There exists an algorithm that, given a graph G = (V, E) with n vertices and m
edges, a spanning tree T of G, a source vertex s, and an ordering h : V \{s} →[n−1], finds the pair
of edges (e, e′) defining an independent cut S ⊆V minimizing the tuple (cutG(S), LN(S), P(S)).
The algorithm runs in time O(m log n + n log n).
The proof of the lemma uses the bipartite problem framework of [GMW20].
Definition 3.11 (The bipartite problem of [GMW20]). Given two trees T1, T2 with edge costs and
a list of non-tree edges L = {(u, v) : u ∈T1, v ∈T2} along with their costs, find a pair of edges
e ∈T1, e′ ∈T2 that minimize the sum of costs of e, e′ plus the sum of costs of edges in L crossing
the cut defined by e, e′. The size of the problem is defined as |T1| + |T2| + |L|.
11


## Page 13


Lemma 3.12 (Lemma 11 of [GMW20]). There exists an algorithm that given an instance of the
bipartite problem of size N finds the optimal solution in time O(N log N).
Lemma 3.13 (Lemma 10 of [GMW20]). There exists an algorithm that, given an edge-weighted
graph G with n vertices and m edges, a spanning tree T on the vertices of G, reduces finding a
minimum independent cut for every tree edge e to multiple instances of the bipartite problem, with
total size O(m) in O(m log n) time.8
We modify the reduction to use P(S) as a tie-breaker. This is achieved by changing the costs
of edges in the trees T1, T2 into tuples of the form (c, P(v↓)) where c is the original cost of the
edge and v is the lower vertex of the edge. Notice that the priority of the cut defined by (e, e′) is
exactly P(v↓) + P(v′↓) where v, v′ are the lower vertices of e, e′ respectively. Therefore, the second
component of the cost captures the total priority of the cut defined by the edges in the trees. In
addition, we modify the cost of edges outside the trees to (c, 0) since they do not define the priority
of the cut.
In order to calculate the modified weights efficiently, we use the fact that the trees T1, T2 are
composed of edges of the original tree T. Therefore, there are at most n −1 of them across all the
trees and their second component can be computed in O(n + m) time using Lemma 3.3. We are
now ready to prove Lemma 3.10.
Proof of Lemma 3.10. Begin by running the reduction of [GMW20] with the modification detailed
above. Notice that it is possible to modify the costs of all edges in each modified tree problem
by first updating the costs of the original tree edges, and then applying the reduction on the tree
with modified costs. The reduction still takes O(m log n) time as the modified edge costs can be
computed in O(n + m) time using Lemma 3.3. In addition, the total size of all bipartite problems
remains O(m) since we only modified the edge costs, and therefore they can be solved in O(m log n)
time by Lemma 3.12.
We now show how to compute the tuple (cutG(S), LN(S), P(S)) for every cut S ⊆V that was
returned by the algorithm. Observe that an independent cut defined by edges (e, e′) with lower
vertices u, v respectively, can be written as S = u↓∪v↓. Therefore, the lexicographic number of
the cut is given by min(LN(u↓), LN(v↓)) and P(S) = P(u↓) + P(v↓). Using the values calculated
in Lemma 3.3, we can compute these values for a cut in O(1) time. Finally, there are at most O(n)
such cuts as the algorithm returns one candidate per edge in the tree, and hence one can compute
the cost tuples of all cuts and return the lexicographically-first of them in O(n) time.
It remains to show that the cut returned is lexicographically first among all independent cuts.
Let (u∗, v∗) define a lexicographically-first independent cut S∗= u∗↓∪v∗↓. Assume without loss
of generality that LN(u∗↓) < LN(v∗↓). Examine the cut T found when the algorithm considers
the tree edge e∗whose lower vertex is u∗. Notice that cutG(T) ≤cutG(S∗) since the algorithm
finds the minimum independent containing e∗, and therefore equality is obtained since S∗is a
minimum independent cut. Furthermore, LN(T) ≤LN(u∗↓) = LN(S∗) as u∗↓∈T, and again
equality is achieved since S∗is lexicographically first. Finally, P(T) ≤P(S∗) since it is used as
a tie-breaker in the algorithm. Therefore, (cutG(S∗), LN(S∗), P(S∗)) = (cutG(T), LN(T), P(T))
and the algorithm returns a lexicographically-first independent cut.

Additional Models of Computation
In this section we prove Theorems 1.3 and 1.4. Both proofs rely on a weaker version of the non-
trivial minimum cut sparsifier (NMC) defined in Definition 1.8. Instead of preserving all minimum
cuts, this weaker version only preserves each cut with some constant probability. We note that in
general this weaker version is also called a non-trivial minimum cut sparsifier, but we denote it as
weak to differentiate between the two versions.
Definition 4.1 (Weak Non-Trivial Minimum Cut Sparsifier). A weak non-trivial minimum cut
sparsifier (weak NMC) of a graph G = (V, E) is a randomized contraction H = (VH, EH) of G such
that for every non-trivial minimum cut S ⊆V in G, it holds that cutH(S) = cutG(S) with constant
probability.
The following lemma shows that by constructing O(1) independent weak NMCs and applying
our tie-breaking mechanism to each, we can find the lexicographically-first minimum cut with
probability at least 2/3.
Lemma 4.2 (Meta-Lemma). Let G = (V, E) be an unweighted graph with a designated source
s ∈V and an ordering h : V \ {s} →[n −1]. Given O(1) independent weak NMCs H1, . . . , Hk
of G, each with κ edges, and the vertex with minimum degree (breaking ties by h), there exists an
algorithm that finds the lexicographically-first minimum cut of G can be found with probability at
least 2/3.
Proof. Begin by setting the vertex order and priorities of the NMC sparsifiers, we do this simi-
larly to the proof of Theorem 1.2. Fix some NMC sparsifier Hi, then for each contracted vertex
u ∈VHi corresponding to Cu ⊆V , set P(u) = |Cu| and h(u) = minx∈Cu h(x). Then, run our
lexicographically-first minimum cut algorithm (Lemma 1.7) on each Hi to find its lexicographically-
first cut S∗
i . Finally, compare all candidate cuts and return the lexicographically-first among them.
We now show that the algorithm finds the lexicographically-first minimum cut with probability
at least 2/3. Let S∗be the lexicographically-first minimum cut of G. If S∗is trivial (i.e., |S∗| = 1),
then it is preserved explicitly as the vertex with minimum degree (breaking ties by h). If S∗is
non-trivial, then by Definition 4.1, each weak NMC preserves S∗with constant probability p > 0.
With k = O(1) independent weak NMCs, the probability that at least one preserves S∗is at least
1 −(1 −p)k ≥4/5 for sufficiently large k. When S∗is preserved by some Hi, our algorithm returns
S∗with high probability. Therefore, the overall probability of returning S∗is at least 2/3.
