Universally Optimal
Decremental Tree Minima
Benjamin Aram Berendsohn
Max Planck Institute for Informatics
An algorithm on weighted graphs is called universally optimal if it is opti-
mal for every input graph, in the worst case taken over all weight assignments.
Informally, this means the algorithm is competitive even with algorithms that
are optimized for only one specific input graph. Universal optimality was re-
cently introduced [Haeupler et al. 2024] as an alternative to the stronger, but
often unachievable instance optimality.
In this paper, we extend the concept of universal optimality to data struc-
tures. In particular, we investigate the following dynamic graph problem:
Given a vertex-weighted forest, maintain the minimum-weight vertex of ev-
ery tree under edge deletions. The problem requires Θ(log n) amortized time
per operation in general, but only O(1) time if the initial forest is a path.
We present a data structure that has optimal total running time for every
fixed initial forest and every fixed number of operations/queries m, when
taking the worst case over all weight assignments and operation sequences of
length m. This definition of universal optimality is easily adapted to other
data structure problems.
Our result combines two techniques: (1) A decomposition of the input into
paths, to take advantage of the O(1)-time path-specific data structure; and
(2) splay trees [Sleator and Tarjan 1985], which, informally speaking, are used
to optimally handle a certain sorting-related subproblem. We apply our data
structure to solve problems related to Cartesian trees, path minimum queries,
and bottleneck vertex/edge queries, each with a certain universal optimality
guarantee. Our data structure also can be modified to support edge weights
instead of vertex weights. Further, it generalizes to support semigroup sum
queries instead of minimum queries, in universally optimal time.

1. Introduction
In this paper, we study the following dynamic graph problem, which we call Decre-
mental Tree Minima (DTM). We are given a vertex-weighted forest, and need to
support the following two operations: delete-edge(u, v), which does the obvious; and
tree-min(v), which returns the minimum vertex in the connected component (i.e., the
tree) that contains v. Note that vertex weights cannot be changed and edges cannot
be inserted.
We assume weights are pairwise distinct and can only be accessed via
comparisons.
To the author’s knowledge, previous works only considered the fully-dynamic variant
of this problem, where edge insertions are also allowed [GGT91]. Standard dynamic
forest data structures like link-cut trees [ST83, ST85] solve the fully-dynamic problem
in O(n log n) time, when there are n vertices and Θ(n) operations. This is tight by
a reduction from dynamic connectivity [PD06], even when the forest is a collection of
paths at all times.
For the Decremental Tree Minima problem (where insertions are not allowed), the
same Ω(n log n) lower bound holds by a reduction from sorting, so the above solutions
are worst-case optimal. What makes the DTM problem interesting is that it is easy when
the input tree is a path: Using a standard range minimum query data structure [BF00],
we can achieve O(m + n) time for m operations and n vertices.
This begs the question whether we can beat Θ(log n) amortized time per operation
on other input forests.
In this paper, we give a complete answer to this question:
A data structure that has optimal running time on every input forest. To formalize this,
we extend the notion of universal optimality, recently defined for (non-dynamic) graph
algorithms [HHR+24a], to data structures. We also give several applications of our data
structure, which yields universally optimal algorithms. In the following, we first discuss
universal optimality in more detail, and then present our results.
Universal optimality for algorithms.
In classical worst-case complexity, the running
time of an algorithm is usually measured in terms of input size only; i.e., for a fixed input
size, take the worst case over all inputs of that size. For graph algorithms, sometimes
both the number n of vertices and the number m of edges is fixed, and parametrized
graph algorithms additionally fix the value of some parameter. In universal optimality,
the parameter is the graph itself, and the worst case is only taken over additional data
like vertex weights.
More precisely, consider a problem where the input is a graph G with an (edge- or
vertex-)weight function w, and let A be an algorithm for this problem. Let T(A, G, w)
denote the running time of A on input (G, w), and let T(A, G) = maxw T(A, G, w), where
the maximum is taken over all possible weight functions for G.1 Then A is universally
optimal if, for every graph G, and every other algorithm A′, we have T(A, G) ≤c ·
T(A′, G) for some globally fixed constant c. In particular, universal optimality means
that A is competitive with algorithms that are specifically engineered for a single graph.

In contrast, instance optimality means that we have T(A, G, w) ≤c · T(A′, G, w) for
every input (G, w) and some globally fixed constant c. Instance optimality can be seen
as the “ultimate” optimality guarantee;2 unfortunately, it is often unachievable. This
is in particular true for problems that contain sorting as a special case. Indeed, every
sequence can be sorted in linear time by some algorithm, but for every sorting algorithm
there exists a sequence that requires Ω(n log n) time.
We now discuss some problems where universally optimal algorithms are known. First,
in the distance ordering problem, we are given a directed edge-weighted graph G and a
starting vertex s, and need to order the vertices by distance from s. Haeupler, Hlad´ık,
Rozhon, Tarjan, and Tˇetek [HHR+24a] showed that Dijkstra’s algorithm, equipped with
a special priority queue, solves this problem in universally optimal running time.
A related problem is partial order sorting. Here, we are given a set of elements and the
Hasse diagram of a partial order on these elements. We need to sort the elements using
comparisons, under the promise that the sorted order is a linear extension of the given
partial order. For universal optimality, the Hasse diagram corresponds to the graph G,
and the underlying order takes the role of the weight assignment. Two different univer-
sally optimal algorithms for this problem have been found recently [HHI+25, vdHRR25b].
Finally, there is an algorithm for convex hull [KS86, ABC17] that has been called
universally optimal [vdHRR25a]. This is obviously not a graph problem; however, the
concept of universal optimality can be generalized to arbitrary input types, as long as
we can identify a primary input part (replacing the graph), and a secondary input part
(replacing the weight assignment). For convex hull, the primary input part is taken as
the set of input points, and the secondary input part is the order in which they are
given. A universally optimal algorithm by this definition is instance-optimal among all
algorithms that behave the same irrespective of input order; accordingly, the term used
originally was instance optimality in the order-oblivious model [ABC17].
Note that all three problems have worst-case lower bounds of Ω(n log n) (where n
denotes the number of vertices in the graph, the number of elements to sort, or the
number of points). These lower bounds are achieved if the input is a star, a partial order
consisting of a single antichain, or a set of points in convex position, respectively. In all
three cases, worst-case optimal algorithms have been known for a long time.
On the other hand, the following easy cases can be identified: For the distance-ordering
problem, if G is a directed path starting at s, then the problem can be solved in linear
time, regardless of the edge weights. Similarly, if the given partial order is a chain, then
no comparisons are necessary to determine the sorted order. Finally, it is known that
a convex hull can be computed in linear time if it only contains a constant number of
points, regardless of the input order [KS86, Cha96].
Thus, worst-case running times range between Θ(n log n) and Θ(n) depending on
the primary input part (i.e., the graph, partial order, or point set). It is reasonable
to ask for some interpolation between these extremes.
A well-known result in that
direction are the output-sensitive convex hull algorithms of Kirkpatrick–Seidel [KS86]
and Chan [Cha96], which take O(n log h) time, where h is the number of points on

Universal optimality for data structures.
Recall the Decremental Tree Minima
(DTM) problem defined above. We start with a vertex-weighted forest, we can delete an
edge with delete-edge(u, v), and we can find the minimum-weight vertex in the tree
containing a given vertex v with tree-min(v). In the following, we call vertex weights
priorities, to distinguish them from numerical weights. We assume priorities in the input
forest are pairwise distinct and can only be accessed via comparisons.
When the input forest G has n vertices, then Θ(n) DTM operations can be performed
in O(n log n) time [GGT91]. This is tight if G is a star where the central vertex has
priority ∞. Indeed, in this case a DTM data structure can sort the leaf priorities with
alternating tree-min queries and edge deletions, which requires Ω(n log n). On the other
hand, if G is path, then DTM can be solved with O(n) time preprocessing and O(1)
time per operation (details are given in section 2.3).
We are thus in a similar situation as for the aforementioned algorithmic problems:
The worst-case running time for Θ(n) operations a fixed graph can be Θ(n log n) or
Θ(n), depending on the graph (in fact, it can be anything in between). However, it
is not immediately obvious how to define universal optimality for data structures. In
particular, the restriction to Θ(n) operations may not adequately capture the complexity
of the problem. On the other hand, if the number of operation is arbitrary, the worst-case
total running time for any fixed graph is unbounded.
We hence use the following definition, which can be easily adapted to a wide range of
dynamic graph problems (see below). We model a problem instance as a tuple (G, p, σ),
where G is the initial tree, p is the priority assignment and σ is the sequence of operations.
The primary input part for universal optimality is (G, |σ|), i.e., the graph and the number
of operations. Note that σ is revealed one-by-one, and not even |σ| is known at the start.
More precisely, if D is a data structure for the DTM problem, G is a graph, and
m ∈N, then T(D, G, m) denotes the total time D requires for an input (G, p, σ), in
the worst case over all possible priority assignments p and all valid operation sequences
σ with |σ| = m. We call D universally optimal when, for each G, each m, and each
other data structure D′, we have T(D, G, m) ≤c · T(D′, G, m) for some globally fixed
constant c. Our main result is:
Theorem 1.1. There is a universally optimal data structure for the Decremental
Tree Minima problem.
Alternative definitions.
Our definition is not the only reasonable interpretation of uni-
versal optimality. For the DTM problem specifically, one could require tree-min to
run in constant time, and measure the total time for preprocessing plus the at most n
edge deletions. This is in line with the idea of “maintaining” tree minima. However, our
definition is stronger and more directly generalizes to other decremental graph problems.
Another definition may count each operation separately. For example, for DTM, we
may consider pairs m1, m2 ∈N instead of a single value m, and take the worst case over

Cartesian trees on graphs.
Our second result is a universally optimal algorithm for
computing a certain graph decomposition, using our Decremental Tree Minima data
structure. We start with some definitions. An elimination tree on a connected graph
G is a rooted tree T with V (T) = V (G), constructed as follows (see fig. 1, left/center):
First, pick an arbitrary vertex r ∈V (G) as the root of T. Then, recursively construct
elimination trees on each component of G−r, and add them as child subtrees to r. Note
that if G is a path, then T is a binary tree, and fixing a direction on the path induces
the usual left and right children. Elimination trees have been studied in the context of
matrix factorization, vertex search, and structural graph theory; see section 1.3 for more
details.
A priority assignment p uniquely determines an elimination tree T on G as follows
(see fig. 1): Whenever a subtree root is picked, pick the currently available vertex with
minimum priority. Alternatively, T is the unique elimination tree on G such that for
each ancestor-descendant pair u, v, we have p(u) < p(v). We call T the Cartesian tree on
(G, p) (since it generalizes the concept of so-called Cartesian trees on sequences [Vui80]),
and write C(G, p) = T. The Cartesian Tree problem consists of computing C(G, p),
given G and p. Some variants of the Cartesian Tree problem have been considered
before [Liu86, Cha87, ZM94, DM13, DLW14].

Path minimum and bottleneck queries.
Suppose we are given a tree G with priority
assignment p, and we want to preprocess it to answer the following query:
• path-min(u, v) →w returns the minimum-priority vertex w on the path between
u and v.
Note that since G is a tree, the path between u and v is unique. It is not hard to see
that if T is the Cartesian tree C(G, p), then the answer to path-min(u, v) is the lowest
common ancestor (LCA) of u and v in T. Since we can preprocess T in O(n) time to
answer LCA queries in O(1) time [HT84], we have:
Theorem 1.3. There is a data structure that, given a tree G and a priority assignment p,
can answer path-min queries in O(1) time, with O(log |E(G)|) preprocessing time.
This data structure is not universally optimal in any strong sense.

if G is a star, we can compute path minimum queries in constant time, without any

and constant query time [AS87].

Edge-weighted graphs.
All of our results generalize to a setting where priorities are
given for edges instead of vertices. The Decremental Tree Minima problem and the
static path-min data structure problem generalize in the obvious way, and bottleneck
vertices become bottleneck edges, another well-studied concept [VWY07, DLW14].
Elimination trees also can be adapted as follows: An edge-partition tree (EPT) on a
connected graph G is a rooted binary tree T with V (T) = E(G) ∪V (G), where edges of
G correspond to inner nodes of T, and vertices of G correspond to leaves of T. An EPT
is constructed as follows: Pick an arbitrary edge e as the root of T, then recursively
construct up to two child subtrees on the up to two components of G −e.
An edge-priority assignment p again uniquely determines an EPT on the given graph G.
These Cartesian EPTs have been studied before under several different names [Cha87,
Net99, BMN+04, BDR11, DM13, DLW14].
All these edge-weighted variants reduce to the corresponding vertex-weighted problem
with the following reduction: Place a vertex “on” each edge, i.e., replace each edge with a
path of length two. That vertex receives the priority of the original edge, and all original
vertices are assigned priority ∞. We can then apply our solutions to the resulting graph,
with only minor modifications.
Since the number of newly introduced vertices is linear, worst-case optimality is main-
tained. We can also prove our universal optimality guarantees with some additional work.
In particular, our universally optimal algorithm for computing Cartesian EPTs strictly
improves upon early O(n log n) solutions for trees [Cha87], as well as the O(n log ℓ)
algorithm of Dean and Mohan for trees with ℓleaves [DM13].
Semigroups.
Consider the following variation of the DTM problem, which we call
Decremental Semigroup Tree Sums.
Instead of priorities, each vertex v is as-

all vertices in the same component as v. Since the set of priorities under taking minima
forms a commutative semigroup, this is a strict generalization of the DTM problem. It
turns out that our data structure can be generalized to solve the this problem as well.
Theorem 1.5. There is a universally optimal data structure for the Decremental
Semigroup Tree Sums problem.

Incremental and offline variants.
Finally, let us briefly consider the incremental tree
minima or tree semigroup sum problem. Adding an edge merges two trees into one, and
the new minimum (or sum) can be computed in constant time. Thus, the problem boils
down to finding the component containing a query vertex. This is the well-known union-
find problem, which can be solved in almost-linear time6 [Tar75]. The offline variant of
the incremental problem, where all operations are given in advance, can even be solved
in linear time [GT83]. Since the offline incremental and offline decremental variants are
equivalent, offline Decremental Tree Minima can also be solved in linear time.
1.1. Techniques
In this section, we briefly present the main ingredients of our universally optimal data
structure for Decremental Tree Minima and the associated lower bound. For sim-
plicity, we only assume the initial forest is a tree, the number of operations is linear in
the number of vertices, and every edge is deleted eventually.
Dynamic trees with chain compression.
As mentioned above, classical dynamic tree
data structures achieve a running time of O(log n) per operation, but for paths, we can

achieve O(1) time via range minimum queries. The first idea is to combine these two data
structures. To do this, we partition the initial tree into induced paths (called chains),
as shown in fig. 2. For each of the chains, we maintain the constant-time DTM data
structure. We also maintain the tree obtained by contracting each chain into a single
node (called a super-node), using a logarithmic-time DTM data structure D based on
dynamic forests.
The priority of each super-node is always the minimum of the associated chain; thus,
a tree minimum can always be found with D.tree-min. An edge deletion may affect
up to one of the constant-time DTM data structures, and either deletes an edge in D
(see fig. 2, top right) or “splits” a super-node in D (see fig. 2, bottom right). The latter
operation is not standard in dynamic forests, but easy to implement.
Observe that when the initial tree has ℓleaves, then it can be partitioned into O(ℓ)
chains. Thus, the compressed tree stored in D initially has O(ℓ) super-nodes. While
“splitting” can create new super-nodes, it can be shown that the number of super-nodes
in a single tree in D cannot ever be more than O(ℓ). This implies that every dynamic
tree operation takes O(log ℓ) time. Since the operations on the chain data structures
only take constant time, the overall running time for O(n) operations is O(n log ℓ). This
is strictly better than Θ(n log n) for some initial trees, but not universally optimal.
Lower bound.
Before refining the data structure above, we describe our lower bound.
Recall that if the initial tree is a star, then we can sort the leaf priorities by repeatedly
deleting the (edge to the) minimum-priority leaf. Actually, for any initial tree, we can
sort its leaves this way, which implies a general Ω(ℓlog ℓ) lower bound. Thus, for trees
with Θ(n) leaves, our previous algorithm is optimal. However, for some trees, neither
the O(n log ℓ) upper bound nor the Ω(ℓlog ℓ) lower bound is tight.
A tight lower bound can be obtained as follows. Make the initial tree T rooted by
choosing an arbitrary root. Suppose that for each node v in T, each ancestor of v has
larger priority.
This means that tree-min will always return a leaf.
Thus, we can
again sort the nodes in T by priority by repeatedly deleting the minimum-priority leaf.
This is not general sorting, since the set of possible priority assignments is restricted by
the condition above. Instead, we get a special case of the aforementioned partial order
sorting problem. Taking T as the Hasse diagram of a partial order P, then the possible
orderings respecting the above condition is the set L(P) of linear extensions of P. By
the information-theoretic lower bound, we need log |L(P)| comparisons to sort, so we
have an Ω(log |L(P)|) lower bound for 2n DTM operations on T.
Matching the lower bound with splay trees.
Now, if we continue assuming that the
minimum is always a leaf, then we can match the Ω(log |L(P)|) bound using known
results on partial order sorting.
In particular the optimal algorithm of Haeupler et
al. [HHI+24], in our language, maintains the set of leaves in a special fast priority queue.
It repeatedly extracts the minimum leaf from the priority queue, removes it from the
tree, and then, if this makes another vertex a leaf, inserts that vertex into the priority
queue.

For our data structure, we follow the same basic framework. However, we cannot
use the same priority queue implementation: In the final data structure, general edge
deletions will be allowed, which sometimes require splitting the set of leaves in a certain
way. To support this, we instead use a splay tree [ST85] that maintains the leaf set in
left-to-right order, and supports finding the minimum as well as arbitrary splits.7 The
analysis is very different.
Putting things together.
We now go back to the original algorithm using dynamic
forests and chain compressions. We modify it as follows. The dynamic tree D is now no
longer responsible for maintaining the priorities of the root and leaf super-nodes of the
compressed forest; their priorities are permanently set to ∞in D. The leaf super-nodes
of each tree are stored in a splay tree, and the root super-node priority is maintained
explicitly for each tree. We can now find the minimum of a tree by checking (1) the root
super-node, (2) the corresponding tree in D, and (3) the leaf splay tree.
The running time analysis very roughly goes as follows. We always explicitly update
tree minima when deleting edges, so tree-min takes constant time. For edge deletions,
we distinguish between three cases: When we delete an edge within a root super-node,
only that super-node needs to be updated, in constant time. When we delete an edge
within a leaf super-node, only the corresponding splay tree needs to be updated, in
optimal amortized time by the above discussion.
The only remaining case are edge deletions within other super-nodes, or between
super-nodes, which take (essentially) O(log ℓ) amortized time to update D and to split
a splay tree. However, it can be shown that such edge deletions only happen O(ℓ) times
overall. Thus, the total time for these edge deletions is O(ℓlog ℓ), which is accounted
for by the basic Ω(ℓlog ℓ) leaf sorting lower bound.

The only exception is the path-specific DTM implementation that uses

1.2. Conclusions
We defined universal optimality for data structures, and gave a universally optimal data
structure for Decremental Tree Minima. Our definition could be applied to other
data structure problems, not necessarily restricted to dynamic weighted graphs. In par-
ticular, any problem where both “easy” special cases and tight worst-case bounds are
known could be a good candidate for universal optimality. Our techniques for Decre-
mental Tree Minima are robust enough to allow replacing vertex weights with edge
weights, and generalize tree minima queries to arbitrary semigroup tree sum queries.
We applied our data structures to obtain a universally optimal algorithm to compute
Cartesian trees. An interesting generalization is weighted centroid trees. Here, a vertex-
weighted tree (G, w) is given, and we need to construct the elimination tree on G where
the root of every subtree is the centroid of the respective subgraph H of G. A vertex v
is a centroid of H if removing v splits H into components whose weight is at most half
the total weight of H [KH79, BGKK23].
The special case where all weights are distinct powers of two is equivalent to Cartesian
trees; thus, our lower bounds hold. However, our approach does not work for centroid
trees; essentially, the problem of computing centroids does not decompose as nicely as
the problem of computing minima. We leave open the question whether there exists a
universally optimal algorithm for computing weighted centroid trees.
We used Cartesian trees to give a static data structure for Path Minima, with a re-
stricted universal optimality guarantee, which holds only if all path-min queries perform
zero comparisons. If comparisons in path-min queries are allowed, an inverse-Ackermann
tradeoff between preprocessing and query time is possible and optimal [Cha87, Pet06].
Since Path Minima on paths (i.e., the range minimum queries problem) can be solved
with linear preprocessing and constant query time, this is another candidate for universal
optimality.
As a final note, observe this paper and several recent results [HHR+24a, HHI+25,
Ber25] use adaptive data structures (splay trees here and working-set heaps in the other
references). In this context, adaptivity means that these data structures are able to
exploit certain sequential patterns in access sequences. These results suggest that they
are also useful to exploit the input graph structure, i.e., the topology of an input.

In this section, we briefly review relevant literature that was not mentioned above.
Dynamic and semi-dynamic graph data structures.
A dynamic graph data structure
maintains a changing graph, e.g., under edge insertions and deletions, while maintaining
certain properties of the graph or allowing certain queries.
The special case of forests is also well-studied, from the early link-cut trees of Sleator
and Tarjan [ST83, ST85], to the more recent top trees of Alstrup, Holm, De Lichtenberg,
and Thorup [AHDLT05, TW05, HRT18]. The latter provide a very flexible framework
to support a variety of queries (including tree-min) under edge insertions and deletions,
in O(log n) time per operation. An earlier data structure for tree-min queries in forests,
based on link-cut trees, was given by Goldberg, Grigoriadis, and Tarjan [GGT91] for use
in a maximum flow algorithm.
Semi-dynamic problems, either decremental (only edge deletions) or incremental (only
edge insertions) often allow for better running times or simpler algorithms [Hen18]. In the
special case of forests, the running time per operation can drop from the usual Θ(log n)
to constant or almost-constant.
For example, fully-dynamic connectivity (where we
need to answer whether two vertices are connected or not) requires Ω(log n) amortized
time per operation on forests [PD06].
In contrast, the decremental variant requires
only O(1) time per operation [ASS97], and the incremental variant can be solved with
almost-constant (inverse-Ackermann) time per operation via the classical union-find data
structure [Tar75].
An interesting problem that is closely related to Decremental Tree Minima is the
list splitting problem [Gab85]. While not originally formulated in the language of graph
theory, it is equivalent to DTM on collections of paths, with an additional operation that
allows decreasing the priority of a vertex. List splitting has several applications [Pet06],
and the best known data structure has almost-constant amortized running time per
operation [PR05]. When we drop the priority-decreasing operation, we can solve the
problem with linear preprocessing and constant amortized time per operation, using the
aforementioned range minimum query data structure.
In another related paper, Brodal, Davoodi, and Rao [BDR11] design data structures
for path-min queries (and their generalization to semigroups) in a dynamic tree, for a
comparably limited set of graph-editing operations.

Cartesian trees have been first studied

can be seen as binary trees on a sequence. The name Cartesian tree comes from an

2. Preliminaries
In the following, we fix some notation and give basic graph-theoretic definitions. In sec-
tions 2.1 to 2.3, we define relevant data structure problems and make some observations.
All graphs in this paper are undirected. For a graph G, we let V (G) denote the set
of vertices and E(G) the set of edges. If e ∈E(G), then G −e is the graph obtained
by removing e. If v ∈V (G), then G −v is the graph obtained by removing v and its
incident edges.
Rooted forests.
Internally, our algorithms and data structures usually operate on
rooted forests. We use the following notation for a rooted forest F. The sets of nodes
is V (F), the set of edges is E(F), and we write |F| = |V (F)| for short. For each node
v ∈V (F), we denote by Fv the subtree rooted at v, i.e., the subtree induced by v and
all its descendants.
We define two operations that modify rooted forests; one for basic edge deletion, and
one for internal use. Figure 3 shows examples.
Definition 2.1. Let F be a rooted forest, and let v ∈V (F) The operation cut(v)
deletes the edge between v and its parent, assuming that v is not a root. The operation
split(v) replaces v by two new nodes u1, u2, such that u1 inherits the parent of v, and
u2 inherits the children of v. The tuple (u1, u2) is then returned by split.
Observe that split, when applied to a leaf or root, does nothing but create a new
isolated node. This case will be easy to handle by our data structures, which makes the
following lemma useful:

Lemma 2.2. Let F be a forest with n nodes, and consider any valid sequence of cuts
and splits applied to F. Then, the sequence contains no more than n −1 cuts, and at
most n −2 splits are applied to non-root non-leaf nodes.
Proof. Observe that no new edges are ever introduced. Since each cut removes one of
the up to n −1 edges, the first bound is immediate. For the second bound, observe that
the number of non-root-non-leaf nodes is at most n−2 at the start. Each split(v) on a
non-root non-leaf node v replaces v by a root and a leaf. Thus, there are at most n −2
such splits.
Priorities.
In this paper, P denotes some totally ordered universe of priorities. We
assume priorities can be compared in constant time, but not accessed otherwise (see
below). Our algorithms may internally use a special priority ∞that is larger than all
other priorities given in the input. A priority function maps a set of elements (usually
the vertices of a graph) to distinct priorities.
Machine model.
We assume the standard Word RAM model with logarithmic word
size and the usual modification for comparison-based algorithms, specified in the follow-
ing. Priorities are not given explicitly. Instead, our algorithms have access to an oracle
that answers queries of the form p(v) < p(u), where u and v are vertices in the input
graph (represented as integers), and p denotes the input priority function. Whenever an
algorithm “stores” a priority somewhere, it really stores the node with that priority. The
special priority ∞is stored as a special integer, and comparisons with it are resolved
without calling the oracle.

2.2. Decremental Tree Roots
In this section, we describe a data structure for rooted forests that maintains a mapping
from each node v to the root of the tree containing v. This will be useful if we want
to store some information about a tree (like the minimum-priority vertex), since we can
store that information in the root.
Definition 2.4. A data structure for the Decremental Tree Roots problem main-
tains a rooted forest F under the following operations:
• root(v) →r returns the root r of the tree containing v:
• cut(v) removes the edge from v to its parent (as in definition 2.1)
• split(v) →(u1, u2) splits v into two new nodes u1, u2 (see definition 2.1).
It was observed before [AHR98, DLW14] that a data structure by Alstrup, Secher, and
Spork [ASS97] can be adapted to partially solve this problem with linear preprocessing
time and constant time per operation. This data structure supports the root and cut
operations. Below, we show how to also support the split operation.
Lemma 2.5. There is a data structure for Decremental Tree Roots that performs
m operations with an initial forest on n nodes in O(m + n) time.
Proof. To support splits, we first preprocess the initial forest F 0 as follows. For each
node v, we apply a split operation to v, obtaining a node pv that inherits the parent
of v, and a node cv that inherits the children. Call V (F 0) the original nodes, and let
F 1 be the modified forest.
Now initialize the data structure mentioned above (without support for split) with
the modified forest F 1. Call this data structure X. At any given point, let F denote
the forest we are maintaining (initially F = F 0), and let F ′ denote the modified forest
maintained by X (initially F ′ = F 1). Besides X, we also explicitly maintain F, and
keep track of which nodes in F are original. (New non-original nodes will be introduced
every time we perform a split in F.)
We maintain following two invariants. First, at any point, F ′ is precisely the forest
obtained from F by applying the above split operation for each original node still
contained in F. Second, every non-original node in F is a root or leaf.
We now show how to implement the three operations. Consider cut(v). If v is original,
we call X.cut(pv). Otherwise, we call X.cut(v).
Consider now split(v). If v is original, we call X.cut(cv), and return (pv, cv). Oth-
erwise, v must be a root or leaf. We can thus simply create a new isolated node u and
return either (u, v) (if v is a root) or (v, u) (if v is a leaf).
Finally, consider root(v). if v is original, we compute r ←X.root(pv); otherwise, we
compute r ←X.root(v). Then, if r = pu for some original node u that is contained
in F, we return u. Otherwise, we return r.
Each operation clearly takes O(1) time. Further, it is easy to see that cut and split
maintain the invariants, and thus root is correct.

4. Step-by-step towards universal optimality
In this section, we present our data structure for Decremental Tree Minima. For
now, we will prove optimal running time for every initial tree T, for a worst-case sequence
of operations of length at least 2|V (T)| −2 (matching corollary 3.4). We start with a
relatively naive attempt, and then gradually improve our algorithm. The full proof of
universal optimality (for an arbitrary number of operations) is given in section 5.
4.1. An O(n log n) algorithm with dynamic forests
A dynamic forest data structure [ST83, ST85, AHDLT05] maintains a rooted forest
and some associated data along with edge insertion and deletion. We use the following
specification. Note that for our O(n log n) Decremental Tree Minima data structure,
we only need the operations cut and find-min, and only need O(log n) amortized upper
bounds for their running time. The operations set-priority and split will be useful
later.
Definition 4.1. A dynamic forest data structure represents a rooted forest F with vertex
priorities p: V (F) →P. It supports the operations listed below.
• D.find-min() →v returns the node v with minimum priority.
• D.cut(v) removes the edge between v and its parent (see definition 2.1).
20


## Page 21


• D.set-priority(v, q) sets p(v) ←q.
• D.split(v) →(u1, u2) splits v into two new nodes (see definition 2.1). The prior-
ities of the two new nodes u1 and u2 are initialized as p(v).
Lemma 4.2. There is a dynamic forest data structure such that:
• Initialization takes O(n) time, where n is the number of nodes in the given initial
forest;
• find-min takes O(1) time;
• split(v) takes O(1) time when v is a root or a leaf;
• split in every other case, as well as cut and set-priority, all take O(1+log n)
time, where n is the number of nodes in the tree containing the affected nodes.
All running times are amortized.
Proof. All operations besides split can be implemented in O(log n) amortized time by
standard solutions [ST83, ST85, GGT91]. Suppose we have such a data structure X,
which also supports the operation X.link(u, v) that makes u a child of v.
We can implement split(v) by first calling X.cut(v), then adding a new child u1 to
the former parent of v using X.link(u1, v). Then, we set the priority of u1 to p(v) and
finally return (u1, v). This yields the required running time of O(log n) in the general
case.
To implement find-min in O(1) time, we store the minimum value of each component
S of F explicitly in the root r of S, as a value qr. We maintain a Decremental Tree
Roots data structure on F to access r. Whenever we need to update qr, we compute it
with the standard O(log n)-time find-min operation of X. This happens at most twice
after each cut or split, so we stay within the O(log n) budget.
Finally, we describe how to perform split in O(1) time for roots and leaves. Suppose
v is a leaf. For split(v) we create a new, disconnected vertex u2 with priority p(v), and
return (v, u2). This requires only calling set-priority(u2, p(v)), which takes O(1) time
since u2 is an isolated vertex. Moreover, the only newly created root is u2, we clearly
have qu2 = p(v), and qr does not need updating for any other root r.
If v is a root, we proceed similarly.
Lemma 4.2 implies that, starting with a tree with n nodes, we can perform m DTM
operations in O(m log n + n) time.
4.2. Chain compression
In this section, we give an improved data structure with O(log ℓ) running time per

Other standard BST data structures, such as AVL trees [AVL62], keep the height of
the BST at O(log n), to ensure O(log n) worst-case search time. In contrast, splay trees
do not provide such a guarantee. Instead, after every search, they rebalance themselves
in order to speed up future searches. While only an amortized O(log n) running time
per search is ensured by splay trees, they have the upside of a simple implementation
without additional bookkeeping, and also can be shown to perform better then O(log n)
per operation when the search sequence has a certain structure.
The central operation for splay trees is the eponymous splay(x), which moves a node
x to the root of the splay tree through a sequence of rotations. It is performed after
every search, where x is the found node. splay is also useful to implement insertion
and deletion of keys. For definitions of rotations and the splay operation, we refer to
Sleator and Tarjan [ST85]. For us, the only important detail is the rotations (and thus
splay) do not change the symmetric order of the nodes.
Here, we use splay trees in a different way; we never need to search for keys, but instead
use it as a dynamic decomposition of a sequence as in definition 4.5. The nodes will
maintain minima of contiguous subsequences, and splay will be useful to implement
the operations replace and split-interval. There are other examples of a similar
“structural” use of splay trees, most prominently the dynamic forest data structure of
Sleator and Tarjan [ST83, ST85].

• splay(x), which brings x to the root of T with a series of rotations. The exact

• Attach the root r′ of another splay tree T ′ as a left or right child to the root r
of T.
• Detach a child from the root r of T, producing a new splay tree.

6.1. The number of elimination trees

Lemma 6.2. Let G be a tree, let T be an arbitrary rooting of G, and let p be a T-

6.2. Computing Cartesian trees on graphs
In this section, we show how to reduce the general Cartesian Tree problem to the
tree case, in universally optimal time. Ultimately, we will prove:
Theorem 1.2. There is an algorithm that, given a graph G and a priority assignment p,
computes C(G, p) in universally optimal time O(|E(G)| + log |E(G)|).
The following lemma is the main insight needed for the reduction.
Lemma 6.6 (Zhu and Mutchler [ZM94]). Let (G, p) be a graph with vertex priorities.
Let C be a cycle and let e be an edge incident to the minimum-priority vertex of C.
Then C(G, p) = C(G −e, p).
Proof. Let v be the minimum-priority vertex of G, and let G′ = G −e. If v is contained
in C, then e is incident to v by definition. Thus G −v = G′ −v. The Cartesian trees
C(G, p) and C(G′, p) both have root v, and the child subtrees of v are Cartesian trees on
the components of G −v = G′ −v. Thus, we have C(G, p) = C(G′, p)
Now suppose v is not contained in C. Then C is fully contained in some connected
component H of G −v. By induction, C(H, p) = C(H −e, p). This implies that also
C(G, p) = C(G′, p).

6.3. Path Minima
We now use Cartesian trees to build a data structure for the Path Minima problem.
We follow common approaches for the edge-weighted variant of the problem [Cha87,
DLW14].¸ The following lemma is crucial.
Lemma 6.11. Let G be a tree with priority function p, and let T = C(G, p). Then,
for every pair u, v ∈V (G), the minimum-priority vertex on the path between u and v is
precisely the lowest common ancestor of u and v in T.
Proof. Consider the lower common ancestor a of u and v, let H = G[V (Ta)], and let P
be the path between u and v in G. Then H is connected by definition, but H −a has at
least two connected components, one containing u, and one containing v. Now observe
that:
• Since G[V (Ta)] is connected, we have V (P) ⊆V (H).
• Since removing a from H disconnects u and v, we have a ∈V (P).
• By definition, a is the minimum-priority vertex in H.
These three observations imply that a is the minimum-priority vertex of P.
We can now solve Path Minima as follows: Compute a Cartesian tree T on (G, p),
and then preprocess T such that lowest common ancestors in T can be found in constant
time. This is possible in time O(|V (T)|) ≤O(log |E(G)|) using any one of a variety of
data structures [HT84, SV88, BF00, FH06]. Thus, we have:
Theorem 1.3. There is a data structure that, given a tree G and a priority assignment p,
can answer path-min queries in O(1) time, with O(log |E(G)|) preprocessing time.
We now prove a matching lower bound. The idea is that we can solve Cartesian
Tree solely with a (static!) Path Minima data structure. This means that the overall
number of comparisons made by the Path Minima data structure must be at least
log |E(G)|. Since the number of path-min queries is large, we do not get any nontrivial
lower bound for the running time.
However, if we assume that no comparisons are
allowed within path-min queries, then preprocessing needs Ω(log |E(G)|) comparisons.

7. Semigroup sums
In this section, we show:
Theorem 1.5. There is a universally optimal data structure for the Decremental
Semigroup Tree Sums problem.
Recall that the input is now a a vertex-weighted tree (T, w), with weights from some
commutative semigroup (S, +, 0), and we need to answer the query tree-sum(v), which
returns the sum of all nodes in the same tree as v.
Most of our data structure can be used as-is, with the only change being changing
min(x, y) to x + y. We list all places where our data structure computes minima in the
following:
• The dynamic tree D maintains the minimum super-node. We can easily maintain
the sum of all super-node weights instead.
• In our splay-tree-based Splittable Sequence Minima data structure, each node
x in the splay tree T maintains the minimum priority qx of Tx. We can instead
maintain the sum of weights in Tx, and easily update it for each relevant binary
tree operation (rotation, attaching to the root, detaching from the root).
The
crucial observation here is that a sum qx can be recomputed from the weight of x
and the sums of its (up to two) children.
• In contrast, the path-DTM data structures for each chain depend on certain prop-
erties of the minimum function and need to be entirely replaced; see below.
• Finally, to answer tree-min queries, we compute the minimum of three values;
instead, we can simply take their sum.
It remains to show how to solve Decremental Semigroup Tree Sums on a path.
As mentioned in the introduction, a sufficiently fast semigroup range query data struc-
ture does not exist. However, we can instead directly solve the problem, with linear
preprocessing time and constant query time.
Our data structure is based on an algorithm of Weiss [Wei94] for constructing Carte-
sian trees on paths in linear time. While a much simpler algorithm for this task ex-
ists [GBT84], Weiss’s approach is still useful to us.
Lemma 7.1. There is a data structure for the Decremental Semigroup Tree Sums
problem on paths with linear preprocessing time and constant query time.
Proof sketch. Weiss’s algorithm for Cartesian trees works as follows: Identify the min-
imum vertex of the path, make it the root of the Cartesian tree, remove it, and then
recurse on the (up to) two remaining paths.
It is easy to check that, actually, the
algorithm supports removing an arbitrary edge instead of specifically the (up to) two
edges incident to the minimum vertex. The minimum of each path is always maintained
explicitly. This gives us a data structure for DTM.
Generalizing this data structure to semigroup turns out to be quite easy. Suppose the
input path has n = 2k nodes. There are two places where minima are computed:
46

• At the start, for each interval of the form Ip,q = [q · 2p + 1, (q + 1) · 2p] with
0 ≤p ≤k and 0 ≤q < n/2p, the algorithm computes the minimum of the subpath
corresponding to I, in O(n) total time. This can easily be done for the respective
semigroup sums.
• For each current subpath, the data structure stores precisely the minimum set of
intervals Ip,q whose union corresponds to the subpath. These intervals are stored
in a double-ended queue (deque) that supports finding the minimum in addition
to the usual deque operations, all in constant time.
This deque is due to Gajewska and Tarjan [GT86], and is called, somewhat de-
ceptively, a deque with heap order. This data structure implements a deque with
the familiar technique of using two stacks for the left and right part of the deque.
An amortization argument shows that m deque operations can be performed using
O(m) stack operations.
Each stack maintains the minimum of each of its suffixes. This requires O(1) time
to maintain per stack operation, and allows computing the minimum of the deque
by taking the minimum of the two whole stacks. Observe that the same can be
done with semigroup sums.
With this, we have shown:
Theorem 1.5. There is a universally optimal data structure for the Decremental
Semigroup Tree Sums problem.

constructed on the up to two components of G −e. We also write CE(G, p) = T. Let
EE(G) denote the set of possible Cartesian EPTs on G.

B. The Dijkstra-Jarn´ık-Prim algorithm with working-set heaps
In this section, we give a technical description of how to compute a minimum spanning
tree in the time required by theorem 1.2. The main theorem follows.
Lemma 6.10. There exists an algorithm that computes a maximum spanning tree of an
edge-weighted graph (G, w) in time O(|E(G)| + |E(G)|).
We first specify the priority queue data structure used in the Dijkstra-Jarn´ık-Prim
algorithm. We use the classical operation names, where our priorities are called keys.
Definition B.1. A priority queue maintains a set of elements S and an injective priority
assignment p: S →P, under the following operations:
• delete-min() →x removes and returns the minimum-priority element x in S.
• insert(x, q) inserts an element x and sets p(x) ←q.
• decrease-key(x, y) sets p(x) ←q, assuming x ∈S and q is smaller than the
previous value for p(x).
• get-key(x) →q returns q = p(x).

Q.insert(s, ?)
▷Priority is arbitrary

▷Predecessors
Initialize map p: V (G) →P with ∞
▷Current priorities
Initialize set U ←∅
▷Visited vertices
while Q is not empty do
u ←Q.delete-min()
U ←U ∪{u}
for each neighbor v of u with v /∈U do

R[v] = u

We use a stronger priority queue implementation, which is said to have the working set
property [HHI+25] or is alternatively called timestamp-optimal [vdHRR25a]. We use the
terminology of van der Hoog, Rotenberg, and Rutschmann here [vdHRR25a].
Consider a sequence of priority queue operations. Define the timestamp of each op-
erations to be the number of insert operations executed so far, including the current
operation. Observe that multiple operations may share the same timestamp.
Theorem B.2 ([HHR+24a, vdHRR25a]). There exists a priority queue implementation,
called a timestamp-optimal priority queue, where each insert and decrease-key takes
O(1) amortized time, and each delete-min(x) takes O(log(t −sx)) time, where t is the
timestamp of the delete-min operation, and sx is the timestamp of the insert operation
that inserted x.
Let G be a graph and s ∈V (G). A linearization of (G, s) is any ordering of V (G)
that can be obtained by assigning edge weights to G and ordering the vertices by dis-
tance to s (assuming all distances are distinct) [HHR+24a, vdHRR25a]. Let N(G, s)
denote the set of linearizations of (G, s). Berendsohn [Ber25] showed that linearizations
are precisely the orderings produced by the vertex search antimatroid of (G, s), which
is the set of orderings starting with s where each prefix forms a connected subgraph
of G. Consequently, the reverses of linearizations are obtained by progressively remov-
ing vertices other than s without ever producing a disconnected graph.
This means
that linearizations are in bijection with degenerate elimination trees with root s, so
|N(G, s)| ≤|E(G)|.
We now prove that algorithm 1 with a timestamp-optimal priority queue has running
time O(m+n+log |N(G, s)|). By the discussion above and using lemma 6.5, this implies
lemma 6.10. We closely follow van der Hoog, Rotenberg, and Rutschmann [vdHRR25a].

x∈V (G) log(tx −sx) ∈O(n+log |N(G, s)|).
