Abstract
We study Single-Source Shortest-Path (sssp) on unweighted intersection graphs whose node
set corresponds to a set D of n constant-complexity objects in the plane. We prove sssp can
be solved in O(U(n) polylog n) expected time for any class of objects whose union complexity
is U(n). In particular, we obtain an O(n2α(n) log2 n) algorithm for arbitrary pseudodisks, and an
O(λs+2(n)2O(log∗n) log2 n) algorithm for locally fat objects, where s is the maximum number of
intersections between any pair of boundary arcs of the objects, and λt(n) is the the maximum length
of a Davenport-Schinzel sequence of order t on n symbols. This significantly extends the class of
objects for which sssp can be solved in O(n polylog n) time: so far, O(n polylog n) sssp algorithms
were not even known for pseudodisks that are fat and convex and similarly-sized.
Our second result concerns the Diameter problem, which asks for the maximum distance
between any two nodes in a graph. Even for intersection graphs, near-quadratic algorithms are
already difficult to obtain, and the O(n2 polylog n) running time that follows from our sssp algorithm
is the first near-quadratic running time for such general classes of intersection graphs. Obtaining
subquadratic running time is even more challenging. We prove that the diameter of a set of arbitrary
pseudodisks can be computed almost exactly, namely up to an additive error of 2, in ˜O(n2−1/14)
expected time. This generalizes and speeds up a recent algorithm by Chang, Gao, and Le (SoCG
2024) that works for similarly-sized disks (or similarly-sized pseudodisks that are fat and satisfy a
strong monotonicity assumption) and runs in ˜O(n2−1/18) time. To this end, we develop a so-called
star-based r-clustering for intersection graphs of pseudodisks—this is similar to an r-division for
planar graphs—which is interesting in its own right. Our star-based r-clustering can also be used to
obtain an almost exact distance oracle for pseudodisks that uses O(n2−1/13) storage and has O(1)
query time.

Introduction
The sssp problem.
Single-Source Shortest-Path (sssp) asks to compute the distance
from a given source node to all other nodes in a graph G = (V, E). In an unweighted graph,
the problem can be solved in O(n + m) time using breadth-first search, where n := |V | and
m := |E|. sssp is one of the most fundamental algorithmic graph problems—perhaps even
the most fundamental—and it shows up as a subproblem in many applications.
We are interested in sssp on (unweighted) intersection graphs. Let D be a set of n objects
in the plane. Then the intersection graph G×[D] has D as its node set, and it has an edge

between two objects D, D′ ∈D iff D intersects D′. If the objects in D are (unit) disks, then
G×[D] is called a (unit-)disk graph. Similarly, segment graphs and pseudodisk graphs are
intersection graphs where D is a set of line segments or pseudodisks, respectively. (A set of
pseudodisks is a set D of topological disks such that any two objects in D are either disjoint
or their boundaries intersect in at most two points [29].) Since an intersection graph can have
Ω(n2) edges, solving sssp by computing its edges explicitly and then running a BFS takes
quadratic time in the worst case. The edges of an intersection graph are defined implicitly,
however, so there is hope that sssp on intersection graphs can be solved in subquadratic
time. This is indeed possible for many types of objects.
One approach to obtain a subquadratic sssp algorithm is to implement BFS using a
dynamic (deletion-only) data structure for intersection queries on the set D. Given an object
D ∈D at distance j from the source, we use the data structure to find the not-yet visited
objects that intersect D (which thus have distance j + 1 from the source) and delete them
from the data structure. For line segments there exists such a data structure (a partition
tree) that has ˜O(n4/3) preprocessing time1 and ˜O(n1/3) query and update time. Thus, sssp
on segment intersection graphs can be solved in ˜O(n4/3) time. This is likely optimal, since
Hopcroft’s problem—given a set L of n lines and a set P of n points, decide if there is a
point-line incidence—can be solved by running sssp on G×[L ∪P] with one of the lines as the
source. A running time of O(n4/3) is conjectured to be optimal for Hopcroft’s problem, and
Erickson [22] actually proved an Ω(n4/3) lower bound for so-called partitioning algorithms.
For other types of objects, however, it is possible to achieve O(n polylog n) running times.
For axis-aligned segments, for example, the approach sketched above immediately gives
an O(n polylog n) sssp algorithm using standard data structures for orthogonal segment-
intersection queries. O(n polylog n) algorithms also exist for disk graphs, on which much of
the research on sssp in intersection graphs has focused. For unit disks, Cabello and Jejčič [8]
and Chan and Skrepetos [10] gave O(n log n) algorithms, which are optimal in the algebraic
decision-tree model. The semi-dynamic data structure of Efrat, Itai, and Katz [21] also gives
an O(n log n) algorithm. For arbitrarily-sized disks, Kaplan et al. [28] and Liu [32] presented
the first O(n polylog n) algorithms, obtaining a running time of O(n log4 n). Klost [30]
recently improved this to O(n log2 n). Even more recently, Brewer and Wang [5] and De Berg
and Cabello [18] independently presented optimal O(n log n) sssp algorithms on disk graphs.
The algorithms of Klost and of De Berg and Cabello both rely on an efficient intersection-
detection data structure for disks, which can be obtained from an additively weighted Voronoi
diagram on the disk centers. The algorithm of Brewer and Wang also relies on additively
weighted Voronoi diagrams and Delaunay triangulations.
For pseudodisks, approaches based on (weighted) Voronoi diagrams will not work—for
that, the objects need to be the same up to scaling and translation. Moreover, data structures
with O(n polylog n) preprocessing and O(polylog n) query time for intersection queries do
not exist for pseudodisks. Chang, Gao, and Le [13] recently observed that the sssp algorithm
of Chan and Skrepetos [12] for unit disks, can be adapted to pseudodisks that are fat and
similarly-sized and have the following strong monotonicity property: there is a point c
inside each object D such that the parts of D on either side of the horizontal line through
c are x-monotone and the parts of D on either side of the vertical line through c are y-
monotone.2 Observe that convexity of the pseudodisks does not guarantee this property.
Thus, the following question is still wide open: can sssp on pseudodisk graphs be solved in

Our results and techniques on sssp.
We define an object to be a topological disk whose
boundary consists of constantly many x-monotone arcs, each of which is described by a
polynomial of constant maximum degree (plus its endpoints). The assumption that the
boundary arcs are x-monotone is without loss of generality, since a constant-complexity
arc can always be split into O(1) x-monotone pieces. We denote the maximum number of
intersection points between any two boundary arcs by s; because the boundary arcs have
constant complexity, s is also a constant.
Our sssp algorithm is efficient when the union complexity of the input set D is small: its
expected running time is O(U(n) polylog n), where U(n) denotes the union complexity of
the objects in D. More precisely, U(·) is a function such that the combinatorial complexity
of the union of any subset D′ ⊆D is at most U(|D′|). It is well known that U(n) = O(n) for
pseudodisks [29], and that U(n) = O(n2O(log∗n)) for so-called locally fat3 objects [1]. Thus,
for these classes of objects we obtain an O(n polylog n) algorithm.
The following theorem states our result more precisely. The function λt(n) in the theorem
is the maximum length of a Davenport-Schinzel sequence of order t on n symbols [37], which is
near-linear for any fixed constant t. In particular, λt(n) = O(n log∗n) for any constant t [39];
more precise bounds, which depend on the exact value of t, are known as well [35].
▶Theorem 1. Let D be a set of n constant-complexity objects from a family of objects
with union complexity U(n), and such that any two boundary arcs intersect at most s times.
Then we can solve sssp on the intersection graph G×[D] in O(λs+2(U(n)) log2 n) expected
time. In particular, the expected running time is O(λs+2(n) log2 n) for pseudodisks and it is
O(λs+2(n)2O(log∗n) log2 n) for locally fat objects.
At a very high level, our algorithm follows the same approach as used by Klost [30] and by
De Berg and Cabello [18]. Let Dsrc be the source object, define Lj ⊂D to be the set of
objects at distance j from Dsrc, and define union(Lj) to be the union of the objects in Lj.
Then, instead of querying with each object D ∈Lj to discover the objects in Lj+1, we do
the following: we identify a set Cj+1 ⊇Lj+1 of candidate objects, and we determine which of
them intersect union(Lj) (and are thus in Lj+1). The main challenges are (i) to ensure that
each object is a candidate only a few times, and (ii) to determine efficiently which of the
candidates in Cj+1 intersect union(Lj). Klost [30], and De Berg and Cabello [18], heavily
use the fatness of the objects to overcome (i), and they use Voronoi diagrams (or, for fat
triangles, intersection-detection data structures) to overcome (ii). Hence, we must develop
completely different tools.
Our main tool, which is useful to overcome both challenges, is what we call a random
stacking. This is a subdivision of union(D) obtained by adding the objects “on top of each
other” in random order; see Figure 1. The important properties of a random stacking
are that the expected number of faces of the subdivision is O(U(n)), that the expected
number of crossings between object boundaries and face boundaries is O(U(n) log n), and

because we can prove that each component of f \ union(Lj) is simply connected.
The Diameter problem.
The Diameter problem, which asks for the maximum distance
between any two nodes in a graph, is another fundamental algorithmic problem on graphs.
In general graphs, it can be solved in O(nm) time by running sssp n times, once with each
node as the source. One can also use fast matrix multiplication to obtain an O(nω) time
algorithm, where ω ≈2.37 is the matrix-multiplication exponent, which is faster for dense
graphs. A major open problem has been whether there is a truly subquadratic algorithm for
sparse graphs. Cabello [7] achieved a breakthrough in this area by showing that Diameter
on planar graphs can be solved in ˜O(n11/6) expected time. (His algorithm even works for
weighted graphs.) This was improved to ˜O(n5/3) by Gawrychowski et al. [26].
For intersection graphs the situation is less rosy: even deciding whether the diameter
of an intersection graph of unit-length segments is at most 3 cannot be done in O(n2−ε)
time for any ε > 0, assuming the Strong Exponential-Time Hypothesis [6]. The same
holds for unit-size equilateral triangles. For unit disks, Chan et al. [9] recently presented
an O(n2−1/18+o(1)) algorithm for Diameter. (For arbitrarily-sized axis-aligned squares
and axis-aligned unit squares, they obtain ˜O(n2−1/12) and O(n2−1/8+o(1)) running time,
respectively.) It is still open whether a subquadratic algorithm for Diameter exists for
arbitrarily-sized disks. In fact, even near-quadratic algorithms are rare: so far they only exist
for classes of objects for which sssp admits a near-linear algorithm. Thus, our sssp algorithm
for objects with near-linear union size provides the first near-quadratic exact algorithm for
sssp for pseudodisks and for general fat objects.
The difficulty of Diameter led Chang, Gao and Le [14] to study the problem of
computing the diameter almost exactly, namely, up to an additive constant. They presented
a subquadratic algorithm for similarly-sized disks (and for similarly-sized fat pseudodisks
satisfying a strong monotonicity condition; see above). Their algorithm runs in ˜O(n2−1/18)
time and it computes the diameter up to an additive error of 2. In the arXiv version of
the paper [13], they improve the error to 1. To obtain this result, they first prove that the
so-called distance VC-dimension and the distance-encoding VC-dimension of a pseudodisk
graph are at most 4; see [14, Theorems 12 and 14]. Their proofs are purely topological, so
they do not require the pseudodisks to be fat, convex, or similarly sized. They then describe
a framework to compute the diameter almost exactly, which requires two ingredients: an
algorithm that computes a so-called clique-based r-clustering for the given graph class—this is
a generalization of r-divisions [23] for planar graphs—and an O(n polylog n) sssp algorithm.
They present an algorithm that computes a clique-based clustering for similarly-sized fat
pseudodisks, and an sssp algorithm for similarly-sized fat objects satisfying a monotonicity
condition.

Our results on Diameter.
To obtain a Diameter algorithm for pseudodisks, we need to
supply two ingredients: a suitable r-clustering and an sssp algorithm. The latter is the first
contribution of our paper, as discussed above. For the former we observe that the subgraphs
that make up the boundary in the r-clustering need not be cliques, as was the case in [14]: it
suffices that each of these subgraphs has a representative node that is a neighbor of any other
node in the subgraph. Thus, instead of working with a clique-based r-clustering, we may
also work with a star-based r-clustering. We show how to compute a star-based r-clustering
for a pseudodisk graph—in fact, our algorithm works for any class of objects with near-linear
union complexity—with similar quality guarantees as the clique-based r-clustering of Chang,
Gao and Le [14]; interestingly, our algorithm for computing an r-clustering also uses random
stackings. Since r-divisions for planar graphs have found many applications, we expect that
our star-based r-clusterings may find other applications as well.
Our star-based r-clustering has a stronger bound on the number of stars that comprise
the boundary of a cluster, as compared to the number of cliques that comprise the boundary
of a cluster in the clique-based clustering of [14]. This allows us to not only obtain an
algorithm for a much larger class of objects, but it also allows us to improve the ˜O(n2−1/18)
running time, as stated in the following theorem.
▶Theorem 2. Let D be a set of n constant-complexity pseudodisks. Then we can solve
Diameter on the intersection graph G×[D] in ˜O(n2−1/14) expected time, up to an additive
error of 2.
Distance oracles.
A distance oracle for a graph G = (V, E) is a data structure that
can report the distance between any two query nodes u, v ∈V .
For arbitrary graphs,
exact distance oracles require Ω(n2) bits of storage in the worst case, irrespective of query
time [40]. Hence, research on distance oracles focused on special graph classes such as planar
graphs, where the goal is to obtain sublinear query time with subquadratic storage. The
survey by Sommer [38] gives an overview of the work done until 2014, and the paper by
Charalampopoulos et al. [15] and the references therein give an overview of more recent work.
For geometric intersection graphs only a few results are known [2, 9, 11, 13, 20, 25]. Both
Gao and Zhang [25] and Chan and Skrepetos [11] show that an (1 + ε)-approximate distance
oracle with O(n log n) storage4 and O(1) query time exists for unit-disk graphs; their oracle
also works in the weighted setting. Chang, Gao and Le [13] show that their technique for
computing the diameter almost exactly, can also be used to obtain a distance oracle for
similarly-sized fat pseudodisks that uses O(n2−1/18) storage, has query time O(1), and an
additive error of 1. The paper by Chan et al. [9] that provides the first exact subquadratic
Diameter algorithm for unit disks also provides the first exact distance oracles for unit
disks; it uses O(n2−1/20+o(1)) storage and has O(log n) query time. (For axis-aligned squares
they obtain better bounds.) We show that our star-based r-clustering can be used to extend
the distance oracle of Chang, Gao and Le to arbitrary pseudodisks, and improve the storage
bound at the same time. Our oracle uses O(n2−1/13) storage—note that this bound is smaller
than the computation time of our Diameter algorithm—and has O(1) query time, and it
can report distances with an additive error to 2.

Stackings.
Let π be a permutation of {1, . . . , n}, which defines an ordering of the objects
in our input set D. (See the introduction for the definition of “object”.) Imagine drawing
the objects one by one in the order given by π, such that each object is drawn on top of
the previous ones, that is, each object hides the parts of the objects already drawn that are
covered by it. We call the resulting subdivision of union(D) a stacking5 of the set D, and

the faces in S∗

the boundary arcs of the objects. This boils down to solving the following variant of the
red-blue intersection problem: given a set R of x-monotone red arcs that are the edges of a
connected9 planar subdivision, and a set B of x-monotone blue arcs, compute all intersections
between a red arc and a blue arc. We call these intersections purple. Note that there are no
intersections between two red arcs (except at shared endpoints, which we do not consider to
be intersections). There can be many intersections among the blue arcs—we call them blue
intersections—and our goal is to avoid spending time on them.
Let m := |R| + |B| and let k be the number of purple intersections. The general red-blue
intersection problem requires Ω(m4/3 + k) time, even when R is a connected set of line
segments and B is a set of points. There are, however, variants that can be solved in
O((m + k) polylog m) time. In particular, Basch, Guibas, and Ramkumar [3] showed that
the version where the red set is connected and the blue set is connected—more formally,
the union of the arcs in the red (resp. blue) set should be connected—can be solved in
O(λs+2(m + k) log3 m) time. The running time was later improved to O(λs+2(m + k) log m)
expected time by Har-Peled and Sharir [27]. In our setting, B is not necessarily connected,
but because R is the edge set of a connected subdivision, we can still use the technique of
Har-Peled and Sharir. The key insight is that Har-Peled and Sharir need B to be connected
to be able to process R efficiently, but processing R is easy anyway when the red arcs do not
cross each other.
▶Theorem 7. Let R be a set of x-monotone red arcs that are the edges of a connected planar
subdivision, and let B be a set of x-monotone blue arcs. Let s be the maximum number of
intersections between any two arcs in R ∪B. Then we can solve the red-blue intersection
problem on R ∪B in O(λs+2(m + k) log m) expected time, where m := |R| + |B| and k is the
number of purple intersections.
Proof. We first sketch the algorithm of Har-Peled and Sharir [27], which was designed for
the setting where both R and B are connected sets, and then we adapt it to our setting.
The algorithm sweeps a vertical line ℓfrom left to right over the plane, with the goal
of maintaining visibility pairs, which are pairs consisting of a red arc ρ and a blue arc β
that see each other along ℓ. (More formally, a visibility pair at a given position of ℓis a

charges the time spent for the simultaneous sweep to hot red or blue trapezoids and purple
intersections.

3.2
The Diameter algorithm
We now present an algorithm to approximate the diameter of the intersection graph G :=
G×[D] of a set D of pseudodisks, up to an additive error of 2. Note that the objects in D
must be pseudodisks; it is not sufficient if their union complexity U(n) is near-linear. Also
recall that U(n) = O(n) for pseudodisks. In the following, it will be convenient to denote
the node set of G×[D] by V (even though V = D).
Let d(u, v) denote the hop distance between two nodes u, v in G. Recall that the eccentricity
of a node u is defined as ecc(u) := maxv∈V d(u, v). Thus, diam(G) = maxu∈V ecc(u) and it
is sufficient to approximate the eccentricity of each node u ∈V up to an additive error of 2.
Following the framework of Chang, Gao, and Le [14] we will approximate the eccentricities
using an (in our case star-based) r-clustering and using so-called patterns, as introduced by
Fredslund-Hansen, Mozes, and Wulff-Nilsen [24]. The concept of patterns has also been used
in earlier works [31, 41].
Patterns.
Let Q = ⟨q0, . . . , qk−1⟩be a sequence of (not necessarily neighboring) nodes in a
given graph G. The pattern of a node v with respect to Q is the k-dimensional vector Pv,Q
such that Pv,Q[i] = d(v, qi) −d(v, q0) for every 0 ⩽i ⩽k −1. The distance between some
node u and a pattern Pv,Q is defined as d(Pv,Q, u) := mini{d(u, qi) + Pv,Q[i]}.
Observe that if two nodes u, v have the same pattern with respect to Q, then d(u, qi) =
d(v, qi) + δ for all i, where δ := d(u, q0) −d(v, q0). Hence, either all distances from u to the
nodes in Q are the same as the distances from v, or they are all larger, or they are all smaller.
This can be used to speed up the diameter computation for a planar graph G, as follows.
Let C be a region in an r-division (C, S) of G, and suppose we want to determine the node
v ̸∈C that is furthest away from any of the nodes in C. Then, by the observation just made,

In our setting, we have a pseudodisk graph and we will use a star-based r-clustering C.

The

to a node in C must pass through a node in S(C) but observe that for nodes u and v for
which a shortest path π(u, v) goes through a node (which is a star center) in Q, we have
d(u, v) = d(Pv,Q, u) + d(v, q0). When π(u, v) visits a node adjacent to a node in Q, then we
have a slightly weaker guarantee, as stated in the following lemma. The lemma is similar to
Lemma 16 by Chang, Gao, and Le [14].
▶Lemma 22. Let Q be an arbitrary sequence of nodes in a graph G.
(i) For any two nodes u, v ∈V we have d(u, v) ⩽d(Pv,Q, u) + d(v, q0).
(ii) If there is a shortest path π(u, v) that contains a neighbor of a node in Q, then we
additionally have d(Pv,Q, u) + d(v, q0) ⩽d(u, v) + 2.
(iii) If there is a shortest path π(u, v) that contains a node in Q, then d(Pv,Q, u) + d(v, q0) =
d(u, v).
Proof. Because d(Pv,Q, u) + d(v, q0) is the length of a valid path between u and v—namely
a path via a node in Q—we have d(u, v) ⩽d(Pv,Q, u) + d(v, q0). This proves (i).
Now suppose π(u, v) contains a node w that has a neighbor q ∈Q. Note that d(Pv,Q, u) +
d(v, q0) ⩽d(u, q) + d(q, v) because q ∈Q. Because w and q are neighbors, we have
d(u, q) + d(q, v) ⩽d(u, w) + d(w, v) + 2 = d(u, v) + 2,
which proves part (ii) of the lemma. Part (iii) follows in a similar manner.

The algorithm.
Our algorithm is the same as that of Chang, Gao, and Le [14], except that
we replace their clique-based r-clustering with our star-based r-clustering and replace their
sssp algorithm with ours.
The additive error of 2 in the computation does not change: they can pick any node
in a clique as a representative, while we must take the center of a star, but the important
property is that this representative has distance 1 to all other nodes in the clique or star.
This is enough to give an additive error of 2; see our Lemma 22 and their Lemma 16. We
note that the improvement to an additive error of 1, which is described in the arXiv version
of their paper [13], does not apply when working with stars instead of cliques.
Our running time is better than theirs, as explained next.
Recall that we use the
nodes in S(C) to define the patterns for a cluster C. Our clusters have local boundary
complexity O(√r) and size r. By Lemma 24, this means that the number of different
patterns for a cluster is O((r√r)4) = O(r6). They only have a bound on the global boundary
complexity, so they obtain a bound of O((r · r)4) = O(r8) on the number of patterns. A
careful analysis shows that this improves the running time from ˜O(n2−1/18) to ˜O(n2−1/14).

Recall that the goal of the algorithm is to compute the eccentricity of each node. We
start by giving the intuition behind the algorithm.
We use our star-based r-clustering C on the intersection graph G := G×[D], which allows
us to distinguish two types of shortest paths: shortest paths that are fully contained in one
cluster C ∈C, and shortest paths that leave the cluster. To handle the first type we can
simply do the following for each cluster C: run the sssp algorithm from Theorem 1 on G×[C]

clusters, this takes ˜O(r2 · (n/√r)) = ˜O(n2/√r) time.

Concluding remarks
We presented the first O(n polylog n) sssp algorithm for arbitrary (constant-complexity)
pseudodisks. This significantly extends the class of objects for which sssp can be solved in
near-linear time: so far, the only O(n polylog n) sssp algorithm for pseudodisks required them
to be similarly-sized, fat, and satisfy a strong monotonicity assumption, or (for arbitrarily-
sized objects) be a Euclidean disk. Our algorithm not only works for any arbitrary set
of pseudodisks, but it works for any set D of constant-complexity objects whose union

29
complexity is O(n polylog n). More precisely, the expected running time of our algorithm is
O(λs+2(U(n))·log2 n), where U(n) denotes the union complexity of D and s is the maximum
number of intersections between any pair of boundary arcs.
An obvious question is whether the running time can be improved. We note that until
recently [5, 18] the fastest sssp algorithm for Euclidean disks ran in O(n log2 n) time, and
that these recent improvements for disks use techniques that do not apply in our much more
general setting. Hence, improving the O(λs+2(U(n)) · log2 n) running time that we achieve
might be quite challenging.
Apart from log-shaving, one can also wonder if there are more general families of objects
that admit an O(n polylog n) sssp algorithm. This is most likely not possible for segments,
because of Erickson’s Ω(n4/3) lower bound [22] for Hopcroft’s problem. We do not see any
natural class of objects that is more general than objects with near-linear union complexity
but less general than segments, so it is not quite clear what to look for.
We also presented an efficient star-based r-clustering for objects with small union
complexity; this is a variant of widely used r-divisions of planar graphs [23]. We expect that
our star-based clusterings may find other applications as well.
Finally, we showed that our sssp algorithm and star-based r-clusterings together are
enough to run the Diameter algorithm of Chang, Gao, and Le [14] to approximate the
diameter of a pseudodisk graph up to an additive factor of 2. This not only extends the
class of objects for which the diameter can be computed almost exactly, but the stronger
complexity guarantees of our star-based r-clustering also mean that the ˜O(n2−1/14) running
time that we achieve is better than what Chang, Gao, and Le obtain. Can the running time
be improved even further? Or can we extend the result from pseudodisks to objects with
near-linear union complexity? For computing the exact diameter, this is ruled out (under
SETH) by the lower bound of Bringmann et al. [6], but does a subquadratic algorithm exist
that is almost exact? And can we perhaps even obtain an exact algorithm with subquadratic
running time for pseudodisks? Since this is so far only known for unit disks and squares, a
more modest goal would be to obtain a subquadratic exact algorithm for (arbitrarily-sized)
disks.
