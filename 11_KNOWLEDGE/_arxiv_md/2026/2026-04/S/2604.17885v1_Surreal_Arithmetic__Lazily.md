LLOYD ALLISON
Monash University, Australia
(email: lloyd.allison@monash.edu)
Abstract
Conway’s surreal numbers were aptly named by Knuth. This note examines how far one can get towards
implementing surreals and the arithmetic operations on them so that they execute efficiently. Lazy
evaluation and recursive data structures yield a considerable speed up.
keywords: surreal numbers, arithmetic, functional programming, circular program, corecursion
1
Introduction
Conway defined the surreal numbers as described in his ‘ONAG’ book [2]; initially he had
simply called them ‘numbers’ but Knuth coined the name ‘surreal numbers’ [3] which is
very appropriate given the bewitching universe of numbers that the system created and it
was readily accepted [4]. From the simplest of beginnings the full surreal numbers propagate
to include integers, rationals, irrationals and even transfinite numbers, forming the largest
ordered field [1].
Various authors have played more or less deeply in the programming of surreals to see
how much to do with them can be implemented in computer programs. Perhaps the most
practical prior work of this kind, as its title suggests (although “practically” can be read
in two ways), is by Roughan [5] who used the programming language Julia as the means.
In considering earlier efforts he noted that “There are several prior implementations of the
surreals in various programming languages ... Most of these are very incomplete” which
pretty much holds today.
This note describes a more practical way of implementing surreal numbers that have finite
representations, with the operators ≤, <, ≥, >, =, ≠, +, −, × on them, as they are specified
by Conway, and that runs quickly through the use of laziness and mutually recursive data-
structures and functions. An interactive calculator has been programmed and is available1 to
play with.

All attempts at “everyday” programming with surreals limit themselves to “short” surreals
– those having finite representations. Values like 1/3,
√

representations as surreals although each of these examples is computable in that we can write
a program that returns a short surreal that is as close as desired to the real value. The focus
therefore has been on implementing the short surreals, the comparisons and the operators
+, −, ×.
Before getting down to the business, there is the matter of the rules of the game. If we just
wanted to evaluate expressions with short surreals as quickly as possible we would likely
convert them to rational numbers, which some languages and some hardware already support,
compute with those and convert the result back to surreals. However that would be cheating.
Instead the ethical path is to implement Conway’s definitions as far as is possible and to see
what emerges from that.
We can define the “Genealogy” Tree of surreals, SNs, as in figure 2. It is an infinite Tree
but just finite parts are built, only as necessary from use. Given an arbitrary representation, 𝑥,
the function canonical searches for the node where the surreal that 𝑥represents was born

At least one more optimisation is possible. The select operation acts in the style of
canonical by following the path from zero to the birth of x in SNs and tracing out a similar
path in another Tree, tr, in order to find the node that corresponds to x. To do so it carries out
a number of comparison operations, ultimately ≤operations; these are not atomic operations.
To avoid them where possible, the parent of each child in the SNs tree can be kept within the
tree together with whether the child was the left- or the right-child. For a canonical surreal in
the SNs Tree, knowing parents allows the tracing of the paths in question without the use of
comparisons. Note that zero and non-canonical representations do not have parents.
3
Implementation
The methods described above have been implemented in javascript – which can be used as a
quite passable functional programming language. It is not a lazy languages so the laziness
is implemented explicitly in the code however javascript does have the advantage of easily
leading to an interactive calculator which runs within a web-page without having to install
any special software.
With regard to speed, for Roughan’s Julia implementation note “computation times for 3×5
... were reduced from 39.9 to 28.5 h in going from Julia 0.6 to 1.0” [5] (p.298). In comparison,
times for the multiplication 𝑛× 𝑛using the javascript implementation and the methods
described here are given in table 1. There are two columns, one for not using the “parents”
optimisation and one for using it. Note that addition is much faster than multiplication.
To make its results more readable the calculator gives each surreal number a meaningful
name but names are just for the benefit of human readers and do not enter into calculations
which are carried out according to Conway’s rules.

Speculation
The short surreals have finite representations and are born in finite generations. Conway
[2] (p.12) introduces the first non-finite surreal 𝜔= ⟨1, 2, 3, ...|⟩born in generation 𝜔. The
surreal 𝑒, 𝜋,

Summary
An interactive calculator for short surreal numbers has been created (sec.3), following
Conway’s rules of arithmetic [2], and using recursively defined data structures and functions
(sec.2) and lazy evaluation to run orders of magnitude faster than previous implementations
of surreal arithmetic.
