A Simple Average-case Analysis of
Recursive Randomized Greedy MIS
Mina Dalirrooyfard
Konstantin Makarychev∗
Slobodan Mitrović†
Abstract
We revisit the complexity analysis of the recursive version of the randomized greedy algorithm
for computing a maximal independent set (MIS), originally analyzed by Yoshida, Yamamoto,
and Ito (2009). They showed that, on average per vertex, the expected number of recursive calls
made by this algorithm is upper bounded by the average degree of the input graph. While their
analysis is clever and intricate, we provide a significantly simpler alternative that achieves the
same guarantee.
Our analysis is inspired by the recent work of Dalirrooyfard, Makarychev, and Mitrović
(2024), who developed a potential-function-based argument to analyze a new algorithm for
correlation clustering. We adapt this approach to the MIS setting, yielding a more direct and
arguably more transparent analysis of the recursive randomized greedy MIS algorithm.

Introduction
Given a graph G “ pV, Eq, a subset of vertices I is called independent if it contains no pair of
adjacent vertices. If, in addition, I cannot be augmented by adding new vertices to it while remaining
independent, I is a maximal independent set (MIS). While the maximum independent set problem
is NP-hard, MIS admits a simple linear-time greedy algorithm. In the context of sublinear-time
algorithms, in 2008, Nguyen and Onak [7] asked how efficiently one can determine whether a given
vertex belongs to a maximal independent set (MIS).1 For that purpose, they studied the randomized
greedy MIS (RGMIS) approach – outlined as Algorithm 1 – and analyzed its recursive version, which
can be phrased as follows. Given a vertex v and a permutation π, recursively test whether any of
the neighbors u of v with πpuq ă πpvq is in MIS. If it is, return that v is not in MIS; otherwise,
return that v is in MIS. Nguyen and Onak showed that, on graphs with maximum degree ∆, this
recursive algorithm, when executed from an arbitrary vertex, makes at most 2Op∆q recursive calls
in expectation, where the expectation is taken over all permutations π.
In the same work, Nguyen and Onak conjectured that the following natural heuristic optimiza-
tion yields a faster algorithm for testing whether a vertex is in MIS or not: in the recursive test,
v examines its neighbors in increasing order with respect to π and returns that v is not in MIS
upon encountering the first neighbor that has already been included in MIS. This version
is given in Algorithm 2.

In 2009, Yoshida, Yamamoto, and Ito [10] provided an ingenious analysis showing that this
conjecture is not only true, but executing Algorithm 2 from every vertex in the graph requires at
most m recursive calls in total, in expectation over π. That result is typically stated in the literature
as an average-case guarantee: in expectation over all vertices v P V and all π, RGMISpv, πq performs
at most m{n ď ∆{2 recursive calls.
Over recent years, the analysis and result of Yoshida, Yamamoto and Ito has been used in
and has inspired several important discoveries, including developing sublinear-time algorithms for
approximating the minimum vertex cover [8] and the maximum matching size [3], designing a more
efficient MPC algorithm for maximal matching [5], obtaining a very fast parallel algorithm for almost
3-approximate correlation clustering [4], analyzing average sensitivity of graph algorithms [9], and
developing an algorithm for stochastic matching [2]. For instance, Behnezhad, Charikar, Ma, and
Tan [4] build, in a clever way, on the analysis of [10] to show that a truncated version of the
celebrated Pivot algorithm [1] yields an almost 3-approximation for correlation clustering.2 This
truncation is the key reason why their algorithm can be implemented in small depth in parallel
settings and in a small number of passes in the semi-streaming model. We believe that our work
opens avenues for novel results and alternative analyses for these and related problems.

Counting Recursive Calls using Query Paths
We first show how to bound the expected number of recursive calls in Algorithm 2 by analyzing
Algorithm 1. Consider the recursive calls made by Algorithm 2 when it is invoked on a vertex u.
Suppose the algorithm makes a recursive call from RGMISpv, πq to RGMISpw, πq.
We define the
oriented edge pw, vq as a query edge (although it may seem more natural to call pv, wq a query edge,
we adopt this definition for convenience later on). It is easy to see that any sequence of recursive
calls with parameters u “ uk, uk´1, . . . , u1 corresponds to a directed path pu1, . . . , ukq in which
each edge is a query edge. We refer to such paths as query paths; we define this notion formally in
the following section. Then, the number of recursive calls for vertex u equals the number of query
paths that end at u. To count recursive calls, we are going to consider the sequential version of
Algorithm 2 presented in Algorithm 3.
In Algorithm 1, we did not specify how to determine whether any neighbor of π´1ptq is in I.
This detail is crucial for our proof: for the proof to go through, we need to consider the neighbors
of π´1ptq in the order given by π, as shown in Algorithm 3. Algorithm 3 implements the same
greedy heuristic but differ in the way they construct the membership dynamic table RGMISpv, πq:
Algorithm 3 uses a bottom-up approach, while Algorithm 2 uses a top-down approach.
Thus,
RGMISpv, πq returns true if and only if Algorithm 3 includes v in the set I.
Note that we can identify query paths by observing the behavior of Algorithm 3 rather than
that of Algorithm 2: an edge pw, vq is a query edge if Algorithm 3 examines vertex w during the
iteration πpvq – the iteration in which it determines whether v is in the MIS. Thus, we can count the
number of recursive calls made by Algorithm 2 when invoked on vertex u by running Algorithm 3,
marking the query edges, and counting the number of directed query paths that end at vertex u.
