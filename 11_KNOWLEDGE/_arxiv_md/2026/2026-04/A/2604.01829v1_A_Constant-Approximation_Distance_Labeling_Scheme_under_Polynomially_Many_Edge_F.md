A Constant-Approximation Distance Labeling Scheme
under Polynomially Many Edge Failures
Bernhard Haeupler∗
Yaowei Long†
Antti Roeyskoe‡
Thatchaphol Saranurak§
Abstract
A fault-tolerant distance labeling scheme assigns a label to each vertex and edge of an undi-
rected weighted graph G with n vertices so that, for any edge set F of size |F| ≤f, one can
approximate the distance between p and q in G \ F by reading only the labels of F ∪{p, q}.
For any k, we present a deterministic polynomial-time scheme with O(k4) approximation
and ˜O(f 4n1/k) label size. This is the first scheme to achieve a constant approximation while
handling any number of edge faults f, resolving the open problem posed by Dory and Parter
[DP21]. All previous schemes provided only a linear-in-f approximation [DP21, LPS25].
Our labeling scheme directly improves the state of the art in the simpler setting of distance
sensitivity oracles. Even for just f = Θ(log n) faults, all previous oracles either have super-linear
query time, linear-in-f approximation [CLPR12], or exponentially worse 2poly(k) approximation
dependency in k [HLS24].

Introduction
A labeling scheme for a graph problem is a distributed data structure that assigns short labels to
vertices and/or edges, with the capability to answer queries given only the assigned labels of the
query arguments (and no other access to the underlying graph). Early work on labeling schemes
focused on schemes for adjacency [Bre66, BF67, KNR92], with connections to induced universal
graphs [ADK17, AKTZ19]. Other schemes have been developed for graph connectivity [KKKP04,
HL09, IN12, PSY22] and basic queries on trees, such as ancestry and lowest common ancestors
[AAK+06, AHL14, ADK17].
Distance Labeling Schemes: Well-Understood.
One of the most extensively studied prob-
lems in this area is the distance labeling scheme formalized by Peleg [Pel00]. Given an n-vertex
graph G = (V, E), the task is to assign a label L(u) ∈{0, 1}s to each vertex u so that, for
any p, q ∈V , the distance between p and q in G can be decoded from only the labels L(p) and
L(q). A scheme with optimal label size of s = Θ(n) bits was established following the resolution
of the squashed cube conjecture [GP72] by Winkler [Win83], and the bound was further refined
in [GPPR04, WP11, AGHP16a, GKU16]. Allowing for approximation, Matousek’s ℓ∞-embedding
[Mat96] implies labeling schemes with sublinear size. For any k ≥1, the scheme achieves a 2k −1
approximation using ˜O(n1/k) label size.1 Thorup and Zwick [TZ05] later improved the decoding
time to O(k).
As argued in [TZ05], this approximation-size trade-off is tight under the Erdős
girth conjecture, and an unconditional lower bound of nΩ(1/k) holds. Thus, the optimal trade-off is
essentially settled.
Fault-Tolerant Distance Labeling Schemes.
The problem becomes significantly more chal-
lenging in the fault-tolerant labeling setting introduced in [CT07]. Here, we assign a label to each
vertex and edge so that, for any p, q ∈V and edge set F ⊆E of size |F| ≤f, the distance between
p and q in G \ F, the graph where edges in F fail, can be decoded from the labels L(p), L(q), and
L(e) for all e ∈F.
In the exact case, the best-known label size is ˜O(n2−1/2f ) [BP23], which is trivial when f =
Ω(log log n) as one can store the entire graph in labels of size Θ(n2). When allowing approximation,
previous schemes [DP21] can only guarantee an approximation ratio linear in the maximum number
f of faults. Specifically, in [DP21], Dory and Parter showed a reduction to fault-tolerant connectivity
labeling schemes, where the task is to check connectivity instead of estimating distances. Plugging
in known connectivity labeling schemes [DP21, LPS25], their reduction implies, for any k ≥1, a
labeling scheme with (8k−2)(f +1) = O(kf) approximation and label size ˜O(n1/k) for a randomized
scheme or ˜O(√fn1/k) for a deterministic one. Note that the approximation quality worsens as f
increases, and that notably, the scheme is unable to provide constant approximation under any
nonconstant number of failures.
Thus, Dory and Parter posed an open problem in [DP21]: “Finally, it will be also important to
provide fault-tolerant distance approximate labeling schemes whose stretch bound is independent of
the number of faults f”.
1.1
Main Result: Constant-Approximate FT Labeling Scheme
We affirmatively answer the open problem posed by Dory and Parter: we present the first constant-
approximate fault-tolerant distance labeling scheme that can handle any number of faults.

Theorem 1.1. For every k ≥1, there is a fault-tolerant distance labeling scheme for an undirected
n-vertex graph with edge lengths in [1, poly(n)] undergoing f edge faults, with O(k4) approximation
and ˜O(f4n1/k) label size. The approximate distance can be decoded from the input labels in near-
linear ˜O(f5n1/k) time. The labels can be computed deterministically in polynomial time.
Theorem 1.1 completely removes the dependency on f from the approximation ratio of previous
schemes [DP21], and has only a polynomial label size dependency on f. In other words, we can
tolerate even a polynomial number of failures f = O(n1/k), while still guaranteeing a constant
approximation and small nO(1/k) label size.
The improvement comes at the cost of a worse O(k4)-approximation dependency on k. We note
that this dependency can be improved to O(k3) if exponential construction time is allowed. See
Theorem 5.1 for the more detailed statement of Theorem 1.1.
1.2
Consequence: Improved Sensitivity Oracles
Theorem 1.1 also significantly improves the state-of-the-art of one of the most extensively studied
graph data structure problems: the distance sensitivity oracle problem.
In this problem, we must build a data structure on a graph G = (V, E) so that, given any
p, q ∈V and edge set F of size |F| ≤f, one can quickly approximate the distance between p
and q in G \ F. Observe that an oracle is a strict relaxation of a labeling scheme because, given
the input {p, q} ∪F, the algorithm can adaptively read any part of the data structure, instead of
non-adaptively reading only the labels of {p, q} ∪F. Additionally, a labeling scheme must evenly
distribute useful information among vertices and edges, whereas an oracle faces no such restriction.
Previous Oracles: Few Faults or Inefficient.
Despite extensive research, almost all previous
oracles either can handle at most f = O(log n) faults or require super-linear query time or super-
polynomial space. Specifically, most exact oracles [DTCR03, DTCR08, BK08, BK09, DP09, Wil11,
BK13, DZ17, CC20, GR21, BCFS21, Ren22, DG24a] handle only f ≤2 faults. More recently, oracles
for multiple faults have been discovered [DR22, DG24b], but their query time is super-exponential
in f and, hence, super-linear when f = ω(log n).
The query time of [WY13, vdBS19, KS23]
is also always super-linear.
Even when approximation is allowed, every oracle from [CCFK17,
BCC+23b, BCC+23a, BCC+24] requires exponential-in-f space and, thus, super-polynomial when
f = ω(log n). An approach based on fault-tolerant spanners [LNS98, CLPR09, BDR21, BDR22]
also requires directly computing distance on top of the spanners, taking super-linear query time.
The Exceptions.
To our knowledge, only two known oracles do not suffer from the above limita-
tions. The first oracle, by Chechik, Langberg, Peleg, and Roditty [CLPR12], has (8k −2)(f + 1) =
O(kf) approximation, ˜O(fkn1+1/k) space, and ˜O(f) query time for any k ≥1. However, its ap-
proximation is still linear-in-f.
The second oracle follows from the recent dynamic distance oracle with worst-case update time
by Haeupler, Long, and Saranurak [HLS24].
It provides an oracle with 2poly(k) approximation,
O(mn1/k) space, and O(fn1/k) query time for any k ≤logo(1) n.
Theorem 1.1 implies a new oracle that handles any number of faults and significantly improves
upon both [CLPR12, HLS24].
Corollary 1.2. For every k ≥1, there is a deterministic distance sensitivity oracle for undirected
n-vertex graphs with edge lengths in [1, poly(n)] undergoing f edge faults, with O(k4) approximation,
˜O(f4n1+1/k) space, and ˜O(f5n1/k) query time. The oracle can be constructed in polynomial time.

1.3
Our Technique
We bridge the theory of length-constrained expanders [HRG22, HHT24, HHL+24, HLS24] to the
area of labeling schemes. Our technique strengthens two recent developments as follows:
1. We lift the centralized technique from the dynamic distance oracle of [HLS24], which also uses
length-constrained expanders, to the distributed setting of labeling schemes. Additionally, we
improve their approximation ratio from 2poly(k) to poly(k).
2. We strengthen the technique from the connectivity labeling scheme of [LPS25], which uses
standard expanders, to work with length-constrained expanders, enabling distance computa-
tion instead of just connectivity.
We briefly explain why the techniques in [HLS24, LPS25] are insufficient for our result. Firstly,
we must avoid the two key primitives in [HLS24], the dynamic router and local flow subroutines,
as they are highly centralized. Furthermore, [HLS24] inherently pays at least a constant factor in
approximation for each of the k levels of their data structure, resulting in the 2poly(k) approximation.2
Lastly, length-constrained expanders are inherently more complex than the standard expanders
used in [LPS25].
In particular, it is unclear how to define a single spanning tree based on the
expander hierarchy as in [LPS25], and length-constrained cuts are fractional cuts, which introduces
complications.
The key step to overcome these obstacles is by introducing a stronger expander hierarchy called
the nested length-constrained expander hierarchy.

Our Technical Contribution: Nested Length-Constrained Expander Hierarchies.
Our
technical contribution is two-fold. First, we show how to utilize a nested length-constrained ex-
pander hierarchy to obtain our distance labeling scheme, which we will outline in Section 2. Sec-
ond, we present an approach to construct a nested expander hierarchy that generalizes to the
length-constrained setting. Indeed, previous approaches [Räc02, BKR03, HHR03, RST14, GRST21,
LRW25] do not seem to generalize to length-constrained expansion. In contrast, our approach is
simple, generic, and can extend to other notions of expansion, such as directed expansion.
We believe that both the concept of a nested expander hierarchy in the length-constrained setting
and our generic construction will likely find broader applications.
1.4
Other Related Results
Exact distance labeling schemes have been extensively studied in special graph classes, including
trees [Pel00, ABR05, AGHP16b], planar graphs [GKK+01, GPPR04, Tho04, GU23], and more
[KKP00, GP03a, GP03b, BG05, GL05].
In planar graphs [ACG12] and graphs with bounded doubling dimension [ACGP16], Abra-
ham et al. gave near-optimal fault-tolerant distance labeling schemes with (1 + ϵ)-approximation
and poly(log(n)/ϵ) label size. In the single fault setting where f = 1, there are labeling schemes
for (1 + ϵ)-approximation of single-source distances [BCHR20], exact distances in planar graphs
[BCG+22], and (1 + ϵ)-approximation of distance in directed planar graphs [BCG+25].

Overview
In this section, we will provide an overview of our fault-tolerant approximate distance labeling
scheme. However, for ease of presentation, our discussion is mostly under the oracle setting, where
the data structure is centralized and can be accessed without restrictions. We note that considering
the simpler oracle setting does not substantially simplify our algorithm, and thus it is sufficient to
illustrate the main intuition of our approach.
In fact, regardless of whether we work under the oracle or labeling scheme setting, our high-
level strategy is essentially the same: we aim to limit the number of vertices that need to be
touched/accessed when answering a query. More concretely, given a distance query between vertices
p and q under edge failures F, we hope to construct a small graph Gdisc called the discovered
graph (which includes the touched original vertices and edges, possibly augmented with additional
artificial ones), such that Gdisc approximately preserves the distance between p and q after failures,
i.e., distGdisc(p, q) ≈distG\F (p, q), and thus the query can be answered by running a shortest path
algorithm on Gdisc. To achieve a fast query time in the oracle setting, it is necessary that the
discovered graph Gdisc has a small size, bounded by poly(f, n1/k). Moreover, we construct Gdisc by
extracting local information from vertices p, q and the failed edges F, which makes it possible to
store the precomputed data structure in a distributed manner as a labeling scheme.
Our approach to constructing the discovered graph is expander-based, following a line of work on
expander-based oracles/labeling schemes for edge- and vertex-fault-tolerant connectivity problems
(e.g. [PT07, LPS25]). However, in order to solve the distance problem, we leverage the more pow-
erful notion of length-constrained expanders, which enables us to further capture distance-related
information. We point out that, when assuming the input graph is a good expander, all the afore-
mentioned expander-based algorithms (including ours) collapse into a simple and unified framework
(although the previous algorithms for connectivity do not need to construct the discovered graph
explicitly). We will discuss this in Section 2.1 for better understanding, and it already demonstrates
the power of length-constrained expanders in solving fault-tolerant distance problems.

However, extending the simple algorithm from expanders to general graphs entails not only
significant technical complications but also deeper fundamental challenges, resulting in an algorithm
that is very different from the counterparts for connectivity [PT07, LPS25]. Interestingly, such
challenges become easier to identify from a labeling-scheme perspective, and this is also the reason
why we obtain a labeling-scheme result first. To overcome these challenges, one of our technical
contributions is the introduction of nested length-constrained expander hierarchy, which is crucial
for achieving a poly(k) vs. poly(f, n1/k) tradeoff between approximation and label size. We will
elaborate on this in Section 2.2.
Lastly, we note that we compare our approach with: (1) previous O(kf)-approximation fault-
tolerant distance algorithms [CLPR12, DP21] in Section 2.1, and (2) previous expander-based fault-
tolerant connectivity algorithms [PT07, LPS25] at the end of Section 2.2.
2.1
The Expander Case
In this warm-up case, we assume the input graph G = (V, E) is a length-constrained expander. The
precise definition of a length-constrained expander is not very important, and we will only exploit one
of its key properties, which we will mention soon. Also, for simplicity, we only consider the single-
distance decision version of the problem. That is, we additionally receive a target distance h at the
beginning, and for each query ⟨p, q, F⟩, we want to correctly certify either (FAR) distG\F (p, q) > h
or (CLOSE) distG\F (p, q) ≤h · α for some approximation factor α ≥1.
To solve the original
problem, it is sufficient to check different length scales h (for example, taking different powers of
two as h). We first focus on the oracle setting, and will slightly discuss the labeling scheme setting
in the last paragraph.
Previous O(kf)-Approximate Oracles.
To motivate our algorithm, we first quickly outline the
previous O(kf)-approximate fault-tolerant distance oracles [CLPR12], and see where the linear-in-f
dependency comes from. The oracle is constructed in two steps.
Step 1. First, we construct a sparse neighborhood cover N of G with covering radius hcov = h,
diameter hdiam = kh, and width ω = ˜O(n1/k) [ABCP98].
Recall that such a neighborhood cover is a collection of ω many clusterings S ∈N, each of
which is a collection of disjoint clusters S ⊆V . The covering radius is hcov, meaning that for each
vertex v ∈V , its radius-hcov neighborhood B(v, hcov) = {v′ | distG(v, v′) ≤hcov} is contained by
some cluster S ∈S ∈N (we write S ∈N for short). The (strong) diameter is hdiam, meaning that
for each cluster S ∈N, the induced subgraph G[S] has diameter hdiam.
Step 2. For each cluster S ∈N, construct a fault-tolerant connectivity oracle Conn(S) for the
subgraph G[S].
To simplify the analysis, we use a tree-based fault-tolerant connectivity oracle
here (see, e.g., [DP20]). The connectivity oracle Conn(S) fixes a shortest path tree TS of G[S]
(rooted at an arbitrary vertex) and precomputes certain additional data structures that we omit
here. Whenever a connectivity query ⟨p, q, F⟩comes, the failed tree edges F ∩TS will break the tree
TS into at most f + 1 components, and the connectivity oracle simply connects these components
via the non-failed, non-tree edges (with the aid of the additional data structures).
To answer a distance query ⟨p, q, F⟩, we look at the cluster Sp containing the neighborhood
B(p, hcov). If its corresponding connectivity oracle Conn(Sp) indicates that p and q are connected
in G[Sp] \ F, return (CLOSE), otherwise return (FAR).
The correctness of the output (FAR) is easy to see: if distG\F (p, q) ≤h, then the underlying
shortest path must fall inside G[Sp] (this is guaranteed by the covering radius), and thus p and q
must be connected in G[Sp] \ F. The approximation O(kf) comes from the analysis of the output

The Key Property of Length-Constrained Expanders.
Therefore, to get rid of the f factor
in the approximation, we will exploit the following key property in Lemma 2.1, which holds when
the input graph G is a length-constrained expander. For a vertex subset Γ ⊆V , we let degG(Γ)
denote the total degree of vertices in Γ.
Lemma 2.1 (The key property). When G is a length-constrained expander, there is a value τheavy =
˜O(f · n1/k) satisfying the following. For any two vertex subsets Γ, Γ′ ⊆V , if they satisfy that
1. degG(Γ), degG(Γ′) ≥τheavy, and
2. distG(u, u′) ≤hdiam for all pairs u, u′ ∈Γ ∪Γ′,
then regardless of the set F of up to f edge failures, distG\F (Γ, Γ′) ≤hdiam · k, i.e. there exists a
path of length at most hdiam · k in G \ F from some u ∈Γ to u′ ∈Γ′.
We now give a high-level explanation of how exploiting Lemma 2.1 allows us to avoid an additive
loss at each component. For this, classify the components of TSp \ F into heavy components and
light components, where a component Γ is heavy if degG(Γ) ≥τheavy and light otherwise. Then, we
have the following win-win scenario:
For each light component Γ, it is affordable to touch all its incident edges in the query phase
(note that there are degG(Γ) < τheavy = ˜O(f ·n1/k) incident edges), so intuitively there is no additive
loss at all when going through a light component.
For the heavy components, Lemma 2.1 shows that any pair of heavy components Γ and Γ′ have
distG\F (Γ, Γ′) ≤hdiam · k; the components Γ and Γ′ satisfy condition 1 by definition, and satisfy

condition 2 as they are contained in the same cluster Sp of diameter hdiam. Therefore, intuitively,
when we want to find an approximate shortest path after failures, there is no need to go through
more than 2 heavy components: we can just jump from the first heavy component to the last heavy
component by paying an extra additive loss of hdiam · k. Each of the two heavy components still
incurs an additive loss of 2hk to traverse within, so the total additive loss is 4hk+hdiam·k = O(hk2).
In summary, we expect a total additive loss of O(hk2) , and should thus be able to achieve an
O(k2)-approximation.
Our Oracle.
We are ready to provide a formal description of our O(k2)-approximate fault-tolerant
distance oracle (for length-constrained expander graphs).
Proprocessing. The construction of the oracle is basically the same, which includes the neighborhood
cover N and, for each cluster S ∈N, the shortest path tree TS.
The Query Algorithm. The main difference lies in the query algorithm. Denote again by Sp ∈N
the cluster containing the neighborhood B(p, hcov) of the vertex p. We first define the discovered
graph Gdisc. The vertices V (Gdisc) of Gdisc include (1) for each light component Γ in TSp \ F, the
original vertices inside or adjacent to Γ, i.e. Γ ∪N(Γ), (2) for each heavy component Γ, an artificial
vertex called a component vertex, denoted by π(Γ), and (3) the two query endpoint vertices p and
q. There are three types of edges in Gdisc.
1. (original edges) First, we add all the original non-failed edges incident to light components.
2. (between original vertices and heavy components) For each original vertex v ∈V (Gdisc)∩V (G),
if the component Γv containing v is heavy, add an artificial edge between v and π(Γv) with
length 2hdiam = 2hk. Note that 2hdiam upper bounds the diameter of components.
3. (between heavy components) For each pair of heavy components Γ and Γ′, add an artificial
edge between π(Γ) and π(Γ′) with length hdiam · k + 4hdiam = hk2 + 4hk. Note that hdiam · k
upper bounds the distance between any two heavy components in G\F, and hdiam ·k +4hdiam
the distance between their furthest two vertices.
Providing the discovered graph Gdisc, we return (CLOSE) if distGdisc(p, q) ≤10hk2; otherwise, we
return (FAR). Note that we can compute distGdisc(p, q) by running any exact shortest path algorithm
on Gdisc.

The Labeling Scheme.
Lastly, we briefly discuss how to transform our oracle into a labeling
scheme. By our discussion above, it is sufficient if, by accessing the labels of F, we can extract the
following information for each cluster S and each component Γ of TS \ F: its degree degG(Γ), and
all its incident edges when degG(Γ) ≤τheavy. First, note that we can design labels for each cluster
S independently, because each vertex appears in at most ω = ˜O(n1/k) clusters (by the definition of
the width ω) which only incurs a multiplicative ˜O(n1/k) factor to the final label size.
Fixing a cluster S, a labeling scheme that can recover the above information by accessing the
labels of TS \F has already been shown in [LPS25]. The high-level idea is to consider the Euler tour
order of TS, and exploit that after failures, components will correspond to unions of intervals of the
order, where each such interval is preceded and succeeded by a failed edge. This makes everything
straightforward: (1) we can recover the total degree of an interval if the two failed edges delimiting
it store their prefix degree-sums in the order, and (2) we can detect up to τheavy of the incident
edges to an interval if the two failed edges store up to τheavy of the nearest edges in the order.

Comparison to Previous Expander-Based FT-Connectivity Algorithms.
After providing
an overview of our algorithm, we now highlight again the challenges we overcame, in comparison with
previous expander-based fault-tolerant connectivity oracles and labeling schemes [PT07, LPS25].
When the input graph is general, solving fault-tolerant connectivity problems via (classic) ex-
pander hierarchies admits a straightforward bottom-up merging procedure. For example, in [LPS25],
the clusters and their corresponding trees are very well-structured: the clusters (from all levels) form
a laminar family, and thus there is a single global tree serving as the skeleton of these clusters (i.e.,
14


## Page 17


the tree of a cluster is simply a subtree of the global tree). Consequently, the components generated
in a FT-connectivity query are also well-structured, which enables a simple bottom-up merging
procedure.
In contrast, since we are dealing with a distance problem, we need to employ tools that capture
distance information, such as length-constrained expanders and sparse neighborhood covers, which
introduce additional technical complications. In particular, we can no longer rely on a single global
tree, and therefore, require a novel top-down approach instead. We also face additional difficulties
with the aforementioned fractional cuts required for length-constrained expander decompositions.
Handling these fractional cuts typically requires randomization, but we employ additional techniques
to derandomize our whole algorithm.

Compiling a Distance Oracle for G \ F
While the Thorup-Zwick (2k −1)-approximate distance labeling scheme [TZ05] has labels of size
O(kn1/k), it only needs O(k) work to answer a distance query between two vertices u and v given
(pointers to) the labels of u and v. Our main result in Theorem 1.1 does not have this advantage,
taking an amount of work polynomial in the label size.
In this section, we show that this is not an issue in a setting where the edge failures are fixed
first, followed by multiple time-critical distance queries in G\F. Specifically, we show how to extend
any fault-tolerant distance labeling scheme so that given only the labels of the failed edges F, one
can “compile” an approximate distance oracle that can subsequently be used to answer approximate
distance queries on G \ F extremely efficiently in time O(k + log f).

n-vertex graph with polynomially bounded edge lengths ℓ(e) ∈[1, poly(n)] undergoing f edge faults,
assigns in polynomial time to each edge a label of size ˜O(f4n1/k) and to each vertex a label of size
˜O(n1/k), such that

• Compilation. Given only the edge labels of a set F ⊆E of failed edges of size |F| ≤f, one

• Distance Queries. Given only the data structure D and vertex labels of two query vertices

The extension only requires black-box access to the underlying fault-tolerant distance labeling
scheme, and we obtain Theorem 6.1 as a direct corollary of a general template in Lemma 6.4.
The idea of the extension is to reduce a query for the approximate distance between p and q to
a query for the approximate distance between two failed edge endpoints sp and sq, which can then
be precomputed in the compilation step. Each step works as follows:
1. Labels. For the vertex labels, use Thorup-Zwick vertex labels with parameter k. For edge
labels, use the fault-tolerant distance labeling scheme’s edge labels, appended with for both
of the edge’s endpoint vertices the fault-tolerant scheme’s vertex label of that vertex and the
Euler tour ranges of that vertex in each of the cluster-trees in Thorup-Zwick.
2. Compilation. Given only the edge labels of the failed edges F, let S be the set of vertex
endpoints of the edges in F.
Compute an O(|F|2)-size table of all pairwise approximate

Then, store in a hash table for each cluster-tree in the Thorup-Zwick distance oracle containing
at least one failed edge endpoint, a data structure containing the Euler tour ranges of every
failed edge endpoint s ∈S appearing in that tree.
3. Distance Queries. Afterwards, given a query for the approximate distance between p and q
in G \ F, compute the (implicit) Thorup-Zwick path P between p and q in G using the labels
of p and q, and the first and last failed edge endpoints sp, sq ∈S that appear on the path
using the labels of p and q and the compiled data structure D.
If no failed edge endpoint appears on the path, return length(P). Otherwise, return length(P)
plus the precomputed approximate distance between sp and sq in G \ F.
Note that the prefix of P from p until sp and the suffix of P from sq to q contain no failed edges

distG\F (sp, sq) ≤length(P) + distG\F (p, q) ≤(2k −1) distG(p, q) + distG\F (p, q) ≤2k distG\F (p, q).
