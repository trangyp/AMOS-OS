Introduction
Subgraph detection and counting in large graphs is a fundamental problem in computer science.
Given an undirected graph G and a small pattern graph H (e.g., a triangle or a four-cycle),
the goal is to detect or count the number of subgraphs (not necessarily induced) of G that are
isomorphic to H. Such small pattern graphs, or motifs [29], play a crucial role in understanding
structural properties of networks. Subgraph counting has diverse applications in different areas,
including social network analysis [32], biological systems [15], and database theory [5].
This problem has been extensively studied in the graph streaming model, which is relevant
for massive graphs where storing the entire graph in main memory is infeasible. In this model,
the edges of the graph arrive sequentially in an arbitrary (potentially adversarial) order, and
the algorithm has limited memory and may make a constant number of passes over the stream.
Depending on whether a single pass or multiple passes are used, we refer to the corresponding
settings as the single-pass or multi-pass streaming models. While single-pass algorithms are nec-
essary in time-critical settings like network monitoring, multi-pass algorithms are highly effective
in cases where the data is too large to fit into main memory but multiple passes over the data
are feasible, such as in external memory or I/O-bound computations.
Formally, let G = (V, E) be an undirected graph with n vertices and m edges that is rep-
resented as a graph stream, and let H be a small pattern graph. Denote by T the number of
subgraphs in G isomorphic to H. The objective of subgraph counting in the streaming model is
to solve one of the following tasks using sublinear space and a small number of passes:
• Detection: Distinguish between the case where G contains no copy of H and the case
where it contains at least T copies.
• Counting: Estimate T within a factor of 1 ± ε.
While the majority of streaming algorithms for detecting/counting small pattern graphs have
focused on triangles [6, 17, 11, 2, 9, 22, 32, 13, 28, 10, 7, 34, 30, 16, 18, 26, 8], other more complex

In this paper, we focus on four-cycles, i.e., cycles of length four, which are the next simplest
class of pattern graphs after triangles. In bipartite graphs, four-cycles (also known as butterflies)
are the simplest non-trivial motifs, playing a similar role to triangles in general graphs. They
are used to cluster users in online recommendation systems [1] and for computing the butterfly
clustering coefficient, a standard measure of cohesiveness in bipartite networks [24, 3].
Despite their simplicity, the streaming complexity of detecting and counting four-cycles is,
perhaps surprisingly, not yet fully understood. This is in stark contrast to the space complexity
of triangle counting, which has been well-characterized (see, e.g., [28, 7]). Indeed, McGregor and
Vorotnikova [27] observed: “Estimating the number of 4-cycles in the arbitrary order model is
significantly more challenging than estimating the number of triangles”.

To control the variance, we need to identify nodes (or edges and wedges, i.e., paths of length
two) that participate in “many” four-cycles and exclude those four-cycles from our estimators.
To this end, we enhance the commonly used concept of heavy nodes (edges or wedges). The
heaviness of a node v is the number of four-cycles in which v appears, and v is considered heavy
if its heaviness is above a heaviness threshold that we set in our analysis. (The heaviness of an
edge or wedge is defined analogously.) In most previous works on four-cycle (or other subgraph)
counting, this heaviness threshold was uniform across all nodes, making being heavy a property
that depends only on the graph itself. In contrast, in our analysis, for each node, edge or wedge
and each possible way it might get sampled, we must define an individual heaviness threshold to
properly bound the variance of our estimator. That is, whether a node is heavy depends on its
sampling probability.
Moreover, we observe that a straightforward definition of node heaviness cannot be efficiently
estimated within our target space bounds. To overcome this, we introduce a refined notion of
heaviness, which can be checked efficiently while remaining sufficiently accurate for our variance
analysis. This refinement, however, introduces additional technical challenges. For example, it
may cause certain four-cycles to be double-counted. We show that such overcounting affects only
an ε-fraction of all four-cycles and therefore does not impact our final bounds.
We believe our techniques are of independent interest and, due to the generality of our vertex
sampling approach, they will also be applicable to other subgraph counting problems in the
streaming model. We present a more detailed overview of our algorithm and our analysis in
Sections 3 and 4.
Other related work.
For counting four-cycles using single-pass algorithms, Manjunath et al.
[26] provided a eO(m4/T 2)-space algorithm. From a lower bound perspective, we observe that
the lower bounds by Bera and Chakrabarti [7], Kallaugher et al. [20] (for the stronger adjacency

counting four-cycles) imply the following: There is no single-pass algorithm with space complex-
ity O(m/T 1−δ) for constant δ > 0 for general T = poly(m). This rules out single-pass algorithms
with space complexities as achieved by our 3-pass algorithm. We note that for single-pass algo-
rithms for counting four-cycles there remains a gap between the upper and lower bounds.

Preliminaries
Throughout the paper, we consider undirected unweighted graphs G = (V, E) with n nodes and
m edges. For notational convenience, we assume that V = {1, . . . , n} such that for u, v ∈V we
have a natural ordering on the nodes given by <. Further, we assume that we obtain the edge
set E as an arbitrary order stream.
We let T denote the number of four-cycles in G. In the detection version of our problem,
our goal is to distinguish whether G has 0 four-cycles or at least T four-cycles. In the counting
version, our goal is to output a value eT such that (1 −ε)T ≤eT ≤(1 + ε)T for given ε > 0.
As is standard in this line of work, we assume that the algorithm is given an α-approximate
lower bound of T as input for some constant α ≥1, and that an upper bound on α is known in
advance. This assumption is necessary for setting the sampling probabilities (see [9, Section 1]
and [28, Section 1.2] for extensive discussions on this assumption). In the counting problem, we
assume (without loss of generality) that ε = 2−k for some integer k.

3.1
Previous Approaches Based on Edge Sampling
We start by briefly discussing the previous algorithms by McGregor and Vorotnikova [27] and
by Vorotnikova [35], which were heavily based on edge sampling. In a nutshell, their algorithms
works as follows: In the first stream pass, sample each edge with probability p =
1
T 1/3 to obtain a
set of edges S. Then perform a second pass over the stream and, for each arriving edge e = (u, v),
count how many 3-paths in S start at u and end at v, and thus complete a four-cycle with e. At
the end, return the number of such four-cycles after rescaling appropriately.
While this is a very natural algorithm, it is inherently limited to using space Ω(m/T 1/3):
When we sample edges uniformly at random from the stream with probability p, we must pick
p such that for at least Ω(1) four-cycles we sample a 3-path of their edges. For each four-cycle,
this event happens with probability 4p3. Thus, to sample Ω(1) four-cycles in expectation, we
need to set p ≥
1
T 1/3 and thus the sampled edge set S contains Ω(m/T 1/3) edges in expectation.
The main work of the papers by McGregor and Vorotnikova [27] and by Vorotnikova [35] then
goes into the analysis of their oracles, which they need to classify edges and wedges as heavy or
light. This is done to ensure that their estimator’s variance does not get too large.
As mentioned above, this algorithm is very natural and this is perhaps the reason why Vorot-
nikova [35] conjectured that space O(m/T 1/3) is optimal for counting four-cycles. Indeed, observe
that it is not at all obvious how this algorithm should be improved using edge sampling.

To bound the probability that our algorithm detects a four-cycle, we have to bound the
variance of the random variable counting the number of four-cycles in the sample. As in previous
works, the variance of this variable is high if a substructure appearing in many four-cycles is
sampled with small probability, where a substructure is either a node, an edge or a wedge. Thus,

4.2
Extension to Counting
Next, we extend our detection algorithm to counting. Recall that we previously showed how to
detect (i.e., find) Θ(1) four-cycles. To extend this to the counting setting, we use the following
approach: for each of the Θ(1) detected four-cycles A, check whether A was sampled with its
assigned configuration (A, κA, xA, yA), and then scale the counts appropriately (see Algorithm 2
for the pseudocode of our approach). This enables us to filter out configurations that may lead
to high variance while still obtaining a good estimate of the number of light four-cycles, which
in turn serves as a good approximation of T. However, efficiently verifying whether a sampled
four-cycle conforms to its assigned configuration — within eO(m/

T) space — presents us with
significant technical challenges.

property with respect to the parameter κ, causing significant challenges.
To understand this, let us briefly reconsider our detection algorithm. There, a substructure
is heavy if t(z) > θ(z,κ,ℓ) (i.e., using our old heaviness notion t(z)). This is a very convenient
definition because t(z) is fixed and only θ(z,κ,ℓ) depends on κ. Since θ(z,κ,ℓ) is a monotone function
in κ, whether a substructure is heavy is a monotone property in κ. Now, since we picked κA
as the smallest κ ∈K such that A has a light configuration, this suggests the following natural
approach to check whether κ = κA: If (A, κ, x, y) is light and (A, κ/2, x, y) is heavy, then return
that κ = κA, otherwise return κ ̸= κA.
Unfortunately, for our new notion of refined heaviness t(z, κ, ℓ), this approach no longer works.
Now, a substructure is heavy if t(z, κ, ℓ) > θ(z,κ,ℓ) — where both sides depend on κ. Indeed,
note that in Equation (1) the configurations that we are counting heavily depend on the choice
of κ. Now, we can construct examples (see Figure 4) where the property t(z, κ, ℓ) > θ(z,κ,ℓ) is no
longer monotone in κ. Thus, our simple approach for checking κ = κA from before (for t(z)) no
longer works. Further, we also cannot check this property for all κ′ ∈K with κ′ < κ as this will
require too much space if κ′ ≪κ.
We resolve these issues, by only considering configurations c = (A, κ, x, y) which are light and
locally minimial, i.e., they satisfy that all (A, κ′, x, y) with ε2κ ≤κ′ < κ are heavy and that c
is light. This can be checked efficiently within our desired space eO(m/
√
T) since we only have
to check κ′-values in a small, local neighborhood around κ. However, the problem is that with
this definition some four-cycles may now have multiple light and locally minimal configurations,
i.e., we introduce some double-counting. Fortunately, we manage to show that this is only the
case for at most O(εT) four-cycles, which still allows us to obtain our desired approximation
guarantees.
Challenge 3: The third challenge arises from our refined heaviness definition t(z, κ, ℓ). To
decide whether t(z, κ, ℓ) ≤θ(z,κ,ℓ) we have to estimate t(z, κ, ℓ). However, in the estimation, we
have to ensure that we only count configurations c′ such that certain labeled substructures in
c′ are light. For instance, if z is a node, then for each sampled configuration c′ we must ensure
that its wedges and edges are light (as per Equation (1)). The latter can only be done by again

rithm decides whether a graph has 0 four-cycles or at least T four-cycles. It performs two passes
over the stream and uses space eO(m/
√
T), and it is the basis for our counting algorithm below.
We summarize its guarantees in the following theorem.
Theorem 5.1. There exists a 2-pass algorithm which obtains a graph G as an arbitrary-order
edge stream and correctly decides whether G has 0 or at least T four-cycles using eO(m/
√
T) space
with high probability.

To bound the variance of our estimator below, we must ensure that our sample does not contain
substructures of too high heaviness compared to the probability with which they were sampled.
Thus, below we categorize each labeled substructure (z, κ, ℓ) as heavy or light based on whether
the heaviness t(z) exceeds a heaviness threshold θ(z,κ,ℓ) = eΘ(Tp(z,κ,ℓ)) which depends on the
probability with which this labeled substructure is realized.

defined as the number of four-cycles containing z. Next, the heaviness of an opposite node pair
z with V (z) = {u, v} is the number of four-cycles containing the node as an opposite pair, i.e.,
t(z) = os(u, v) (note that this does not count four-cycles in which u and v are adjacent).

Theorem 1.1. There exists a 3-pass algorithm that obtains a graph G as an arbitrary-order

Before we describe our algorithm, we give a short overview of how our approach from Section 5
has to be adapted to extend our algorithm to the approximate counting setting.
Recall that in Section 5.3 we described configurations σA that we assigned to four-cycles A.
Then the crucial part of our analysis was to show that the set
Cdetect = {σA | A ∈T , σA is light}
satisfies (1 −ε)T ≤|Cdetect| ≤T. The most difficult part was to show that Cdetect contains
configurations for at least (1 −ε)T four-cycles (see Proposition 5.6), i.e., to satisfy the first
inequality, whereas the second inequality was trivial. Then, to show that our algorithm detects
a four-cycle, we only needed to bound the probability that at least one configuration from Cdetect
is realized. While the variance of the number of sampled four-cycles is generally high, we proved
that the variance of the number of realized configurations from CDetect is small.
Thus, the natural approach for extending our detection algorithm to counting four-cycles is
to estimate |CDetect|. Indeed, we would immediately get a (1±ε)-approximate counting algorithm
(after adapting our analysis from Section 5), if we could decide the following question during the
algorithm:
Given a realized configuration c, is c ∈Cdetect?
The main problem here is that to check whether c ∈Cdetect, we have to verify that the
heaviness thresholds that we introduced in Section 5.3 are satisfied for all labeled substructures
(z, κ, ℓ) ∈c. However, this is not possible, as we can show that there exist graphs for which
verifying t(v) ≤θ(v,κ,ℓ) for some labeled node (v, κ, ℓ) ∈c requires space ω(m/
√
T). Thus, we
have to abandon the idea of checking whether c ∈Cdetect.
To fix this, we refine our heaviness notion. Concretely, now we define a new heaviness notion
t(z, κ, ℓ) that replaces the old heaviness notion t(z) in the definition of heavy and light substruc-
tures. This allows us to check whether substructures are heavy (i.e., whether t(z, κ, ℓ) ≤θ(z,κ,ℓ))
using oracles that only use space eO(m/
√
T). Now we can define a new set of configurations C
for which we will be able to answer the following question using one additional stream pass:
Given a realized configuration c, is c ∈C?
Similar to Cdetect, the new set C still only contains light configurations, but now it satisfies
the relaxed property (1 −ε)T ≤|C| ≤(1 + ε)T. The main obstacle will be to show that our
new heaviness notion t(z, κ, ℓ) satisfies all properties that we need to adopt our variance proof

(Non-)Monotonicity.
Next, we discuss a drawback of our refined heaviness notion. For this,
recall that in Section 5.3 we defined assigned configurations σA = (A, κA, xA, yA). We used these
assigned configurations to ensure that each four-cycle has at most one assigned configuration
and to argue that |Cdetect| ≤T. There, we intuitively chose κA as the smallest κ ∈K over all
light configurations of A. Thus, if we wanted to build an oracle for checking whether c = σA for
some configuration c of A, this suggests the following strategy: If c = (A, κ, x, y) then check if
(A, κ/2, x, y) is light; if that is the case, then report that c ̸= σA, otherwise report that c = σA.
Note that for this approach, it is crucial that if we fix A, x and y, then whether a configuration
is light is a monotone function with respect to the parameter κ. Note that the same holds for
all substructures.
Now the main disadvantage of the refined heaviness definition is that the property of a
substructure being heavy is not monotone in κ anymore: Let (v, κ, ℓ) be a labeled node. The
property of (v, κ, ℓ) being heavy is monotone in κ for the true heaviness since the node heaviness
t(v) is constant for different κ ∈K, while the heaviness threshold θ(v,κ,ℓ) changes monotonically.
However, for the refined heaviness t(v, κ, ℓ) we lose this nice property, as now not only the
thresholds θ(v,κ,ℓ) but also the heaviness t(v, κ, ℓ) itself can vary for different κ. In particular, the
definition of t(v, κ, ℓ) might include some configurations only for specific values of κ. An example
