Abstract
We give a poly(s, 1/ε)-query algorithm for testing whether an unknown and arbitrary func-
tion f : {0, 1}n →{0, 1} is an s-term DNF, in the challenging relative-error framework for
Boolean function property testing that was recently introduced and studied in a number of
works [CDH+25b, CPPS25a, CPPS25b, CDH+25a]. This gives the first example of a rich and
natural class of functions which may depend on a super-constant number of variables and yet
is efficiently testable in the relative-error model with constant query complexity.
A crucial new ingredient enabling our approach is a novel decomposition of any s-term DNF
formula into “local clusters” of terms. Our results demonstrate that this new decomposition
can be usefully exploited for algorithms even when the s-term DNF is not explicitly given; we
believe that this decomposition may have applications in other contexts.

Introduction
Property testing, starting with the works of [BLR93, RS96, GGR98], provides a general algorithmic
framework for determining whether a given object satisfies a property or is far from satisfying
it, by making a small number of queries to the object. The key idea and motivation is that for
many combinatorial structures such as graphs, functions, or distributions, global properties of the
structure can often be approximately tested by examining only a very tiny fraction of the input.
One of the most intensively studied property testing domains is Boolean function classes where
efficient testers have been designed for a broad range of function classes; moreover, the techniques
developed have led to new insights and connections with other areas, including Fourier analysis of
Boolean functions and learning theory.
In the standard testing model for a class of Boolean functions, the tester is given query access
to an input function f and parameter ε, and should distinguish between f belonging to the class,
versus f having Hamming distance at least ε from every function in the class. (See Section 1.2
below for more background.) While property testing in the standard model has been incredibly
successful, a significant drawback of the standard model is that it is poorly suited for testing sparse
Boolean functions, which have only a very small fraction of all 2n points in {0, 1}n as satisfying
assignments, simply because any such function is trivially close to the constant-0 function. This
limitation — that sparse functions are trivial to test under the uniform distribution — arguably
sidesteps much of the richness and complexity of a number of interesting Boolean function classes,
including the fundamental class of s-term DNF formulas which is the subject of this work. For
example, the class of s-term DNF formulas is notoriously challenging to deal with in the context
of efficient PAC learning, and the source of difficulty is precisely the fact that DNF formulas may
have terms that are “wide” (containing many variables). However, s-term DNF formulas with only
“wide” terms are sparse, and hence are trivial to test in the standard model since they are close to
the constant-0 function.
In an effort to meaningfully extend the scope of property testing to encompass questions about
testing sparse Boolean functions, [CDH+25b] introduced a new variant of Boolean function property
testing that is known as relative-error testing. The relative-error testing model defines the distance
from the unknown f : {0, 1}n →{0, 1} that is being tested to another function g : {0, 1}n →{0, 1}
to be
reldist(f, g) := |f−1(1) △g−1(1)|
|f−1(1)|
.
In contrast to the standard model, in the relative error model, the distance from f to g is
measured as a function of f’s support size, f −1(1), and not just globally across all 2n inputs. This
distinction is crucial in applications like feature selection, or fault detection where the underlying
functions often describe rare but important events, or in large but sparse data domains. Relative
error property testing also connects property testing to several other areas where distances are
measured in a relative sense e.g., PAC learning under general distributions, noise stability and
approximate counting.
Note that if only black-box MQ(f) queries were allowed, as in the standard model, then an
enormous number of queries could be required to obtain any information about f at all for very
sparse f. Hence, the model also allows the testing algorithm to obtain independent uniform elements
of f−1(1) from a sampling oracle SAMP(f).

It is intuitively obvious and simple to show (see Fact 3.1 of [CDH+25b]) that relative-error
testing is at least as hard as standard-model testing. Moreover, an easy example of an (artificial)
class of functions (see [CDH+25b]) shows that relative-error testing can be hard, requiring 2Ω(n) calls
to MQ(f) or SAMP(f), even for classes that are easily testable with O(1) queries in the standard
model. However, it is a priori unclear how easy (or hard) it is to do relative-error testing for natural
function classes of interest.
1.1
Our Main Result: Relative-Error Testing for DNFs
In this paper we focus on the class of s-term DNF formulas; the class of all functions f : {0, 1}n →
{0, 1} that can be expressed as f = T1 ∨· · · ∨Ts′ for some s′ ≤s, where each Ti is a conjunction
of Boolean literals. DNF formulas are a rich and intensively studied class of functions with a long
history in logic and theoretical computer science. As a universal model that can express any Boolean
function, DNF formulas are one of the most important classes of Boolean functions, central in the
study of Boolean function analysis, learning theory, computational complexity, and testing.
DNFs are also particularly interesting from the vantage point of relative-error property testing.
On the one hand, s-term DNF formulas are a highly expressive class which unlike juntas (and
subclasses of juntas), can depend on a superconstant number of variables. On the other hand, they
appear to be quite challenging in the relative-error testing model compared to the standard model.
In the standard-error model, s-term DNFs are testable with only ˜O(s/ε) queries ([Bsh20, DLM+07,
CGM11]). In contrast, a straightforward consequence of previous work in learning theory gives a
relative-error tester for s-term DNFs that makes nO(log(s/ε)) queries. (See Appendix A for details.)
A key challenge in improving relative-error testing of DNFs is the lack of smoothness: small
changes to a DNF such as deleting a single variable from a term can cause large changes in the
number of satisfying assignments1, complicating both testing and approximation. Understanding
the complexity of DNF testing in the relative error model thus provides a window into how com-
binatorial structure interacts with multiplicative accuracy guarantees, and whether efficient testers
can exist in settings where absolute and relative notions of distance diverge.
Our main result is a relative-error testing algorithm for DNF formulas with query complexity
independent of the ambient dimension n:
Theorem 1 (Relative-error testing of s-term DNF). For 0 < ε ≤1/2, there is an ε-relative-error
testing algorithm for the class of s-term DNF formulas over {0, 1}n which makes poly(s, 1/ε) queries.
This is a dramatic improvement to the nO(log(s/ε)) query relative-error DNF tester mentioned
above. We remark that our new tester has query-complexity that is equivalent to the state-of-the-art
DNF tester in the standard model ([Bsh20, DLM+07, CGM11]), up to polynomial factors.

classes) are efficiently testable in the standard model.

circuits with unbounded fan-in [DLM+07, CGM11, Bsh20]).
Relative-Error Testing. Recall that in the relative-error testing model, the distance from f to g is
measured at the “relative” scale of |f−1(1)| rather than at the “absolute” scale of 2n = |{0, 1}n|. The
model is thus similar in spirit to well-studied models in graph property testing (see [GR02, PR02]
and Chapters 9 and 10 of [Gol10]) which are suitable for testing sparse N-vertex graphs that have
o(N2) edges.
Several recent works have given efficient relative error testers for a variety of well-studied classes.
[CPPS25b] showed that s-juntas and subclasses of s-juntas that are closed under renaming variables
(and satisfy an additional mild technical condition, see [CPPS25b] for details) can be efficiently
tested in the relative-error model, using only poly(s, 1/ε) oracle calls. Building on very different
techniques, another recent work [CPPS25a] showed that the classes of Boolean conjunctions and
1-decision lists, of any length, are also efficiently relative-error testable, using only ˜O(1/ε) queries.
The [CPPS25a] result provides an interesting contrast to [CPPS25b] because neither conjunctions
nor decision lists are subclasses of juntas; however, both conjunctions and decision lists are rather
simple and inexpressive types of Boolean functions. On the negative side, a slightly richer class which
generalizes both conjunctions and 1-decision lists, namely the class of linear threshold functions, was
recently shown not to be constant-query testable: [CDH+25a] proved that any relative-error testing
algorithm for LTFs must have ˜Ω(log n) query complexity.
Relation to distribution-free testing.
We remark that relative-error testing is not the first Boolean function property testing model
to measure the distribution between two functions f and g using a distance notion other than the
fraction of points in {0, 1}n on which they disagree. In the distribution-free testing model, the
distance between two functions f and g is measured according to Prx∼D[f(x) ̸= g(x)], where D is
an unknown and arbitrary distribution over the domain {0, 1}n. In addition to making black-box
oracle queries, distribution-free testing algorithms can also draw i.i.d. samples from the unknown
distribution D.
However, it turns out that many classes of functions which are constant-query
testable in the standard model, such as decision lists, linear threshold functions, and conjunctions
(which are s-term DNF for s = 1), require a superconstant — in fact, polynomial in n — number
of queries in the distribution-free setting, see e.g. [GS09, CX16, CP22, CFP24].
We further remark that the relative-error testing model is incomparable to distribution-free
testing; one reason for this is because the distance between functions is measured differently in
the two settings. In the distribution-free model, the distance Prx∼D[f(x) ̸= g(x)] between two
functions f, g is measured vis-a-vis the distribution D that the testing algorithm can sample from,
and these samples will typically include both positive and negative examples of the function f that is
being tested. In contrast, in the relative-error setting the distribution D that the tester can sample
from is the uniform distribution over f −1(1), i.e. it is supported entirely on positive examples of f.

Moreover, the relative distance reldist(f, g) is not equal to Prx∼f−1(1)[f(x) ̸= g(x)]: a function g

Technical Overview
In this section we explain the main ideas behind our algorithm, Test-DNF, for relative-error
testing of DNFs. In Section 2.1, we begin with a conceptual overview of the high-level ideas un-
derlying our approach and describe its two algorithmic components, Find-Factored-DNFs and
Test-Factored-DNF. We then proceed from that to discuss some of the most significant hurdles
that need to be overcome to make the approach work in Sections 2.2 and 2.3. See Figure 2 for an
illustration of the detailed structure of our testing algorithm.
2.1
High-level ideas
Factored-DNFs. To explain our approach, a crucial preliminary notion is that of a factored-DNF.
Roughly speaking, a factored-DNF is a function of the form H ∧f1, where H is a term (conjunction)
of arbitrary length and f1 is a (≤s)-term DNF that depends on only poly(s) many variables; see
Definition 18 for a more precise definition. Note that we can think of the conjunction H (which
again may be of arbitrary length) as a common part that has been “factored out” of each of the terms
of an initial DNF. We sometimes refer to H as the “head” and f1 as the “tail” of the factored-DNF.
With the notion of a factored-DNF in hand, we are ready to describe our new decomposition.
A new decomposition of DNFs. Our approach crucially employs a new technical and concep-
tual ingredient, which is a novel structural decomposition result for arbitrary s-term DNFs. This
structural decomposition result, informally speaking, says the following:
Given any s-term DNF f, there is a sub-DNF f′ of f, created by removing some terms
of f (so f′−1(1) ⊆f−1(1)), which has the following properties:
(i) Almost all satisfying assignments of f are also satisfying assignments of f ′;
(ii) f′ can be partitioned into an OR of no more than s many sub-DNFs h1, . . . , h≤s
(so each term in each hi is one of the original s terms of f), each of which is a
factored-DNF as described earlier;
(iii) A uniform random satisfying assignment of f ′ (satisfying some sub-DNF hi) is
extremely likely to disagree with every term in every other sub-DNF hj, j ̸= i,
in a large number of coordinates.

2.2
Finding factored DNFs
We now give more details on how Find-Factored-DNFs generates oracle simulators for factored-
DNFs h1, . . . , h≤s that form a decomposition of f described earlier, when f is an s-term DNF.
This starts with Section 4, where we describe a simple greedy clustering procedure that, given
explicitly the terms T1, . . . , Ts of f, partitions them into clusters D1, . . . , D≤s such that by setting gi
to be the sub-DNF defined using terms in Di, we would obtain a decomposition of f into g1, . . . , g≤s
that satisfy all three properties given earlier in Figure 1. (Here we used gi’s instead of hi’s because
these are not exactly the functions returned by Find-Factored-DNFs.) This is done by making
sure that, roughly speaking, (1) every two terms in the same cluster are “close” and (2) every two
terms in two distinct clusters are “far,” where the reader may consider the distance between two
terms measured by their symmetric difference (though it needs to be done in a more careful manner
in Section 4). Naturally, (1) leads to property (ii) and (2) leads to property (iii) in the decomposition
of Figure 1. The latter is because every two terms in the same cluster Dℓare close to each other and
thus, they can be factored out to form a factored-DNF (see Corollary 17). We emphasize that our
algorithm does not and cannot carry out this procedure, since it does not “know” the terms. This
clustering D1, . . . , D≤s should be considered as the ideal goal for Find-Factored-DNFs, which
will play a crucial conceptual role in its design and analysis.
For convenience, we will refer to
D1, . . . , D≤s as the canonical clusters in the rest of this section.
At a high level, Find-Factored-DNFs starts by drawing poly(s/ε) samples from f −1(1). For

2.3
Testing factored DNFs
How can we design an efficient relative-error tester for factored-DNFs? A clue to this is provided
by the recent work of [CPPS25a], which gave a ˜O(1/ε)-query relative-error tester for decision lists.
The connection between decision lists and factored-DNFs is as follows: as is clear from a moment’s
thought, any nontrivial decision list can be viewed as being of the form H ∧L, where H is a
conjunction (of arbitrary length) and L is another decision list that is “dense”: L outputs 1 on
a constant fraction of all input assignments. At a high level, the [CPPS25a] algorithm essentially
works by running a standard-model algorithm for testing decision lists on the list L (note that this is
not at all straightforward to do because of the presence of the head H; however, we omit discussion
of those issues in this overview).
In the current context, instead of a decision list of the form H ∧L where L is a “dense” decision
list, we have a factored-DNF of the form H ∧f1, where f1 is an s-term DNF depending on poly(s)
variables. Standard-model testing algorithms are known for the class of s-term DNFs [Bsh20], and
it is natural to think that by swapping in such an algorithm for the standard-model decision-list
testing algorithm used in [CPPS25a], we might be able to obtain a testing algorithm for factored-
DNFs. However, the standard-model s-term DNF testers do not suffice for our purpose, because
an s-term, poly(s)-variable DNF f1 need not be “dense;” it could have only a 2−poly(s) fraction of
satisfying assignments (this would be the case if, for example, each term were of length s).
Instead, our approach to testing factored-DNFs brings in ideas and tools from a different paper
[CPPS25b]. The main result of [CPPS25b] is a poly(k/ε)-algorithm for relative-error testing of any
subclass of k-juntas which is closed under permuting input variables; note that the class of s-term
DNFs which depend on only k = poly(s) many variables clearly meets this condition. At a high level,
our approach to testing factored-DNFs is to use a relative-error tester for s-term, poly(s)-variable
DNFs in place of the (standard-model) decision list tester to “implicitly learn” an approximation of
f1 (up to small relative error) within the framework of the overall [CPPS25a] tester.
We give more details on how all this is done later in Section 7, but before moving on, let’s give
a bit more detail on the concept of “implicit learning,” or “learning up to the names of the relevant
variables.” By “implicit learning” an approximation of the tail f1 (i.e., an s-term, poly(s)-variable
DNF), we mean that if f1 depends on k variables from x1, . . . , xn, the implicit learning algorithm
identifies a function g : {0, 1}k →{0, 1}, depending on variables which we call y1, . . . , yk, such that
after some (unknown) mapping of the yi variables to {x1, . . . , xn}, the function g is close to f.4 In

it running on the perfect oracles MQ(hi) and SAMP(hi) minus 0.01.

Clustering terms of a DNF
The goal of this section is to establish our structural result about s-term DNFs. This result shows
that given any representation of an s-term DNF f, and any positive integer K, there is a unique
partitioning (“K-clustering”) of the terms of f, denoted Clustering(f, K), into disjoint “clusters” (sub-
DNFs) with useful properties that we will employ later in the “yes”-case analysis of our relative-error
testing algorithm for DNFs. Roughly speaking, the properties we need about Clustering(f, K) are
1. For any cluster C of terms in Clustering(f, K), all terms “look similar” to each other (see
Lemma 13). More formally, the sub-DNF of C can be written as T ∧(T1 ∨· · · ∨T|C|) such
that the number of variables involved in T1, . . . , T|C| is bounded by O(s2K). Note that this
bound is polynomial in s and K but is independent of n.
2. For any T and T ′ in two different clusters of Clustering(f, K), where T is not too wide, we
have that |T ′ \ T| = Ω(K) (see Corollary 15). This implies that it is very unlikely for a
uniform random satisfying assignment a ∼SAMP(f) that satisfies a term T to have small
distance dist(a, T ′) from any term T ′ that is not in the same cluster as T. (See Corollary 17
for a precise statement.)
Throughout this section we fix f to be an s-term DNF, and we fix a particular representation of f
as an s-term DNF.

6.3
The Find-Factored-DNFs procedure
We are now ready to present the Find-Factored-DNFs algorithm, Algorithm 6. This algorithm
has five main phases; in this subsection we give a high-level overview of these phases, before the
detailed presentation of the algorithm, and give the simple proof of the algorithm’s query complexity.
The first phase, “Building Pools,” draws a collection S of N 3 many assignments, each drawn
uniformly at random from the set f −1(1) of satisfying assignments. S is then partitioned into a
collection of pools G based on the outcome of running Test-Weak-Equivalence(a, b, MQ(f)) on each
pair a, b ∈S. (We note that this property, that G is a partition of S, is maintained throughout
the Find-Factored-DNFs algorithm.) Intuitively, if f is an s-term DNF then the different pools
resulting from this phase will consist of (some of) the satisfying assignments of different factored-
DNFs in a representation of f as a disjunction over a family of factored-DNFs.
The second phase, “Sanity Check,” halts and rejects if strictly more than s pools were formed
in the first phase (as suggested above, this should not occur if f is actually an s-term DNF).
The third phase, “Merging Pools,” uses Test-Equivalence and a small number of fresh samples
from f−1(1) to merge some pairs of pools in G. As was discussed in Section 2.2 this step is carried
out to ensure that property (iii) of Figure 1 holds.
The fourth phase, “Removing low weight pools,” uses In-Pool and another small collection of fresh
samples from f−1(1) to identify a subset of the pools in G that are “heavy” pools. The high-level
intuition here is that heavy pools are the ones for which we can have high confidence that random
draws from SAMP(f) in the rest of the algorithm will satisfy some term covered by that pool.
We remark that in Phase 4, the “sufficiently long” random string strP should be viewed as a huge
random string, with enough randomness to make all calls to In-Pool during and after this phase
fully deterministic. In particular, for every z ∈f −1(1), strP contains the random bits required to
simulate In-Pool deterministically for every possible input z. (Having a global random string will
be useful in the analysis when we prove Theorem 23.)
Finally, in the fifth phase, for each “heavy” pool Pi we run Algorithm 7 and Algorithm 8
to construct MQ∗and SAMP∗simulators for a function hi corresponding to that “heavy” pool.

reldist(f, h), reldist(h, f) ≤ε/100. This implies that in step 3, there is at most a 1/10 chance that
any of the 10/ε random samples from f −1(1) fails to satisfy h, and likewise with the roles of f and
h reversed; so with probability at least 79/100 the algorithm will accept.
Now, suppose that f has reldist(f, g) > ε for every s-term DNF formula g. If the procedure
rejects in step 2 then we are done, so suppose that step 2 succeeds in finding an s-term DNF
h with reldist(h, h′), reldist(h′, h) ≤ε/1000. Now, since h is an s-term DNF we must have that
reldist(f, h) > ε. From this it is easy to show that with high probability (at least 2/3), either some
sample among the 10/ε random samples from f −1(1) will fail to satisfy h or some sample among the
10/ε random samples from h−1(1) will fail to satisfy f. Hence the procedure rejects with probability
at least 2/3, and we are done.

Distribution-free testing and relative-error testing are incompa-

In this section we record the fact that distribution-free testing and relative-error testing are incom-
parable models: for each of these two models, there is a class of functions which is easy to test in
the first model (i.e. testable with only constantly many queries) but hard to test in the other one
(i.e. the query complexity must grow with the dimension n). The following observation makes this
quantitatively precise:
Observation 86 (Distribution-free testing and relative-error testing are incomparable).
1. There is a class of functions F1 which can be ε-tested in the relative-error model using only
O(1/ε) samples and membership queries, but which requires ˜Ω(n1/3) samples and membership
queries for ε0-testing in the distribution-free model, for some absolute constant ε0 > 0.
2. There is a class of functions F2 which can be ε-tested in the distribution-free model, for any
ε > 2−n/3, using zero samples and membership queries, but which requires Ω(2n/3) samples
and membership queries for ε-testing in the relative-error model for any ε < 1.
For part 1, we can take F1 to be the class of all conjunctions over {0, 1}n. The positive re-
sult for relative-error testing is established as Theorem 1 of [CPPS25a], and the negative result is
Theorem 1.4 of [CX16].
