Abstract—We propose an algorithm for counting below-
threshold triangles in weighted graphs under local weight dif-
ferential privacy. While prior work has largely focused on
unweighted graphs, edge weights are intrinsic to many real-world
networks. We consider the setting in which the graph topology is
publicly known and privacy is required only for the contribution
of an individual to incident edge weights, capturing practical
scenarios such as road and telecommunication networks. Our
method uses two rounds of communication. In the first round,
each node releases privatized information about its incident edge
weights under local weight differential privacy. In the second
round, nodes locally count below-threshold triangles using this
privatized information; we introduce both biased and unbiased
variants of the estimator. We further develop two refinements: (i)
a pre-computation step that reduces covariance and thus lowers
expected error, and (ii) an efficient procedure for computing
smooth sensitivity, which substantially reduces running time
relative to a straightforward implementation. Finally, we present
experimental results that quantify the trade-offs between the
biased and unbiased variants and demonstrate the effectiveness
of the proposed improvements.

I. INTRODUCTION
Over recent years, differential privacy [12] has emerged
as the de facto standard for formal privacy guarantees. It
provides a rigorous mathematical framework under which
the inclusion or exclusion of any single individual’s data
has only a limited effect on the released statistics, thereby
preventing an adversary from drawing reliable inferences about
any particular data record from the published output.
Initially developed for tabular datasets, differential privacy
was subsequently adapted to graph-structured data via edge-
differential privacy, which protects the presence or absence
of individual edges in a network [16]. A key limitation
of both the central differential privacy and edge-differential
privacy models is their reliance on a trusted curator to collect
and sanitize the data. Local differential privacy [21], [30]
and its graph analogue, local edge-differential privacy [30],
address this concern by shifting randomization to the user side,
thereby eliminating the need for a trusted central server while
providing strong privacy guarantees.
A substantial body of work has investigated differential
privacy for weighted graphs, which model practical settings
such as road and telecommunication networks. In these set-
tings, the graph topology is typically public, so the presence
or absence of edges is not considered sensitive. Instead, the
sensitive information lies in the edge weights, which must be
protected. Representative results include differentially private
shortest-path algorithms [32], [6], [10], [11], mechanisms for
releasing privatized versions of the underlying weighted graph
[23], [38], and algorithms for privately releasing cut values [1],
[9].
There is also prior work on local differential privacy for
weighted data publication [35], [7] and weighted graph learn-
ing [37]. These studies typically treat both edge existence and
edge weights as sensitive attributes. In contrast, we focus on
the setting where only the weights are sensitive and the graph
topology is public. Consequently, the privacy notion adopted
in those works is strictly stronger than the one we consider
here, which may limit the range of settings in which it can be
practically applied.
Triangle counting problem has been extensively studied in
the unweighted setting under local differential privacy [13],
[18], [19], [22], [26]. In the unweighted case, triangle counting
plays a central role in applications in graph mining, bioinfor-
matics, and social networks [27], [3], [25]. Since the network
topology is a public information in our setting, counting the
number of triangles is straightforward in our privacy notion.
A. Our contributions
We study the problem of counting triangles whose total
edge weight is smaller than a given threshold under local
differential privacy. This triangle count and related measures
such as the weighted clustering coefficient have been used to
identify congested regions, which are central to urban traffic
planning [29], [31]. By designing mechanisms that count
triangles whose weight lies below (equivalently, above) a given
threshold, our approach directly supports this line of work
while providing strong privacy guarantees. Moreover, efficient
triangle-counting techniques often extend to more general
subgraph counting, as has been shown in the unweighted
setting [5], [34], and we expect similar extensions to hold
for weighted graphs.
The number of triangles with small or large weights can be
used to generate a synthetic graph that preserves key properties
of the original graph. Finally, prior differentially private work
on shortest-path cycles [32], [6], [10], [11] has primarily

In Section III, we propose an algorithm for counting the
number of triangles whose total weight falls below a given
threshold, fully leveraging the flexibility of the differential
privacy notion for weighted graphs. The key contributions of
our algorithm are twofold:
a) We design an assignment that minimizes the variance
of the triangle count in Section IV: Each triangle is incident
to three nodes. It is known that assigning each triangle to a
carefully chosen node and letting only that node report it can
greatly reduce the variance and thus the error in triangle count-
ing [18], [26]. In the unweighted setting, however, the server
does not know the graph structure, so prior work relied on
indirect statistics such as noisy degree estimates to guide this
assignment. In contrast, under differential privacy for weighted
graphs, the server is allowed to know the graph structure. We
exploit this additional information to construct an efficient and
scalable constant-factor approximation algorithm for choosing
the assignment so as to (approximately) minimize the counting
variance.
b) We develop a scalable algorithm to compute the
smooth sensitivity in Section V.: Smooth sensitivity [28] is
a standard tool for reducing the amount of noise added to
released statistics and can yield substantial accuracy improve-
ments in the weighted setting. However, computing a suffi-
ciently tight smooth sensitivity bound is often computationally
expensive in practice [17]. Although there are algorithms
for computing smooth sensitivity in the unweighted setting,
directly applying those bounds to the weighted setting would
drastically overestimate the sensitivity and therefore inject far
more noise than necessary. To overcome this, we develop
an algorithm that computes the local β-smooth sensitivity
in O(d2 log3 d) time for a node of degree d. Importantly,
this running time is independent of the magnitude of the
edge weights, so the method remains scalable even when
weights are large. The key idea is to maintain and update
two balanced binary search trees so that we can capture
the relevant local changes without recomputing from scratch.
We remark that in typical road or communication networks
node degrees are generally well below 104. This implies that
our smooth sensitivity computation, which depends on the
maximum degree, can be carried out within practical running
time and is therefore scalable in these settings.
In addition to these two main contributions, in Section III
we adapt the unbiased estimator from [14], originally proposed
for privately releasing histograms, so that it can be used to
release an unbiased estimate of the number of triangles under
our weighted-graph model. This extends the use of unbiased
randomized response techniques for subgraph counting from
the unweighted setting [34] to the weighted setting considered
here. When we use the biased estimator, the resulting error
scales linearly with the number of triangles in the input
graph. In contrast, with the unbiased estimator, the error scales
on the order of the square root of the number of triangles.
Consequently, for graphs with many triangles, our algorithm
achieves a significantly smaller relative error.
In Section VI, we evaluate our method on two real-world
graphs: a telecommunication network in Milan, Italy, and
a biological network used for integrated transcriptional and
metabolic analysis [24], [4]. Compared to a naive baseline that
first releases all edge weights using the Laplace mechanism
and then counts triangles from the noisy graph, our algorithm
achieves up to two orders of magnitude smaller relative
counting error.

B. Local weight differential privacy
In this section, we introduce the formal notations for our
privacy setting together with a discrete and continuous privacy
mechanism. In the setting of local weight differential privacy it
is assumed that the graph topology, nodes and edges, are public
and the private information we want to protect is encoded
in the edge weights. This assumption is natural in applica-
tions such as road and telecommunication networks, where
the underlying connectivity (streets, intersections, or network
links) is typically public, while sensitive usage information is
encoded in the edge weights.

In this section, we present experimental results on two
graphs: one derived from telecommunication data collected
in the city of Milan, Italy, and one produced by GAM,
a web service for integrated transcriptional and metabolic
network analysis [24], [33]. The implementation used in our
experiments is publicly available1. All experiments were run
on the SHIROKANE supercomputer, provided by the Human
Genome Center, Institute of Medical Science, The University
of Tokyo2.
These experiments illustrate the empirical difference be-
tween the unbiased and biased estimators, and demonstrate
how the use of smooth sensitivity reduces the average ℓ2 error.
A. Dataset preparation
In 2014, Telecom Italia, in collaboration with several re-
search institutions, organized the ”Telecom Italia Big Data
Challenge,” releasing an anonymized telecommunications
dataset for the city of Milan [4]. The dataset records aggre-
gated communication intensity between geographic areas of
Milan, which are partitioned into a 100×100 grid of equally
sized cells. For every pair of areas, it reports the volume of
telecommunication activity in 10-minute intervals.
In our analysis, we consider the 10-minute interval on
Sunday, November 3, 2013, from 19:50 to 20:00 (local time).
We assume that each base station serves a 6×6 block of
cells, which yields a total of 278 base stations across the
city. From this, we construct an undirected weighted graph
in which each node corresponds to a radio base station, each
edge represents a connection between two stations, and each
edge weight is the number of calls between them. Under
local weight differential privacy, the privacy of individual
calls is protected. In particular, publishing the number of
below-threshold triangles does not reveal whether a specific
individual made a call, nor where that call took place.

C. Experimental results for ML-Tele-278
In this section, we report the experimental results on ML-
TELE-278. As shown in Figure 3, all algorithms, including
the baseline, achieve meaningful accuracy on this dataset:
the relative error is below 0.1 across almost all experiments.
Despite the fact that the graph has very high degree and all
computations are performed centrally on the server rather than
being distributed across nodes, the total runtime remains below
five minutes even for the smooth-sensitivity mechanism. This
demonstrates that the smooth-sensitivity approach introduced
in Section V is both scalable and practical for large graphs.
a) Varying the privacy budget ε: We begin by examining
how the privacy budget ε influences the relative error. For
all two-step algorithms, we divide the budget evenly, i.e.,
ε1 = ε2 = ε/2. As shown in Figure 3(a), our algorithm
with the unbiased estimator outperforms all other methods for
almost all values of ε. In particular, for ε ∈{1, 2}, it improves
over the baseline by roughly two orders of magnitude. Consis-
tent with the theoretical analysis, the smooth-sensitivity variant
achieves about one order of magnitude smaller relative error
than the global-sensitivity variant. The unbiased estimator is
only worse than the biased estimator when ε ≪1, which
matches the theoretical dependence: the biased estimator has
error on the order of ε−6, whereas the unbiased estimator
has error on the order of ε−2. We observe that, for ε = 4,
our unbiased algorithm and the baseline achieve comparable
relative error. This is because a privacy budget of this size
allows all methods to produce highly accurate estimates.
b) Varying the number of triangles in the input graph
|∆|: Figure 3(b) reports the results as we vary the number of
triangles |∆| in the input graph. To obtain graphs with different
values of |∆|, we uniformly sample vertex subsets of fixed size
and run each algorithm on the induced subgraph. We consider
n ∈{100, 150, 200, 250}. Under this sampling procedure, the
true triangle count grows linearly in |∆|, since each triangle
is included with equal probability. The results show that the
improvement provided by our unbiased estimator becomes
more pronounced as the number of triangles increases. This
is consistent with Theorem 4, which states that the biased
estimator’s squared ℓ2-error grows quadratically in |∆|, re-
sulting in a constant relative ℓ2-error as depicted. Theorem 5
shows that the squared ℓ2-error of the unbiased estimator
grows only linearly in |∆|. As a result, the relative error of
the unbiased estimator is decreasing for growing |∆|, and its
advantage becomes stronger on graphs with many triangles.
We observe that the relative errors of both the biased estimator

c) Varying the threshold λ: We now evaluate perfor-

most triangle weights are very small; even after adding discrete
Laplace noise to the edge weights, only a few triangles exceed
a large threshold. In such regimes, the two-step algorithms
still incur error from the second step, where Laplace noise is
added to the below-threshold counts. This introduces a roughly
constant error term, which becomes dominant when the true
count above the threshold is very small.
D. Our results on GMWCS
We next evaluate our methods on a second graph, denoted
GMWCS. We use the largest instance from the benchmark
set of [24], which was also included in the Generalized
Maximum-Weight Connected Subgraph (GMWCS) track of
the 11th DIMACS Implementation Challenge in Collaboration
with ICERM: Steiner Tree Problems. The properties of this
instance are summarized in Table I. Although this graph has
more nodes than ML-TELE-278, it is extremely sparse. The
average degree is only slightly above one, and it contains only
132 triangles. This setting is difficult for our algorithm: each
node contributes noise, but the true below-threshold triangle
count is very small. Moreover, Figure 3 already suggests that
our approach performs less favorably on graphs with very few
triangles. Nevertheless, Figure 4 shows that we can still release
meaningful statistics. In particular, the biased estimator with
smooth sensitivity achieves an average relative error that is
not much larger than one. While the non-interactive baseline
attains lower error than all variants of our algorithm, the gap
is typically within a factor of five.
VII. CONCLUSION
In this work, we investigate the problem of counting below-
threshold triangles in weighted graphs under local differential
privacy, and we introduce a two-step algorithm to address
this challenge. We develop both biased and unbiased esti-
mators: the biased estimator incurs error that scales linear
with the number of triangles, whereas the unbiased esti-
mator substantially improves accuracy at the expense of a
stronger dependence on the privacy budget. To further improve
performance, we incorporate a preprocessing procedure that
balances the triangle-counting workload across nodes and can
be computed in time linear in the number of triangles. In
addition, we present an efficient algorithm for computing
