Abstract
In this paper we initiate the study of computing a maximal (not nec-
essarily maximum) repeating pattern in a single input string, where the
corresponding problems have been studied (e.g., a maximal common sub-
sequence) only in two or more input strings by Hirota and Sakai starting
2019. Given an input string S of length n, we can compute a maximal
square subsequence of S in O(n log n) time, greatly improving the O(n2)
bound for computing the longest square subsequence of S. For a max-
imal k-repeating subsequence, our bound is O(f(k)n log n), where f(k)
is a computable function such that f(k) < k · 4k. This greatly improves
the O(n2k−1) bound for computing a longest k-repeating subsequence of
S, for k ≥3. Both results hold for the constrained case, i.e., when the
solution must contain a subsequence X of S, though with higher running
times.

Introduction
Computing (non-contiguous) patterns in two or more input strings is a classical
problem which has found many applications.
The textbook example is the
longest common subsequence (LCS) of two strings of a total length of n, which
was solved by Wagner and Fischer in O(n2) time and space [14] and then in
O(n2) time but O(n) space by Hirschberg [6]. It has been researched and applied
in various applications, sometimes with additional constraint, e.g., the LCS
must also contain a pattern X, which is a subsequence appearing in both input
strings A and B. If A, B and X are all of length O(n), Tsai gave an O(n5) time
algorithm [13]. The bound was improved to O(n3) by Chin et al. [3] and also

A few years ago, based on the observed phenomena in applications that
sometimes the longest common subsequence might not capture the truely needed
or observed pattern in many applications, Sakai studied the maximal common
subsequence (MCS) of two strings [10, 11]. For two strings A and B with a

an algorithm which can compute an MCS in O(mn log n) time [4].
Both of
these algorithms work for the case when the solution must contain a pattern (or
subsequence) of A and B.
In many biological applications, sometimes useful non-contiguous patterns
exist in a single input string.
For example, plants go through up to three
whole genome duplications; hence there is a general repetition pattern (even
after some subsequent local mutations) [16].
Applications like this motivate
the Longest Square Subsequence (LSS) problem, i.e., a longest pattern like AA
where both AA and A itself are subsequences of an input sequence S of length
n, for which Kosowski gave an O(n2) time algorithm in 2004 [7]. For the longest
k-repeating subsequence, i.e., a longest pattern like Ak where both Ak and A are
subsequence of S, there is a trivial algorithm: just enumerate k−1 cuts in S and
then compute the longest common subsequence of the resulting k strings. This
results in an O(n2k−1) time algorithm; unfortunately, this is the best known
algorithm for k ≥3. For k = 3, Wang and Zhu gave a parameterized O(q2n3)
time algorithm, where q is the minimum number of letters deleted in S to have
a solution [15]. However, when q = O(n) the worst-case running time of this
algorithm remains to be O(n2 × n3) = O(n5).
Recently, motivated by recovering patterns from tandem duplications, Lai
et al. studied the Longest Letter-duplicated Subsequence (LLDS) and related
problems [9]. Here a letter-duplicated subsequence (LDS) is a subsequence of
S in the form Qk

Preliminaries
2.1
Basics
Let Σ be an alphabet and S be a given sequence over the alphabet Σ. We let
n = |S| denote the length of S and m = |Σ| denote the size of Σ, respectively.
For every 1 ≤i ≤|S|, we denote by S[i] the i-th character in S. A sequence X
is a subsequence of S if there exist 1 ≤i1 < i2 < . . . < i|X| ≤|S| such that X =
S[i1]S[i2] . . . S[i|X|]; in this case we also abuse the notation by writing X ⊆S.
We denote the empty string as ϵ. Given two positive integers 1 ≤i < j ≤|S|,
we denote by S[i, j] the substring of S that begins with S[i] and ends at S[j].
Note that we define S[j, i] = ϵ when j > i. Furthermore, S[1, j] is called a
prefix of S, while S[i, n] is called a suffix of S. Given a character σ ∈Σ, we
use σℓto denote the concatenation of ℓcopies of the character σ. We use open
interval notation to indicate exclusive index substrings; i.e., S[i, j) = S[i, j−1],
S(i, j] = S[i + 1, j], and S(i, j) = S[i + 1, j −1]. Moreover, we define #S(σ)
to be the number of occurrences of σ in S.
Given two sequences S and T, a maximal common subsequence C of S and T
is one which is not a subsequence of any other common subsequence C′ of S and
T. (Note that the longest common sequence of S and T is simply the longest
maximal common subsequence.)
Sakai’s algorithm is based on the following
observation (which was not explicitly stated in [10]).
Observation 2.1 Let C be a common subsequence of two input strings S and
T.
Either C is maximal, or C can be augmented into a maximal common
subsequence C′ of S and T by inserting letters.
Note that this property does not hold for the longest common subsequences,
i.e., one cannot always augment an arbitrary common subsequence into a longest
one. Sakai’s algorithm [10] basically greedily searches a common subsequence of
S and T from right to left and uses additional maximality property to check if it
is maximal; if not, then backtrack by adding more letters until the maximality
property holds (i.e., a maximal common subsequence is computed).

Basics on One String
A square subsequence of S is a subsequence S and can be represented in the
form XX. A square subsequence B of S is maximal if there is no other square
subsequence C of S that properly contains B. As a warm-up, we first study the
maximal square subsequence problem that seeks a maximal square subsequence

it from the sequence since it will never appear in a maximal square subsequence.
Therefore, we can assume that every character appears at least twice in S.
Definition 2.1 Suppose that X = Y Y is a square subsequence of S. We say X
is right-extendable (left-extendable, respectively) if there is a character y such
that Y yY y (yY yY , respectively) is a subsequence of S.
Similarly, X = Y Y is inner-extendable if there is a character y such that
Y1yY2Y1yY2 is subsequence of S where Y = Y1Y2 and neither of Y1 and Y2 is ϵ.

Observation 2.2 Let σ be a letter in S which appears ℓtimes. Then there
must be a maximal square subsequence containing 2⌊ℓ/2⌋copies of σ.

Computing a Maximal k-repeating Subsequence
4.1
Definitions
Definition 4.1 (alignment) Given two strings A and S, an alignment of A
on S is a one-to-one function ϕ from [1, |A|] to [1, |B|] such that the order of
the indices in A are preserved by ϕ and the letter at the every index of A is the
same as letter in S its index gets mapped to. Note that A is subsequence of S if
and only if there is some alignment of A on S.
Definition 4.2 (k-repeating subsequence) Let S be a string and let k ∈
Z>0. A subsequence X ⊆S is called a k-repeating subsequence of S if and only
if Xk ⊆S. We denote the set of all k-repeating subsequences of S by kRep(S).
Definition 4.3 (maximal-k-repeating subsequence) Let S be a string and
let X ∈kRep(S). We say that X is a maximal k-repeating subsequence of S
if and only if for every subsequence Y with Y ⊃X, we have Y /∈kRep(S). We
denote the set of all Maximal-k-Repeating subsequences of S by MkRep(S).
For a string S, an index i ∈[1, |S|], and X ⊆S, we use NextS(X, i) to
denote the smallest index j ≥i such that S(i, j] contains X as a subsequence. If
X ̸⊆S(i, |S|], we define NextS(X, i) to be Null. Likewise we use PrevS(X, i)
to denote the largest index l ≤i such that S[l, i) contains X as a subsequence.
If X ̸⊆S[1, i), we define PrevS(X, i) to be Null. Intuitively, PrevS(X, i)
and NextS(X, i) adapt definition 3.1 to both left and right and to work for any
index.
Definition 4.4 (σ-start) Given the string S and r ∈Z>0, a σ-start for σr is
a k-tuple (p1, p2, . . . , pk) such that the following three conditions are satisfied:
1. 1 ≤p1 < p2 < . . . < pk ≤|S| and;
2. S[p1] = S[p2] = . . . = S[pk] = σ and;
3. For the ease of presentation, we let pk+1 = |S| + 1. Then σr is a subse-
quence of S[pj, pj+1 −1] for every j = 1, 2, . . . , k.
Definition 4.5 (σ-split point) Given string S, let A, B ∈Σ∗, the σ-split
points for A and B are p ∈[1, |S|]k where each index in p corresponds a σ
in S and for every i ∈[1, k], NextS(B, pi) and PrevS(A, pi) are not Null
with NextS(B, pi) < PrevS(A, pi+1) when i ̸= k.
Note that a σ-start for σr is also a σ-split point for ϵ and σr−1; conversely,
any such σ-split point corresponds to a σ-start for σr. We use these definitions

4.2.1
Finding one maximal subsequences in a collection
Similarly to the Maximal Square Subsequence problem, when searching for k-
repeat subsequences, we use the subsequence relation as means to compare
and order strings instead of using their length. To provide intuition for our
algorithm, first consider the problem of finding a single string in a collection
S = {A1, A2, . . . , Ak} with no proper supersequences in S (e.g., a maximal
string in S with respect to the subsequence relation) as opposed to the longest
string. Suppose we start by selecting some string Ai in S which we treat as
candidate for being a maximal string in S. When we attempt to verify if Ai
is maximal, we either find some element in S that is a proper supersequence
of Ai (thus Ai is not maximal) or we cannot and therefore Ai is maximal. In
the first case, we are able to insert some characters into Ai to produce a larger
(with respect to subsequence relation) string in S which we can use as a new
candidate for a maximal string in S. Thus, repeating this process allows us to
find some additional characters which we can insert into Ai to produce another
string in S, however, as S only has a limited number of strings, we eventually
must find a supersequence of Ai in S that cannot be improved any further by
inserting additional characters. This means a maximal subsequence of S can
always be found by adding characters to an initial guess. If we, instead, were
searching for the longest string in S, this may not be possible, as every longest
string in S may require us to delete parts of Ai to produce it.
For a concrete example, take S = {aba, ababb, aa, c, xyxyay}. If we start
with aa, we can produce a maximal string in S by first jumping to aba by
inserting b into aa and then jumping to ababb by inserting bb on the end of aba.
At this point, see that we can no longer improve ababb and therefore we have
found a maximal string. However, if we are searching for the longest string in S,
it is impossible to obtain xyxyay starting from aa merely by inserting additional
letters; doing so would require deleting one a from aa.
The example above highlights another quirk related to searching for maximal
strings. If we instead pick c as the first candidate, we would have immediately
found a maximal string in S despite c also being the shortest string in S. Further,
unlike aa, where we may need to through two rounds of searching for letters to
insert before reaching a maximal solution, here we would have to go through

only one. Taken together, this means (1) when looking for maximal strings in a
collection, we can start by selecting any string and look for characters to insert
into it until it becomes a maximal string. (2) The initial candidate can affect
how long it takes us to produce a solution. Picking a good first candidate could
be dramatically faster even if it is small.

4.2.2
Algorithm for k-Repeating Subsequences
We provide an overview of how our algorithm works to finds a new candidate
for a maximal k-repeating subsequence given a initial candidate X in S. At
a high level, our algorithm starts by picking a “guess separator” letter σ in
X and writing X as AσB where A is the prefix in X that ends just before
the first σ and B is the suffix in X that ends just after the first σ in S. We
then attempt to iteratively build up a new prefix A′ that contains A and suffix
B′ that contains B by exhaustively scanning all locations for σ in S where
a supersequence A′′σB′′ with a equal or larger (with respect to subsequence
relation) suffix and prefix could be. Note if we verify we can not extend our
suffix or prefix given any location, observation 4.1 implies we have maximal
solution. At each location in our scan, we apply the algorithm by Hirota and
Sakai [4] to improve our current A′ and B′ and eliminate the possibility that any
k-repeating subsequence A′′σB′′ can be found at the current locations such that
we could increase the size of A′σB′ by inserting characters into our prefix or
suffix and taking the produced string as our new candidate. After our algorithm
has exhausted all locations, we know no characters can be inserted before our
prefix and suffix to produce a proper supersequence that is also k-repeating in
S; thus, our current string A′σB′ is maximal.
Now fix a string X ∈kRep(S) which is our initial candidate for the algo-
rithm. We can write X = AσB, where A ∈(Σ \ {σ})∗, B ∈Σ∗, for any σ ∈Σ
that appears in X. Let r = #X(σ) be the number of occurrences of σ in X and
R = #S(σ) −k · r. Since X ∈kRep(S), there must exist an alignment of Xk
as it is a subsequence of S. In particular, the first occurrence of σ in each copy
of X must be mapped to some occurrence of σ in S thus, R is the number of

σ in S not used in an alignment of Xk. Intuitively, our algorithm proceeds by
enumerating and iterating over all potential alignments of these first σ for our
initial candidate. To do this we consider locations for the R remaining σ across
the k blocks of r σ placed consecutively where the start position of the next
block is determined by the position of the last block placed and some number of
the remaining R σ we choose to not use in a block. Note that, for any potential
alignment of the first σ, there must exist at least r number of σ between the
starting positions of the first σ in each consecutive block; otherwise, it cannot
be a potential starting alignment of the first σ. However, note that, for the
potential positions of first σ we consider, there is no guarantee that we can
align A to the left and B to the right of each σ at the position we guess such
that their placement forms an alignment for (AσB)k. This is because the only
guarantee is that there are at least r occurrences of σ in S between the consec-
utive starting positions of the first σ in k blocks of r σ, which is a necessary but
not sufficient condition for any first σ in each block of a sequence containing σr
such as X. Thus we consider a superset of all positions for the first σ in each
block for Xk. Given a potential alignment of the first σ, the algorithm attempts
to extend the left and the right parts of each block (relative to the first σ) in
order to form a larger candidate k-repeating subsequence. As a result, the main
computational work comes from iterating over all potential alignments of the
first σ in X. Fortunately, we can bound the number of such alignments using a
stars-and-bars argument.
Suppose Y ∈MkRep(S) such that Y ⊇X. Then the alignment of some
σ, although maybe not the first, in each block of Y must also correspond to
some starting alignment of the first σ in X. This means that by systematically
considering all possible alignments of the first σ in X and attempting to extend
our current candidate with the algorithm by Hirota and Sakai [4], our procedure
is guaranteed to find a maximal k-repeating subsequence that contains X. To
calculate the number of such alignments, observe that if X ∈kRep(S) and
contains r occurrences of σ, then aligning k copies of X will consume k·r occur-
rences of σ in S and the remaining number of unused σ is R. These remaining R
occurrences can be distributed in the gaps between the locations of the first σ as
described earlier, which is equivalent to partitioning R indistinguishable items
into k + 1 distinguishable bins. Clearly, there is a bijection between the set of
potential alignments of the first σ in each block and the set of such partitions.
This gives us a concrete way to bound the number of guesses the algorithm
needs to make and, consequently, to derive its worst-case running time.

Concluding Remarks
We give efficient algorithms to compute the maximal square subsequence (resp.
maximal k-repeating subsequence) of an input string S of length n, with run-
ning time O(n log n) (resp. O(f(k)n log n)). These are much faster than the
‘maximization’ versions, with running time O(n2) and O(n2k−1) respectively.
However, for the constrained versions where a pattern X of S must not ap-
pear in a maximal square subsequence (resp. maximal k-repeating subsequence),
the problems are completely open.
