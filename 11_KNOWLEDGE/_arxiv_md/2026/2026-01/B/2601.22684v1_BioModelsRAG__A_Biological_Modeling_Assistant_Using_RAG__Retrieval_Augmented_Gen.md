Abstract
The BioModels database is one of the premier databases for com-
putational models in systems biology. The database contains over 1000
curated models and an even larger number of non-curated models. All
the models are stored in the machine-readable format, SBML. Although
SBML can be translated into the human readable Antimony format,
analyzing the models can still be time consuming.
In order to bridge this gap, a LLM (large language model) assistant
was created to analyze the BioModels and allow interaction between
the user and the model using natural language. By doing so, a user
can easily and rapidly extract the salient points in a given model. Our
analysis workflow involved ‘chunking’ BioModels and converting them
to plain text using llama3, and then embedding them in a ChromaDB
database. The user-provided query was also embedded, and a simi-
larity search was performed between the query and the BioModels in
ChromaDB to extract the most relevant BioModels. The BioModels
were then used as context to create the most accurate output in the
chat between the user and the LLM. This approach greatly minimized
the chance of hallucination and kept the LLM focused on the problem
at hand.

Introduction
BioModels is a repository of mathematical models of biological and biomedical
systems. It hosts a large selection of existing literature-based physiologically
and pharmaceutically relevant mechanistic models in standard formats such
as SBML [1][2]. However, even with their associated published paper, these
models can be hard to understand without explicit understanding of the
biological mechanism described in the model. This limits the usage of these
model for biologists without background information in systems biology
modeling. In addition, the BioModels website does not provide the more
human-readable version of SBML in the form of Antimony [3].
LLMs or Large Language Models include models such as ChatGPT,
Claude, and Gemini [4].
These models function by using deep learning
architectures, trained on massive datasets from the internet, such as books,
and the GitHub repository. In generating code and text, LLMs have shown
great potential [5]. Therefore, LLMs have great possibilities in analyzing
Antimony models, specifically in converting Antimony into even simpler
human-readable text to facilitate understanding by the user.
Retrieval Augmented Generation (RAG) is a technique that can be used to
reduce hallucinations in LLMs. Hallucinations often occur in LLMs, and this
is due to the fact that when LLMs are unable to produce coherent output, they
fill in the blanks by including data that is plausible, but incorrect, especially
while performing knowledge-intensive Natural Language Processing (NLP)
tasks [4][6]. RAG can be used to provide relevant context to the LLM, so
it is able to draw information from the context and fill in the hyper-specific
information not present in its training data, and prevent hallucination of
the model, which could be detrimental to the user’s understanding. In this
study, RAG was used to implement a chatbot where the user can query
for different BioModels and subsequently "converse" with the LLM about a

Methods
In alignment with the objectives highlighted in the introduction, a Retrieval-
Augmented Generation (RAG) based system was developed using Large
Language Models (LLMs) to provide a user-friendly interface for individuals
to dynamically interact with biomodels, even those without extensive back-
grounds in systems biology or computational modeling. The chatbot was
also deployed as a web application, enabling users without a command line
interface or an IDE set up to use the chatbot through the web.
In order to construct the RAG assistant, a multi-part pipeline was created.
The first part of the pipeline is preparing and caching the models on a vector
database. The second part of the pipeline is retrieving the relevant context
from this database using user’s query, putting it into the prompt, passing
into the LLM and returning the LLM’s response to the user. The following is
the detail of each step of the pipeline.
2.1
Downloading, converting, and segmenting BioMod-
els
All biomodels were downloaded via an API connecting the chatbot’s backend
to a GitHub repository with the SBML version of the models. Using the
Tellurium and Antimony libraries, all models were converted from SBML
format to Antimony format to enable easier segmentation [2] [7].
2.2
Conversion of the Antimony model into plain text
Through some preliminary experiments, we noticed that when the entire
Antimony model was provided to the LLM and a simple query was asked,
the LLM failed to accurately answer the question. We deduced that this was
due to the fact that providing the LLM with the entire model caused it to
overload the LLM’s context window. In order to prevent this, the model was
split into its constituents.
The models were split into the following sections using text-based splitting:
• Compartments and species

2.3
Storage of the Antimony models in a vector database
Embedding is the process of converting unstructured data (such as text) into
a numerical representation that computers can understand. The text chunks
are projected as vectors into a multi dimensional space, which allows them
to be represented as numbers [8]. Each summarized segment was added to a
ChromaDB (a database hosted by the organization Chroma), to be queried
with the user’s prompt later on so that the user can get the most relevant
pieces of context in their response. Embedding was conducted using the
sentence-transformers package, specifically the all-MiniLM-L6-v2 model. The
all-Mini-LM-L6-v2 model is better suited for this task compared to earlier
models as it is a very lightweight model that processes queries quicker than
previous models. The ChromaDB was initialized through the web service
so that once every biomodel was processed, they could be queried from the
database without needing to regenerate the summaries.
2.4
Receiving user’s query
The user’s query is received from the frontend of Streamlit through a text
entry box. Once the query is received by Streamlit, it used to query the
database in the next step.
2.5
Database querying
In order to find the most relevant parts of the biomodel that correlate with
the query, a vector search is performed on the Chroma database initialized in
the previous step. In order to perform the vector search, cosine similarity is
calculated between the user-provided query and every query in the database.
Cosine similarity is a representation of how closely "related" the two vectors
are. It does this by calculating the cosine of the angle formed by the two
vectors, once they are projected into a higher dimensional space. A higher
cosine similarity indicates a higher correlation between the two text chunks.
A database search is done and the 5 pieces of context with the highest cosine
similarity are used as context with the final answer generation.

Results
In order to test the RAG system’s performance, two measures were used:
fuzzy string matching (which is measured using token set ratio), and cosine
similarity. These properties were used to test the following properties: whether
the "main idea" is correct, whether the LLM "hallucinated" (or in layman’s
terms, "made up") the final answer, and whether the response is on-topic.
Fuzzy string matching was used to determine how similar the "main
idea" is between the text by removing common words like “the”, “and”, and
others, and only retaining the words that add meaning to the text. When
we compare the provided context, and the LLM output, we can determine
whether the LLM is including words that are not referenced in the context,
indicating that it could be hallucinating. If the token set ratio is higher
(implemented through fuzzy string matching), there is increased similarity,
indicating that it is more similar, and therefore containing less hallucination.
Cosine similarity was used after it was established that the RAG sample
contained less hallucination and relevant to the context (measured using
the token set ratio). Cosine similarity measured how relevant the non-RAG
sample was to the RAG sample, which determined whether the non-RAG
sample was on-topic and actually answered the user’s question. When token
set ratio and cosine similarity were calculated, significant differences were
found between the RAG and non-RAG samples.
To conduct these tests (as well as create the LLM that the local version of
the chatbot was deployed with), the following custom parameters were found
through preliminary tests. Custom parameters (temperature of 0, topk of 25
and topp of 1.5) improved the summarization output, by slightly increasing
the token set ratio (slightly decreasing the likelihood for hallucination to
be present in the summarization output). The topp is a parameter that
controls the "randomness" of the model’s output, the topk restricts the range
of possible of words by reducing the part of the probability distribution that
the LLM samples from when picking the next word, and the temperature is
another parameter that controls the randomness of the output. The goal of
these tests was to find the optimal set of parameters to prevent the LLM from
making up information (hallucination). Through these tests, we discovered
that a temperature of 0, and the provided topp of 1.0 and topk of 20 were the
most optimal.
These results have shown that responses using the RAG technique are
more detailed (as indicated by the higher token set ratio) and have reduced
8

hallucination due to the fact that the LLM has the context necessary to output
a scientifically accurate response. This project also streamlined the process
of getting the SBML model from the BioModels repository and converting it
into Antimony using tellurium. Overall, in this study, RAG was applied to
biomodels to create a LLM assistant for researchers to help with modelling
processes.
The results of using the RAG-based approach allows users to understand
the vast amount of information available in the BioModels repository in
layman’s terms to aid their modeling efforts.
In order to test the fact that the RAG system shows reduced hallucination
compared to the Llama3 output without RAG, fuzzy string matching using
token set ratio was utilized to find the commonalities between the provided
context and the final generated output. Finding the percentage of commonality
between the context and final generated output can be used to find out whether
the RAG system hallucinates - if there are significant semantic and word
differences between the context and the final generated response, that could
very likely mean that the model is hallucinating ideas and words that are not
present in the context.
To measure the hallucination and how off topic the non-RAG samples
were compared to the RAG sample, cosine similarity was used to determine
whether or not the non-RAG samples were off-topic and also were hallucinated
answers [9]. Cosine similarity embeds the text and calculates the similarity
between the two text vectors - the more similar they are, they less likely the
non-RAG output is to be off topic, as the RAG output has been established
as the non-hallucinated and on-topic baseline.

Llama3 Output Without RAG: Example 1
Assumptions and Clarifications
I think there may be a few assumptions or misunderstandings in your
question that need to be addressed. Firstly, the concept of “energy pool”
is not a standard term in chemistry. It’s possible that you’re referring
to the activation energy Ea required for a reaction to occur, but I’ll
assume it’s something else entirely.
Secondly, increasing the concentration of ions is not necessarily related
to the energy where ions are reactants. The two concepts are distinct:
concentration refers to the number of particles per unit volume, while
energy is a measure of the ability to do work.
Impact of Ion Concentration
That being said, let’s consider how increasing the concentration of ions
might affect the reaction:
1. Concentration-dependent reactions:
If the reaction is
concentration-dependent (i.e., the rate of reaction depends on the
concentrations of reactants), then increasing the concentration of
ions could lead to an increase in the reaction rate. This is because
there are more particles available to collide and react.
2. Rate equations: The reaction rate can be described by a rate
equation, which takes into account factors like concentrations,
activation energy, and other kinetic parameters. Increasing the
concentration of ions might lead to a higher reaction rate, but
this depends on the specific rate equation and the values of the
kinetic parameters.
However, exponential growth is unlikely in most chemical reactions.
Chemical reactions typically follow power-law or logarithmic dependen-
cies, rather than exponential ones. To illustrate this, consider a simple
example:

The Arrhenius Equation
The rate constant k for a reaction can be described by the Arrhenius
equation:
k = Ae−Ea
RT ,
where A is a frequency factor, Ea is the activation energy, R is the gas
constant, and T is the temperature. Increasing the concentration of
ions would not directly affect the exponential term in this equation.
Exponential Growth
In general, exponential growth occurs when there are feedback loops
or autocatalytic processes involved. Chemical reactions typically don’t
exhibit these types of feedback mechanisms, so exponential growth is
less common in chemical reactions.
Conclusion
To summarize: increasing the concentration of ions might lead to
an increase in reaction rate, but this depends on the specific rate
equation and kinetic parameters. Exponential growth is unlikely in
most chemical reactions unless there are specific feedback loops or
autocatalytic processes involved.

The assignment rule for ATP is a set of guidelines that determines how
the phosphate groups are transferred from one molecule to another
during cellular energy conversion.
Rules of the Assignment
The assignment rule states that:
1. The first phosphate group (α-phosphate) is always transferred to
ADP (Adenosine Diphosphate) to form ATP.
2. The second phosphate group (β-phosphate) is always transferred
to the next acceptor molecule, which is usually another enzyme
or protein.
3. The third phosphate group (γ-phosphate) is also transferred to
the next acceptor molecule.
In other words:
• α-phosphate →ADP + Pi
• β-phosphate →Next acceptor molecule
• γ-phosphate →Next acceptor molecule
This assignment rule ensures that the energy stored in ATP is efficiently
transferred to the cellular machinery, allowing cells to perform various
functions such as muscle contraction, nerve impulses, and biosynthesis.

Implementation/Deployment
In order to allow users who might not have an IDE set up to be able to use
the RAG system, we also deployed the functionality on a website (https://
biomodelsrag.streamlit.app/). The website provides the ability to choose
specific biomodels from a drop down menu, visualize the model, and then
enter a query. The previous conversation is also used as context.
The website was deployed as a Streamlit space [11]. The website also uses
the same version of llama 3.1 (llama3.1-8b), but the instant version is used in
the website, and the instruct version is used in the Python package.
In the website, the Groq Chat Completion API was used, and in the
Python package, a local deployment of ollama was used.

Conclusions and Implications
The BioModelsRAG package and website presents an advancement in the text-
based analysis and interaction with biological models. As stated by Clusmann
et al., LLMs could have a significant impact on the field of medicine by
aiding doctors in understanding and synthesizing information, and this can
be extended to researchers as well in understanding the variety information
available in BioModels [12].
In conclusion, the pipeline described in this paper summarizes Antimony
format models by creating a chatbot for users to better understand and
analyze biomodels. To begin this workflow, a biomodels model is chosen
by the user and is downloaded from a separate GitHub repository. The
are converted from SBML into Antimony, segmented into specific sections
and summarized using an LLM. The processed model is added to a vector
database and is queried with the user’s query to get the most accurate pieces
of context for the LLM to use. This pipeline is a convenient way for users to
investigate specific biomodels using a natural language interface.
By leveraging Retrieval Augmented Generation (RAG) techniques, the
package efficiently bridges the gap between complex biological models and
user inquiries, serving as an effective assistant for researchers and educators
[6]. This integration enables researchers and practitioners to interact with
biomodels in a dynamic, user-friendly manner, facilitating deeper insights
and understanding of biological processes. In addition, BioModelsRAG has
reduced hallucination as seen in the Query examples. Further avenues of
research may include implementing GraphRAG to increase the relevance/accu-
racy of the output beyond baseline RAG. In all of the samples included in this
paper, the token set ratio was above 60, indicating their reduced hallucination
compared to the context they were based off of. However, for the non-RAG
samples, their cosine similarity was 0.335, indicating their irrelevance and
possible hallucination compared to the on-topic RAG output.
As the field of biological modeling continues to evolve, BioModelsRAG
offers a robust, extensible framework for integrating advanced language pro-
cessing capabilities, paving the way for future developments in AI-assisted
biological analysis and interpretation.
