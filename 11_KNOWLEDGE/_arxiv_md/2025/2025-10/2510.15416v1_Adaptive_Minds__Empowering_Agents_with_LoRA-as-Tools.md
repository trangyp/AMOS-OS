ABSTRACT
We present Adaptive Minds, an agentic system that treats LoRA adapters as domain-specific tools.
Instead of relying on a single fine-tuned model or rigid rule-based routing, our approach empowers the
base LLM itself to act as a semantic router analyzing each query and dynamically selecting the most
relevant LoRA tool. This enables the agent to seamlessly switch between different domain experts on
demand. By combining the flexibility of multi-agent orchestration with the efficiency of parameter-
efficient fine-tuning, Adaptive Minds delivers accurate, specialized responses while preserving
conversational ability. The system is built with LangGraph for workflow management, supports both
API and web interfaces, and is fully open source, providing a scalable and extensible foundation for
domain-adaptive AI assistance. Code: https://github.com/qpiai/adaptive-minds
Keywords Multi-agent systems · Domain-specific AI · LoRA fine-tuning · Semantic routing · Agentic AI frameworks ·
Parameter-efficient fine-tuning · Tool-augmented LLMs

Introduction
The rapid advancement of large language models (LLMs) has enabled remarkable capabilities in natural language
understanding and generation. However, while general-purpose models excel at broad knowledge tasks, they often
lack the depth and specificity required for specialized domains such as chemistry, medicine, or finance. Traditional
approaches to domain specialization typically involve either training separate models from scratch or fine-tuning entire
models for each domain, both of which are computationally expensive and resource-intensive.
Recent developments in parameter-efficient fine-tuning, particularly Low-Rank Adaptation (LoRA) [1], have made it
feasible to create domain-specific adaptations of large models with minimal computational overhead. However, a critical
challenge remains: how to intelligently route user queries to the most appropriate domain expert while maintaining
system coherence and user experience[2].
This paper introduces Adaptive Minds, an agentic system that addresses this challenge through AI-powered intelligent
routing. Our key contributions are:
• LoRA-as-Tools: A unified framework where specialized LoRA adapters are dynamically selected and applied
as needed.
• Semantic Routing: The base model performs query analysis and routes to the right domain adapter without
handcrafted rules or keyword matching.
• Modular Multi-Agent Design: Built with LangGraph, separating routing from expertise for scalability and
extensibility.
• Visible Routing Decisions: The system outputs the chosen domain adapter for each query, providing
transparency into how requests are directed.
• Open Source System: Full implementation with Docker, API, and web interfaces for easy deployment.

Related Work
2.1
Multi-Agent Systems for NLP
Multi-agent systems have been extensively studied in artificial intelligence, with recent applications to natural language
processing showing promising results [3, 4]. Traditional multi-agent NLP systems often rely on predefined rules or
simple classification models for task routing. Our approach differs by using the base language model itself as the
routing intelligence, leveraging its semantic understanding capabilities.
2.2
Parameter-Efficient Fine-Tuning
Parameter-efficient fine-tuning methods, particularly LoRA [1] and its variants [5, 6], have revolutionized domain
adaptation for large language models. While most work focuses on individual domain adaptations, our system
demonstrates how multiple LoRA adapters can be orchestrated within a single multi-agent framework.
2.3
Domain-Specific Language Models
Previous work on domain-specific language models includes BioBERT [7], FinBERT [8], and ChemBERTa [9]
for medical, financial, and chemical domains respectively. These models typically require full fine-tuning and
operate independently. Our approach enables multiple domain experts to coexist within a unified system with shared
computational resources.
2.4
Intelligent Task Routing
Task routing in multi-agent systems has been addressed through various approaches including reinforcement learning
[10], classification-based routing [11], and rule-based systems [12]. Our AI-semantic routing represents a novel
approach that leverages the language understanding capabilities of the base model for routing decisions[13, 14].

Methodology
3.1
System Architecture
Adaptive Minds is structured around two main agents (Router Agent + Expert Agent) orchestrated via LangGraph.
While in our experiments we used a LLaMA-3.1 8B base model and five domain adapters, the architecture is designed
to support any base model and any existing LoRA adapters, and allows you to train and add new ones seamlessly.
3.1.1
Router Agent
The Router Agent is responsible for analyzing incoming queries and selecting the most appropriate domain expert.
Unlike traditional routing approaches that rely on keyword matching or separate classification models, our Router
Agent leverages the base LLM’s semantic understanding to perform domain inference.
Routing Process:
1. Query Analysis: The router receives a user query and constructs a structured prompt containing the query and
available domain experts.
2. Semantic Evaluation: The base model analyzes the query semantically, considering context, intent, and
domain relevance.
3. Domain Selection: The model returns the name (or identifier) of the chosen adapter/domain.
4. Validation and Fallback: If the choice is ambiguous or invalid, the system can validate the output (e.g. match
against a canonical adapter list) and fall back to a safe default (e.g. a “General” adapter).
Routing Prompt Template:
Adaptive Minds does not use a hardcoded routing prompt. Instead, the Router Agent
maintains metadata about each registered LoRA adapter (e.g. domain name, description, instructions, keywords) in a
configuration file. When the system is started, the router dynamically builds its routing prompt from the metadata file.
This approach makes routing logic flexible, maintainable, and scalable. You can add, remove, or update domain
adapters by modifying configuration metadata—without touching the core router code.

3.2
Domain Expert Implementation
3.2.1
LoRA Adapter Configuration
In our design, each domain expert is realized as a LoRA adapter, which is applied on top of a shared base model (e.g.,
Llama 3.1-8B). This arrangement allows us to maintain a single backbone while specializing behavior via lightweight
adapters.
Mathematically, each LoRA adapter introduces a low-rank update to the original weight matrix W of the base model
layer. Instead of updating all parameters, LoRA represents the change as the product of two smaller matrices A and B
scaled by a factor α:
W ′ = W + ∆W,
∆W = α · BA,
(1)
where A ∈Rr×d and B ∈Rd×r with r ≪d. This low-rank decomposition significantly reduces the number of
trainable parameters while preserving expressive capacity.
We store each adapter in a Hugging Face repository, and associate with it descriptive metadata and a domain-specific
system prompt to steer the adapter’s behavior.

3.3
LangGraph Workflow Implementation
Adaptive Minds employs LangGraph [15] as the underlying framework for workflow orchestration and process
management. LangGraph provides a structured yet flexible way to define and execute agent workflows, enabling the
system to coordinate routing, inference, and memory components efficiently. It manages the conversation state across
multiple interactions, ensuring that contextual information is consistently preserved and accessible throughout the
dialogue. Furthermore, its robust error-handling and fallback mechanisms improve reliability by allowing the system
to recover gracefully from failed operations. LangGraph’s modular design also facilitates rapid experimentation and
extensibility—new nodes, agents, or workflows can be introduced without disrupting existing functionality. In addition,
its built-in logging and monitoring tools provide transparency and traceability across agent decisions, making it an ideal
backbone for scalable, interpretable, and adaptive AI systems.
While LangGraph serves as the primary orchestration framework in this implementation, the workflow design of
Adaptive Minds is framework-agnostic and can be replicated using other agent frameworks or even through custom
orchestration logic without relying on any dedicated agent framework.
3.4
Conversation Memory and Context
To ensure continuity and coherence in dialogue, Adaptive Minds incorporates a structured conversation memory
mechanism. The system retains a selective history of recent user–assistant exchanges, allowing each new query to be
interpreted in the context of prior interactions. During inference, the router and expert modules integrate this contextual
information directly into their prompts, enabling more accurate and contextually grounded responses. Memory length
is dynamically managed to balance contextual richness with computational efficiency—older, less relevant turns are
pruned to maintain optimal performance. This design ensures that the model remains responsive and context-aware
without incurring excessive memory or latency overhead.

Experimental Setup
We conducted all experiments on a single NVIDIA L40s GPU, using the Meta LLaMA 3.1-8B-Instruct as the base
model (8 billion parameters, 128 K token context length, 16-bit precision). The system was fully orchestrated in this
environment to ensure consistency and reproducibility.
For domain adaptation, we used LoRA with rank = 16, α = 32, and dropout = 0.1, applied to the query, key, value, and
output projection layers. Each domain-specific adapter was fine-tuned via QpiAI Pro, a no-code platform that enables
rapid prototyping through seamless dataset creation, fine-tuning, and deployment of LLMs and Vision models. The
training datasets used were:
• Chemistry: AI4Chem/ChemData700K
• Finance: gbharti/finance-alpaca
• AI/Technology: pavan01729/GPT_AI_5.0_alpaca
• Medical: Kabatubare/medical-alpaca
• General: mhenrichsen/alpaca_2k_test
For deployment, the system is packaged in a containerized architecture to support portability and reproducibility. The
backend is implemented in FastAPI, responsible for query processing, routing, and adapter orchestration. The frontend
is built in Streamlit for interactive use. The full stack is deployed via Docker with GPU support (using the NVIDIA
Container Toolkit). At startup, the base model and all LoRA adapters are preloaded; adapter switching incurs negligible
overhead. We include automated downloading, caching, and versioning of adapters and base models from Hugging
Face repositories.
4.1
Deployment Requirements
The system requires a GPU with at least 16 GB of VRAM, 16 GB or more of system RAM, and a minimum of 30 GB
of available storage for model files. On the software side, the deployment environment should include Docker with
GPU support, the NVIDIA Container Toolkit, and Python 3.10 or later. These specifications ensure smooth model
loading, adapter switching, and real-time inference performance.

Use Cases and Applications
To illustrate the flexibility and real-world potential of the Adaptive Minds framework, we present several representative
use cases. These examples show how the system can adapt across domains and evolve over time.
5.1
Representative Scenarios
Multi-Domain Virtual Assistant
An organization wants a single intelligent assistant that can handle questions in HR, finance, product support, legal, and
technical domains. Rather than building separate bots, Adaptive Minds lets the assistant route queries to the appropriate
LoRA adapter (e.g., “HR”, “Finance”, “Technical”) and respond with domain-aware expertise. As new departments or
topics emerge, new adapters can be trained and added without changing the core system.
Support Desk for SaaS / Enterprise Tools
In a software product support setting, users might ask about billing, feature usage, integration issues, bug diagnostics,
or account settings. Adaptive Minds routes each ticket or chat query to the right adapter (e.g., “Billing / Finance”,
“Product / Usage”, “Technical / Debugging”) to provide accurate, context-sensitive answers. As the product evolves,
additional adapters (e.g., “Analytics”, “Security”) can be incorporated seamlessly.
Educational Tutoring System
A tutoring platform supports multiple school subjects (mathematics, chemistry, biology, computer science, history).
When a student poses a question, Adaptive Minds identifies and activates the corresponding subject LoRA (e.g., “Math”,
“Chemistry”) to produce a precise explanation. When a new subject is added (e.g., economics), a new adapter can be
trained and integrated into the system without altering routing logic.

Resource Utilization
Despite supporting five LoRA adapters simultaneously, Adaptive Minds adds only a minimal memory overhead

utilization between 12–18% during inference.

touching the core routing logic. The framework supports end-to-end training and deployment of new adapters, and
lets organizations rapidly expand into new domains. This modularity ensures that as your needs grow, the system can
evolve: more adapters, updated models, custom specializations—all coexist seamlessly within the same architecture
8.3
Limitations
Adaptive Minds demonstrates strong modularity and adaptability, but several limitations remain. First, each query
requires two inference passes—one for routing and another for expert generation—which adds latency compared to a
single fine-tuned model. Second, certain user queries naturally span multiple domains (e.g., pharma and chemistry),
making it difficult for the system to assign a single expert without losing contextual richness. Third, as the number
of concurrently loaded LoRA adapters increases, potential interference between adapters may affect stability and
performance. Finally, evaluating domain-specific quality remains challenging, as it requires expert human annotation
and large-scale validation to ensure fairness, reliability, and consistency across specialized domains.
8.4
Future Work
Future work will focus on enhancing both scalability and intelligence within the Adaptive Minds framework. One
key direction involves enabling the system to dynamically load new LoRA adapters during the ReAct loop. In the
current setup, once an expert adapter is selected, the entire response is generated using that adapter alone. By contrast,
dynamic loading would allow the router to activate or switch adapters mid-inference as reasoning unfolds—similar
to how an agent decides which external tool to call next. This would enable context-aware specialization, where
different sections of a response could draw on different domain experts in real time. We also plan to explore weighted
adapter fusion, allowing the router to assign proportional importance to multiple domains (e.g., 0.3 for Medical and
0.7 for Chemistry) for more nuanced outputs. Additional goals include reducing computational overhead through
lighter or inline routing, and investigating caching and quantization strategies for efficient on-demand adapter loading.
Finally, we will expand evaluation to larger multi-domain benchmarks and incorporate transparency features that
display which adapters contributed to each output. Together, these efforts aim to make Adaptive Minds more adaptive,
memory-efficient, and responsive to complex, interdisciplinary queries[2].
9
Conclusion
We introduced Adaptive Minds, an agentic framework that treats LoRA adapters as modular tools the base LLM can
call on demand. Rather than building many specialized monolithic models or brittle rule systems, the backbone LLM
acts as a semantic router: it inspects each query and dynamically selects the most appropriate LoRA tool to handle it.
This lets the system combine focused, expert knowledge with natural conversational behavior, so users get specialist
answers without losing dialogue quality.
The key strength of Adaptive Minds is its flexibility and scalability. The architecture is model-agnostic — it can run with
any base model, ingest existing LoRA adapters, and support training and registration of new adapters without changing
the core routing logic. This design unlocks many real-world use cases (enterprise assistants, tutoring, healthcare triage,
finance, research aids, etc.) while keeping compute and storage efficient through parameter-efficient fine-tuning. Our
LangGraph-based implementation, together with API and web interfaces and an open-source codebase, provides a
practical, extensible foundation for deploying domain-adaptive agents.
