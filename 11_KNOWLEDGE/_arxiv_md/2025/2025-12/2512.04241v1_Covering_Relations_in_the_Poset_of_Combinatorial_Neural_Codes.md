attempted to tackle this decision problem, but only partial results were achieved. In fact,
a previous study showed that the decision problem of convex neural codes is NP-hard.
Furthermore, the authors of this study conjectured that every convex neural code can be
realized as a minor of a neural code arising from a representable oriented matroid, which
can lead to an equivalence between convex and polytope convex neural codes. Even though
this conjecture has been confirmed in dimension two, its validity in higher dimensions is
still unknown.

characterization of the covering relations within the poset PCode of neural codes.

1. Introduction
In 1971, John O’Keefe and Jonathan Dostrovsky discovered individual hippocampal neurons
in rats that were active when the rats were in specific locations (O’Keefe and Dostrovsky,
1971). These neurons are known as place cells, and the regions in the environment where
these neurons fire are called place fields. For long, these neurons have been thought of as
encoding a cognitive map of a mammal’s environment. Many mathematical tools such as
algebraic topology have been used to decode any meaningful representation of neural signals
coming from place cells. Curto and Itskov applied topological data analysis to place cell
data in (Curto and Itskov, 2008) and found that many topological features of the stimulus
space can be extracted from cell groups when place fields were assumed to be convex and
even when a small portion of them was multi-peaked. Every neural code obtained from
cell groups also turns out to carry one geometric information of place fields, their convexity
(Curto et al., 2013), (Curto, 2017). This encoded information is intrinsic because it can be

full term combinatorial neural code.

has a realization. Furthermore, if there is a realization U consisting of open convex subsets
of Rd, we say that C is an open convex neural code.

These connections gave them a nice way of showing that the decision problem of open convex
neural codes is in fact NP-hard and that open convex polytope neural codes (a subclass of
open convex neural codes) are essentially those that lie below some representable oriented
matroids in PCode. They also conjectured that open convex neural codes are open convex
polytope.
Conjecture 3 (Kunin et al., 2020) A neural code C is convex if and only if C lies below
some representable oriented matroid in PCode.
The above conjecture is true in the plane R2 (Bukh and Jeffs, 2023), but has not been
proven in general. If this conjecture holds, we can avoid the decision problem of open convex
neural codes and instead check the representability of all oriented matroid codes lying above
a given code. While being ∃R-hard2, the representability of oriented matroids is still an
active area of research and can be solved for small ranks. However, to be certain of this
replacement, we need to validate or refute Conjecture 3. One way to do this is to construct
a method to travel up the poset PCode towards oriented matroid codes above it. Although,
for the time being, we have not been able to fully construct a method for this idea, we know
how one can “climb up” from one code to any code that covers it, which will be presented
in this paper. Our paper is structured as follows: some background of the poset PCode is
given in Section 2, and the reader can find our main contribution which is the method of
traveling upward PCode in Section 3. All supporting results can be found in Appendix A
and Appendix B.
2. The Poset of Combinatorial Neural Codes

An obvious property of trunks is that the intersection between any two trunks is again a
trunk (Jeffs, 2020, Proposition 2.2). The purpose of the trunks in a neural code is to encode
important combinatorial properties of certain groups of codewords, and the mappings which
preserve these important combinatorial relations among the codewords in a neural code
are called morphisms or neural codes. Intuitively, the notion of trunks in neural codes is
analogous to that of open stars in simplicial complexes. Morphisms of neural codes is then in
analogy to that of continuous functions between topological spaces: they are “continuous”
with respect to trunks.
Definition 6 (Morphisms of neural codes)
A function f : C →D is a morphism of
neural codes if the preimage f−1(T) of every proper trunk T in D is a proper trunk in C.
This definition uses proper trunks to define code morphisms rather than just any trunks
as in (Jeffs, 2020). As for this adjustment mentioned in (Jeffs, 2021, Remark 3.1.2.), it
ensures several nice properties of neural codes under morphisms.
The following, which
implies that the image of every neural code in the domain is a subcode of the neural code
in the codomain, is an example.
Proposition 7 If f is a morphism of neural codes, then f(∅) = ∅.
Proof See (Jeffs, 2021, Proposition 3.1.3).
Definition 8
Given some proper trunks T1, . . . , Tm in C. Then, the function f : C →2[m]
given by c 7→{j ∈[m] | c ∈Tj} is called the morphism determined by T1, . . . , Tm.
Proposition 9 The function described above in Definition 8 is a morphism. Moreover,
every morphism arises in this way: if D ⊆2[m] and f : C →D is any morphism, then f can
be obtained by restricting to D the codomain of the morphism g determined by the trunks
Tj = f−1(TkD(j)) in C.
Proof See (Jeffs, 2020, Propositions 2.11 and 2.12) .
Remark 10 Sometimes, it will be convenient to talk about the morphism determined by
a set of trunks without indexing the trunks. We may do this when we only care about the
isomorphism class of a neural code because a choice of indexing simply corresponds to a
permutation of neurons in the codomain, which is an isomorphism.
In the following, we present the poset PCode that was first introduced in (Jeffs, 2020)
and then slightly modified in (Jeffs, 2021). The formulation below has the advantage that
we no longer need to consider “replacement by a trunk” as a possible covering relation, since
every nonempty trunk in C, up to adding the ∅-codeword ∅, is a minor of C via a surjective
morphism (see Proposition 12). The formulation below allows us to maintain the previously
desirable properties of PCode while accounting for the usual neural code convention that ∅
is always a codeword.

Definition 11 (The poset PCode) Let C and D be neural codes. We say that D is a
minor of C (written D ≤C) if there is a surjective morphism f : C →D. As a consequence,
this relation defines a partial order on the set of distinct isomorphism classes of neural codes,
denoted by PCode.
Note that the above definition no longer allows “replace C by a trunk” as a possible
covering relation as in (Jeffs, 2020) since we require the ∅-codeword to be in every code.
However, the following proposition shows that with a small adjustment we do not lose too
much when doing this.
Proposition 12
Let T be a (possibly empty) trunk in a neural code C. Then, {∅}∪T ≤C.
Proof
Consider the function sending T ⊂C to itself and all other codewords in C to ∅.
This function from C to {∅} ∪T is obviously surjective and a morphism of neural codes
because the preimage of any proper trunk TkT (σ) in T is equal to TkC(σ) ∩T which is a
proper trunk in C.
3. Upward Covering Relations in PCode
In this section, we provide a method to describe all codes that cover a given neural code D in
PCode as opposed to Appendix A. To fully understand the development of how we construct
covering codes, the reader may read Appendix B before this section.
In Appendix B,
we instead described C in terms of D when they both are intersection-complete. In the
following, we extend the idea in Appendix B to all neural codes. We start by showing
that every covering relation C and D in PCode extends in a natural way to a covering
relation between their intersection-completions. The hat notation (e.g. bC) will be used to
denote the intersection-completion of any code (e.g. C). This extension will be a key tool
in characterizing all upward covering relations in PCode.

Our first result below says that the constructions in Definition 18 do not differ too much:

code, we will always obtain the covering code bD[I] of Definition 32 (Appendix B).
Theorem 19
Let D be a code, I ⊆bD an isolated subset with the minimal codeword µ,
and C one of the covering codes described in Definition 18. Then bC = bD[I].
Proof
In every type of covering code in Definition 18, we see that the new neuron α is
only added to elements of D ∩I (possibly, except for µ). Comparing this to Definition 32
(Appendix B), we see that C ⊆bD[I]. Since bD[I] is intersection-complete, this immediately
implies that bC ⊆bD[I].
It remains to prove the reverse inclusion. Let c ∈bD[I]. We must show that c is an
element or an intersection of elements of C. First, suppose that c contains α and is not
µ∪α. Then c\α is an element of I and equal to an intersection of some codewords in D. If
any of the codewords whose intersection is c \ α is not an element of I, then Definition 17
implies that c \ α = µ, a contradiction. Therefore, c \ α is an intersection of codewords in
(D ∩I) \ {µ}. In every type of covering code, we add α to all such codewords, and hence c
is an intersection of some codewords in C as desired. Next, suppose that c does not contain

Corollary 20
Every covering code C described in Definition 18 covers D in PCode.
Proof
Let C be one of the covering codes of Definition 18. Note that there is a natural
surjective morphism f : C →D given by deleting the neuron α. By Lemma 13 we obtain
a unique surjective morphism g : bC →bD, which extends f. By Lemma 14, C covers D if
and only if bC covers bD. Theorem 19 tells us that bC is equal to bD[I], which covers bD by
Theorem 40 (Appendix B). Thus, C covers D as desired.

Appendix A. Downward covering relations in PCode: a revision

assumption that the ∅-codeword exists in any neural code. We will characterize the down-

covered by a given neural code C in PCode.
Definition 22 (Trivial and redundant neurons)
Let C ⊆2[n] be a neural code.
A

exists σ ⊆[n] \ {i} such that TkC(i) = TkC(σ).
Definition 23 (Covered neural codes)
Let C ⊆2[n] and for j ∈[n] let Tj = TkC(j).

Tj ∩Ti ̸= Ti}. This code is denoted C(i).

Appendix B. Intersection-complete neural codes
This section is supplementary to Section 3. We will focus only on intersection-complete
codes. It turns out that describing all codes that cover a given neural code C in PCode is a
simpler task if we assume that C is intersection-complete and restrict our attention to the
intersection-complete codes that cover it. We will use these results in Section 3 to describe
the general case. Isolated subsets defined in Definition 17 are the key objects that we will
use to describe the covering relation in PCode for intersection-complete codes. Our main
construction is as follows.

Proposition 33
A code C is intersection-complete if and only if the assignment σ 7→
TkC(σ) defines a bijection between C and its nonempty trunks.
Proof Assume the map σ 7→TkC(σ) is a bijection between C and its nonempty trunks. Let
σ1, σ2 ∈C, and T an inclusion-minimal trunk that contains both codewords. Then there is
σ such that T = TkC(σ). Clearly, c ⊆σ1 ∩σ2 since σ is contained in both σ1 and σ2. If σ
were a proper subset of σ1 ∩σ2, then TkC(σ1 ∩σ2) would be properly contained in T, which
is a contradiction to the choice of T. Thus, σ = σ1 ∩σ2.
Conversely, suppose C is intersection-complete. The assignment σ 7→TkC(σ) clearly
defines an injection because σ is the unique minimal element of its trunk in C. The map
is a surjection because if T is a nonempty trunk then the intersection of all elements of T
must be a codeword σ such that T = TkC(σ).
This proposition gives us a quick way to compare the numbers of trunks between any
two intersection-complete codes based on the numbers of their codewords.
Proposition 34
Let C be an intersection-complete code and I ⊆C an isolated subset of C
with minimal element µ. Then, {µ} ∪(C \ I) is intersection-complete.
Proof Definition 17 implies that the intersection of codewords in C \I is an element of C \I
or equal to µ. Intersecting an element of C \I with µ itself yields either µ or some codeword
in C that is below µ which is definitely not in I. Thus {µ}∪(C \I) is intersection-complete.

Let C be an intersection-complete code and I ⊆C an isolated subset. The
code C[I] of Definition 32 is intersection-complete.

(ii) f(µ) = f(µ \ {i}).
Proof
For (i), suppose for contradiction that µ \ {i} was not a codeword of C. Then
