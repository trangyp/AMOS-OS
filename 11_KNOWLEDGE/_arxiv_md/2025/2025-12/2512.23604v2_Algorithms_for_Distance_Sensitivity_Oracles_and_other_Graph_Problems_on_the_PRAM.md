Algorithms for Distance Sensitivity Oracles and other Graph
Problems on the PRAM∗
Vignesh Manoharan and Vijaya Ramachandran
Abstract
The distance sensitivity oracle (DSO) problem asks us to preprocess a given graph G = (V, E) in
order to answer queries of the form d(x, y, e), which denotes the shortest path distance in G from vertex
x to vertex y when edge e is removed. This is an important problem for network communication, and
it has been extensively studied in the sequential setting [7, 5, 23, 16] and recently in the distributed
CONGEST model [14]. However, no prior DSO results tailored to the parallel setting were known.
We present the first PRAM algorithms to construct DSOs in directed weighted graphs, that can
answer a query in O(1) time with a single processor after preprocessing. We also present the first work-
optimal PRAM algorithms for other graph problems that belong to the sequential ˜O(mn) fine-grained
complexity class: Replacement Paths, Second Simple Shortest Path, All Pairs Second Simple Shortest
Paths and Minimum Weight Cycle.

Introduction
In a network modeled by a graph G = (V, E), we investigate the problem of computing shortest path distances
when an edge e ∈E fails. Specifically, we need to answer queries d(s, t, e) for s, t ∈V, e ∈E, where d(s, t, e)
is the shortest path distance from s to t in G when edge e is removed. This is a fundamental problem in
network communication for routing under an arbitrary edge failure.
Let |V | = n, |E| = m. Since explicitly computing all distances would be prohibitively expensive due
to output size, we instead consider Distance Sensitivity Oracles (DSOs).
In the DSO problem, we first
preprocess the graph G to construct an oracle that stores certain information in order to answer queries
quickly. Note that without any preprocessing, we can answer a query using a single source shortest path
(SSSP) computation. The goal in DSO construction is to obtain a faster query time, ideally constant query
time, while keeping the preprocessing cost reasonable.
The DSO problem has received considerable attention in the sequential setting. Starting from [7], al-
gorithms with different tradeoffs between query time and preprocessing time were obtained, culminating
in an efficient algorithm with preprocessing time ˜O(mn), which constructs a distance sensitivity oracle of
size ˜O(n2) that can answer any query in O(1) time [5]. This construction nearly matches the best runtime
of APSP. Other algorithms addressed DSO for dense graphs [16], and higher query time [23]. Recently,
the DSO problem was studied in the distributed CONGEST model [14] where the input graph models the
communication network itself.
Despite the importance of the DSO problem, no non-trivial DSO constructions are known for the parallel
setting. In this paper, we present three PRAM algorithms for computing DSOs in directed weighted graphs.
All our algorithms involve a preprocessing step, after which queries can be answered in O(1) time using
a single processor.
Our algorithms have a range of tradeoffs between work and parallel time used for
preprocessing.
While our main focus in this paper is on the DSO problem, we address other related graph problems as
well. If the source and target vertices s, t ∈V are fixed, the problem of finding all distances d(s, t, e) is known

1.1
Preliminaries
The PRAM model
In the Parallel RAM (PRAM) model [19], computation is performed by a number
of synchronous processors accessing a shared memory. We specifically use the work-span model to ana-
lyze the cost of computation, which avoids concerns such as number of processors and scheduling tasks to
processors. The total number of operations performed over all processors is called the work. The longest
chain of dependencies between these operations is called the span. There are different variants of the PRAM
model - EREW, CREW, CRCW - depending on whether more than one processor is allowed to read (Exclu-
sive/Concurrent Read) or write (Exclusive/Concurrent Write) to the same location in the shared memory.
In our algorithms we use the CREW model, but we can readily translate between these models using known
reductions with only polylogarithmic increase in cost. We use the notation ˜O to hide poly-logarithmic factors
in our costs.
Let G = (V, E) be a directed weighted graph, let |V | = n, |E| = m. Each edge (s, t) ∈E (for s, t ∈V )
has a non-negative integer weight w(s, t). We denote the shortest path distance from s to t by d(s, t). We
use d(s, t, e), for s, t ∈V, e ∈E, to denote the shortest path distance from s to t in the graph G −{e}, i.e.,
the graph G with edge e removed, also known as the replacement path distance.
We first define the DSO problem as follows.
Definition 1. Distance Sensitivity Oracles (DSO) Problem: Compute d(x, y, e), the x-y shortest path dis-
tance when e is removed, for any pair of vertices x, y ∈V and any e ∈E. A DSO algorithm is allowed to
perform some preprocessing on the graph G to construct on oracle, which then answers queries of the form
d(x, y, e).
In a PRAM algorithm for DSO, we assume that the query can be accessed by any processor. When the
query algorithm terminates, the answer to the query is stored in the shared memory. The parameters of
interest in a PRAM algorithm for DSO are as follows:
1. Preprocessing work and parallel time: The work and parallel time required during preprocessing to
construct the DSO.
2. Query work and parallel time: The work and parallel time to answer a distance query.
3. Oracle Size: Total number of words stored for the oracle after preprocessing.
In this paper, we primarily focus on DSOs with a query cost of O(1) work on a single processor.

Roadmap

1.3
Prior Work
The DSO problem has been studied extensively in the sequential setting (e.g.
[7, 4, 5, 23, 16, 8]).
No
non-trivial algorithms for DSO were known in the PRAM setting. The other graph problems studied in
this paper (such as RPaths, MWC, and 2-APSiSP) also have not been previously investigated in the PRAM
model.
PRAM algorithms for shortest path problems in graphs have been studied extensively: The first algo-
rithms for SSSP tailored to PRAM were given in [12, 20], with the current best work-optimal algorithm for
directed exact SSSP taking ˜O(m) work and ˜O(n1/2+o(1)) parallel time [6]. Approximate SSSP has also been
studied, with improved ˜O(1) parallel time for undirected graphs [18].
APSP can be solved in the PRAM in ˜O(n3) work and ˜O(1) parallel time [9]. For sparser graphs, a
deterministic algorithm for directed weighted APSP was given in [10] that takes ˜O(mn + (n/d)3) work and
˜O(d) parallel time, for a parameter d ∈[1, n]. This improves on a randomized parallel transitive closure
trade-off of [21].

Framework for Distance Sensitivity Oracle
Our PRAM algorithms for DSO use techniques from sequential DSO algorithms [7, 5, 16, 23]. In this section,
we describe a framework for DSO construction due to Bernstein and Karger [5]. In Sections 4 and 5, we
will use different implementations of this framework along with other techniques in our PRAM algorithms.
We present our results for edge removal (this can be modified for vertex removal as in [5]). Recall that the
sequential DSO construction of [5] has ˜O(mn) preprocessing time, ˜O(n2) space requirement, and O(1) query
time.
The DSO framework of [5] is described in Algorithm 1.
We described the essential aspects of this
algorithm now.
Each vertex in the input graph G = (V, E) is assigned a priority k, where k ∈{1, 2, . . . log n}, and a
vertex with priority k is called a k-center. In each x-y shortest path, for x, y ∈V , the algorithm identifies a
sequence of centers of strictly increasing priority up to the maximum, followed by strictly decreasing priority
to y. A center x covers an edge e, if e is on its outgoing (or incoming) shortest path tree, and there is no
center of higher priority on the shortest path from x to e. Thus, the sequence of centers partitions the path

The algorithm precomputes distances d(x, y, e) for all y ∈V and edges e ∈E that are covered by center

interval that maximizes the replacement path distance when it is removed. The following data is computed
during preprocessing, where x, y ∈V, e ∈E and i ∈{1, 2, . . . 2 log n} :
• CR[x, y, i]: first center of priority-≥i on x-y shortest path.
• CL[x, y, i]: first center of priority-≥i on reversed y-x shortest path (edge directions flipped).
• BCP[x, y]: biggest center priority on x-y shortest path.
• Di[x, y, e]: distance d(x, y, e), where x is a center of priority i that covers e.
• BV [x, y, i]: bottleneck edge of interval i on x-y shortest path.
• DBV [x, y, i]: distance d(x, y, BV [x, y, i]), for each interval i.
In the PRAM model, we can store these values in the shared memory and utilize them to answer queries.

looking up O(1) values, as shown in Algorithm 1. Note the distinction from the distributed DSO algorithms
in [14] had to perform additional work, as these values may be computed at different nodes and then need
to be communicated.

PRAM algorithms for other graph problems
We present PRAM algorithms for other graph problems in the sequential ˜O(mn) time fine-grained complexity
class: RPaths, 2-SiSP, 2-APSiSP, MWC and ANSC. We define these problems as follows:
Definition 3. Replacement Paths (RPaths) : Given a pair of vertices s∗, t∗∈V and a shortest path Ps∗t∗
from s∗to t∗, for each edge e ∈Ps∗t∗, compute d(s∗, t∗, e), the s∗-t∗shortest path distance when e is removed.
Definition 4. Second Simple Shortest Path (2-SiSP) : Given a pair of vertices s∗, t∗and a shortest path
Ps∗t∗from s∗to t∗, compute the weight d2(s∗, t∗) of a shortest simple path P2 from s∗to t∗that differs from
Ps∗t∗by at least one edge.
Definition 5. All Pairs Second Simple Shortest Path (2-APSiSP): Compute d2(x, y), the x-y second simple
shortest path (2-SiSP) distance, for all pairs of vertices x, y ∈V .
Definition 6. Minimum Weight Cycle problem (MWC): Compute the weight of a shortest simple cycle in
G.
Definition 7. All Nodes Shortest Cycles (ANSC): For each vertex u ∈V , compute the weight of a shortest
simple cycle through u in G.
Our main strategy in developing PRAM algorithms for these problems is to adapt existing sequential
algorithms, leveraging work-optimal PRAM subroutines for APSP [10] and SSSP [6].
6.1
RPaths and 2-SiSP
In this section, we present our algorithms for RPaths and 2-SiSP in different graph types. Our algorithm
for directed weighted RPaths and 2-SiSP uses a subroutine for APSP, adapting a sequential result from [2].
Our directed unweighted algorithm adapts a sequential result from [17] and uses SSSP as a subroutine.
Finally, our undirected (weighted or unweighted) algorithm uses SSSP in addition to a characterization of
replacement paths from [11].
Theorem 8. Given a graph G = (V, E), vertices s∗, t∗, we can compute RPaths and 2-SiSP in the PRAM
model in the following bounds:
A. If G is directed and weighted, the algorithm takes ˜O(mn) work and ˜O(n1/3) parallel time.
B. If G is directed and unweighted, the algorithm takes ˜O(m√n) work and ˜O(√n) parallel time.
C. If G is undirected (weighted or unweighted), the algorithm takes ˜O(m) work and ˜O(√n) parallel time.
Proof.
A. For directed weighted RPaths, we employ a reduction from RPaths to APSP in [2]. A similar
reduction was explored for a distributed directed weighted RPaths algorithm in [13]; here, we adapt
it to the PRAM model. This reduction involves constructing a modified graph, a step that requires
only O(m+n) work and O(1) parallel time in the PRAM model. The dominant cost is the subsequent

## Page 11


APSP computation. By applying the work-optimal sparse APSP algorithm of [10] (which takes ˜O(mn)
work and ˜O(n1/3) parallel time), we achieve the stated bounds. Computing 2-SiSP is straightforward
once RPaths has been computed, as we just compute the minimum among replacement path distances
in O(n) work and ˜O(1) parallel time.
B. For directed unweighted RPaths, we implement a sequential algorithm in [17] on the PRAM. This
algorithm handles short and long paths separately. For short paths, it constructs √n auxiliary graphs
and computes SSSP in each. For long paths, it samples ˜Θ(√n) vertices and computes SSSP from each
sampled source. In the PRAM model, these ˜O(√n) SSSP computations can be executed in parallel. We
can readily verify that the computation apart from the SSSP subroutines can be performed in O(m+n)
work and ˜O(1) parallel time. Using the ˜O(m) work and ˜O(√n) time SSSP algorithm from [6] for each
of the ˜O(√n) instances yields the total ˜O(m√n) work and ˜O(√n) parallel time.
Whether this parallel time can be improved while maintaining work-optimality remains an interesting
open problem.
C. For undirected RPaths, a characterization of replacement paths in [11] gives us a method to compute
RPaths using SSSP computations. Implementing this algorithm in the PRAM setting, using the work-
optimal SSSP algorithm of [6], yields a PRAM algorithm with ˜O(m) work and ˜O(√n) parallel time.
6.2
MWC and ANSC
We now present our PRAM algorithms for MWC and ANSC. For both directed graphs and undirected
graphs, we use a reduction to APSP and then apply the PRAM APSP algorithm of [10].
Theorem 9. Given a graph G = (V, E), we can compute MWC and ANSC in the PRAM model in the
˜O(mn) work and ˜O(n1/3) parallel time.
Proof. The reduction from directed ANSC to APSP requires computing minu∈V d(u, v) + w(v, u) after all
APSP distances d(u, v) are computed. Clearly, the minimum computation can be implemented in PRAM in
˜O(n2) work and ˜O(1) time. MWC can be readily computed after ANSC distances are computed.
A similar reduction from undirected ANSC to APSP is more involved but again involves computing
minimums among O(n2) values (see [2, 22]).
In both cases, the bottleneck is the initial APSP computation. Therefore, applying the APSP algorithm
of [10] directly yields the ˜O(mn) work and ˜O(n1/3) parallel time bounds.
6.3
2-APSiSP
For 2-APSiSP, a work-optimal algorithm can be obtained by implementing a sequential algorithm of [1],
using ideas from a distributed CONGEST algorithm for 2-APSiSP in [14](TODO Alg refreence). However,
its parallel time of ˜O(n) is notably slower than the ˜O(n1/3) and ˜O(√n) bounds achieved for the other
problems. We leave improving the parallel time for a work-optimal algorithm as an open problem.
Another approach to compute 2-APSiSP is to apply our DSO algorithms, and then use DSO queries to
compute 2-SiSP distances. Using DSO-B gives us an ˜O(n3) work and ˜O(1) parallel time algorithm, which is
work-optimal for dense graphs.
Theorem 10. Given a directed weighted graph G = (V, E), we can compute 2-APSiSP in the PRAM model
in:
A. ˜O(mn) work and ˜O(n) parallel time.
B. ˜O(n3) work and ˜O(1) parallel time.

Proof. We use two different methods:
A. For our first algorithm, we build on the sequential algorithm of [1]. For ease of explanation, we follow
the steps of a distributed CONGEST implementation of this 2-APSiSP algorithm presented as Algorithm 6
in [15]. For completeness, we repeat this distributed implementation in the appendix as Algorithm 3.
The APSP computation and the n exclude computations used in Algorithm 3 can be implemented in a
work-optimal manner in ˜O(mn) work and ˜O(n1/2) parallel time: APSP only needs ˜O(n1/3) parallel time,
and implementing an exclude computation requires the same time as an SSSP computation [7].
Implementing the loop in Lines 7-13 of Algorithm 3 however, requires up to n iterations of extracting
elements from a priority queue to finalize each 2-SiSP distance. While the computation for paths ending
at different vertices y ∈V (i.e., handling Hy) can be parallelized, the computation within Hy seems to be
sequential and requires O(n) parallel time.
The work done per vertex y (for all x ∈V ) is still ˜O(n), and computing d2(x, y) for all y ∈V requires
˜O(n2) work (subsumed by ˜O(mn)). Thus, the total work is ˜O(mn), and the parallel time is ˜O(n).
B. Our second approach is to use the PRAM DSO algorithms that we designed in this paper. Once a DSO
is computed, the 2-SiSP distance can be computed as d2(x, y) = mine∈Pxy d(x, y, e), where Pxy is an x-y
shortest path for x, y ∈V . Thus, after computing APSP (which is done as part of DSO preprocessing) to
get the edges in each path, we need |Pxy| ≤n queries to compute d2(x, y) for a single vertex pair x, y. Thus,
2-APSiSP requires O(n3) queries for all O(n2) vertex pairs.
Thus, if we have a PRAM DSO algorithm with O(1) work to answer any query, and preprocessing cost
Pw work and Pt parallel time, then we obtain a 2-APSiSP algorithm with Pw + O(n3) work and Pt + ˜O(1)
parallel time. Using DSO-B with Pw = ˜O(n3) and Pt = ˜O(1) proves our result.
7
Conclusion and Open Problems
In this paper, we have presented the first non-trivial PRAM algorithms for DSO under single edge failure:
We constructed a work-efficient algorithm for dense graphs with ˜O(n3) work and ˜O(1) parallel time, match-
ing APSP. We also presented a work-efficient algorithm for sparse graphs with preprocessing work ˜O(mn)
matching sequential DSO [5] but with parallel time ˜O(n1/2+o(1)). While we have presented a work-time
tradeoff algorithm that can achieve sub-√n parallel time, it is not work-efficient.
We have obtained work-efficient PRAM algorithms for many other graph problems in the sequential
˜O(mn) time fine-grained complexity class, including RPaths, 2-SiSP, MWC, ANSC, 2-APSiSP. For 2-APSiSP,
we have presented two algorithms: a work-efficient ˜O(mn) algorithm with ˜O(n) parallel time, and an ˜O(n3)
work and ˜O(1) parallel time algorithm that is work-efficient for dense graphs.
Some open problems remain:
• The main open problem for DSO is whether there is a work-efficient DSO preprocessing algorithm with
˜O(mn) work and ˜O(n1/3) parallel time, matching the current best work-efficient PRAM algorithm for
APSP [10].
• A larger open problem is whether we can reduce the parallel time beyond n1/3 for both APSP and
DSO, while maintaining ˜O(mn) work.
• For 2-APSiSP, can we improve the ˜O(n) parallel time for our work-efficient ˜O(mn) work algorithm?
