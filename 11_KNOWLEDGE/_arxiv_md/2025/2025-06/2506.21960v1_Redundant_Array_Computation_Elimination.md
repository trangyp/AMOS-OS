Redundancy elimination is a key optimization direction, and loop nests are the main optimization target
in modern compilers. Previous work on redundancy elimination of array computations in loop nests lacks
universality. These approaches either focus on specific computation patterns or fail to recognize redundancies
with complex structures. This paper proposes RACE (Redundant Array Computation Elimination), a more
general redundancy elimination technique. RACE utilizes a novel two-level scheme to identify the data
reuse between array references and the computation redundancies between expressions. It traverses the
expression trees in loop nests to detect redundancies hierarchically in linear time and generates efficient
code with optimized auxiliary arrays that store redundant computation results. Furthermore, RACE supports
the expression reassociation with various aggressive strategies to improve the redundancy opportunities.
Experimental results demonstrate the effectiveness of RACE.
Additional Key Words and Phrases: Redundancy elimination, array computation, loop nests

INTRODUCTION
Redundancy elimination is one of the key optimizations in modern compilers [2, 16]. Generally,
redundancies fall into two types, unnecessary data movement and redundant computation. The first
type includes peephole optimization, copy propagation, and dead-store elimination. The second
type contains lazy code motion, dead code elimination, constant folding, common subexpression
elimination, value numbering [8, 9, 17, 18, 24, 27]. Most techniques in both types target scalar
variables and employ the data-flow analysis.
The loop nest transformation is another critical branch of optimizations. It reschedules the
computation in the iteration space of the loop nest, such as loop fusion, loop skewing, loop
unrolling, vectorizing, and loop tiling [1, 14, 29]. The primary purpose of these transformations is to
improve the data locality and/or expose loop parallelism. In addition, there are several techniques
to eliminate redundancies in loop nests. The loop-invariant code motion and induction variable
elimination remove redundant computations [2, 25], but they still focus on scalar variables. The
scalar replacement and array contraction target arrays, but they only reduce the array reference
overhead.
Computation redundancies widely exist in loop nests of real-world applications. Furthermore,
the redundancies are often related to arrays and across loop iterations, which is beyond the scope
of the above-mentioned classic compiler optimization techniques. Several techniques are developed
to exploit this kind of redundancy. Cooper et al. [10] propose the first redundancy elimination

Techniques related to arrays usually rely on data dependence analysis [13, 20, 23]. The data
dependence detection is generally undecidable since the addresses can be arbitrary functions.
Although most array references are expressed by affine functions of loop index variables, solving
the dependence precisely over the integer domain still constitutes an NP-hard problem, Diophantine
equations [4].
This paper proposes RACE, a novel redundancy elimination method for array computations
across loop iterations. Unlike previous work, which often utilizes data dependency analysis to
explore the redundancy, RACE distinguishes the principles between the data dependency for loop
transformation and the data reuse for redundancy detection. Then it utilizes a novel two-level
scheme to identify the array references reuse and the expression computation redundancy. The
redundancy can be easily discovered by grouping the expressions with the same identification
value.
RACE traverses the expression trees in loop nests to detect redundancies hierarchically. Previous
work usually requires all pair comparisons between expressions and incurs the 𝑂(𝑛2) complexity
for 𝑛expressions. However, RACE can complete the detection on the expression trees in linear
time based on the two-level identification scheme. It generates efficient redundancy-eliminated
codes with optimized auxiliary arrays that store redundant computing results. The code preserves
the original order in the expression evaluation by only considering redundancies between binary
operations, i.e. binary expression trees. Thus the result consistency is guaranteed.
Furthermore, RACE supports the expression reassociation with various aggressive strategies to
improve the opportunity for redundancy. This is equivalent to detecting redundancies on n-ary
expression trees, where the computation order can be reorganized. This paper makes the following
contributions:
• A novel two-level scheme to identify the array references reuse and the expressions compu-
tation redundancy.
• A linear accuracy-preserved algorithm for detecting hierarchical redundancies on binary
operations.
• An algorithm supporting expression reassociations for discovering more redundancies on
n-ary trees.
The remainder of this paper is organized as follows. Section 2 presents an example to explain
the basic idea of this work. Section 3 provides an overview of the related work. The two-level
identification scheme for finding the array reference reuse and expression computation redundancy
is introduced in Section 4. Section 5 describes the linear redundancy detection algorithm on binary
expression trees based on the two-level identification scheme and the optimization of the auxiliary
array organization. Section 6 provides the enhanced algorithm focusing on n-ary expression trees
and the simplification of the detection strategy. Section 7 presents the evaluation and Section 8
concludes the paper.

RELATED WORK
3.1
Data Dependence
The data dependence test [3, 16, 30] targets two array references and at least one of them is a
write. On the contrary, redundant computation means two or more expressions performing the
same operation on the same array elements (or the same values). Thus, the redundancy detection
focuses on reads. However, this is not an essential difference. The dependence techniques can also
be applied to find two array reads to the same memory address.
The essential differences between the data dependence test and the computation redundancy
elimination are three-fold. First, the dependence test seeks to check whether there is at least one
iteration that the two references access the same memory address. However, the redundancy
elimination in loops only targets a large number of common computations. Second, the practical
general dependence test technique is often conservative in the sense that it may report a false
dependence but must report all real data dependence. However, as an optimization technique,
the redundancy elimination should ensure a potential performance improvement. Finally, the
data dependence test focuses on array references, while the computation redundancy targets
expressions. Therefore, it needs a new method to determine the redundancy between two data
reuses and between two expressions.

3.2
Redundancy Elimination
Two classic redundancy elimination techniques for the scalar computation are the value numbering
and common subexpression elimination (CSE) [8, 9, 26]. The key idea underlying both methods is
to record the identification of the operands. The value numbering assigns the same number to the
variables that share the same value, while CSE utilizes the available expression in the data-flow
analysis to recognize the operand change. However, they only target scalar variables.
Cooper et al [10] propose the enhanced scalar replacement (ESR), the seminal redundancy
elimination method for loops. ESR employs two classic optimization techniques, value numbering
and classic scalar replacement (CSR) [6]. ESR has the following disadvantages. First, ESR only
considers the recomputation across the innermost loop. It fails to discover all redundancies. Second,
ESR incorporates the scalar replacement, which relies on advanced data dependence analysis.
However, data dependence is not suitable for redundancy detection, which requires a more precise
definition and method. Third, ESR is a two-step method that separates the name partition and
index alignment. It will compare the unnecessary expressions that are not redundant. Fourth, the
affinity graph in ESR fails to discover redundant computations of the arrays within the same name
partition. Finally, ESR seeks to find the maximal computation redundancy in a single execution of
their algorithm. However, as the example in Section 2 demonstrates, the computation redundancy
may exhibit a hierarchical property.
Deitz et al [12] proposed array subexpression elimination (ASE) for sum-of-product array ex-
pressions. Like ESR, it also aims to eliminate the redundancies over the innermost loop dimension.
ASE depends on a specific framework called neighborhood tablet to search the redundancy. Basu
et al [5] targeted stencil computations and designed a specific optimization scheme. It employs
extra arrays to buffer partial sums within the leading plane of the whole iteration space. However,
it only focuses on simple stencils and reduces redundant computations effectively for stencils with
symmetric coefficients. These methods lack generality and fail to process complex subexpressions,
e.g. 𝑎(𝑖) ∗𝑐(𝑗,𝑘). Chi and Cong [7] developed heuristic search–based reuse (HSBR) for stencil
computations. They did observe the conflict between expressions but did not formalize it as we do.
RCE (redundant computation elimination) [31] is able to explore redundancies with temporal
locality for stencils but their search algorithm compares all possible expressions and incurs high
overhead. This scheme is also utilized by the loop-carried CSE method proposed in [19]. On the
contrary, our method assigns each expression a hash number and redundancies can be easily
identified by extracting expressions with the same hash number. Wen et al [28] implemented a
profiler to pinpoint redundant computations by runtime checking. It finds redundancies in several
stencil computations and eliminates them by hand-written optimizations
Redundancy elimination, as well as many other compiler optimizations, such as loop transforma-
tion, memory access optimization and vectorization, relies on the results of aliasing analysis [11, 15].
Alias analysis disambiguates memory references, primarily serving for the legality verification or
candidate selection. For example, existing work like ESR [10] selects the redundancy candidates
using the results of data dependence analysis which implicitly incorporates alias analysis. Thus,
alias analysis is orthogonal to these optimizations to some extent. Furthermore, existing aliasing
analysis techniques are powerful but not panaceas. Other mechanisms such as the restrict key-
word, -fno-alias compiler option, and #pragma ivdep directive are provided to enable more
aggressive optimizations. Therefore, in this paper, RACE focuses on the detection technique of
redundancies, instead of directly incorporating alias analysis.

REDUNDANCY IDENTIFICATION
This section first limits the scope of this paper. Then, the following two parts describe the two-level
redundancy identification scheme. The first level focuses on data sharing among array references.
Each array reference is assigned with an identification to determine its reference pattern. Array
references with the same identification value may access a sufficiently large set of common array
elements. The second level identifies the redundancies among expressions. As mentioned before,
the proposed method detects redundancies hierarchically. Thus, the second identification only
focuses on expressions with two operands, and larger expressions will be processed iteratively.
With this two-level hash mechanism, RACE achieves linear-time redundancy detection, while
all previous methods require direct pair-wise comparisons between expressions which incurs a
quadratic time complexity. The computation redundancy can be easily discovered by grouping the
expressions with the same identification value in linear time.
4.1
Target
This paper describes our work using perfectly nested loops, where all the statements are inside
the innermost loop. The experiment was also conducted on perfectly nested loops with no branch
statement inside the loop. However, the design is easy to be extended and our implementation is

5.1
Detection Algorithm
Redundancy elimination stores the intermediate result and reuses it for the same succeeding
calculations. Therefore, it can intrinsically guarantee the consistency of the final computing result.
Results consistency is usually important for scientific applications that involve floating-point
arithmetic operations. To achieve this, the computing order must be respected. Thus we first
present the detection algorithm working on the high-level intermediate representation (IR), where
the computation order is fixed.
The value numbering works on linear IR, such as the three-address code. It just requires one
sequential traversal of the IR code to find all redundancies. The reason is that each expression
𝑎= 𝑏⊕𝑐can be assigned a number used for the following redundancy check, regardless of whether
𝑏and 𝑐are redundancies. However, in the array redundancy detection of 𝑎= 𝑏[. . . ] ⊕𝑐[. . . ], the
rpi is only defined on array references 𝑏[. . . ] and 𝑐[. . . ], and the eri can only be computed on 𝑎. If
there is a following statement 𝑒= 𝑎⊕𝑑[. . . ], it cannot check the redundancy of 𝑒until 𝑎is replaced
with a new array 𝑓[. . . ] storing the redundant value 𝑏[. . . ] ⊕𝑐[. . . ].
To find all redundancies in linear time, the detection algorithm of array computations works on
the binary expression trees in a bottom-up scheme, as shown in Algorithm 3. First, the rpi values
of all the leaves in the expression trees are set to ∞. In each iteration of the do-while loop, all
the leaves are associated with their rpi values, and the expressions whose two sons are leaves are
assigned their eri values. Then, all the eri values are compared to find redundancies.

the corresponding operations with auxiliary array references in the expression trees. These new
references must coordinate their subscripts. To do this, we select one representative expression
for each auxiliary array. For example, cos(𝑢𝑙𝑎𝑡(𝑖, 𝑗)), cos(𝑢𝑙𝑎𝑡(𝑖, 𝑗−1)), cos(𝑢𝑙𝑎𝑡(𝑖−1, 𝑗)) and

It may demand the reorganization of expressions to find redundancies for array computations and
even classic scalar calculations with commutative, associative, and distributive operations. Consider
the two expressions 𝑥+ 𝑦+ 𝑧and 𝑥+ 𝑧. Compilers may specify a pre-defined order for the former

right-associative rule, but none of them can detect the redundancy with 𝑥+ 𝑧unless the expression
is allowed to be reordered by commutative, associative, and even distributive reorganizations. Note
that the commutative law here is not the same as the one used in the eri calculation, where the
expressions only have two operands.
However, to produce consistent results, it is generally illegal to perform the operation reasso-
ciation even for the integral computation. Take the expression 𝑥+ 𝑦+ 𝑧as an example again, if

ertheless, compilers usually provide options to control the expression reorganization for aggressive
optimizations and leave the decision to users.
Therefore, the implementation of RACE provides several options to control the reassociation
scheme. We describe them by three aggressive levels. First, if a consistent result is required, the
reassociation is prohibited and the linear redundancy detection algorithm described above is
employed. Second, all the parentheses in the source code are respected, and the reorganization
can be only applied inside each parenthesis which includes more than two operands. Third, the
parenthesis is removed when the operators are consistent with the one outside the parenthesis.
Finally, the distributive law is applied to remove more parentheses. The tree flattening algorithm is
trivial according to the aggressive level. It simply traverses the original binary tree in a post-order
manner and merges the children that have the same operator as the current node after visiting
them.
The first three levels are simple. However, the distributive law should be applied cautiously. It may
destroy existing redundancies. For example, it is obvious that there are two pairs of redundancies
in 𝑒= (𝑎[𝑖] +𝑏[𝑖]) ∗(𝑐[𝑖] +𝑑[𝑖]) + (𝑎[𝑖+ 1] +𝑏[𝑖+ 1]) ∗(𝑐[𝑖+ 2] +𝑑[𝑖+ 2]), i.e. eri(𝑎[𝑖] +𝑏[𝑖]) =
eri(𝑎[𝑖+ 1] +𝑏[𝑖+ 1]) and eri(𝑐[𝑖] +𝑑[𝑖]) = eri(𝑐[𝑖+ 2] +𝑑[𝑖+ 2]). However, if the distributive law
is applied, both of the redundancies disappear since none of the binary multiplication expressions
has the same eri. Moreover, the distributive law may incur more computations. For example, there
are 2 multiplications and 5 additions in 𝑒, but 8 multiplications and 7 additions after removing the
parentheses. The detailed discussion is beyond the scope of this paper.
In practice, we only apply distributive law to a constant or loop-invariant scalar variable multiplier.

It is well-known that MIS is an NP-hard problem. For a small number of expressions, the optimal
solution can be found by the exhaustive method that enumerates all the possible MIS solutions
within a reasonable time. However, for loop nests with numerous expressions and operands, the
exhaustive method becomes computationally infeasible within a reasonable time. We then introduce
a heuristic strategy to reduce the problem size by considering expressions with specific conditions.
6.3
Heuristic Strategy
The array’s memory access patterns in real applications are typically regular and symmetric. As
described in Section 5.2, the auxiliary arrays can be compressed to lower dimensions to save
memory and improve the cache performance. Based on the observation, we propose a heuristic
algorithm called dimension-first extraction, which aims to find solutions with a higher potential
for compression while reducing the problem size. This approach increases the opportunity to
leverage cache locality and vectorization. Figure 4 illustrates how the dimension of auxiliary arrays
can be further reduced using the dimension-first extraction method. For instance, if we choose
𝑅(𝑖−1,𝑘, 𝑗) + 𝑅(𝑖+ 1,𝑘, 𝑗) as an auxiliary array in the first iteration of our algorithm, it cannot
be compressed to a one-dimensional array because its reuses are along the 𝑗or 𝑘dimension.
Furthermore, other solutions like 𝑅(𝑖−1,𝑘−1, 𝑗) + 𝑅(𝑖−1,𝑘, 𝑗−1) are irregular and may result in
discrete memory access, leading to poor locality. In contrast, if 𝑅(𝑖,𝑘, 𝑗−1) + 𝑅(𝑖,𝑘, 𝑗+ 1) is chosen,
it can be reused along 𝑖dimension.
Dimension-first extraction is a greedy algorithm that prioritizes selecting expressions with zero
delta in the innermost dimension, i.e., 𝑒.exprDelta[𝑖𝑛] = 0. A zero delta in the innermost dimension
indicates that the reuses are more likely to occur along the innermost 𝑖𝑛dimension, as demonstrated
in the example in Figure 4. The algorithm runs in a try-until manner. First, it only generates the
nodes with exprDelta[𝑖𝑛] = 0 when constructing Delta Graph. This forms a subgraph of the original
Delta Graph, containing significantly fewer nodes. If any solutions are found, the algorithm accepts
them and returns the control to the Algorithm 5 to proceed to the next extraction iteration. If
no solution is found, the algorithm will generate a new subgraph containing only nodes with
exprDelta[𝑖𝑛−1] = 0 and try to find the solution of this graph, repeating this process until it finds a
solution at some dimension 𝑖.
This algorithm improves the performance of finding the solution by significantly reducing the
number of nodes and edges in the Delta Graph. Without this algorithm, the mgrid case will generate
more than one hundred nodes in the Delta Graph. In practice, the solution for Figure 4 is found
almost immediately with the dimension-first algorithm, whereas the search algorithm may take
much longer to find a suboptimal solution. Additionally, there are multiple solutions satisfying

CONCLUSION
This paper proposes RACE, which defines a two-level hashing algorithm to detect redundant
array computations in nested loops. The first-level hash uses rpi to determine whether two array
references share the same memory access pattern. The second-level hash computes eri for each
binary expression as an attribute within the expression, which encodes the expression-level reuse
without explicitly comparing two different expressions. A linear-time detection algorithm for binary
expression trees is proposed based on eri. After extraction, code generation and optimization of
the auxiliary arrays are discussed.
Furthermore, tree flattening and the Delta Graph are introduced to identify redundancies in n-ary
trees. The objective function for optimal single-iteration redundancy elimination is defined using
the Delta Graph, which is reduced to a maximum independent set (MIS) problem. To accelerate the
solution of this problem, a memory-friendly heuristic algorithm is presented to identify auxiliary
arrays with inner-loop reuse.
Experiments show that our algorithm achieves significant speedups on various benchmarks,
and the effectiveness of the detection algorithm for n-ary trees and the dimension-first heuristic
strategy is demonstrated.
