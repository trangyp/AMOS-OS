1. Introduction
Strings are fundamental data structures in many programming languages,
widely used to model sequences such as DNA, RNA, protein molecules, and
even time series.
A string s is defined as a finite sequence of characters
drawn from a (typically finite) alphabet Σ. A key concept in analyzing sim-
ilarities between strings is a subsequence—a sequence derived from a string
by deleting zero or more characters without changing the order of remaining
characters. Detecting structural similarities among multiple strings is cen-
tral to both stringology and molecular biology. One of the most widely used
tools for this purpose is the identification of common subsequences, which can
help uncover relationships among sequences and reveal meaningful biological
or structural patterns, such as mutations. Advances in genome sequencing
have further enabled the analysis and reconstruction of genomic data using
such techniques. A core optimization problem in this context is the Longest
Common Subsequence (LCS) problem [1], defined as follows: Given a set of
input strings, find a longest sequence that is a subsequence of each of the
input strings. The LCS problem has broad applications in computational
biology [2], file plagiarism detection, data compression [3, 4], text editing [5],

and spatial data analysis, such as identifying road intersections from GPS
traces [6]. Practical applications include file comparison tools like the Unix
diff command [7] and revision control systems such as Git.
To solve the LCS problem when the number of input strings m is fixed,
polynomial-time algorithms based on dynamic programming (DP) have been
proposed [8]. However, their practical applicability remains limited due to
the rapidly growing computational complexity in respect to the number of
strings and the strings’ lengths.
To address this, several advanced meta-
heuristics have been developed to solve LCS variants more efficiently in prac-
tice. State-of-the-art methods are based on effectively exploring the state
space graph [9, 10, 11], combined with carefully crafted, problem-specific
search guidance strategies. These methods have been tested on both arti-
ficial and real benchmark datasets, revealing the strengths and drawbacks
of these approaches on various instance distributions.
In parallel, exact
approaches have advanced through the use of best-first search frameworks
and their extensions to hybrid anytime algorithms [12]. Over the past two
decades, practical variants of the LCS problem have gained increasing at-
tention in the research community. Notable examples include the longest
common arc subsequence problem [13], the repetition-free LCS problem [14],
and the constrained LCS problem [15], among many others.
More recently, research efforts have turned toward understanding gene
mutations and reconstructing genomic data, aiming to uncover the evolution-
ary history of molecular sequences. This goal is formalized by the Longest
Filled Common Subsequence (LFCS) problem, which is inspired by another
real-world application, the scaffold filling problem [16, 17] from genomic data
reconstruction. The LFCS problem (LFCSP) was introduced by Castelli et
al. [18]. Briefly, the problem involves two sequences: the original sequence
and one that requires repair. Additionally, a multiset of symbols is provided,
which can be used for the repair. The goal is to insert some (or all) of these
symbols into the second, shorter, sequence to maximize its similarity to the
original sequence.
The application of LFCSP can clearly extend towards
a broader range of research areas involving sequential data that may suffer
from information loss, such as audio querying or corrupted text recovery [19].
Concerning the methodological appraoches to solve the LFCSP from the
literature, in [18] the authors proposed two 3

gave a formal proof on the APX-hardness of the LFCSP, even when the first
input string contains at most two occurrences of each symbol from the al-
phabet Σ. This result was established via a reduction from the maximum

• Scalability: Existing benchmark instances are limited to small and

ity and limitations of these methods have not been fully thoroughly
explored.
Moreover, the current literature lacks real-world problem
instances, or at least instances with characteristics appearing in real-
world applications.
• Heuristic Potential: The heuristic methods developed stand far from
leveraging advanced search operators or learning mechanisms com-
monly used in modern optimization, leaving room for significant method-

• Explainability: There is a lack of systematic analysis to explain the
performance of algorithms based on instance characteristics or inter-
nal algorithmic behaviors—a growing area of interest in optimization
research.

• A state-of-the-art ILP-based metaheuristic approach is proposed for

solving approaches. The second dataset comprises realistic LFCSP in-

2. Problem Definition and Notations
Given two input strings A and B over an alphabet Σ, and a multiset
M in which symbols from Σ may appear arbitrary many times, we call a
sequence B∗a filled subsequence of B w.r.t. M if it can be obtained by
inserting (some) symbols from M into the string B. The LFCSP seeks to
find a filled sequence B∗such that the length of the LCS among A and B∗
is maximized across all possible filled versions of the initial string B.
This LFCSP can alternatively be formulated in terms of deleting symbols
from input string A, allowing a possibly more intuitive interpretation and
more constrained search space for solving the LFCSP: Consider looking for
symbols from M that match symbols in A and deleting these symbols from A,
resulting in a subsequence A′. Let r be the number of these removed symbols,
i.e., r = |A| −|A′|. We are now aiming for a solution that maximizes this
number plus the length of the longest common subsequence among A′ and
B, i.e.,
obj(A′) = r + LCS(A′, B).

3.1. Approximation Algorithms
Castelli et al. [18] described two approximation algorithms for the LFCSP.
As both provide the same approximation factor of 3/5, and as, during ex-
perimentation, we observed no statistically significant difference between the
results of the two approaches, we limit ourselves to providing the details of
one of them here.
The basic workflow of the algorithm, henceforth called Approx, is as
follows.
• Determine an LCS of A and B. Let R1,a denote the set of positions in
A matched by the alignment of the LCS.
• Remove all positions of R1,a from A, and denote the resulting string by
A′.
• By applying the procedure GreedyMatch as described below, com-
pute a set R1,i of positions of A′ of maximal size that matches M by
insertion.
• Let R1 = R1,a ∪R1,i be the set of resulting positions returned by the
algorithm, representing the LFCSP solution.
Procedure GreedyMatch(A′, M) works as follows:
• Set ˜A = ε, R1,i = ∅
• Proceed letter-by-letter from left to right over string A′ and check if the
current symbol A′[i] = α is free/available to be matched, i.e., appended
to ˜A.
• If yes (α ∈M is confirmed), append α to ˜A ( ˜A ←˜A · α), remove α
from M (M ←M\{α}), and add i to R1,i. Otherwise, skip the letter
and move to the next letter of A′;
• When all letters of A′ were considered, the algorithm terminates by
returning ˜A and the set of positions R1,i.

3.2. A Randomized Greedy Construction Method
The following randomized greedy solution construction was proposed by
Mincu and Popa [20].
• Select a subset of symbols from A to match as many symbols as possible
from M. Let the positions of these matched symbols in A be denoted by
R1,a. For instance, if A contains three a ∈Σ symbols and M contains
four, all three a symbols in A (and their positions) are subsequently
matched. Conversely, if A has four a symbols and M has three, then
three out of the four a positions in A are randomly selected to match
between symbols.
• Obtain string A′ by removing all selected positions in R1,a.
• Determine an LCS for A′ and B; the quality of the obtained solution
equals to LCS(A′, B)+|A| −|A′|.
Mincu and Popa apply this randomized construction nrand = 10000 times
and finally return a best obtained solution, and so do we in our experimental
comparison.
3.2.1. Local Search Methods
The following local search method has also been proposed by Mincu and
Popa [20].
• For a fixed k, we consider all consecutive substrings of size k of string
A, i.e., A[1, k], A[2, k + 1], etc. obtained by windowing sequence A.
• For each such substring, we take all possible combinations of letters (2k
of them) and match them with symbols from M. For the remaining
(non-matched) parts of sequences A and B, the LCS is determined, and
the quality of the obtained filled common subsequence (i.e., solutions) is
reported. Following a first-improvement strategy, any new best solution
identified is accepted as new incumbent.
• In each major iteration, up to 2k ·(n−k) candidate solutions are there-
fore considered and evaluated.
The authors refer to the algorithm as Sk, and the two settings k = 2 and k =
4 are considered in the evaluation. We will do the same in our experimental
comparisons.

4. A New Hybrid ILP/Metaheuristic Approach for the LFCSP
The ILP from the last section performs well on small- to medium-sized
instances, roughly up to n = 80, see [20]. We build on this and set out to
develop an ILP-based metaheuristic capable of efficiently solving significantly
larger instances. A promising frameworks for this purpose is the Construct,
Merge, Solve, and Adapt (CMSA) approach originally proposed by Blum et
al. [21]. Since its introduction, CMSA has achieved state-of-the-art results
in a wide range of problem domains, including bioinformatics [24], the field
of software engineering and the product line of software [25], planning [26],
packing and routing [27], among others. For more information on CMSA and
its variants, the reader is referred to the recent survey paper [28]. The core
idea of CMSA is to iteratively generate promising subproblems that are solved
using an external solver, which—in our case—shall be an ILP solver applied
to a model based on the previously presented one. Over successive iterations,
the components that form these subproblems are adapted based on their
historical contribution to high-quality solutions. This is achieved through
an aging mechanism, where promising components are retained longer in the
search process, while less useful components are discarded rather quickly.
This dynamic adjustment enables the approach to continuously refine the
search space and improve solution quality over time.
10


## Page 11


In each major iteration, CMSA performs four main steps, as already indi-
cated by the title of the algorithm. The construction phase is responsible for
a typically rather fast generation of a set of diverse solutions of reasonable
quality. The merge phase defines a sub-instance of the problem of restricted
size that considers only solution components of an initially empty pool plus
the newly generated solutions’ components. The solving phase, solves this
sub-instance with a time limit. Finally, the adapt phase takes care of award-
ing or penalizing solution components and preparing the pool for the next
iteration. The model that is usually used is the aging model, i.e., each com-
ponent that appears in the new incumbent solution is awarded by resetting
its age to zero, while the age of all other components is incremented. Com-
ponents whose age exceed a threshold are removed from the pool.
To improve the robustness of CMSA—particularly its sensitivity to pa-
rameter tuning across different instance sizes—several variants have been
proposed in the literature. Among them, the self-adaptive CMSA (or Adapt-
CMSA) has demonstrated enhanced performance on various problems, in-
cluding influence maximization in social networks [29] and graph partition-
ing [30]. For a comprehensive overview of CMSA and its variants, we refer
to [22]. In contrast to the basic CMSA, the self-adaptive variant eliminates
the need for a manually parameterized adapt phase. Instead, the compo-
nents of a sub-instance are retained only during the iteration in which they
are generated. The algorithm dynamically adjusts key parameters such as
the number of generated solutions (na) and a similarity threshold (αbsf) that
govern the balance between intensification and diversification. This param-
eter adaptation is driven by the solution obtained during the solve phase of
each iteration. At the end of each iteration, components from the best-so-far
solution are passed to the subsequent iteration which, combined with newly
generated solutions, will serve to create a new subproblem. The size of the
sub-instance in the next iteration is controlled by the value αbsf—the larger
αbsf, the larger is the diversity in the components of newly generated solu-
tions. This mechanism allows the algorithm to continuously refine its focus
based on accumulated search experience, leading to improved scalability and
robustness across diverse problem instances.

6. A Case Study: Audio Fingerprinting
Audio fingerprinting is a widely used technique for identifying songs based
on short, potentially noisy audio excerpts. A canonical system is Shazam [33],
which extracts prominent spectral peaks from a song and hashes pairs of them
into compact fingerprints. These are stored in a large-scale database and en-
able fast, noise-tolerant matching even for low-quality recordings.
Other
robust alternatives include Panako [34] and Audfprint [35], among others.
These methods generally rely on exact or approximate matching of robust
audio features and assume at least partial preservation of time-local struc-
ture.
When audio is recorded using low-end microphones or under challenging
conditions such as high noise levels, lossy compression, or variable latency,
much of the structure typically relied upon by fingerprinting systems may
be lost or severely degraded. While established systems like Shazam and its
variants are highly effective in many practical settings, they are not designed
to operate with extremely fragmented or partially observed data. In such
scenarios, alternative formulations like the LFCSP approach offer a different
perspective. Rather than competing directly with conventional fingerprint-
ing, LFCSP represents one of several directions that could be further explored
to address highly degraded or incomplete audio inputs.
To compare songs meaningfully, a variety of signal representations have
been proposed:
• Spectrograms: A basic but powerful representation computed using
the Short-Time Fourier Transform (STFT), showing how amplitudes
are distributed across frequencies over time.
• Mel-Spectrograms: Spectrograms warped onto the Mel scale to better
reflect human perception of pitch and loudness.
• MFCCs: Mel-Frequency Cepstral Coefficients summarize the spectral
envelope of a sound and are popular in speech and speaker recognition.
• Learned Embeddings: Models such as OpenL3 [36], VGGish [37] pro-
duce high-level embeddings from audio using deep learning trained on
25


## Page 26


large datasets. These embeddings capture abstract musical or semantic
properties.
• Energy Profiles: A simplified yet informative representation used in this
work is the energy profile, where consecutive parts of audio (seconds
in our study) are converted into discretized energy levels (e.g., one of
10 bins from {0, .., 9}).
This results in a one-dimensional symbolic
sequence that captures loudness and dynamics, and is robust to time
stretching and pitch shifts.
LFCSP in the context of audio footprinting is defined over three compo-
nents:
1. Sequence A (candidate song),
2. Sequence B (noisy audio query),
3. Multiset M of additional symbols derived from B but without known
temporal positioning.
In this application, the solution to LFCSP is used to identify a song
from a known database of high-quality recordings, i.e., a set of candidate
sequences As = {A1, A2, . . .} based on a noisy or incomplete energy profile
B (evidence), supplemented with additional unordered energy information
M, which acts as a histogram of symbols with unknown temporal positions.
We construct audio fingerprinting LFCSP instances1 based on energy pro-
files of 8 well-known songs:
• A1: Adele – Rolling in the Deep
• A2: Daft Punk – One More Time
• A3: Fugees – Killing Me Softly (reference song)
• A4: Madonna – Like a Prayer
• A5: Queen – Bohemian Rhapsody
• A6: Radiohead – Creep
• A7: Rihanna & Calvin Harris – We Found Love

(referring to an alphabet Σ = {0, . . . , 9}). In a practical system, identification
would typically proceed in two phases. The first phase would quickly elimi-
nate vast majority of songs from a large-scale database (potentially millions
of entries) by comparing coarse global features, such as energy histograms.
Only a small set of candidates, those whose histograms closely resemble that
of the query would proceed to the second, more precise phase in which the
LFCSP algorithm is applied to this refined set of similar candidates.

7. Model Explainability Analysis
To provide a more comprehensive comparison of the algorithms, we apply
explainable algorithm performance prediction. This analysis is conducted on
both the Small and Large benchmark sets. Each dataset is partitioned into
training and test set scenarios, with 25% of the problem instances randomly
selected for testing. For each algorithm, a separate single-target regression
(STR) model is trained using four instance features to predict its final so-
lution quality.
To evaluate the contribution of these features, we employ
the SHapley Additive exPlanations (SHAP) method [38].
SHAP provides
both global feature importance—indicating the overall impact of each fea-
ture on the model’s predictions across the entire dataset—and local feature
importance—reflecting the influence of each feature on individual instance
predictions. By computing feature importance for each algorithm-specific
model, we enable a comparative analysis of how instance characteristics af-
fect predicted performance across the different algorithms.

8. Conclusions and Future Work
This paper addressed the Longest Filled Common Subsequence (LFCS)
problem, a combinatorial optimization problem with practical relevance in
bioinformatics, particularly for identifying gene mutations and reconstruct-
ing genomic data. To effectively solve this problem, we utilized a variant
of the robust metaheuristic framework known as Construct, Merge, Solve,
Adapt (CMSA). Our proposed variant incorporates several tailored compo-
nents. In the construction phase, we adapted a randomized algorithm from
the literature to generate diverse solutions within a parameterized neigh-
borhood of the current best solution. The generated solution components
are then merged efficiently to build a promising subproblem, which is solved
40


## Page 41


using an Integer Linear Programming (ILP) technique. At subsequent it-
erations, new subproblems are dynamically generated based on the quality
of the obtained solution, automatically adjusting the number of solutions to
be constructed in each iteration as well as the value of the parameter that
controls the level of diversification between the solutions. To evaluate the
scalability and robustness of our approach relative to five existing methods
from the literature, we introduced an additional synthetic dataset compris-
ing 120 large-scale problem instances. These instances are approximately an
order of magnitude larger than those previously studied, allowing for a more
thorough and realistic assessment of algorithmic performance under practical
conditions. A comprehensive experimental evaluation has demonstrated the
effectiveness of our CMSA-based approach, which consistently outperformed
all competing methods in terms of solution quality across all datasets. This
superiority is further confirmed by the number of instances for which the
approach was successful in identifying optimal solutions. Specifically, out of
1,510 problem instances solved to optimality, our method successfully solved
1,486 problem instances–substantially more than the second-best approach.
In addition to synthetic problem instances, a set of real-world problem in-
stances is generated. These are used in a case-study analysis involving audio
fingerprinting, demonstrating the reliability of LFCSP in identifying proper
songs within a noisy audio query scenario. To further investigate the rela-
tionship between instance features and algorithmic performance across all six
approaches, an explainable AI technique is applied, specifically the Shapley
Additive Explanations (SHAP). This analysis identified key combinations of
features that significantly influence algorithm performance. For our CMSA-
based method, the most influential feature was the length of the first input
sequence (n), followed by the cardinality of the multiset M (k). Interestingly,
the length of the second input sequence (|B|) had a largely negligible effect
on performance, particularly on the large synthetic benchmark set. This ob-
servation suggests that the ability to effectively identify a substantial number
of matchings between elements of the first sequence and those of the multiset
represents a critical set of decisions for producing high-quality solutions.
For future work, the ability and robustness of our approach in practical
gene data reconstruction scenarios could be exploited.
Furthermore, sev-
eral variants of CMSA from the literature offer a huge potential for further
performance enhancements. In particular, the reinforcement learning-based
CMSA method proposed by Reixach et al. [40] avoids traditional greedy de-
cision making during solution construction, potentially improving solution

formulation, which could lead to improved solution quality within the CMSA

Moreover, integrating insights from various machine learning
models tailored to the problem domain presents an exciting research direc-

strategies by identifying promising symbols and respective positions for a
quick omission when constructing high-quality solutions.
