We introduce CLAPP (CLASS LLM Agent for Pair Programming), an interactive AI assistant de-
signed to support researchers working with the Einstein-Boltzmann solver CLASS. CLAPP leverages
large language models (LLMs) and domain-specific retrieval to provide conversational coding sup-
port for CLASS—answering questions, generating code, debugging errors, and producing plots. Its
architecture combines multi-agent LLM orchestration, semantic search across CLASS documenta-
tion, and a live Python execution environment.
Deployed as a user-friendly web application,
CLAPP lowers the entry barrier for scientists unfamiliar with AI tools and enables more produc-
tive human-AI collaboration in computational and numerical cosmology. The app is available at
https://classclapp.streamlit.app/
I.
INTRODUCTION
Modern cosmology depends critically on advanced,
well-established computational tools.
A prominent
example is CLASS1 (Blas et al., 2011; Lesgourgues,
2011; Lesgourgues and Tram, 2011) (the Cosmic Lin-
ear Anisotropy Solving System), a widely used Einstein-
Boltzmann solver for calculating cosmic microwave back-
ground anisotropies and large-scale structure observ-
ables.
CLASS is, alongside CAMB (Lewis et al., 2000),
one of the major codes in the community and is widely
used in cosmological research. CLASS, like many cosmo-
logical tools, contains a large codebase with extensive
documentation, which can be difficult to navigate and
time-consuming to work with even for experienced re-
searchers. For new users, the sheer size of CLASS—over
60,000 lines of code and 198 tunable parameters in its
explanatory.ini configuration file—presents a signifi-
cant challenge. Typically, engaging with such a codebase
involves studying technical manuals, reverse-engineering
examples, and extensive trial-and-error—processes that
are often tedious and error-prone.
In
parallel,
recent
advances
in
artificial
intelli-
gence—especially the advent of large language models
(LLMs) such as GPT-4—have shown promise in assist-
ing with code generation, natural language querying,
and technical problem-solving.
These models are in-
creasingly capable of understanding complex instructions
and producing helpful responses. However, off-the-shelf
LLMs are not trained on specialized scientific software
and may hallucinate incorrect details or fail to under-
stand domain-specific context. They often also provide

CLAPP9 is an AI-based pair-programming assistant tai-
lored specifically for the CLASS code. It provides a con-
versational interface that understands the structure and
functionality of CLASS and its Python wrapper classy,
and assists users by answering technical questions, writ-
ing and executing code, debugging, and generating plots.
CLAPP is designed with accessibility in mind, aiming to
support both experts and cosmologists with no prior ex-
perience in AI tools.
In this article, we present the design and function-
ality of CLAPP, and explain how it integrates emerging
AI techniques into the computational workflows com-
mon in cosmology. We highlight three key components of
its architecture: (1) multi-agent LLM orchestration, (2)
retrieval-augmented generation (RAG) over a vectorized
CLASS knowledge base, and (3) live code execution and
plotting through a secure Python environment. Our goal
is both pedagogical and practical: to demonstrate how
LLM-based systems can be applied to real-world scientific
codebases, enabling new modes of human-AI collabora-
tion.

II.
CLAPP ARCHITECTURE AND FEATURES
CLAPP is built as a multi-component system that or-
chestrates language model agents, a knowledge database,
and the CLASS code execution environment. At a high
level, a user interacts with CLAPP through a chat inter-
face, asking questions or requesting assistance with cod-
ing tasks related to CLASS. Under the hood, CLAPP’s ar-
chitecture (illustrated in Fig. 1) ensures that the AI’s re-
sponses are accurate, relevant, and actionable by combin-
ing several advanced components. We outline the main
features here, corresponding to the three technical pillars
of the system.
A.
Multi-Agent LLM Orchestration
Rather than relying on a single monolithic AI agent,
CLAPP employs a team of specialized language models
that collaborate to generate high-quality responses. This
architecture is built using the AG2 10 (Wang et al., 2024;
Wu et al., 2023) multi-agent framework, which enables
coordinated interaction among multiple LLMs within a
shared conversational context.
In Deep Thought Mode, a specialised CLASS agent first
drafts a response to the user’s query.
A review agent
then evaluates this draft, scoring it and providing feed-
back on any logical, stylistic, or technical issues. Subse-
quently, the response is updated based on the feedback
received. This review–improvement loop continues until
the response meets a predefined quality threshold or a
maximum number of iterations is reached. Then the fi-
nal, validated response is processed by a formatting agent
and returned to the user.
Each agent is powered by either an OpenAI or Gemini
model and is guided by a role-specific prompt—for exam-
ple, the reviewer is instructed to be especially critical and
precise.
This division of labor effectively simulates an
automated peer-review process, allowing CLAPP to catch
errors and refine explanations before delivering them to
the user.
Alternatively, users can opt for Fast Mode, which re-
turns the initial draft immediately without any internal
review. While this mode may be less accurate, it sup-
ports real-time streaming and is well-suited for rapid,
iterative workflows.

Knowledge
A key feature of CLAPP is its ability to ground responses
in the official CLASS documentation and codebase of the
latest available CLASS version.

All relevant materials—including the CLASS user man-
ual, parameter descriptions, example scripts, and docu-
mentation for the Python wrapper classy—are prepro-
cessed and stored in a local vector database. When a
user submits a query, CLAPP does not rely solely on the
LLM’s internal knowledge (which may be incomplete or
outdated). Instead, it performs a semantic search over
the vectorized CLASS documentation to retrieve the most
relevant context. This is done by embedding the user’s
question into a high-dimensional vector space and match-
ing it against precomputed embeddings of the documen-
tation using a FAISS vector store with HuggingFace em-
beddings. In the current version, we employ the embed-
ding model all-MiniLM-L6-v2 with a chunk size of 1000
and overlapp of 200 tokens.
The four top-matching snippets are then injected into
the LLM prompt, allowing CLAPP to quote or paraphrase
authoritative content directly from the CLASS materials.
This approach significantly reduces hallucinations and
ensures that responses are consistent with the actual be-
haviour and structure of the CLASS codebase.
For example, when asked “What does the parameter
omega b do in CLASS?”, CLAPP retrieves the relevant sec-
tion from the manual and accurately explains that it
represents the physical baryon density—grounding the
answer in the original documentation. The same mech-
anism applies to code generation tasks, where retrieved
code snippets guide the LLM in producing correct API
calls or configuration options.
The knowledge base is also modular and updateable:
new content (e.g., additions to the class-data/ direc-
tory) can be indexed and incorporated without retrain-
ing.
In this way, CLAPP combines the generative ca-
pabilities of large language models with the reliability
of curated scientific resources, producing answers that
are both informative and trustworthy for cosmology re-
searchers.
C.
Agent–Human Chat
CLAPP is designed as an interactive chat interface be-
tween the user and the CLAPP AI. Internally, CLAPP em-
ploys a team of specialized AI agents; however, this com-
plexity is abstracted away in the user interface, which
displays only finalized, formatted responses while omit-
ting the internal agent-to-agent dialogue.
To maintain continuity across interactions, we aggre-
gate the outputs of both the main AI agent and the
user into a conversational memory using the LangChain
framework11 LangChain (2024). This enables seamless,
11 https://www.langchain.com
context-aware dialogue by preserving the history of the
exchange.
In Fast Mode, CLAPP additionally supports real-time
message streaming, also powered by LangChain, to en-
hance responsiveness.
This design allows users to engage in an iterative work-
flow with the AI—akin to pair programming with an
expert collaborator who remembers previous steps and
adapts accordingly.
D.
Code Execution and Plotting
What further sets CLAPP apart is its integration with
an actual runtime environment for CLASS. CLAPP not only
talks about code – it can run code. Through the use of
an "Install CLASS" button, the app downloads the full
CLASS code, compiles it and installs its Python wrapper
classy in the current Python environment.
The user
can check the installation and a plot is produced to ver-
ify that the installation was successful (see appendix A
for details).
When the app detects that Python code
was generated, a "Run Last Code Block" button will
be activated which can be pressed to execute the classy
code. This behavior can be equally obtained by typying
"execute!" or "plot!" in the agent chat. If the code
produces a plot, CLAPP captures the image and displays
it in the chat. If the code contains errors, the error mes-
sages are captured and a sequential chat is started where
the executor and debugger agent interact with each other
up to three times, to correct mistakes or bugs in the code,
see lower part of fig. 1. The error message is automat-
ically analyzed by a debugging agent, which provides a
corrected version of the code – this might involve fixing
a typo, adjusting a function call, or reminding the user
to install missing dependencies. This error-recovery loop
continues until a working solution is found or a clear ex-
planation of the failure is provided.
CLAPP essentially
serves as a virtual “pair programmer,” catching mistakes
and providing fixes in real-time. The ability to generate
plots on the fly is particularly useful for scientific ex-
ploration: a researcher can ask for “a plot of the linear
matter power spectrum for a given set of parameters,”
and CLAPP will produce the code, execute it, and display
the plot – all within the chat window. This tight inte-
gration of documentation, code generation, and execu-
tion shortens the cycle of experimentation dramatically,
letting users focus on understanding results rather than
wrestling with software syntax.
