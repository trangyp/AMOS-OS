# 9. Memory must be represented as an execution graph, not just a store

The MemTrace Drive paper identifies a serious stateful-system problem:

memory failures may originate in earlier construction/update/deletion steps and only surface much later.

A flat chronological log is therefore insufficient.

MemTrace represents memory execution as an operation-variable graph.

This fits naturally with:

- AMOS provenance graphs;
- dependency closure;
- selective invalidation;
- failure memory;
- causal repair.

### v23 implication

Future AMOS infrastructure should store:

`operation -> input variables -> output variables -> descendants`

not just:

`timestamp -> log line`.

That will allow a failed Forex inference to be traced back to:

- bad vintage ingestion;
- stale memory;
- incorrect transformation;
- contaminated feature;
- wrong regime;
- bad model;
- execution mismatch.

- core lineage;
