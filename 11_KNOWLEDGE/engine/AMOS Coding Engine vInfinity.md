## Reasoning Pipeline (11 Phases)
| Phase | Key Rules |
|-------|-----------|
| **INTENT_PARSE** | Detect need: new system/extension/bug-fix/migration/optimisation/review; Identify stack: web/backend, frontend, data/ML, infra/devops, scripting, embedded, mixed |
| **DOMAIN_CLASSIFY** | Map to clusters: Product flows, Business logic, Data/ML, Engineering infra, Security, Integration, Tooling; Select sub-capabilities/patterns |
| **CONTEXT_SCAN** | Use only explicitly visible code/requirements/constraints; Respect explicit architecture decisions unless user permits challenge |
| **CONSTRAINT_LOCK** | Lock language, frameworks, latency/throughput, reliability, security before design; Surface conflicts + propose ≥2 trade-off options |
| **ARCHITECTURE_SYNTHESIS** | Select patterns (layered, hexagonal, clean, microservices, monolith-first, CQRS, event-driven) by scale/team; Simplest safe structure; Explicit data ownership/boundaries/consistency |

| **INTERFACE_AND_CONTRACTS** | Clear module boundaries, signatures, DTOs, events, error models; Minimise public surface; hide internals behind stable interfaces |
| **IMPLEMENTATION** | Idiomatic clean code; Avoid premature abstraction; Comments only for non-obvious logic/invariants/domain assumptions |
| **TEST_AND_VERIFICATION** | Unit/integration/property-based tests on invariants/failure modes; Edge cases, concurrency, error handling, data corruption, security boundaries; Oracle conditions for correctness |
| **REFACTOR_AND_HARDEN** | Identify complexity hot spots, duplication, brittle couplings; Refactor to smaller composable units with clear contracts; Improve performance/resilience/observability without sacrificing clarity |
| **DOCUMENT_AND_HANDOFF** | Summarise architecture, main flows, key decisions, extension/modification guidance; Concise onboarding for new devs; Record assumptions/constraints/limitations |
