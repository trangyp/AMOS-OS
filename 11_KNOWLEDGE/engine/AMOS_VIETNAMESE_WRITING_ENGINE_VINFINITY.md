## Phase 1: Foundational Writing Principles (v1.0)
**GOAL**: Build highest-level Vietnamese writing system for corporate leadership, national planning, strategic negotiation, tech markets, executive comms. Focus: clarity, precision, logic flow, real impact, persuasion of senior leadership.

### 10 Foundational Principles
1. **Structure-first**: Objective → Arguments → Evidence → Conclusion. Never write without structure.
2. **Every sentence answers a question. Every paragraph solves a problem.**
3. **Write for clarity/decision, not "beauty"**: rõ, hiểu, ra quyết định.
4. **Executive tone**: trọng tâm, đẳng cấp, súc tích, không rườm rà.
5. **No emotion, no flowery language**: phẳng, chuẩn, gọn.
6. **Logic priority**: cause→effect, root cause→solution→action.
7. **Short words, short sentences, short points — but deep.**
8. **Always close the loop**: open issue → process → action conclusion.
9. **Signature style**: sắc, thẳng, sạch nhiễu, trọng lượng.
10. **Zero waste**: no extra words, lines, or ideas.

### Universal Writing Structure (8 Rules)
- Rule 1: Every doc starts with "What problem does this solve?"
- Rule 2: 40% diagnosis — 40% solution — 20% recommendation
- Rule 3: 3-part structure: Context — Problem — Solution (always works)
- Rule 4: Long docs = 7 sections: objective, current state, gap, root cause, options, impact, implementation conditions
- Rule 5: For busy leaders: What? Why? How? When? Who? Cost?
- Rule 6: For tech teams: Standards, requirements, changes, risks, timeline, metrics
- Rule 7: For government: Systemic benefit, safety, standards, social impact, national strategy alignment
- Rule 8: For foreign partners: Clear, transparent, data-driven, logical, no circularity

**GOAL**: Absolute precision — every sentence exact, short, unambiguous. 20× power via sentence structure, processing speed, instant decision transmission.

| SECTION_47_AMBIGUITY_SUPPRESSION_ENGINE | No dual-meaning words in business context. If 2 interpretations possible → rewrite. No unquantified phrases: "somewhat", "to some degree". No implicit questions. Every sentence = clear endpoint. |
| SECTION_48_HIGH_DENSITY_INFORMATION_MODEL | Short sentences with full logic. Don't split meaning if combinable. Fewer words, more meaning. Every word must earn its place. Avoid adjectives unless direct value. |
| SECTION_49_DECISIVE_LANGUAGE_ENGINE | Prefer: choose, eliminate, deploy, confirm, decide, require. Ban: may, should, perhaps, try, explore further. Sentences conclude, don't open. No permission. No probing. No hedging. Tone = decision authority. |
| SECTION_50_EXECUTIVE_SENTENCE_STRUCTURE | Open with action/conclusion, not context. No subordinate clause before main clause. Avoid weak conjunctions ("and", "but") if splittable. Structure: Goal → Requirement → Impact. Consistent sentence order throughout. |
| SECTION_51_EXECUTIVE_CLAUSE_COMPRESSION | Max 18-22 words/sentence. Max 1 comma/sentence. No nested clauses. If >20 words → evaluate split. Long sentences = mandatory info; short sentences = action priority. |
| SECTION_52_SIGNAL_TO_NOISE_RATIO | SNR ≥ 0.85 (85% info, 15% connectors max). No paragraph SNR < 0.7. Paragraphs lead with most important info. Noise = non-value words → minimize. 1 message/paragraph, never more. |
| SECTION_53_ALIGNMENT_WITH_EXECUTIVE_READING_PATTERN | Leaders read vertically, not horizontally. Each sentence standalone meaningful. Avoid inter-sentence dependencies. Paragraph structure: wide → narrow → conclusion. Info order = decision logic order. |
| SECTION_54_HIGH_CLARITY_GRAMMAR_RULES | Prefer explicit subjects; avoid hidden subjects. Avoid passive unless needed. Punctuation for clarity, not length. No ellipsis — weakens power. No rhetorical questions in admin writing. |
| SECTION_55_CLARITY_TESTS_ENGINE | Test 1: Can a newcomer understand immediately? Test 2: Remove 30% words — meaning intact? Test 3: Read only this sentence — action clear? Test 4: If 2 interpretations possible → default WRONG. Test 5: If needs example to clarify → not standard yet. |
| SECTION_56_SENTENCE_ERROR_DETECTION | Detect: unnecessary subordinate clauses, context/condition openings, weak/impactless verbs, ambiguous words, sentences not driving clear action. |
| SECTION_57_SENTENCE_REWRITE_ENGINE | Rewrite rules: passive→active, description→conclusion, speculation→action, long→short, vague→clear. |

1. Every doc serves decision, not performance.
2. Every doc answers: What? Who? When done?
3. Prefer short/clear. Long only when needed (policy, regulations, contracts).
4. Respect hierarchy, but no excessive deference.
5. Minimize adjectives/adverbs.
6. Minimize quotation marks for emphasis; only for official quotes.
7. Direct: proposals, recommendations, warnings — no beating around.
8. Tone control: no negative/personal attacks; only systems, processes, results.
9. Prefer pure Vietnamese; English terms only when necessary with explanation.
10. Anti-vague: sentences with "need/should/consider" must have owner + deadline.

## TRANG_VN_PRO_WRITING_ENGINE v2.0
**GOAL**: Standardize VN writing + formatting for CTO/BoD level. Clear, formal, practical for internal reports, BoD papers, legal docs, biz proposals, government docs, technical docs, SOPs.

### Formatting Global Standards (10)
Font: Times New Roman/Arial. Size: 13 body, 14 heading, 16-18 cover. Line spacing: 1.3-1.5. Paragraph spacing: 6pt before/after. Margins: T2/B2/L2.5/R2 cm. Numbering: 1.0, 1.1, 1.1.1. Left align. Tables: titled, thin borders, 12-13pt. Charts: 1 main + 1 accent color, cite source/units. Header/footer: doc name/unit + "Page X/Y".

### 7 Document Type Formats
- **Internal docs**: 1-3 pages, professional/neutral, bullets, whitespace
- **Email**: Subject format [Action]-[Content]-[Time]; Body: Greeting→Reason→Content→Request→Thanks; Max 2 topics, 25 lines
- **Board Paper**: Cover page, 1pg exec summary (bullets: issue, option, cost, risk, ask), 5-15pg body, visuals minimal, tone formal/action-oriented
- **Government Docs**: VN admin template (State emblem, motto, date, sender, recipient); Tone respectful/cautious, legal citations; Structure: Legal basis → Proposal → Social benefit → Request; 3-7 pages; Minimize English, no flowery words, facts first
- **Policy/SOP**: Title → Scope → Definitions → Process → Forms → Effective; Imperative style: "Phải", "Không được", "Chỉ được khi"; Flowcharts, step tables, checklists; Legal/policy consistency
- **Technical**: Specs → Parameters → System reqs → Testing → Standards; Precise, no inference, data/tables; SI/industry units; Numbered figures
- **Business Proposal**: Summary → Opportunity → Product/Solution → Biz model → Financials → Roadmap → Support ask; Revenue-cost-breakeven 3 scenarios; Realistic, no hype; Cultural fit: safety, stability, sustainable growth, policy alignment; PDF+Word; No legal binding without legal review; End: specific ask (meeting, decision, next step)

### Tone & Language Rules (10)
No McKinsey fluff. VN leader style: short, direct, deep, shows system understanding + responsibility. No personal criticism. Clear verbs: triển khai, đánh giá, rà soát, phê duyệt, điều chỉnh. Zero emotion words: "rất", "quá", "cực kỳ". No vague: "kha khá", "tương đối", "hơi", "có lẽ". No direct commands — use "đề nghị", "yêu cầu theo chức năng". Proper honorifics. No grandstanding: "đột phá", "cách mạng" without data. VN culture: respect, humility, but clear and effective.

### Structure Logic Engine (10)
Every doc answers: Why? What? How? Logic order: Context→Problem→Analysis→Solution→Recommendation→Action. Minimize noise: no emotion/speculation/verbose examples. Data first. Simple graphics: bars, lines, 3-row comparisons. Risk honesty: every decision doc = risks + mitigations. Actionable steps: specific steps, owners, deadlines. No unbounded promises. Clear splitting: 1,2,3 not run-on. 3-pass review: logic-language-format.

### Advanced Corporate Writing (10)
